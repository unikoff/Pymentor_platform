# Структура `src`

- `app/` — запуск React-приложения, его сборка и общие стили; Dockview, реестр панелей, команды и сохранение раскладки сгруппированы в `app/workspace/`.
- `features/` — функциональные области: авторизация, обучение, аккаунт и админ-панель. API, состояние и типы предметной области находятся рядом с функцией; `index.ts` каждой области задаёт её публичные импорты для `app/`.
- `shared/` — повторно используемые UI-компоненты, темы, API-клиент, общие контракты и утилиты; этот слой не зависит от `features/`.
- `lessons/` — реестр и материалы уроков, сгруппированные по главам. `components/` содержит общие блоки страниц; `shared.ts` сохраняет единый публичный импорт для уроков.

Общие стили оболочки подключаются через `app/styles.css`. Стили авторизации, кабинета, админ-панели, теории, практики и интерпретатора импортируются их компонентами и загружаются вместе с ними. Новую логику следует размещать рядом с функцией-владельцем; в `shared/` переносить только код, который действительно используется несколькими областями.

## Где менять интерфейс

| Область | Владелец |
| --- | --- |
| Цвета, поверхности, статусы, подсветка кода и схем | `shared/theme/palettes.ts` |
| Список доступных тем, их названия и базовая схема | `shared/theme/catalog.ts` |
| Применение и сохранение темы | `shared/theme/ThemeProvider.tsx` |
| Шрифты, шкала отступов, радиусы и размеры | `app/styles/tokens.css` |
| Базовые правила браузера и доступности | `app/styles/base.css` |
| Оболочка, навигация, вкладки и раскладка | `app/styles/workspace-*.css`, `app/workspace/` |
| Общий редактор, кнопки запуска, разделитель и терминал | `features/learning/code-workbench/` |
| Условие, запуск, проверка и состояние практики | `features/learning/practice/` |
| Регистрация и загрузка учебных страниц | `lessons/page-registry.ts`, `lessons/chapter_*/index.ts` |
| Каркас урока, задания, демонстрации и диаграммы | `lessons/components/`, `lessons/components/styles/` |
| Календарь и профиль ученика | `features/account/` |
| Аккаунты, прогресс и расписание администратора | `features/admin/`, `students/`, `progress/`, `slots/` |

Файлы `workspace.css`, `lesson-theory.css` и `practice.css` — точки подключения блоков стилей. Правила редактируются в соответствующем блоке. Общие кнопки и сообщения находятся в `shared/ui/controls.css`; стили отдельной панели импортируются непосредственно её компонентом. Порядок импортов важен для каскада. Стиль одного конкретного урока размещается рядом с этим уроком; общие блоки не копируются в главы.

## Отложенная загрузка

Публичные реестры областей объявляют панели через `lazyNamed`, а `AsyncBoundary` показывает ожидание и ошибку загрузки. `usePanelOpened` допускает загрузку содержимого Dockview только после первого фактического показа: восстановленная скрытая вкладка не загружает свой код и CSS. После открытия содержимое сохраняется при переключениях, включая код и результаты. Если панели расположены рядом, каждая видимая панель загружается сразу.

Календарь и доступные слоты запрашиваются внутри `AccountWorkspace` при открытии кабинета. Регистрация дня посещения выполняется отдельно в рабочей области. В админ-панели расписание и профиль ученика загружаются при выборе соответствующего раздела. При добавлении панели не импортируйте её CSS в общий манифест: подключайте его из компонента-владельца.

## Добавление темы

Тема — отдельный идентификатор и полная палитра. `colorScheme` определяет базовое поведение браузера и Dockview и может быть `dark` или `light`; количество идентификаторов тем этим не ограничено.

Добавьте запись в `shared/theme/catalog.ts`, наследуя подходящую палитру:

```ts
forest: {
  label: "Лесная",
  colorScheme: "dark",
  palette: { ...darkPalette, bg: "#101813", accent: "#a5df94" },
},
```

`ThemeId` и список вариантов выводятся из реестра. Когда вариантов больше двух, общий переключатель автоматически показывает выбор темы и в рабочей области, и на странице входа. Существующий ключ `pymentor-theme` сохраняется; неизвестное сохранённое значение приводит к теме по умолчанию.

Компоненты получают тему через `useTheme()`. В CSS используйте смысловые роли `--accent`, `--text`, `--surface`, `--error`, `--syntax-keyword` и другие переменные палитры. Цветовые значения задаются в палитре. Для прозрачности используется `color-mix()` с нужной ролью. Различия базовых схем оформляются через `data-color-scheme`, а не через название конкретной темы.

## Правила расширения

- `app/` собирает области через их публичные `index.ts`; состояние предметной области остаётся в своей `features/`.
- Общие части практики и интерпретатора меняются в `code-workbench/`; сохранение черновиков и результатов остаётся у каждого сценария.
- Общее необязательное хранилище находится в `shared/lib/storage.ts`. Ключи с пользователем, уроком и ревизией сохраняются, чтобы не смешивать черновики.
- Реестр главы содержит соответствия `путь .md из API → локальная страница без расширения`. Страницы загружаются при открытии через общий `defineLessonPages`; имя экспортируемого компонента совпадает с именем файла. При добавлении страницы достаточно одной записи в реестре главы. Ошибки загрузки и ожидание обрабатывает общий `LessonPageBoundary`.
- Новый учебный контент использует блоки из `lessons/shared.ts`. Большой файл с уникальным текстом урока не заменяется абстракциями ради количества строк.
- Зависимость проходит от страницы к компонентам и утилитам; `shared/` не импортирует `app/`, `features/` или `lessons/`.

Проверка фронтенда: `npm run build` из `frontend/` проверяет TypeScript и собирает стили и приложение.
Сохранённая в Git production-сборка обновляется командой `npm run build -- --base=/platform/`: хостинг не собирает фронтенд самостоятельно. При публикации нужен весь `dist/`, включая отдельные модули уроков.

Открывается одна пара учебных панелей: теория и практика выбранного занятия. Их общие `trackId` и `lessonId` обновляются вместе; расположение панелей сохраняется при смене занятия. Список занятий открывается в левой выдвижной панели из общей навигации, а Dockview управляет только учебными вкладками, аккаунтом и админ-панелью.

Кэш курсов и временное состояние практики находятся в `features/learning/`; Dockview управляет только расположением. Раскладки сохраняются отдельно для пользователя и гостя, а также для мобильного и настольного режимов. Предыдущие раскладки преобразуются в одну учебную пару. Сброс расположения не удаляет черновики и прогресс.
