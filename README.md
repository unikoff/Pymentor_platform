# Pymentor Platform

Личный проект образовательной платформы для самостоятельного изучения Python и backend-разработки. В одном интерфейсе студент проходит последовательную программу, решает практические задачи, отслеживает прогресс и записывается на занятия.

Проект собран как цельный продукт: от учебного контента и проверки кода до авторизации, управления доступом, расписания и административной части.

## Что умеет платформа

- Показывает учебные треки с теорией, видео, практикой и последовательной навигацией.
- Хранит прогресс по занятиям и открывает доступ в зависимости от регистрации и подписки.
- Поддерживает два типа практики: самостоятельные чек-листы и задания с автоматической проверкой Python-кода.
- Позволяет студенту выбрать свободный слот, записаться на занятие и отменить запись.
- Даёт администратору управление пользователями, подписками, квотами и расписанием.
- Ведёт активность по дням и показывает учебную статистику в профиле студента.

Сейчас каталог содержит 9 учебных треков, 230 занятий, 102 задания с проверкой кода и 128 ручных практик.

## Как это работает

```text
Браузер
  -> React-интерфейс
  -> FastAPI API
  -> SQLite: пользователи, сессии, прогресс, квоты и записи

Markdown-материалы
  -> загрузчик учебного контента
  -> треки, занятия и практика в интерфейсе
```

### Учебный контент

Материалы курсов лежат в Markdown-файлах. При запуске приложения они собираются в треки, модули и занятия. Так можно расширять программу без дублирования контента в интерфейсе.

Идентификаторы занятий и заданий зависят от исходного файла, а не от позиции в списке. Добавление нового материала не ломает сохранённый прогресс и открытые страницы занятий. Для ранее сохранённых отметок предусмотрена совместимость с прежними идентификаторами.

### Практика и проверка решений

Ручная практика состоит из понятных шагов и критерия результата. Автоматические задания принимают код, проверяют обязательные конструкции и запускают его в отдельном процессе Python.

Для проверки кода заданы ограничения: лимит длины, запрет небезопасных конструкций и тайм-аут выполнения. Результат возвращает статус, баллы, вывод и сведения о неуспешных тестах.

### Доступ и прогресс

Регистрация и вход работают через серверные сессии и HTTP-only cookie. Доступ к занятиям разделён на открытый, доступный зарегистрированным пользователям и доступный по активной подписке.

После успешной практики платформа сохраняет отметку о прохождении и пересчитывает прогресс по треку. Сервер также хранит активность по дням, записи на занятия и месячные квоты.

### Административная часть

Администратор может находить пользователей, просматривать профиль студента и его прогресс, управлять сроком подписки, квотами и слотами расписания. Удаление пользователя очищает связанные с ним данные и освобождает забронированные слоты.

## Технологии

- Frontend: React, TypeScript, Vite.
- Backend: Python, FastAPI, Pydantic, SQLAlchemy.
- Хранение данных: SQLite.
- Авторизация: серверные сессии и HTTP-only cookie.
- Проверка кода: отдельный процесс Python с ограничениями и тайм-аутом.
- Публикация: GitHub Actions собирает frontend для префикса `/platform/` и выпускает проверенную версию.

## Ключевые инженерные решения

- Учебные материалы отделены от интерфейса и описываются в Markdown.
- Стабильные ID и миграция прогресса защищают пользователей при изменениях каталога.
- Контрольный отпечаток учебного контента подтверждает, что production использует именно новую версию backend, а не только отвечает с HTTP 200.
- Ручная практика и автопроверка используют единый механизм зачёта урока.
- Права доступа проверяются на сервере перед выдачей полной теории, практики и сохранением прогресса.

## Работа с изменениями

Проект использует лёгкий процесс на базе GitHub Flow.

- `main` содержит актуальный исходный код и должен оставаться рабочим.
- `production` является технической веткой выпуска. Её изменяет только CI.
- Одна задача выполняется в одной короткой ветке: `feat/`, `fix/`, `refactor/` или `content/`.
- Изменения проходят проверку через pull request в `main`.
- После проверки используется squash merge, временная ветка удаляется.
- Критический исправляющий релиз оформляется как обычная ветка `fix/` и проходит тот же путь проверки.

Такой процесс оставляет историю понятной, снижает риск случайной публикации и не добавляет лишних промежуточных веток.
