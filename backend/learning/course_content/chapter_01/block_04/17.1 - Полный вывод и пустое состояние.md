# 17.1. Полный вывод и пустое состояние

Расширим просмотр, чтобы видеть каждую сохранённую задачу через прежний formatter.

**Темы:** formatter одной записи · обход списка · пустой случай · чтение без изменения данных

## 00. От добавления к полному просмотру

1. **Точка старта.** После предыдущего шага `add` сохраняет карточки в общем `tasks`, а `list` сообщает пустоту или количество.
2. **Новый вопрос.** Как показать каждую накопленную запись в прежнем формате, не меняя её поля и порядок?
3. **Результат.** Тот же `show_tasks` показывает пустой случай или все карточки через `format_task`, сохраняя данные без изменений.

Мы продолжаем тот же список после добавления: команда `add` уже показала только что принятую запись, а теперь `list` должна снова прочитать все накопленные карточки. Поэтому мы изменим одну функцию просмотра, сохранив прежние данные и формат.

## 01. Одна карточка и весь список

Функция `format_task(task)` уже превращает один словарь в одну строку. Она знает, как показать id, название, приоритет и состояние этой записи. Она возвращает строку, но сама ничего не печатает. Для нескольких карточек нужен отдельный шаг, который проходит по списку, передаёт formatter каждую запись и печатает его ответ.

**Прогноз.** Что вернёт прежний formatter для открытой задачи?

```python
task = {"id": 33, "title": "Review notes", "priority": 3, "is_done": False}
print(format_task(task))
```

Результат:

```text
[33] Review notes | приоритет: 3 | открыта
```

Formatter возвращает одну строку, а `print` показывает её на экране. Здесь выводится одна запись, потому что функция получает словарь, а не весь список. Новый алгоритм форматирования не нужен: функция просмотра отвечает за выбор пустого случая и передачу записей прежнему formatter.

Если formatter возвращает строку, `print()` показывает именно её. Возврат значения и вывод на экран являются разными действиями, хотя в коротком примере они стоят рядом.

В ветке `list` мы передаём `show_tasks()` тот же список `tasks`, с которым работает `add`; временную копию для просмотра не создаём. В цикле имя `task` получает очередной словарь, но сам список не заменяется. Поэтому два вызова `list` без другой команды выводят те же строки. После просмотра управление возвращается в `run()`, а новую запись добавляет только команда `add`.

Такое разделение упрощает изменение вида карточки. Если понадобится поправить подпись или порядок её полей, меняется один formatter, а обход списка остаётся прежним. Можно представить пачку пропусков: `format_task()` оформляет один пропуск, а `show_tasks()` по очереди подаёт ей каждый. Сравнение относится только к ролям: в Python formatter возвращает текст, а функции приходится отдельно напечатать его; она не создаёт и не хранит копию задачи.

Путь одной команды `list` проходит через прежний список: `run()` передаёт его в `show_tasks()`, а та выбирает пустой ответ или показывает записи через formatter. После обеих веток управление возвращается в `run()`. Просмотр не меняет длину, порядок или поля карточек.

Для списка из трёх записей полный просмотр вызывает formatter три раза и печатает три строки. В предыдущем шаге команда `list` отвечала на вопрос «сколько»; теперь она показывает, какие именно задачи уже есть. Каждая строка относится к одному словарю из того же `tasks`. Formatter не получает список целиком. Так мы отдельно замечаем неверную подпись и пропущенную карточку: первое относится к formatter, второе относится к обходу в `show_tasks()`.

## 02. Сначала обработаем пустое состояние

В пустом списке нет первой карточки и тело обхода не выполнится. Сообщение о пустоте показываем до обращения к элементам, затем завершаем только текущую функцию.

**Пошаговый разбор.** Что произойдёт при вызове с пустым списком?

```python
def show_summary(items):
    if len(items) == 0:
        print("Список пока пуст.")
        return
    print("Есть записи")

show_summary([])
```

1. В `show_summary` передаётся пустой список.
2. Длина равна нулю, поэтому условие выполняется.
3. Печатается `Список пока пуст.`
4. `return` завершает `show_summary`, поэтому строка `Есть записи` пропускается.

Пустой `return` возвращает выполнение туда, откуда вызвали функцию. В Planner функция `run()` продолжает цикл меню и принимает следующую команду. Это не команда выхода из приложения. Если мы уберём `return`, выполнение дойдёт до следующей строки; в примере оно напечатает «Есть записи», хотя список пуст. Пустое сообщение относится ко всему набору, поэтому его нельзя печатать внутри цикла для каждой записи.

Представим, что пункт меню поручил сотруднику проверить список. Пустой `return` завершает только эту проверку и возвращает управление тому, кто её вызвал; пункт меню остаётся работать. Граница аналогии здесь точная: мы выходим из `show_tasks()`, но не из `run()` и не из процесса Python.

Проверку ставим до цикла, потому что сообщение нужно вывести один раз для всего списка. Если поместить его в тело `for`, на пустом списке это тело не запустится и сообщение не появится. Если вместо этого обратиться к `tasks[0]`, пустой список не содержит такой позиции и выполнение завершится ошибкой. Ранний выход выбирает понятный пустой сценарий до того, как мы начнём читать карточки.

Если список не пуст, ранний возврат не выполняется: функция проходит по нему и печатает строку formatter для каждой карточки. Промежуточное сообщение только о количестве уступает место полному просмотру; пустое сообщение остаётся отдельной веткой и не дублируется для каждой записи.

## 03. Сохраним порядок и настоящий id

Цикл `for` получает элементы списка по очереди, в порядке их хранения. У каждой карточки есть собственный `id`. Позиция элемента, например 0 или 1, меняется при перестановке и не заменяет этот идентификатор.

**Сравнение.** Какой фрагмент покажет id 10 и 20, а не позиции карточек?

Читаем id из записи:

```python
tasks = [{"id": 10, "title": "SQL"}, {"id": 20, "title": "README"}]
for task in tasks:
    print(task["id"], task["title"])
```

Результат для карточек с id 10 и 20: будут показаны 10 и 20 независимо от положения записей.

Печатаем текущую позицию:

```python
tasks = [{"id": 10, "title": "SQL"}, {"id": 20, "title": "README"}]
position = 0
for task in tasks:
    print(position, task["title"])
    position += 1
```

Здесь получатся 0 и 1. Это места карточек в списке, а не их id. В полном просмотре мы сохраняем порядок списка, но выводим идентификатор из словаря. Для каждой текущей карточки передаём тот же словарь прежнему `format_task()`.

Здесь полезно различать номер посылки и место на ленте: `id` остаётся идентификатором карточки, а позиция возникает из текущего порядка списка. Если две задачи поменять местами, их id не изменятся. Поэтому мы печатаем значение из словаря и оставляем порядок обхода прежним.

Цикл `for task in tasks` последовательно связывает имя `task` с текущим словарём из общего списка. Мы не создаём здесь второй набор и не вычисляем новые номера. Если в списке один элемент, тело выполняется один раз; если записей несколько, каждый следующий проход получает следующую запись. Позиция нужна лишь для описания порядка, а задача узнаётся по сохранённому в ней `id`.

## 04. Состояние показываем, но не переписываем

В модели `is_done` хранит булево значение. Formatter переводит его в понятную строку. Для просмотра не нужно устанавливать флаг или добавлять в словарь другое поле.

**Поиск ошибки.** В примере ниже карточка меняется ради вывода:

```python
task = {"id": 33, "title": "Review notes", "priority": 3, "is_done": False}
task["is_done"] = True
print(format_task(task))
```

Исправление:

```python
print(format_task(task))
```



Одинаковый formatter показывает открытые и выполненные записи. В этом занятии мы проверим оба значения на диагностических карточках. Он читает булево поле и выбирает подпись, а само поле остаётся частью модели. Новую команду завершения и изменение статуса пока не добавляем: они относятся к следующему шагу.

Слова «открыта» и «выполнена» принадлежат представлению для человека; в данных по-прежнему хранится `False` или `True`. Если мы присвоим полю другое значение ради текста, просмотр превратится в изменение задачи и повлияет на команды, которые прочитают список позже. Поэтому ветвление по состоянию остаётся внутри formatter, а `show_tasks()` только вызывает его.

Булево поле сохраняет договор модели: будущая команда завершения проверит именно `is_done`. Строка «открыта» или «выполнена» нужна только в отображении. Если мы запишем её в карточку вместо булева значения, код будет получать другой тип; если добавим отдельное поле `status`, два значения состояния смогут разойтись. Поэтому formatter переводит значение для вывода, но не записывает перевод обратно.

## 05. Чтение не меняет список

Просмотр только читает записи: не вызывает `append()`, не сортирует список и не меняет поля словарей. Повторный просмотр показывает тот же набор, пока другая команда не изменила данные между вызовами. Такой просмотр можно повторять без отдельного восстановления списка. Вывод в терминал заметен человеку, поэтому у функции есть внешний эффект печати. Но этот эффект не меняет предметное состояние Planner: число карточек, их порядок и значения полей. Мы называем просмотр читающим именно в этом смысле, а не потому, что на экране ничего не происходит.

**Прогноз.** Что напечатает этот короткий пример?

```python
task = {"id": 33, "title": "Review notes", "priority": 3, "is_done": False}
before = task.copy()
print(format_task(task))
print(task == before)
```

Результат:

```text
[33] Review notes | приоритет: 3 | открыта
True
```

Здесь карточка состоит из простых значений. Отдельная копия словаря позволяет сравнить его поля до и после вызова. Числа, строки и логическое значение не меняются внутри копии отдельно от исходных полей. Для вложенных списков или словарей копирование верхнего словаря оставит общие внутренние объекты, поэтому такая проверка уже не докажет, что вложенные данные сохранились.

Проверим тот же принцип в реальном запуске: два раза вызовем `list` без промежуточной команды и сравним строки, затем добавим новую карточку и снова посмотрим список. Дополнительная строка появится после действия `add`. Сам просмотр только отражает текущие данные, поэтому порядок и поля не меняются от повторного чтения.

**Проверка понимания.** После двух команд `list` сохраняются порядок, id и поля карточек. `format_task()` возвращает строку одной записи, а `show_tasks()` обрабатывает пустой случай или проходит по коллекции и печатает каждую строку. Ни одна функция просмотра не создаёт задачу и не меняет её состояние.

## 06. Что мы будем делать в практике

Расширим существующую `show_tasks(tasks)` в прежнем `main.py`. Команда `add`, модель карточки и `format_task()` останутся прежними. Для непустого списка заменим промежуточную сводку полным просмотром всех записей.

1. Сопоставим прежний ответ `list` для пустого и непустого списка с форматом одной карточки.
2. Расширим прежнюю `show_tasks()`, чтобы она показывала пустой случай отдельно, а полный список читала через прежний formatter.
3. Проверим повторное чтение нескольких задач в меню и сравним данные диагностических карточек до и после просмотра.


Мы меняем только `show_tasks()`. Проверка через настоящее меню покажет, что добавление продолжает работать, а повторное чтение не дублирует и не перемещает задачи. В следующем занятии мы выберем конкретную запись по её id; поиск, изменение статуса и новые поля модели здесь не добавляем.

После проектной правки мы отдельно посмотрим на две диагностические карточки с разными id и состояниями. Такой сценарий проверяет границу между отображением и изменением данных, а запуск прежних команд подтверждает, что новый полный просмотр встроен в накапливаемый Planner, а не работает на отдельной учебной копии.
