# Список словарей и границы копирования

Соединим список и полную запись задачи. Проследим текущую запись в цикле, отличим позицию от `id` и проверим, какие изменения видны через общие ссылки.

**Темы:** список словарей · позиция и `id` · прямой `for` · изменение записи · alias · поверхностная копия · копии отдельных записей

## 00. От одной записи к общему списку

В предыдущем занятии мы описали одну задачу словарём с полями `id`, `title`, `priority` и `is_done`. Теперь поместим несколько таких записей в список. Так мы подготовим понятную модель данных перед первым знакомством с функциями.

1. **Точка старта.** Мы создаём полную запись, читаем её по ключам и понимаем `copy()` и `is`.
2. **Новый вопрос.** Что именно получает переменная цикла, когда список хранит словари, и какие части списка действительно отделяет копирование?
3. **Результат.** Мы читаем список полных задач, объясняем позицию и `id`, затем различаем общую ссылку, копию списка и отдельные копии записей.

Все записи в опытах ниже учебные. Мы не добавляем их в рабочий `main.py` и не создаём новое состояние Planner раньше времени.

## 01. Список хранит записи

Словарь описывает одну задачу, а список может хранить несколько словарей. Список отвечает за порядок записей. Каждый вложенный словарь отвечает за поля одной записи.

```python
tasks = [
    {"id": 10, "title": "Проверить план", "priority": 2, "is_done": False},
    {"id": 20, "title": "Записать вывод", "priority": 1, "is_done": True},
]

print(len(tasks))
print(len(tasks[0]))
print(len([]), len([{}]))
```

Результат:

```text
2
4
0 1
```

`len(tasks)` считает записи во внешнем списке, а `len(tasks[0])` считает ключи первой записи. Пустой список не содержит ни одной записи. Список `[{}]` содержит одну запись, но эта запись не соответствует договору задачи: у неё нет обязательных полей.

Можно представить папку-картотеку: внешний список задаёт порядок карточек, а каждый вложенный словарь хранит поля одной задачи. Индекс выбирает карточку по месту, ключ находит поле внутри неё. В Python это не бумажная папка: список и словари являются отдельными объектами, а переменные связываются с ними.

**Предскажем, сколько записей пройдёт цикл.**

```python
empty = []
one_record = [{"id": 8, "title": "Прочитать заметку", "priority": 3, "is_done": False}]

for task in empty:
    print(task["title"])

for task in one_record:
    print(task["title"])
```

Первый цикл ничего не выводит: в списке нет элементов. Второй выводит `Прочитать заметку` один раз. Один элемент списка здесь является словарём, а не отдельным полем этой записи.

## 02. Прямой `for` даёт текущую запись

Если нужен каждый словарь, перебираем сам список. На каждом проходе переменная цикла получает текущую запись. Она не получает индекс и не становится копией словаря.

```python
tasks = [
    {"id": 10, "title": "Проверить план", "priority": 2, "is_done": False},
    {"id": 20, "title": "Записать вывод", "priority": 1, "is_done": True},
]

for task in tasks:
    print(task["id"], task["title"])
```

Подготовленный пошаговый разбор:

1. Сначала `tasks` ссылается на список из двух словарей.
2. На первом проходе `task` получает словарь на позиции `0`. Выражение `task["id"]` читает поле этого словаря.
3. На следующем проходе `task` получает словарь на позиции `1`.
4. Цикл выводит `10 Проверить план`, затем `20 Записать вывод`.

Это именно текущая запись. Чтобы прочитать её название, обращаемся к ключу `title`, а не к позиции внутри внешнего списка. Если нужна отдельная переменная со ссылкой на первую запись, можно написать `first_task = tasks[0]`; это не создаёт новый словарь.

Переменная цикла нужна, чтобы назвать текущую запись внутри тела цикла; она не становится отдельной копией. На следующем проходе это имя связывается со следующим словарём, а сохранённое заранее второе имя продолжает указывать на первую запись.

## 03. Позиция, экранный номер и `id`

У одной записи могут быть три числа, и у каждого своя роль. Индекс выбирает позицию списка, экранный номер помогает человеку читать строки, а `id` хранится в словаре и остаётся значением самой записи.

```python
tasks = [
    {"id": 10, "title": "Проверить план", "priority": 2, "is_done": False},
    {"id": 20, "title": "Записать вывод", "priority": 1, "is_done": True},
]

for display_number, task in enumerate(tasks, start=1):
    print(display_number, task["id"], task["title"])
```

Для исходного списка первая строка начинается с экранного номера `1` и содержит `id` `10`. Вторая начинается с `2` и содержит `id` `20`. При этом список выбирает их как `tasks[0]` и `tasks[1]`: индексы начинаются с нуля.

`enumerate(..., start=1)` задаёт экранные номера, начиная с `1`. Он не меняет индекс и не переписывает поле `id`. Если переставить записи, первой станет задача с `id` `20`, а значение `id` останется внутри своего словаря.

```python
first_task = tasks.pop(0)
tasks.append(first_task)
for display_number, task in enumerate(tasks, start=1):
    print(display_number, task["id"], task["title"])
```

Получим строки `1 20 Записать вывод` и `2 10 Проверить план`. Изменился порядок списка, но сами поля записей не перенумеровались.

Индекс выводится из текущего положения записи, поэтому меняется при перестановке. `enumerate` связывает экранный номер с текущим элементом, но не записывает номер в словарь. Для человека это номер строки, а для программы поле `id` остаётся данными самой задачи.

Разведём три числа по их ролям:

- `0` в индексе `tasks[0]` выбирает первую позицию списка.
- `1` из `enumerate(..., start=1)` становится номером строки для человека.
- `10` в поле `task["id"]` является идентификатором записи.

Одинаковые числа могут встретиться случайно, но это не делает роли взаимозаменяемыми. Индекс зависит от текущего порядка, экранный номер выбирается для вывода, а `id` входит в договор записи.

## 04. Имя цикла и объект списка

Переменная цикла связана с текущим словарём. Если изменить поле этого словаря, изменение будет видно через список. Если присвоить переменной цикла другой словарь, мы изменим связь имени, а не элемент списка.

```python
books = [
    {"title": "Город", "available": True},
    {"title": "Река", "available": False},
]

book = books[0]
book["available"] = False
print(books[0]["available"])
```

Вывод будет `False`: `book` и `books[0]` указывают на один словарь. Поэтому изменение его поля доступно через оба имени.

Сравним изменение поля и переприсваивание имени:

```python
books = [{"title": "Город", "available": True}]

for book in books:
    book = {"title": "Черновик", "available": False}

print(books)
```

В списке останется `Город`. В примере цикл связал переменную `book` с новым словарём, но элемент списка не изменился. Чтобы заменить элемент списка, нужно отдельно присвоить словарь в нужную позицию:

```python
books = [{"title": "Город", "available": True}]
books[0] = {"title": "Новый атлас", "available": False}
print(books)
```

Чтобы изменить поле текущей записи, используем `book["available"] = False`.

Поведение выбирают по намерению: изменить поле существующей записи или заменить словарь на конкретной позиции. Само имя `book` не является списком и не заменяет его элементы при переприсваивании.

Имя `book` можно представить как закладку на карточке: если мы меняем поле через эту ссылку, изменение видно и через `books[0]`. Если связать `book` с другим словарём, мы передвинули только закладку; элемент списка остался прежним.

## 05. Чтение и подсчёт не меняют записи

В цикле можно только читать данные и накапливать итог. Для подсчёта начнём счётчик с нуля, проверим поле каждой записи и увеличим число только для подходящих записей.

```python
books = [
    {"title": "Город", "available": True},
    {"title": "Река", "available": False},
    {"title": "Море", "available": True},
]

available_count = 0
for book in books:
    if book["available"]:
        available_count += 1

print(available_count)
print(books)
```

Счётчик будет равен `2`, а словари останутся прежними. В теле цикла мы читали значение и меняли только отдельную переменную `available_count`. Поле `available` не присваивалось, поэтому состояние книг не изменилось.

Тот же принцип применяется к `is_done`: мы можем посчитать записи с `True`, не меняя их флаги. Слово «прочитать» здесь означает получить значение ключа, а не изменить данные под ним.

Фраза «не меняем запись» относится к присваиваниям. Если внутри условия выполнить `task["is_done"] = False`, мы уже изменим словарь, хотя цикл и счётчик останутся прежними. Здесь мы меняем только `done_count`, чтобы отличать вычисление итога от изменения состояния.

## 06. Копия списка сохраняет ссылки на записи

Присваивание создаёт второе имя списка. Метод `copy()` создаёт поверхностную копию: внешний список новый, а вложенные словари остаются теми же объектами.

Представим два лотка с карточками. `stations.copy()` создаёт второй лоток, поэтому новую карточку можно положить только во второй. Но если оба лотка указывают на одну карточку, изменение её поля будет видно из обоих. Это сравнение описывает только два уровня: в Python общий объект не лежит физически в лотке, на него ссылаются списки.

```python
stations = [{"name": "Север", "open": True}]
alias = stations
draft = stations.copy()

draft.append({"name": "Юг", "open": False})
draft[0]["open"] = False

print(len(stations), len(draft))
print(stations is alias, stations is draft)
print(stations[0] is draft[0])
print(stations[0]["open"], draft[0]["open"])
```

Результат:

```text
1 2
True False
True
False False
```

`alias` и `stations` являются одним внешним списком. `draft` является отдельным списком, поэтому добавленная в него станция не увеличила `stations`. Но `stations[0]` и `draft[0]` являются одним словарём. Изменение поля `open` видно через оба списка.

`is` отвечает на вопрос, один ли это объект. Оператор `==` сравнивает содержимое. Списки могут быть равны по содержимому и при этом быть разными объектами; вложенный словарь после поверхностного `copy()` также может оставаться общим.

Разделим два действия. `draft.append(...)` меняет длину только нового внешнего списка, потому что `stations` и `draft` являются разными списками. `draft[0]["open"] = False` меняет общий вложенный словарь, поэтому новое значение видно через оба списка.

## 07. Отдельная копия каждой плоской записи

Если нужна независимость плоских словарей, создадим новый список и скопируем в него каждый словарь. `append()` добавляет очередной результат в новый список, а `copy()` отделяет текущую запись.

```python
stations = [
    {"name": "Север", "open": True},
    {"name": "Юг", "open": False},
]

station_copies = []
for station in stations:
    station_copies.append(station.copy())

station_copies[0]["open"] = False
print(stations[0]["open"], station_copies[0]["open"])
print(stations[0] is station_copies[0])
```

Результат:

```text
True False
False
```

Внешний список и два плоских словаря теперь отдельные. Поэтому изменение поля скопированной записи не меняет исходную. Мы выполнили цикл, создали копию текущего словаря и добавили её в новый список.

Гарантия относится к этим полям. Если словарь содержит вложенный список или другой изменяемый объект, обычный `copy()` не копирует его автоматически. Глубину копирования нужно соотносить с фактической формой данных.

В каждом проходе `station.copy()` создаёт новый словарь для текущей записи, а `append()` помещает его в новый список. Если добавить туда сам `station`, копия списка сохранит ссылки на исходные словари. Мы проверяем именно поле отдельной записи, а не только длину внешнего списка.

## 08. Где заканчивается копия и начинаются разные ошибки

Рассмотрим вложенную настройку. Почему исходное значение может измениться, хотя мы вызвали `copy()`?

```python
profile = {"preferences": {"theme": "light"}}
profile_copy = profile.copy()
profile_copy["preferences"]["theme"] = "dark"
print(profile["preferences"]["theme"])
```

Ошибка ожидания в том, что скопирован только внешний словарь. Вложенный словарь `preferences` общий. Для известной структуры можно отдельно скопировать и вложенный словарь:

```python
profile = {"preferences": {"theme": "light"}}
profile_copy = profile.copy()
profile_copy["preferences"] = profile["preferences"].copy()
profile_copy["preferences"]["theme"] = "dark"
print(profile["preferences"]["theme"])
```

Теперь исходная тема остаётся `light`. Это копирование двух известных уровней, а не универсальная гарантия для любой глубины.

После двух вызовов `copy()` отделены внешний словарь и известный вложенный словарь `preferences`. Это достаточно для этой формы данных. Если добавить туда ещё один уровень со списком, он останется общим, пока мы не скопируем и его отдельно. Поэтому результат зависит от вложенности, а не только от числа вызовов `copy()`.

Кортеж тоже фиксирует свои позиции, но не превращает вложенный словарь в неизменяемый объект:

```python
status = {"name": "draft"}
fixed = (status,)
fixed[0]["name"] = "ready"
print(fixed[0]["name"])
```

Вывод будет `ready`. Мы не заменяли значение в позиции кортежа, а изменили поле словаря, который хранится в этой позиции.

Ошибки позиции и ключа тоже разные. Возьмём неполную запись только для исследования:

```python
incomplete_tasks = [{"id": 10, "title": "Проверить план", "is_done": False}]
```

Здесь намеренно нет обязательного `priority`. Выражение `incomplete_tasks[1]` обращается к отсутствующей позиции и приводит к `IndexError`. Выражение `incomplete_tasks[0]["priority"]` находит запись, но не находит ключ, поэтому приводит к `KeyError`. В постоянной модели такая запись является повреждённой; мы не сохраняем её как обычную задачу.

В следующем занятии мы дадим действию имя и передадим ему данные. Когда в параметр попадёт список или словарь, уже будет понятно, почему изменение записи может быть видно снаружи вызова.

## 09. Что мы будем делать в практике

В практике проверим, как поля одной задачи связаны со списком и его копиями.

1. **Прочитаем записи.** Мы выведем поля двух словарей и отдельно посчитаем записи и ключи.
2. **Разведём три числа.** Мы сравним индексы, экранные номера и `id`, затем увидим, что перестановка меняет порядок строк, а не поля задач.
3. **Проверим изменение.** Мы изменим поле через второе имя и сравним это с переприсваиванием переменной цикла.
4. **Сравним копии.** Мы добавим элемент во внешний список-копию, изменим общую запись и отдельно создадим новые словари.
5. **Проверим вложенность.** Мы проследим, какое значение остаётся общим после поверхностного `copy()` и чем различаются `IndexError` и `KeyError`.

Все шаги используют отдельные учебные списки. Вместе они показывают, на каком уровне произошло изменение и какие объекты видны через исходный список.

Мы не меняем `main.py` и не создаём меню Planner. Итог практики: мы можем предсказать вывод, проверить состояние исходных данных и объяснить границы копирования перед тем, как передавать такие структуры функциям.
