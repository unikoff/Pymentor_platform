Мы уже умеем читать значения по одному, проверять условие и повторять ввод. Теперь сохраним историю длительностей одной сессии и разберём, как список меняется при новых операциях.

3. **Результат.** Мы объясним изменение списка, None, общую ссылку и копию, затем сохраним реальные длительности одного запуска calc.

Сначала мы отделим прежние навыки цикла и накопления от нового свойства списка. Затем проследим и изменение объекта, и значение, которое вернул метод, прежде чем применить список в знакомом calc.

Одного study_minutes недостаточно, чтобы ответить, из каких отдельных занятий сложилась сумма. Значения 20 и 35, а также 25 и 30 дают один итог, 55, хотя исходные данные различаются. ## 01. Список хранит порядок и допускает изменения

Список хранит несколько значений в определённом порядке. Индекс начинается с нуля, а отрицательный индекс отсчитывается с конца. Длина списка показывает число элементов.

**Позиция, длина и срез**

```python
readings = [25, 40, 55]
print(readings[0], readings[-1], len(readings))
print(readings[0:2])
```

Срез выбирает часть последовательности и создаёт отдельный список верхнего уровня. Правая граница не включается: срез с позициями 0 и 1 заканчивается перед позицией 2. Если список пуст, у него нет элемента с индексом 0.

Строка тоже хранит порядок, но её символы нельзя заменить по позиции, а элемент списка можно. Индекс и длина помогают читать оба типа, но изменяемость отличает их. Срез создаёт новый список: если мы сохраним его как part = readings[0:2] и заменим part[0], исходный readings от этого не изменится.

Представим пронумерованный ряд ячеек для результатов: индекс называет позицию, длина показывает число занятых мест, а срез выделяет часть ряда. Сравнение помогает представить порядок и позиции, но настоящая коллекция может менять размер, а её имя связано с объектом, не с бумажной таблицей.

Замена readings[1] = 45 меняет элемент в существующей позиции, но сохраняет длину. Присваивание readings = [45] связывает имя с другим списком и не меняет прежний объект. Добавление в конец выполняем методом, а не записью по позиции len(readings): такого индекса ещё нет. У пустого списка нельзя прочитать ни readings[0], ни readings[-1].

### Предскажем вывод

```python
durations = [25, 40, 55]
print(40 in durations)
print(90 not in durations)
print(bool([]), bool([False]))
```

**Результат**

```text
True
True
False True
```

in и not in проверяют наличие значения. Истинность списка зависит от его пустоты, а не от значения внутри.

Здесь in означает проверку принадлежности. В записи for item in values то же слово связывает цикл с последовательностью. Мы различаем вопрос о наличии значения и обход всех элементов.

Проверка принадлежности возвращает bool и сама не меняет список. True сообщает, что значение найдено, но не говорит, где оно стоит и сколько раз повторяется. Для позиции мы используем индекс, для удаления по значению - remove, а для выбора действия по результату проверки - знакомое if.

Условие if durations проверяет, есть ли в списке хотя бы один элемент. При [False] условие всё равно истинно: значение False не делает список пустым. len(durations) отвечает на вопрос о числе элементов, а in - о наличии конкретного значения. Перед чтением durations[0] нам достаточно проверить непустоту.

### Найдём ошибку

```python
durations = []
print(durations[0])
```

**Вопрос:** Почему этот доступ по индексу завершается ошибкой?

1. Пустой список не содержит позиции 0.
2. len() нельзя применять к списку.
3. Индекс всегда начинается с 1.

**Ответ:** первый вариант. До чтения по индексу мы проверим, что список не пуст. Пустой список ложен, непустой список истинен, даже если внутри хранится False.

```python
durations = []
if durations:
    print(durations[0])
else:
    print("Пока нет длительностей")
```

## 02. Изменение списка и результат метода

Перед операцией уточним, что у нас есть: новое значение, позиция или значение для поиска. Эти способы приводят к разным изменениям.

Разделим операции по их входу и результату:

- `durations.append(value)` добавляет один объект в конец списка.
- `durations[index] = value` заменяет элемент на существующей позиции.
- `durations.pop(index)` удаляет элемент по позиции и возвращает его.
- `durations.remove(value)` удаляет первое совпадение по значению.

Если индекс не передан в pop(), удаляется и возвращается последний элемент. append([25, 35]) добавит один объект, которым является вложенный список, а не два отдельных числа. Для удаления отсутствующего значения сначала проверим принадлежность: remove без совпадения вызывает ValueError. pop у пустого списка вызывает IndexError.

Замена через индекс сохраняет длину, но меняет значение именно в существующей позиции. append увеличивает длину на один элемент. pop и remove уменьшают её, хотя находят удаляемый элемент по-разному. Эти методы меняют тот же список; попутно мы отдельно отслеживаем, вернул ли метод полезное значение.

### Предскажем результат

```python
bookmarks = ["guide", "guide", "notes"]
bookmarks.append(["api", "tests"])
bookmarks[0] = "start"
removed = bookmarks.pop(1)
print(bookmarks)
print(removed)
duplicates = ["guide", "guide", "notes"]
duplicates.remove("guide")
if "missing" not in duplicates:
    print("missing value skipped")
print(duplicates)
```

**Результат**

```text
['start', 'notes', ['api', 'tests']]
guide
missing value skipped
['guide', 'notes']
```

remove(value) останавливается на первом совпадении. Поэтому при повторах он не удаляет все одинаковые элементы. Проверка in помогает не вызывать remove, если нужного значения нет.

Мы можем менять список несколькими шагами, но каждую строку читаем по отдельности. Сначала отмечаем тип входа: одно значение для append, существующий индекс для замены или значение для поиска. Затем обновляем список и только после этого читаем его текущее содержимое.

pop(index) возвращает удалённый элемент, поэтому мы можем сохранить его в отдельное имя. append и remove меняют исходный список, но не возвращают его обновлённую копию. remove принимает значение и удаляет первое совпадение; pop выбирает позицию. Если одинаковое значение встречается несколько раз, pop(1) и remove("guide") могут убрать разные элементы. Мы выбираем операцию по требуемому способу поиска.

### Сравним два варианта

**Вопрос:** Как мы безопасно удалим необязательное значение?

**Сразу вызвать remove**

```python
items.remove("отправлено")
```

Если совпадения нет, возникнет ValueError.

**Сначала проверить наличие**

```python
if "отправлено" in items:
    items.remove("отправлено")
```

Удаление выполнится только при наличии значения. Мы проверяем то же значение, которое затем передаём remove.

## 03. None показывает отсутствие полезного результата

Метод может изменить объект, но не возвращать новое полезное значение. append меняет список и возвращает None. pop меняет список и возвращает удалённый элемент.

**Изменение и возвращённое значение**

```python
marks = [5]
append_result = marks.append(8)
print(marks)
print(append_result)
print(append_result is None)
```

None - специальное значение Python, которое обозначает отсутствие результата. Поэтому мы не присваиваем вызов append обратно имени списка. В таком присваивании имя получит None, хотя прежний список уже изменён.

None не означает, что метод не выполнился: список уже изменился. Это также не False, не ноль, не пустой список и не ещё не созданное имя. В записи append_result is None оператор is проверяет, указывает ли это имя на объект None; это не обычная проверка истинности. В следующем разделе мы применим is к двум именам и разберём, как оно отличается от ==.

Если вызвать marks.append(8) отдельной командой, список изменится через имя marks, и нам не нужно сохранять результат вызова. В примере append_result получает None. Поэтому три print показывают изменённый список, None и True: третья строка проверяет сам результат. Вывод None не отменяет изменение, потому что мы рассматриваем две разные вещи: состояние списка и возвращённое значение метода.

### Найдём ошибку

```python
marks = [5]
marks = marks.append(8)
print(marks)
```

После этой строки marks уже не обозначает список, потому что append вернул None, а присваивание сохранило это значение в marks.

**Исправленный вариант**

```python
marks = [5]
marks.append(8)
print(marks)
```

Мы сохраняем результат pop, когда он нужен, а результат append обычно не сохраняем. Изменение списка и возвращённое значение проверяем по отдельности.

## 04. Два имени могут вести к одному объекту

Присваивание второго имени не копирует список. Если изменить общий объект, новое содержимое будет видно по обоим именам.

Представим один лоток с двумя наклейками folders и alias: добавленный предмет виден через обе наклейки. copy() создаёт второй лоток с теми же начальными значениями. В Python имена не хранят отдельные ящики, а ссылаются на объекты; сравнение показывает общую ссылку, а не физическое размещение значений.

```python
folders = ["входящие", "архив"]
alias = folders
separate = folders.copy()
print(folders == separate)
print(folders is separate)
alias.append("проверка")
print(folders)
print(separate)
alias = ["новый"]
print(folders)
print(alias)
print(folders is alias)
```

**Пошагово**

1. Создаётся один список folders.
2. alias получает ссылку на тот же объект.
3. copy() создаёт отдельный список верхнего уровня с теми же простыми значениями.
4. Содержимое одинаковое, поэтому folders == separate даёт True; объекты разные, поэтому folders is separate даёт False.
5. append меняет объект, на который указывают folders и alias.
6. separate не менялся.
7. После alias = ["новый"] имя alias указывает на новый список, folders остаётся прежним.
8. folders is alias даёт False.

Оператор == сравнивает содержимое, а is проверяет, указывают ли два имени на один объект. Поэтому folders == separate даёт True, а folders is separate - False. Мы применяем is для идентичности и для проверки None, а значения сравниваем через ==. Переприсваивание alias = ["новый"] связывает имя с новым списком, а alias.append("ещё") меняет общий объект folders. Метод copy() создаёт поверхностную копию, то есть отдельный список верхнего уровня. Здесь его элементы - строки, поэтому отдельной копии каждой строки не требуется.

Предел сравнения такой: наклейки помогают представить имена, но в программе они не содержат данные сами по себе. Мы получаем один объект при присваивании и новый внешний объект при copy(). С вложенными изменяемыми данными копия верхнего уровня не отделила бы внутренние объекты; эту границу проверим после появления словарей.

После alias.append folders показывает изменённый общий объект, тогда как separate сохраняет прежнее содержимое, скопированное до добавления. Строка alias = ["новый"] лишь перепривязывает alias: folders от этого не меняется. Мы проверяем состояние объектов выводом и отдельно проверяем идентичность через is; равное содержимое после разных операций само по себе не доказывает общей ссылки.

### Сравним два варианта

**Вопрос:** Как мы получим отдельный список верхнего уровня?

**Назначить второе имя**

```python
separate = folders
```

Оба имени будут вести к одному объекту.

**Создать копию**

```python
separate = folders.copy()
```

Верхние списки станут отдельными объектами. В этой практике значения списка простые, поэтому этого достаточно.

### Верно или неверно

Если a == b равно True, то a is b тоже обязательно равно True.

**Ответ:** неверно. Одинаковое содержимое не доказывает, что это один объект.

## 05. Перенесём список в текущий calc

В проекте уже есть ввод длительностей, повторение и накопление общего времени. Теперь добавим сохранение исходных значений для текущего запуска.

**Независимый пример: порядок и повторы остаются**

```python
steps = ["read", "run", "run"]
print(steps)
print(len(steps))
```

В независимом примере повтор run остаётся на месте: список не сортирует и не удаляет одинаковые элементы сам. В проекте мы используем это свойство для длительностей, введённых в конкретном запуске calc.

После проверки неотрицательного lesson_count мы создаём новый список рядом с начальным study_minutes и до цикла ввода. После преобразования duration_text в duration_minutes добавляем это целое число. Так сохраняются фактические значения, порядок и повторы. Существующее накопление общего времени продолжает работать отдельно.

Например, при lesson_count = 2 и длительностях 20 и 35 список проходит путь [] → [20] → [20, 35], а study_minutes - путь 0 → 20 → 55. Список отвечает на вопрос, какие числа ввели, накопитель - какова их сумма. Десятиминутный перерыв добавляется после цикла и не входит в durations.

Внутри цикла добавляем именно duration_minutes, а не накопитель study_minutes. При вводе 20, затем 35, накопитель по шагам равен 20 и 55; запись накопителя ошибочно дала бы список [20, 55] вместо исходных [20, 35]. Так мы проверяем, что durations хранит каждое наблюдение, а study_minutes остаётся суммой. Оба значения используют тот же ввод, но отвечают на разные вопросы.

Если создавать список внутри цикла ввода, каждое повторение будет стирать предыдущие значения. Если создать его до общего цикла команд, новая сессия может получить длительности прошлой. После цикла мы выводим список. При нуле занятий цикл ввода не запускается, и мы не читаем durations[0]: у пустого списка такой позиции нет.

Представим каждый запуск calc отдельной страницей журнала: введённые длительности занимают строки только на этой странице, а новый запуск начинает чистую. В программе список исчезнет после завершения процесса, он не сохраняет данные в файл. Это сравнение объясняет срок жизни списка, а не добавляет постоянное хранение.

При нуле список остаётся пустым; при одном занятии содержит одно целое число; два значения подтверждают порядок и сохранение повторов. Ещё один запуск calc подтверждает, что мы начинаем его с нового списка, но сохраняем прежнее накопление и один перерыв.

После изменения мы проверим 0, 1 и 2 введённые длительности, а затем два запуска calc с разными числами. Сохраним прежний подсчёт, правило отдельно заданного перерыва и вывод часов с остатком минут. В следующем занятии сравним другие структуры хранения и разберём, как представить пару значений при обходе.

## 06. Что мы будем делать в практике

Начнём с коротких предсказаний, затем проследим связи имён и продолжим прежнюю ветку calc проекта studyhub-console.

1. **Проследим операции.** Мы предскажем изменение после append, замены, pop и remove; отдельно запишем возвращённое значение и итоговый список.
2. **Сравним ссылки.** Мы проверим равенство содержимого, общую ссылку, copy() и None после append на коротком примере.
3. **Обновим calc.** Мы сохраним каждую введённую длительность в новом списке одной сессии и выведем их в исходном порядке.
4. **Проверим результат.** Мы прогоним 0, 1 и 2 занятия, затем повторный запуск; список не сбросится внутри цикла и не смешает сессии.

Первые два шага используют уже объяснённые операции и наблюдаемые состояния, а не готовое решение для изменения проекта. Они готовят нас к отдельной правке calc.

В проекте мы изменим только хранение введённых длительностей. Сохраним прежнее накопление, один перерыв, вывод часов и остатка минут; при нуле занятий список останется пустым без чтения первого элемента. Две сессии подтвердят, что список создаётся для каждого calc отдельно.
