# 18. Поиск задачи по id и завершение

Продолжим существующий StudyHub Planner. Команды `add`, `list` и `exit` уже используют один список задач, а каждая карточка содержит id и `is_done`. Теперь мы добавим поиск одной карточки по id и команду, которая изменяет состояние только этой записи.

**Темы:** поиск по полю · индекс и id · `None` · общая ссылка на словарь · повторяемое завершение

## 00. От полного списка к одной записи

В предыдущем проектном шаге мы научились читать все карточки в одном порядке. Теперь нам нужно выбрать запись по её собственному id. Мы свяжем уже знакомые цикл, условие и словарь с результатом функции поиска.

1. **Точка старта.** Команды `add`, `list` и `exit` используют один список `tasks`. Карточки имеют id и `is_done`, а `format_task` показывает их поля.
2. **Новый вопрос.** Как найти запись по значению id, безопасно обработать отсутствие и завершить выбранную задачу?
3. **Результат.** Команда `find` показывает найденную карточку или сообщает об отсутствии. Команда `done` устанавливает `is_done` только найденной задаче, а повторное выполнение оставляет тот же результат.

Сначала мы отделим идентификатор от позиции записи, затем разберём оба результата поиска. Неизвестный положительный id означает, что совпадения нет. Это не ошибка преобразования числа и не повод удалять или менять другие карточки.

## 01. Значение id не задаёт позицию в списке

Индекс отвечает на вопрос, какое место занимает элемент сейчас. Поле id отвечает на вопрос, какую запись мы ищем. Значения могут не совпасть: список растёт по мере добавления задач, а id записывается внутри словаря.

Представим библиотечный каталог. Шифр напечатан на карточке книги, а номер полки указывает её текущее место. Если книги переставить, место изменится, но шифр останется тем же. Так и в Python: `tasks[1]` означает второй элемент списка, а не задачу с id, равным 1. Аналогия объясняет разницу между положением и идентичностью, но не создаёт для программы тайный каталог. Нужное поле мы проверяем сами, перебирая записи.

Посмотрим на отдельный пример с кодом книги. Функция сравнивает поле каждой записи с отдельным значением. При совпадении мы возвращаем словарь; если весь список просмотрен, но совпадения нет, функция возвращает `None`.

```python
def find_volume(volumes, wanted_code):
    for volume in volumes:
        if volume["code"] == wanted_code:
            return volume
    return None

volumes = [
    {"code": "A-14", "title": "Patterns"},
    {"code": "B-07", "title": "Databases"},
]
print(find_volume(volumes, "B-07")["title"])
print(find_volume(volumes, "X-00"))
```

Первый вызов найдёт книгу по её коду и выведет Databases. Второй проверит обе записи и вернёт `None`. Мы не используем код как индекс и не предполагаем, что список отсортирован. Функция просматривает его по порядку и останавливается только после совпадения.

Проследим похожий поиск по независимым номерам мест:

```python
tickets = [{"seat": 6}, {"seat": 14}]
wanted_seat = 14
for ticket in tickets:
    if ticket["seat"] == wanted_seat:
        found = ticket
        break
print(found)
```

Сначала значение 6 не совпадает с запросом 14, поэтому цикл продолжает работу. На следующей записи условие становится истинным, и в found сохраняется текущий словарь. `break` завершает цикл после найденного места. Число 14 здесь является значением поля seat, а не позицией в списке. В проекте уникальные положительные id выдаёт команда `add`, поэтому одного совпадения достаточно. Поиск не сортирует и не перенумеровывает задачи. Список и значение поля принадлежат разным измерениям. В двух карточках одна вполне может иметь id 40. Выражение `tasks[40]` запросило бы несуществующую позицию, но сравнение поля способно найти эту запись. Поэтому id не ограничен длиной списка, а поиск не зависит от того, идут ли номера подряд.

## 02. Успешный `return` внутри совпадения, отсутствие после цикла

`return` завершает всю функцию, а не только один проход цикла. Поэтому успешную запись мы возвращаем сразу внутри совпадения, а `None` оставляем после полного перебора.

Рассмотрим ошибочную версию:

```python
def find_entry(entries, wanted_number):
    for entry in entries:
        if entry["number"] == wanted_number:
            return entry
        return None
```

При поиске числа 20 среди записей 10 и 20 функция остановится после первого несовпадения. Она не проверит вторую запись, хотя правильный результат находится в списке. Ошибка не в сравнении, а в расположении `return None`. Если отсутствие возвращается внутри цикла, поиск завершается слишком рано.

Мы размещаем успешный `return` внутри совпадения. Он сразу завершает функцию с найденной записью. `return None` ставим после цикла: до этой строки выполнение доходит только тогда, когда все записи проверены. На пустом списке цикл не выполнится ни разу, поэтому функция также дойдёт до `None`. В обоих случаях результат честно сообщает об отсутствии.

Мы различаем два способа остановки. `break` выходит только из цикла, а выполнение функции может продолжиться ниже. `return` одновременно завершает функцию и передаёт её результат вызывающему коду. Поэтому успешная запись возвращается сразу, а отсутствие фиксируется только после полной проверки списка.

## 03. `None` обозначает отсутствие, найденный словарь остаётся общим

У `find_task(tasks, task_id) два результата: исходный словарь карточки или `None`. До чтения полей мы проверяем результат и используем соответствующую ветку.

Условие `task is None` проверяет именно тот результат, который обещан контрактом. Выражение `if not task` проверяет шире, является ли значение ложным. Для корректной карточки оба выражения обычно приведут к ожидаемой ветке, но явная проверка точнее выражает договор функции. При отсутствии записи мы не обращаемся к `task["title"]` и не вызываем formatter.

Если мы сразу читаем `task["title"]`, обычное отсутствие превращается в программную ошибку вместо понятного сообщения. Явная ветка `None` отделяет ожидаемый результат поиска от дефекта в нашей программе.

Найденная карточка остаётся тем же словарём внутри `tasks`. Представим две закладки, которые ведут к одной заметке: если мы изменим заметку, её новое содержимое будет видно через обе закладки. Так локальное имя и элемент списка могут указывать на один объект. Граница аналогии: в Python это ссылки на объект в памяти, а не бумажные закладки.

```python
volume = {"code": "B-07", "title": "Databases"}
found = volume
print(found is volume)
found["title"] = "SQL"
print(volume["title"])
```

Здесь `is` проверяет, что переменные ссылаются на один объект. Первая строка вывода будет `True`, а затем через volume мы увидим название SQL. Поиск только читает найденный словарь и возвращает исходную запись. Отдельная функция завершения изменит поле явно, поэтому чтение и изменение остаются разными операциями.

## 04. Завершение задаёт состояние, а не переключает его

Поле `is_done` хранит текущее состояние: `False` означает, что задача открыта, а `True` означает, что она выполнена. Команда `done` должна установить `True`, а не заменить значение на противоположное.

Присваивание отвечает на вопрос, каким должно быть состояние после операции. Если вместо этого применить not к прежнему значению, команда станет переключателем: первое выполнение закроет задачу, а повторное откроет её обратно. Это не соответствует смыслу команды `done`.

Проверим независимую отметку:

```python
parcel = {"accepted": False}
parcel["accepted"] = True
print(parcel["accepted"])
parcel["accepted"] = True
print(parcel["accepted"])
```

Оба вывода будут `True`. Мы повторно записали конечное значение, поэтому повтор не отменил прежний результат и не создал ещё одну карточку. Действие, которое при повторе сохраняет достигнутое состояние, называют идемпотентным. Простыми словами, одинаковый запрос не делает уже выполненную задачу открытой.

Поэтому `mark_task_done` возвращает `False`, если задача не найдена. Если словарь найден, функция записывает `is_done = True` и возвращает `True`. Это означает, что задача существует и после вызова выполнена; ответ не говорит, изменилась ли она именно сейчас. Функция не читает ввод и не печатает сообщение. Ввод остаётся у `read_task_id`, изменение поля у предметной операции, а подтверждение у обработчика меню. Число выполненных задач мы посчитаем позже по самим карточкам, а не по числу вызовов `done`.

Возвращённый `True` сам по себе не появляется на экране: это значение получает вызывающий код. Так мы отдельно проверяем предметный результат и отдельно выбираем сообщение для пользователя. Для поиска действует та же граница: функция возвращает словарь или `None`, а обработчик решает, что показать. Если увеличивать счётчик при каждом возвращённом `True`, повторный `done` завысит число выполненных задач, хотя флаг всё ещё принадлежит одной карточке. Сводку нужно строить по текущим значениям `is_done` в общем списке, а не по числу успешных вызовов. Поэтому подсчёт мы отложим до следующей части проекта.

## 05. Связываем поиск и завершение с меню

Для `find` обработчик получает положительный id через `read_task_id`, один раз вызывает `find_task` и проверяет результат. При `None` мы сообщаем об отсутствии и возвращаемся к меню. При найденном словаре вызываем привычный `format_task`. Поиск не печатает и не изменяет поля, а formatter только возвращает строку для отображения.

Для `done` обработчик тоже читает id, затем вызывает `mark_task_done`. Эта функция сама использует `find_task`, поэтому меню не дублирует цикл поиска. Функция возвращает `False` или `True`, а обработчик выбирает сообщение. Подтверждение говорит о конечном состоянии, поэтому оно остаётся правильным и при повторной команде. Если общий поиск вернул `None`, предметная функция сразу возвращает `False` и не меняет карточки. Обработчик сообщает об отсутствии и продолжает цикл меню. Только найденный словарь достигает присваивания `True`.

Проверим обе команды на задачах из настоящего меню. Мы создадим две карточки, найдём их по показанным id, завершим первую и повторим `done`. В списке первая останется выполненной, а вторая открытой. Идентификаторы, названия, приоритеты, длина и порядок `tasks` не изменятся. Неизвестный положительный id также оставит данные прежними. После этих проверок мы снова используем `add`, `list` и `exit`.

## 06. Что мы будем делать в практике

Продолжим прежний `main.py`: сначала проверим алгоритм поиска на независимых данных, затем подключим `find` и `done` к существующему меню.

1. **Разберём две ошибки.** Проследим ранний `return None` и отличим id поля от индекса списка.
2. **Добавим общий поиск.** Вернём исходную карточку или `None` и проверим пустой список, найденный и отсутствующий id.
3. **Подключим команды.** Покажем найденную карточку, затем используем тот же поиск в `done` и изменим только `is_done`.
4. **Проверим прежний сценарий.** Повторим `done` и убедимся, что соседняя задача, `add`, `list` и `exit` продолжают работать.

Мы проверим результат в одном запуске и не создадим второй список или отдельный проект. Следующее занятие расширит поиск с точного id до части названия, уже на основе сохранённых карточек и завершения.
