# 17. Добавление и идентичность задачи

Подключим команду добавления к прежнему меню и сохраним каждую принятую карточку в общем списке.

**Темы:** идентификатор записи · накопление максимума · изменение общего списка

## 00. От проверенного ввода к новой задаче

1. **Точка старта.** В прежнем `main.py` есть один список `tasks`, меню `list/exit`, функции `read_title()` и `read_priority()`, фабрика `create_task()` и formatter `format_task()`.
2. **Новый вопрос.** Как добавить одну карточку после проверки полей, выдать ей номер выше существующих и сохранить прежние записи?
3. **Результат.** Команда `add` создаёт карточку прежней формы, добавляет её в тот же список один раз и показывает через `format_task()`.

Мы сохраняем уже проверенные запросы, модель карточки и форматирование одной записи. Новая часть начинается после принятого ввода: задача должна стать частью прежнего списка и остаться там до следующей команды. Полный обход списка мы оставим следующему шагу проекта.

## 01. Номер карточки не равен её позиции

У каждой задачи есть поле `id`. Это идентификатор записи: номер, по которому мы можем обратиться к задаче. Он не вычисляется из позиции и не равен количеству карточек.

Представим книгу с инвентарной наклейкой: номер напечатан на самой книге, а место на полке показывает, где она стоит сейчас. Если книгу переставить, её место изменится, а наклейка останется на ней. В нашей модели поле `id` играет роль наклейки, индекс списка показывает место. Эта аналогия помогает различить запись и её положение, но не обещает, что номер переживёт удаление или перезапуск: функция ниже смотрит на карточки, которые есть в списке сейчас.

Сопоставим три разных значения:

- `task["id"]`: номер, записанный в карточке.
- `tasks[1]`: элемент на второй позиции.
- `len(tasks)`: количество карточек.

Если в списке три карточки с id `2`, `7` и `4`, следующий номер будет `8`. Вычисление `len(tasks) + 1` даст `4`, а последний id плюс один даст `5` только потому, что в этом примере последняя запись имеет номер 4. Если порядок карточек изменится, последнее значение тоже изменится. Мы не перенумеровываем старые записи и не сортируем список: просматриваем каждый id и выбираем наибольший. Для одной карточки с id `5` следующий номер будет `6`, а пустой список начинает с `1`.

Название тоже не заменяет идентификатор: две разные задачи могут называться одинаково, но оставаться отдельными словарями с разными `id`. Мы используем номер, чтобы обратиться к конкретной записи, а не чтобы вычислить её позицию или проверить уникальность текста. Если список изменится, место карточки может сдвинуться, тогда как поле `id` остаётся частью самой карточки.

## 02. Ищем наибольший текущий номер

Для следующего id достаточно запомнить наибольший номер, который мы уже увидели. Это накопитель: при обходе цикла значение обновляется только тогда, когда найден больший id.

**Проследим отдельный список номеров `2, 7, 4`:**

```python
ids = [2, 7, 4]
max_id = 0
for current_id in ids:
    if current_id > max_id:
        max_id = current_id
next_id = max_id + 1
print(next_id)
```

`max_id` последовательно меняется: `0 → 2 → 7 → 7`. Поэтому `next_id` равен `8`. Для пустого набора цикл не выполняет ни одной итерации, и первый номер остаётся равен `1`.

Здесь `max_id` служит накопителем максимума. До цикла мы задаём ему `0`, потому что задачи получают положительные номера. После каждой проверки сохраняем больший id, а меньший не стирает найденный максимум. Единицу прибавляем только после обхода, чтобы получить следующий свободный номер. Начальное значение находится до цикла именно ради пустого списка: если обратиться сразу к первой карточке, возникнет ошибка. Если заново присваивать максимум на каждой итерации, мы потеряем прежний результат и фактически будем смотреть только на последний id. Знакомый `for` позволяет проверить каждую запись, не меняя порядок и содержимое списка.

**Проследим тот же накопитель на другом входе `4, 9, 2`:**

```python
ids = [4, 9, 2]
max_id = 0
for current_id in ids:
    if current_id > max_id:
        max_id = current_id
print(max_id + 1)
```

После чтения `4` максимум становится `4`, затем обновляется до `9`. Последнее число `2` меньше сохранённого значения, поэтому максимум остаётся равен `9`, а результат равен `10`.

**Найдём причину ошибки:**

```python
ids = [2, 7, 4]
max_id = 0
for current_id in ids:
    max_id = current_id
print(max_id + 1)
```

Здесь мы без сравнения заменяем максимум каждым новым значением. После цикла остаётся последний id `4`, поэтому программа печатает `5` вместо `8`. Сравнение `current_id > max_id` сохраняет уже найденный больший номер.

**Что получим для пустого набора?**

```python
ids = []
max_id = 0
for current_id in ids:
    if current_id > max_id:
        max_id = current_id
print(max_id + 1)
```

**Ожидаемый вывод:**

```text
1
```

В проекте мы просматриваем словари задач и читаем их поле `id`. Функция `get_next_id(tasks)` ничего не добавляет и не меняет поля. Она возвращает номер выше всех id, которые есть в списке сейчас. Это правило не хранит историю удалённых карточек и не обещает вечный глобальный счётчик.

get_next_id() рассчитывает на общий договор: у каждой принятой карточки уже есть положительный id. Функция не проверяет вручную созданные словари, не исправляет повторные или неправильные номера и не заменяет проверку пользовательского ввода. В Planner id назначает одна операция после проверки полей. Такое разделение не позволяет обработчикам раздавать номера по разным правилам.

Если в будущей версии из списка исчезнет карточка с наибольшим id, оставшиеся данные уже не сообщат нам, что этот номер когда-то использовался. Вычисление максимума текущих записей сможет выдать его снова. Это не мешает нынешнему добавлению: команда удаления здесь ещё не существует. Мы называем гарантию точно и не выдаём простой обход списка за постоянный счётчик.

Мы можем проверить ход вручную: после первого чтения сохранённый максимум относится к одному значению, после второго охватывает первые два, а после завершения цикла учитывает весь список. Отдельный вызов готовой функции максимума не нужен: явные сравнения показывают знакомое правило `if` и причину каждого обновления. Для пустого списка не создаётся специальная временная карточка и не меняется сам список.

## 03. Фабрика создаёт карточку, операция добавляет её

`create_task(task_id, title, priority)` возвращает новый словарь с полями `id`, `title`, `priority` и `is_done`; новую задачу фабрика создаёт открытой. Она не знает об общем списке и ничего в нём не меняет.

Разделим создание и включение в приложение. Представим мастерскую, которая печатает пропуск, и журнал, куда сотрудник записывает выданные пропуска. `create_task()` создаёт готовый словарь, как мастерская печатает карточку. Но словарь ещё не стал частью списка приложения, пока `add_task()` не добавит его в `tasks`. Эта аналогия объясняет разные роли функций; она не означает, что список становится постоянным хранилищем.

Что вернёт прежняя фабрика для id 8, названия Read SQL и приоритета 3?

```python
task = create_task(8, "Read SQL", 3)
print(task)
```

Ожидаем словарь прежней формы: `{'id': 8, 'title': 'Read SQL', 'priority': 3, 'is_done': False}`.

**Посмотрим, где список действительно изменяется:**

```python
labels = ["draft"]
result = labels.append("ready")
print(labels)
print(result)
```

**Ожидаемый вывод:**

```text
['draft', 'ready']
None
```

`append()` меняет исходный список и возвращает `None`, специальное значение Python для отсутствующего результата. Поэтому результат `append()` нельзя сохранить вместо самого списка. Операция `add_task(tasks, title, priority)` соединит уже знакомые части: получит следующий id, вызовет фабрику, один раз добавит её словарь в `tasks` и вернёт саму новую карточку.

**Найдём ошибку в короткой функции регистрации метки:**

```python
def add_label(labels, label):
    labels = labels.append(label)
    return labels
```

Ошибка в том, что `append()` возвращает `None`. Список уже изменился, но функция вернёт `None` вместо добавленной метки. В `add_task()` возвращаем карточку, которую создала фабрика, а не результат изменения списка.

Итак, операция добавляет запись и возвращает отдельный результат:

```python
tasks.append(task)
return task
```

Если вернуть результат `tasks.append(task)`, список изменится, но вызывающая функция получит `None`. Если сначала вызвать `append()`, а затем вернуть `task`, мы получим и одно изменение общего списка, и сам созданный словарь для подтверждения.

Возвращённый словарь является той же новой карточкой, которую мы добавили в список. Прежние словари остаются на своих местах: фабрика каждый раз создаёт отдельный объект и заполняет все четыре поля по общему договору. Операция не должна собирать карточку второй раз после `append()`, иначе подтверждение может описывать другой объект, чем тот, который хранится в `tasks`.

## 04. Сначала принимаем данные, затем меняем состояние

Функции `read_title()` и `read_priority()` из предыдущего занятия возвращают только проверенные значения. Если ответ ошибочный, они повторяют свой вопрос и не возвращают неподходящее значение. Значит, пока обе функции не завершились успешно, список менять рано.

**Расположим действия в порядке добавления:**

1. Получим допустимый `title` через `read_title()`.
2. Получим допустимый `priority` через `read_priority()`.
3. Вызовем `add_task(tasks, title, priority)` один раз.
4. Покажем возвращённую карточку через `format_task()`.

`handle_add(tasks)` связывает эти действия, но сам не создаёт словарь и не вызывает `append()`. Единственный вызов `append()` остаётся в операции `add_task()`. Так отказный ответ не меняет состояние, а одно успешное добавление даёт ровно одну новую запись.

**Проверим момент изменения списка:**

- До возврата обоих запросов общего изменения нет.
- В `add_task()` создаётся один словарь и один раз добавляется в прежний список.
- После этого `format_task()` строит строку подтверждения, не меняя запись.

В `run()` список `tasks` создаётся один раз до цикла. Команда `add` вызывает обработчик, `list` сохраняет прежнее сообщение о пустоте или количестве, а `exit` завершает работу. Полный вывод карточек в команде `list` относится к следующему шагу проекта.

## 05. Что мы будем делать в практике

Продолжим тот же main.py и подключим добавление к существующему меню, сохраняя уже работающие функции и список.

1. **Проверим правило номера.** Получим 1, 6 и 8 для пустого, одиночного и неупорядоченного наборов, не меняя входные карточки.
2. **Добавим одну запись.** Соединим прежнюю фабрику с одним append() и проверим длину и сохранность старых задач.
3. **Подключим команду add.** Передадим проверенные ответы из прежних запросов в операцию и подтвердим карточку formatter-ом.
4. **Повторим сценарий.** Исправим ошибочный ввод, добавим две задачи и проверим list, неизвестную команду и штатный выход.

Результатом станет первое реальное добавление в Planner: задачи с разными id остаются в общем списке между командами, а отказ ввода не оставляет неполную запись. Мы проверим прежние действия в том же запуске. Полный просмотр карточек появится отдельным следующим шагом; здесь list останется краткой сводкой.
