# Как Python выполняет программу

Разберём путь от написанной инструкции до вывода: запустим одну команду, соберём короткую последовательность и исправим первую ошибку.

**Темы:** первые инструкции · интерпретатор · вывод · `print` · порядок выполнения · комментарий · первые ошибки

## 00. Первый запуск без настройки компьютера

Для первого опыта нам не нужны установленный Python, файлы проекта или терминал. Начнём в редакторе платформы, где среда для запуска уже подготовлена.

1. **Точка старта:** Мы ещё не писали код и не создавали проект; у нас есть редактор платформы.
2. **Новый вопрос:** Разберём, кто выполняет записанные инструкции и как их порядок влияет на вывод.
3. **Результат:** Напишем короткий экран, предскажем его вывод и исправим одну простую ошибку.

Мы записываем инструкции на языке Python. Интерпретатором называют программу, которая читает код на этом языке и выполняет его. Пока кнопка запуска не нажата, команда остаётся текстом редактора. После нажатия платформа передаёт текущий код подготовленной среде, а область вывода показывает напечатанные сообщения.

Напечатанное сообщение не вставляется обратно в редактор и не становится новой командой. Редактор и результат связаны запуском, но выполняют разные роли.

Представим рецепт: записанные шаги похожи на программу, повар, который следует им, напоминает интерпретатор, а приготовленное блюдо соответствует результату. Эта аналогия помогает отделить инструкцию от выполненного действия. Её граница в том, что человек может догадаться о пропущенном шаге, а Python не восстанавливает намерение по смыслу: он выполняет только допустимые инструкции.

Запуск в платформе показывает работу кода в подготовленной среде, но не устанавливает Python на наш компьютер. Локальные файлы и терминал понадобятся позже. Сейчас проследим одну цепочку: мы записали код, запустили его и прочитали наблюдаемый результат.

## 01. Код хранит инструкцию, Python её выполняет

Написанный код ещё не равен результату. Сначала мы запускаем инструкцию, а затем смотрим, что среда Python выполнила и показала.

До запуска предположим: какое сообщение появится после этой команды?

```python
print("Книга открыта")
```

После запуска в выводе появляется `Книга открыта`. Готовая функция `print` передаёт указанное значение в область вывода платформы. Кавычки здесь обозначают текст в коде, а не отдельные символы сообщения. Если мы поменяем текст и запустим код снова, новый запуск покажет результат уже изменённой команды.

Редактор и вывод выполняют разные роли: в редакторе остаются записанные инструкции, а в области результата видны сообщения от их выполнения. Напечатанное сообщение не вставляется обратно в код и не становится новой командой. Поэтому мы проверяем не только строку, которую написали, но и вывод после запуска.

Чтобы проследить порядок, разберём две инструкции на другом примере. В пошаговой модели каждая строка выполняется по очереди и добавляет сообщение к уже полученному выводу.

```python
print("Ставим чашку")
print("Наливаем чай")
```

1. Первая инструкция вызывает `print`. Текст между кавычками становится первой строкой вывода.
2. Затем Python выполняет следующую инструкцию и добавляет её сообщение ниже первой строки.

Здесь показан подготовленный разбор шагов, а не отдельный запуск Python внутри карточки. Мы видим связь строки кода и новой строки вывода: один вызов `print` печатает переданный текст, затем вывод переходит к следующей строке.

## 02. Из чего состоит `print()`

Рассмотрим `print("Библиотека открыта")` слева направо: готовая функция, скобки и текст внутри кавычек работают вместе.

```python
print("Библиотека открыта")
```

1. **`print`:** готовая функция Python, которая отправляет переданное значение в вывод.
2. **Круглые скобки** показывают, какое значение мы передаём функции для выполнения.
3. **Кавычки** обозначают начало и конец текста в коде; в сообщении они не печатаются.

Для обычного текста подойдут прямые одинарные или двойные кавычки. Мы закрываем текст тем же видом кавычек, которым начали его записывать. Фигурные кавычки и кавычки-ёлочки выглядят похоже, но Python не использует их как границы текста.

В выводе появится `Библиотека открыта` без кавычек. Кавычки относятся к записи кода: они помогают Python понять, где заканчивается текст. Если мы уберём их, слово будет прочитано как имя, значение которого нужно найти. Пока мы не создавали такое имя, поэтому запуск остановится с `NameError`. Для исправления в этом примере достаточно снова обозначить слово как текст.

Текст в кавычках выводится таким, каким мы его записали: с теми же заглавными буквами, пробелами и знаками препинания. Python не исправляет опечатки и не превращает сообщение в команду. Если в тексте нужен знак кавычки, способ записать его разберём отдельно; для первых сообщений выберем простую фразу без такого знака.

Одинарные и двойные кавычки здесь выполняют одинаковую роль. Мы можем выбрать любой вид, если закрываем текст тем же видом; меняется запись в редакторе, но не само сообщение.

**Найдём причину:**

```python
print(Готово)
```

Без кавычек Python пытается найти значение с именем `Готово`, которого мы ещё не создавали. Функция `print` умеет выводить текст, а после команды не нужна точка. Исправим строку, обозначив слово как текст.

Исправленная строка:

```python
print("Готово")
```

У каждого вызова `print` есть и заметное поведение: после переданного текста вывод переходит на новую строку. Если мы вызовем `print()` без текста, в результате появится пустая строка. Это отличается от пустого места в редакторе, которое только разделяет команды.

## 03. Команды выполняются сверху вниз

В простой программе каждая команда выполняется один раз в порядке записи. Python не меняет строки местами, даже если сообщение подсказывает человеку более понятную последовательность.

Сравним это с очередью пронумерованных карточек: сначала читается первая, затем вторая, затем третья. В коде роль карточек играют строки, а вывод показывает результат каждой команды на своём месте. Граница аналогии в том, что Python не выбирает важнейшую карточку и не проверяет здравый смысл порядка: он следует записи.

Сначала ставим чашку, затем наливаем чай и только потом делаем глоток. Расположим команды в таком порядке.

```python
print("Ставим чашку")
print("Наливаем чай")
print("Делаем глоток")
```

Если мы собрали строки иначе, переставим их, пока действия не будут идти в нужном порядке. Python выполнит команды именно так, как они записаны. Если две команды поменять местами, их сообщения тоже поменяют порядок. После последней инструкции этот короткий запуск заканчивается: новых сообщений не появляется. Позже появятся способы выбирать команды и повторять их, но для первого прямого примера достаточно точно читать строки сверху вниз.

Сейчас мы рассматриваем прямой участок кода: ни одна команда не пропускается и не повторяется. Смысл текста может подсказать подходящий порядок человеку, но Python не читает сообщения как план действий. Порядок определяется местом каждой строки. Поэтому изменение одной строки не переставит соседние сообщения автоматически.

**Проверим порядок:** в каком порядке появятся сообщения, если строки `print` записаны сверху вниз как «Откроем экран», затем «Начнём работу»?

- Откроем экран, затем Начнём работу.
- Начнём работу, затем Откроем экран.
- Python сам выберет порядок.

Верный ответ: сначала появится «Откроем экран», затем «Начнём работу». В прямой программе Python выполняет первую строку, потом вторую, и не переставляет команды по смыслу их текста.

## 04. Комментарии и пустые строки

Не вся строка в редакторе становится командой. Иногда мы оставляем заметку для человека или пустое место между инструкциями.

Символ `#` начинает комментарий. Python пропускает текст комментария до конца этой строки, поэтому он не добавляет сообщение в вывод. Комментарий остаётся частью кода, чтобы позже напомнить, зачем рядом записаны инструкции.

```python
print("Начало")
# print("Эту команду Python пропускает")

print()
print("Продолжение")
```

Мы получим сообщение «Начало», затем одну пустую строку, а после неё «Продолжение». Комментарий не выполняется. Пустая строка между командами только разделяет текст программы и не меняет результат. Пустой вызов `print()` выполняется и создаёт строку без текста.

В самостоятельном коде комментарий удобно использовать, когда мы хотим временно отключить одну команду и сравнить вывод. Чтобы вернуть её, достаточно убрать `#`. Сначала мы предскажем, какое сообщение исчезнет, а после запуска сравним ожидание с результатом.

Всё, что стоит после `#` на той же строке, Python также считает комментарием. Например, `print("Готово") # это пояснение` выведет только слово «Готово». Комментарий может быть целой строкой или пояснением после команды; в обоих случаях он помогает читающему и не добавляется в результат.

**Проверим себя:** что добавит пустую строку именно в вывод?

- Оставить пустую строку между командами.
- Добавить `#` перед командой.
- Вызвать `print()` без текста.

Верный ответ: вызвать `print()` без текста. Пустое место в коде и комментарий пропускаются, а этот вызов выполняется и печатает пустую строку.

## 05. Две разные причины остановки

Иногда Python не может прочитать запись, а иногда читает её и обнаруживает проблему уже во время выполнения. По этому различию мы выберем, что исправлять.

Представим, что мы передали исполнителю лист с рабочими указаниями. Если в форме записи не закрыта скобка, инструкции нельзя прочитать целиком, поэтому исполнитель не начинает работу. Так ведёт себя наш короткий пример с синтаксической ошибкой: платформа передаёт Python весь фрагмент, и он сначала проверяет его запись.

```python
print("Первая строка")
print("Вторая строка"
```

Здесь не закрыта круглая скобка. Python сообщает `SyntaxError`, то есть ошибку в правилах записи. Поскольку проверяется весь фрагмент, первая строка тоже не успевает выполниться. Точный текст сообщения зависит от места ошибки, поэтому сначала найдём указанную строку и проверим её кавычки и скобки.

Теперь запись составлена правильно, но во второй команде стоит слово без кавычек. Мы пока не создавали значение с таким именем. Python начинает выполнять программу, печатает первую строку, встречает неизвестное имя и останавливается с `NameError`. Третья команда уже не выполняется.

```python
print("Первая строка")
print(Вторая)
print("Третья строка")
```

Ошибка возможна и в имени знакомой команды. Например, в `pritn("Готово")` скобки и текст записаны правильно, но Python не находит функцию с именем `pritn` и останавливается с `NameError`. Мы проверим само имя, а не будем менять сообщение или порядок строк.

Продолжим пример с рабочим листом: если исполнитель начал работу, но на одном из шагов не находит деталь с указанным названием, он останавливается. В Python это похоже на `NameError`: запись читается, выполнение начинается, а неизвестное имя нельзя найти. Сравнение условное, но помогает понять, почему в выводе уже может быть результат предыдущей команды.

Когда запуск остановился, мы прочитаем последнюю строку сообщения и найдём рядом отмеченную строку кода. Затем назовём причину, изменим одну деталь и запустим весь фрагмент снова. Полный разбор всех частей сообщения об ошибке понадобится позже; сейчас нам достаточно отличить запись, которую Python не прочитал, от неизвестного имени при выполнении.

Последняя строка сообщения обычно называет вид ошибки и коротко описывает причину. Строка кода рядом помогает найти место для проверки, хотя иногда Python замечает проблему чуть позже символа, который мы забыли. Мы не будем менять сразу несколько строк: одна небольшая правка позволяет увидеть, какая причина действительно изменила запуск.

**Вспомним:** как по выводу отличить `SyntaxError` от `NameError` в этих примерах?

Подсказка: проверим, появилась ли первая строка до остановки программы.

Ответ: при `SyntaxError` Python не смог прочитать весь фрагмент, поэтому ни одна строка не запустилась. При `NameError` запись была допустимой: первая команда успела выполниться, затем программа остановилась на неизвестном имени.

### Главное после занятия

- Редактор платформы запускает код в подготовленной среде Python, но не устанавливает его на компьютер.
- Интерпретатор выполняет инструкции, а `print` выводит переданный текст.
- Кавычки обозначают текст, команды выполняются сверху вниз, запуск заканчивается после последней инструкции.
- Комментарий начинается с `#`; пустая строка кода отличается от `print()`.
- При `SyntaxError` код не начинается, а при `NameError` он останавливается на неизвестном имени.

## 06. Что мы будем делать в практике

Перенесём изученный путь в короткие действия редактора: изменим сообщение, исследуем вывод, исправим ошибку и напишем стартовый экран StudyHub.

1. **Изменим** текст готового `print` и проверим новое сообщение в выводе.
2. **Исследуем** три строки: предскажем вывод, переставим две команды и временно отключим одну комментарием.
3. **Исправим** одну опечатку в имени команды и добьёмся запуска ожидаемого вывода.
4. **Напишем** три строки экрана и сверим весь результат с заданным текстом и порядком.

Мы выполняем эти действия в редакторе платформы и сопоставляем каждый результат с конкретной правкой. В исследовательских примерах перестановка и комментарий проверяются отдельно от точного стартового экрана.
