# Переменные и базовые типы

Продолжим стартовый экран StudyHub. Дадим значениям понятные имена, научимся читать и заменять их, затем различим четыре базовых типа.

**Темы:** имя и значение · присваивание · `str` · `int` · `float` · `bool` · `type(value)`

## 00. От вывода к данным с именами

Уже работающий `main.py` показывает стартовый экран StudyHub, а Git сохраняет версии этого файла. Теперь посмотрим, что меняется, когда повторяемому тексту и другим значениям дают имена.

1. **Точка старта:** знакомые строки выводятся командами `print`, а Git хранит сохранённую историю файла.
2. **Новый вопрос:** Как назвать значение, прочитать его и отличить число от похожего текста?
3. **Результат:** Стартовый экран с понятными переменными и четырьмя базовыми типами.

Git хранит выбранные версии исходного текста. Переменная связывает имя со значением во время одного запуска. Это разные виды состояния: коммит помогает сравнить и восстановить код, а чтение имени даёт значение, связанное с ним в текущей точке выполнения. Git не записывает все промежуточные значения, которые программа выводила во время запуска.

## 01. Значение получает понятное имя

**Вопрос:** Что проще изменить, если название нужно показать в нескольких местах?

### Повторить литерал

```python
print("ReadNest")
print("ReadNest")
```

Чтобы сменить название, нужно исправить обе строки.

### Дать значению имя

```python
library_name = "ReadNest"
print(library_name)
print(library_name)
```

Название задано один раз и выведено в двух местах. Переменная связывает имя `library_name` с текстом `ReadNest`. Повторные обращения к имени читают это значение.

Значение, которое напрямую записано в исходном коде, называют литералом. Здесь `"ReadNest"` находится прямо внутри команды `print`, поэтому при повторе мы заводим две записи одного названия. В версии с переменной оба вызова читают одно связанное значение, и его проще согласованно изменить.

Переменная нужна не для таблицы и не для красоты. Она даёт данным смысловое имя, чтобы программа могла использовать значение в нужных местах. В реальном приложении так называют настройки, счётчики, статусы и сведения о пользователе.

Представим карточку с подписью в каталоге библиотеки: надпись `library_name` помогает обратиться к текущему названию, а не переписывать его во всех строках. Если мы присвоим имени другое значение, дальнейшие чтения покажут новое. Граница сравнения важна: имя в Python не является физической коробкой и не создаёт независимую копию любого объекта. Сейчас нам достаточно модели «имя связано с текущим значением».

В следующем разделе разберём, что делает знак присваивания. Пока заметим пользу имени: один источник значения упрощает согласованное изменение нескольких строк.

## 02. Присваивание связывает имя со значением

В записи `shelf_name = "New arrivals"` справа находится значение, слева имя. Знак `=` выполняет присваивание: программа связывает имя с результатом справа.

```python
shelf_name = "New arrivals"
print(shelf_name)
```

1. Имя `shelf_name` связывается с текстом `"New arrivals"`. Эта строка сама ничего не выводит.
2. `print` получает значение по имени `shelf_name` и выводит текст.

В этом уроке знак `=` означает присваивание, а не проверку равенства. Сначала Python вычисляет правую часть, затем связывает имя слева с полученным значением. Чтобы увидеть значение, нужна отдельная команда `print(shelf_name)`.

Имя должно быть присвоено до первого чтения. Вызов `print(shelf_name)` не создаёт переменную, он только просит Python найти уже существующее имя.

Если справа находится простое текстовое или числовое значение, мы читаем его именно там, где расположена строка присваивания. Присваивание не выводит результат и не проверяет, совпадало ли прежнее значение с новым. Это отдельное действие программы.

## 03. Имя и текст имени различаются

Кавычки уже показывали границы текста. Теперь сравним текст, записанный в кавычках, с именем, которое Python должен прочитать.

```python
room_name = "Reading room"
print(room_name)
print("room_name")
```

Результат:

```text
Reading room
room_name
```

В первой команде имя без кавычек означает текущее значение. Во второй кавычки превращают запись `room_name` в обычный текст. Python не снимает кавычки и не ищет по ним переменную.

Вывод показывает символы, но не способ, которым они получены. Если в переменной хранится сама строка `room_name`, команды `print(room_name)` и `print("room_name")` могут напечатать одинаковый текст. Чтобы увидеть разницу, прочитаем исходную команду: без кавычек Python ищет значение по имени, а внутри кавычек получает готовую строку.

**Найдём причину ошибки:**

```python
shelf_name = "Maps"
print("shelf_name")
```

Почему команда вывела `shelf_name` вместо `Maps`?

1. Имя в `print` заключено в кавычки и стало обычным текстом.
2. Переменные нельзя передавать в `print`.
3. Текст `Maps` не может быть значением переменной.

Правильный ответ: первый. Кавычки обозначают текст. Чтобы получить значение, передадим в `print` имя без кавычек.

```python
shelf_name = "Maps"
print(shelf_name)
```

## 04. Создадим имя до первого чтения

Python выполняет файл сверху вниз. Если обратиться к имени раньше присваивания, нужного значения ещё нет.

```python
print(branch_name)
branch_name = "Central"
```

На первой строке Python ещё не встречал имя `branch_name`. Чтение незаданного имени вызывает `NameError`.

Рабочий порядок:

```python
branch_name = "Central"
print(branch_name)
```

Для двух значений сначала создадим оба имени, затем прочитаем их:

```python
library_name = "ReadNest"
book_count = 3
print(library_name)
print(book_count)
```

Имена чувствительны к регистру: `project_name` и `Project_Name` для Python разные. Опечатка или другой регистр тоже могут привести к `NameError`.

Если Python встречает имя, которому ещё не присваивали значение, он не подставляет пустую строку и не угадывает намерение. Мы сверяем написание и порядок: имя должно быть создано до чтения, а каждый следующий вызов использует ту запись, которую действительно выполнила программа.

Сообщение `NameError` означает, что Python не смог найти имя в точке чтения. Сначала сверим написание, включая регистр, затем проверим, была ли строка присваивания выполнена раньше.

**Найдём ошибку с регистром:**

```python
project_name = "StudyHub"
print(Project_Name)
```

Имя было присвоено, но Python сообщает `NameError`. Сверим большие и маленькие буквы: `Project_Name` и `project_name` для Python разные. Кавычки здесь не исправят чтение, а превратят запись имени в обычный текст.

```python
project_name = "StudyHub"
print(project_name)
```

## 05. Переприсваивание меняет текущее значение

Одно имя может получить новое значение. При следующем чтении программа увидит новое присваивание.

**Предскажем вывод:**

```python
shelf_status = "open"
print(shelf_status)
shelf_status = "closed"
print(shelf_status)
```

Результат:

```text
open
closed
```

Новое присваивание заменяет текущее значение для дальнейших инструкций. Сам Python не ведёт журнал всех прежних значений переменной. Историю изменений исходного кода хранит Git, а не переменная.

Полезно разделять два наблюдения. Во время запуска мы видим то значение, которое связано с именем в этой строке. В Git мы можем увидеть изменение сохранённого текста программы, если поменяли присваивание в файле и зафиксировали эту правку. Git не превращает несколько чтений имени в журнал выполнения.

В примере первая строка вывода уже содержит `open`, когда программа доходит до нового присваивания. Следующая команда печатает `closed`. Переприсваивание не переписывает текст, который уже появился в выводе, и не меняет задним числом предыдущий шаг.

Здесь мы только присваиваем новое готовое значение. Вычисления вроде увеличения счётчика появятся в следующем занятии, после изучения числовых операций.

## 06. Четыре базовых типа данных

Тип описывает, какое это значение по смыслу. Он помогает читать данные и выбирать подходящие действия, например считать количество или хранить текст.

- `str` хранит текст: название, сообщение или адрес.
- `int` хранит целое число: количество или номер без дробной части.
- `float` хранит дробную величину с точкой, например ширину полки.
- `bool` хранит ответ да или нет: `True` или `False`.

```python
shelf_name = "ReadNest"
book_count = 5
shelf_width_cm = 62.5
is_open = False
```

Значения `5` и `"5"` имеют разные типы. Первое является числом `int`, второе строкой `str`. Аналогично, `True` без кавычек имеет тип `bool`, а `"True"` является текстом. Дробное число записывают с точкой, например `62.5`. Запятая не заменяет точку.

Представим карточку с напечатанным номером и полку с книгами. Символы «5» на карточке помогают найти нужное место, а число пять обозначает количество книг. Для человека записи выглядят похоже, но `"5"` хранит текст, а `5` хранит число. Аналогия помогает различить назначение, но сам тип Python определяет по значению и кавычкам в записи.

Тип помогает выбрать действие, которое имеет смысл для данных. Текстовое название нужно сохранить и показать как текст; количество можно будет складывать после знакомства с арифметикой; состояние готовности пока можно только записать и вывести. Поэтому текст `"True"` не становится ответом да: без кавычек `True` записывает значение типа `bool`, а с кавычками это набор символов типа `str`.

Тип сам по себе не объясняет назначение числа. `int` может быть количеством, номером версии, нулём или отрицательным целым числом. `float` не означает процент автоматически: имя и контекст подсказывают, что измеряет число. Например, `62.5` остаётся дробной шириной полки, а знак процента в числовое значение не входит.

## 07. Выбираем имена, которые объясняют данные

Хорошее имя позволяет понять роль значения без поиска по всему файлу. Для нескольких слов используем стиль `snake_case`.

В этом стиле слова пишутся строчными буквами и разделяются подчёркиванием: `book_count`. Само подчёркивание не меняет значение и не разделяет его на части для Python, зато делает имя понятным человеку. Это соглашение о читаемости, а не новый вид переменной. Имя `BookCount` тоже можно записать, но оно уже отличается от `book_count`: Python учитывает регистр.

```python
book_count = 5
is_open = False
shelf_width_cm = 62.5
```

Имя обычно начинается с буквы или подчёркивания. Внутри могут быть буквы, цифры и подчёркивания. В имени нет пробелов или дефисов, оно не начинается с цифры. Python различает верхний и нижний регистр.

Имя `is_ready` читается как вопрос с ответом да или нет. Название `x` не говорит, что хранится, а имя `book_count` подсказывает смысл.

Обычно в имени отражаем смысл значения, а не его временное состояние. Если название проекта хранится в `project_name`, такое имя объясняет строку и остаётся понятным после изменения самого названия. Короткое имя пригодно в небольшой формуле, но здесь мы учимся читать весь файл без догадок.

Имена `type` и `print` уже обозначают готовые функции Python. Если дать переменной одно из этих имён, привычный вызов может перестать работать как раньше. Оставим встроенные имена функциям, а для своих данных выберем название по смыслу, например `value_type`.

**Заполним пропуск:** соединим слова в понятном имени по стилю `snake_case`.

```text
book___count = 5
```

Нужен символ `_`.

## 08. Проверим тип и прочитаем данные платформы

Когда имя уже выбрано, можно проверить тип связанного с ним значения готовой функцией `type()`.

Запись `type(reading_time)` получает текущее значение по имени и возвращает сведения о его типе. Вложенный вызов передаёт эти сведения функции `print`, чтобы мы увидели их в выводе.

```python
reading_time = 17.5
print(type(reading_time))
```

Результат:

```text
<class 'float'>
```

Строка `<class 'float'>` сообщает тип, это не само значение `17.5`. Для этой проверки достаточно `type(value)`; запись `type(value).__name__` не нужна.

В редакторной задаче платформа заранее задаёт `source_title`, `source_priority`, `source_progress` и `source_done`. Префикс `source_` отмечает значения, которые уже переданы программе. Свяжем их с именами `title`, `priority`, `progress` и `is_done`, выведем значения и типы по порядку. В проверках данные меняются, поэтому прочитаем сами значения, а не подставим константы; это не ввод с клавиатуры.

## 09. Что мы будем делать в практике

Сначала исследуем переданные значения в редакторе, затем изменим тот же `main.py` с уже знакомым стартовым экраном.

1. **Прочитаем данные:** свяжем четыре переданных значения с понятными именами и увидим их значения и типы в выводе.
2. **Продолжим `main.py`:** заменим повторённое название проекта переменной `project_name`; заголовок и заключительная строка будут использовать одно значение.
3. **Добавим сведения:** зададим `version`, `progress_percent` и `is_ready`; каждая строка вывода покажет заданное значение.
4. **Проверим и сохраним:** поменяем только `project_name`, увидим новое название в обоих местах и зафиксируем проверенный файл в прежней истории проекта.

В редакторной задаче проверим значения платформы по описанному правилу и увидим четыре переданных значения вместе с типами. В ручной карточке продолжим тот же `main.py`: одно имя проекта будет управлять двумя строками стартового экрана.

В проекте `progress_percent` зададим вручную: это учебное число, не статистика выполненных задач. После изменения названия сверим весь экран с прежним результатом запуска и убедимся, что знакомые строки сохранились; затем запустим файл и сохраним проверенную правку Git-командами в той же папке. Условия, функции и числовые вычисления пока не понадобятся.

### Главное после занятия

- Переменная связывает понятное имя с текущим значением.
- Имя присваивают до первого чтения, а текст имени заключают в кавычки.
- Повторное присваивание меняет значение для следующих команд.
- `str`, `int`, `float` и `bool` описывают разные виды данных.
- `type(value)` помогает проверить тип существующего значения.
