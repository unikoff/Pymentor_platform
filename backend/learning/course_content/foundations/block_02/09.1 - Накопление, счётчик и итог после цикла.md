# Накопление, счётчик и итог после цикла

Мы уже умеем выполнять шаг для каждого элемента. Теперь сохраним меняющийся итог и используем его после обхода.

**Темы:** накопитель · счётчик · итог после цикла

## 00. От отдельного шага к общему итогу

В прошлом занятии цикл выполнял действие для каждого значения, например печатал текущий элемент. Иногда результата шага недостаточно. Если несколько занятий имеют разную длительность, нужно сохранить все значения вместе в одном общем итоге.

1. **Точка старта.** Мы уже обходим строку, `range` и список, в том числе пустой, и выполняем действие для каждого элемента.
2. **Новый вопрос.** Как сохранить общий итог, пока цикл переходит от одного значения к следующему?
3. **Результат.** Мы проследим сумму и счётчик, а в существующем расчёте сложим длительности занятий и учтём один перерыв.

Например, прежний расчёт умножал количество занятий на одну длительность. Теперь у занятий могут быть разные значения, и одного повторённого действия недостаточно: понадобится сохранить результат предыдущих шагов. Если все длительности снова равны прежней норме, новый расчёт должен дать тот же итог. Это проверит, что мы сохранили старое правило, а не только получили новый способ ввода.

Что понадобится сохранить между двумя соседними шагами обхода? Мы сохраним меняющийся общий итог. Текущий элемент сменится, а накопитель перенесёт результат предыдущего шага дальше.

## 01. Накопитель хранит промежуточный и общий результат

Накопитель хранит меняющийся итог. Это обычная переменная. Один раз до цикла зададим ей начальное значение, а внутри цикла прочитаем сохранённое число, добавим текущий элемент и присвоим имени новый итог.

Здесь состоянием назовём значения, которые нужные программе переменные хранят сейчас. Для накопления это текущее значение `total`. До цикла оно равно нулю, после каждого шага меняется, а затем передаётся следующей итерации. Мы можем назвать точное состояние только вместе с моментом, к которому оно относится.

Зафиксируем сумму после каждого элемента. Стрелка показывает, как прежний итог и текущее значение дают новое состояние `total`.

На схеме показаны четыре состояния одной переменной, а не отдельная копия каждого элемента. Подпись над каждой стрелкой напоминает, какое значение добавилось на этом шаге. Если список пуст, переходов не будет и останется начальное значение `0`.

Представим копилку, в которой лежит сумма денег. Начальное значение `0` соответствует пустой копилке, а текущий элемент здесь играет роль новой монеты. После каждого пополнения мы записываем новый баланс и несём его к следующему шагу. Аналогия помогает понять, почему прежний итог не должен исчезать. Но переменная не хранит отдельные монеты: в ней находится только число, которое мы пересчитываем.

```python
points = [2, 5, 1]
total = 0
for point in points:
    total = total + point
print(total)
```

Проследим состояние на каждом проходе:

1. До обхода задаём `total = 0`. Значение уже существует, даже если список пуст.
2. Первый элемент равен `2`. До сложения сохранённый итог равен `0`; после обновления он равен `2`.
3. На следующем шаге `point` получает `5`, а `total` сохраняет результат `2`. После сложения прежнего и текущего значений итог равен `7`.
4. Последний элемент равен `1`. До обновления `total` равен `7`, после сложения он хранит `8`.
5. Обход закончился, поэтому после цикла печатается общий итог `8`.

В выражении `total = total + point` Python сначала вычисляет правую сторону. Он берёт прежний `total`, прибавляет текущий `point`, затем связывает имя `total` с новым числом. Знак `=` означает присваивание, а не сложение: старое значение нужно явно прочитать справа. Именно поэтому предыдущее обновление участвует в следующем.

Итоговый `print` стоит после цикла и выполняется один раз, когда все элементы уже обработаны. Если перенести печать внутрь тела, она покажет последовательность промежуточных значений. Иногда такой ход полезен, чтобы исследовать изменение суммы, но он не заменяет печать одного общего ответа.

## 02. Сумма, счётчик и порядковый номер

Сумма и счётчик могут обновляться за один проход, но отвечают на разные вопросы. Сумма прибавляет значение элемента, а счётчик прибавляет единицу за обработанный элемент.

В корзину можно добавлять предметы разного веса, а рядом нажимать счётчик посетителей. Общий вес похож на сумму: он меняется на величину текущего предмета. Число посетителей похоже на счётчик: оно растёт на единицу при каждом новом человеке, независимо от его веса. Это сравнение показывает разницу между «сколько всего получилось» и «сколько раз мы обработали элемент». В Python обе переменные остаются обычными числами, и мы сами выбираем, какое значение прибавить.

```python
scores = [3, 5, 8]
total = 0
count = 0
for score in scores:
    total = total + score
    count = count + 1
print(total)  # 16
print(count)  # 3
```

`total = total + score` отвечает на вопрос «Какова сумма значений?». `count = count + 1` отвечает на вопрос «Сколько элементов обработано?». В одном проходе можно хранить оба состояния, потому что они отвечают на разные вопросы.

Для количества начнём с `count = 0`, потому что до обхода не обработан ни один элемент. Для номера, который мы показываем человеку, начнём с `position = 1`. Это первое место в текущем выводе, а не постоянный номер записи. Текст элемента по-прежнему приходит прямо из списка, а отдельный счётчик меняется после обработки строки.

```python
rooms = ["A", "B", "C"]
position = 1
for room in rooms:
    print(position)
    position = position + 1
```

Начальный номер равен `1`. После каждого элемента мы увеличиваем его на единицу, поэтому вывод содержит номера `1`, `2`, `3`.

Не будем смешивать сумму, количество и порядковый номер. Если элементы равны `3`, `5` и `8`, сумма равна `16`, а количество равно `3`. Для показа мы можем начать нумерацию с единицы, хотя количество уже обработанных элементов перед первым шагом равно нулю. Начальное значение зависит от вопроса, который решает переменная.

Проследим оба состояния: сначала пара `(total, count)` равна `(0, 0)`. После значения `3` она становится `(3, 1)`, после `5` это `(8, 2)`, а после `8` получаем `(16, 3)`. Если одним из элементов был бы ноль, сумма на этом шаге не изменилась бы, но количество обработанных элементов всё равно увеличилось бы. Так видно, что счётчик отвечает за число проходов, а не за размер суммы.

## 03. Инициализация и печать должны стоять на своих местах

Начальное значение задаём один раз до цикла. Если сбрасывать накопитель в теле, предыдущая сумма исчезает. Это логическая ошибка: программа может завершиться без исключения, но напечатать неверный ответ.

Вернёмся к списку `[2, 5, 1]`. В теле ошибочного варианта сначала снова выполняется `total = 0`, затем к нулю прибавляется текущий элемент. После шагов остаются только значения отдельных итераций, а общая сумма теряется. Поэтому исправление состоит не в другом сложении, а в переносе начальной установки выше заголовка `for`.

```python
points = [2, 5, 1]
for point in points:
    total = 0
    total = total + point
print(total)
```

Вторая ошибка не сбрасывает сумму на ноль, а заменяет её текущим элементом. При `total = value` справа нет прежнего итога. После нескольких шагов остаётся только последнее значение:

```python
values = [2, 5]
total = 0
for value in values:
    total = value
print(total)  # 5
```

Чтобы сохранить прошлые значения, справа от `=` должно участвовать старое состояние накопителя. Для набора `[2, 5]` неправильное присваивание оставит `5`, а накопление даст `7`. Значит, вход из одного элемента не всегда обнаружит потерю состояния: нужны несколько разных значений.

Подберём вход по ошибке. Несколько разных чисел показывают, сохраняется ли вклад предыдущих шагов. Пустой список показывает, задано ли начальное значение до обхода. Список из одного элемента помогает проверить, что тело повторилось один раз. Разные случаи отвечают на разные вопросы, поэтому один удачный запуск не подтверждает все части механизма.

Печать внутри цикла сама по себе не ошибка. Она подходит, когда мы хотим увидеть прогресс, но выводит несколько строк. Для одного общего ответа разместим её после цикла. Тогда при списке из трёх значений увидим три промежуточных итога внутри и один общий итог после обхода.

Пустой список помогает проверить начальное состояние отдельно. Тело не выполнится ни разу, поэтому заранее созданный `total` останется равным нулю. Тело цикла не присвоит новое значение переменной `value`; если до обхода её не было, после него это имя останется неопределённым. Мы не будем читать итог из переменной цикла: она не заменяет накопитель и не служит ответом для пустого входа.

## 04. Условие внутри цикла отбирает элементы

Знакомый `if` можно поставить внутри тела `for`. Мы проверим каждый элемент, но обновим накопитель лишь тогда, когда условие истинно.

```python
values = [-3, 5, 0, 2]
total = 0
for value in values:
    if value > 0:
        total = total + value
print(total)
```

Условие истинно для `5` и `2`. При `-3` и `0` обновление пропускается, поэтому сохранённая сумма не меняется. До первого элемента накопитель равен нулю. После `-3` он остаётся нулём, после `5` становится равен пяти, после `0` остаётся равен пяти, а после `2` становится равен семи. Если список пуст или не содержит подходящих элементов, начальное значение тоже сохранится.

Так мы соединяем уже знакомые механизмы: `for` посещает элементы, `if` выбирает, менять ли итог на текущем шаге, а накопитель переносит сумму дальше. Новый список для отобранных чисел не нужен. При смене условия, например на `value != 0`, изменится правило отбора, но порядок обхода останется тем же.

## 05. Порядок действий в расчёте

В существующем `main.py` уже есть цикл по количеству занятий, который выводил номер каждого шага. Теперь внутри того же обхода мы получим отдельную длительность для текущего занятия. `input` возвращает текст, поэтому знакомый `int` превратит введённые цифры в целое число перед сложением. Количество занятий остаётся неотрицательным целым числом по прежнему договору.

Это разные переменные с разными задачами. Переменная цикла помогает показать, для какого занятия сейчас задаётся вопрос. `duration_minutes` хранит только ответ текущего шага. `study_minutes` хранит сумму ответов всех уже пройденных шагов. На следующем занятии длительность сменится, а общий итог останется и примет новое значение.

Соберём этапы расчёта по порядку:

1. До цикла один раз задать учебные минуты, равные нулю.
2. На каждом шаге получить текст длительности и преобразовать его.
3. Прибавить число текущего занятия к накопленной сумме.
4. После обхода один раз прибавить перерыв.
5. По общей сумме вычислить часы и остаток, затем вывести их.

Начальное значение создаётся до повторений. Каждый ответ прибавляется к прежнему итогу. Перерыв добавляется после цикла один раз, а часы и остаток вычисляются уже из полной суммы.

Если поместить прибавление перерыва внутрь цикла, два занятия добавят два перерыва. А при нуле занятий перерыв не появится вовсе. Размещение после обхода выражает нужное правило: он относится ко всему расчёту, а не к одному занятию. Знакомое целочисленное деление `//` получает полные часы, а остаток `%` хранит минуты после выделения этих часов. Обе операции используют окончательное число учебных минут с перерывом.

Если занятий ноль, `range(0)` не запускает тело цикла и вопрос о длительности не появляется. Учебные минуты остаются равными нулю. После цикла расчёт добавляет один перерыв, как и раньше: с перерывом в 10 минут общий итог равен 10. Мы сохраняем старое правило пустого расчёта, хотя теперь внутри есть цикл.

Проверим и регрессию прежнего случая. Две длительности по 40 минут дают 80 учебных минут, плюс один перерыв в 10 минут: всего 90 минут, один час и 30 минут. Это совпадает с прежним умножением количества на 40 и прибавлением перерыва. Если ввести 35 и 50, учебная сумма будет 85, общий итог с перерывом равен 95 минутам, а остаток после перевода в часы равен 35 минутам. Так мы видим, что новое решение учитывает каждое значение, а не только последнее.

В практике мы договоримся вводить положительную целую длительность для каждого занятия. Вызов `int()` преобразует корректный текст, но сам по себе не проверяет, что текст состоит из цифр и число больше нуля. Ошибки произвольного ввода и повторный запрос пока не добавляем: для них понадобятся дополнительные темы. Длительности также не сохраняются в новый список. Для этой задачи достаточно получить одно текущее число и прибавить его к общему накопителю.

## 06. Что мы будем делать в практике

Соберём изученную механику по шагам: сначала проверим состояние чисел, затем перенесём накопление в уже знакомый расчёт.

1. **Проследим числа в редакторе.** Составим сумму до запуска для пустого, одиночного и многозначного входа, затем сравним её со счётчиком обработанных элементов.
2. **Проверим правило отбора и ошибки.** Изменим сумму только для положительных значений и найдём, где ошибочный код сбрасывает или заменяет прежний итог.
3. **Добавим счётчик к обходу строк.** Пройдём список напрямую, сохраним порядок, начнём отображение с 1 и проверим пустой список без индексного доступа.
4. **Обновим существующий `calc`.** Введём длительность каждого занятия, сложим все введённые значения, один раз добавим перерыв и сохраним перевод суммы в часы и минуты.

Редакторные примеры изолируют сумму и счётчик, поэтому мы можем отследить каждое обновление и увидеть эффект пустого входа. Затем ручные задания соединят эту механику с уже знакомыми условием, прямым обходом списка и существующей веткой расчёта. Подробные шаги решения останутся в карточках практики.

В проекте проверим ноль занятий, прежние одинаковые длительности и два разных значения. После изменения сохраним прежнюю формулу перевода в часы и остаток. В следующем занятии мы используем понимание состояния, чтобы разобрать цикл `while`, не вводя счётчик и накопление одновременно с новым способом повторения.
