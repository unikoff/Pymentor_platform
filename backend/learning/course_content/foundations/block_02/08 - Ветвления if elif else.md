# Ветвления if / elif / else

Свяжем знакомые проверки с действиями программы: разберём отступы, выбор одной ветки, независимые условия и безопасный запуск прежнего расчёта.

**Темы:** `if` · `elif` · `else` · один управляемый запуск

## 00. От флага к действию

1. **Точка старта:** у нас есть очищенный текст, целое количество занятий и bool-флаги, которые пока только показывают результат проверки.
2. **Новый вопрос:** как использовать проверку, чтобы выбрать действие и не запускать расчёт для неподходящих данных?
3. **Результат:** мы выберем один путь для команды, сохраним прежний расчёт и проверим, что отказ и неизвестная команда не запускают его.

В предыдущем занятии проверка названия и количества давала отдельный ответ `True` или `False`. Этот ответ сам по себе не менял ход программы. Теперь поставим действия внутрь ветвей и проследим, какая часть файла выполняется при каждом входе.

Начнём с одного условия и его блока. Затем сравним остаточную ветку `else`, цепочку вариантов и независимые `if`. В конце перенесём выбор в прежний `main.py`. Следующее занятие добавит повторение для последовательности, поэтому здесь команда будет обработана только один раз.

## 01. if открывает блок действий

`if` можно прочитать как «если». После него стоит выражение с ответом `True` или `False`. Двоеточие завершает строку условия, а отступ показывает, какие действия зависят от ответа. Первая строка без такого отступа уже находится за пределами блока.

Представим вход с турникетом: условие проверяет, можно ли пройти, а строки с отступом находятся за условной чертой и выполняются только при ответе `True`. Строка без отступа остаётся на общем пути. Это сравнение помогает увидеть границу блока; в Python её задают отступы, а не настоящие стены.

Сначала Python вычисляет выражение после `if`. Полученное значение должно быть истинным или ложным. При `True` выполняются строки блока сверху вниз; при `False` блок пропускается. Затем программа продолжает работу со следующей строкой на прежнем уровне отступа.

```python
minutes = 45

if minutes >= 40:
    label = "достаточно времени"

print("Проверка завершена")
```

**Пошаговый разбор**

1. `minutes` получает целое значение 45. **Состояние:** `minutes = 45`.
2. Проверка `45 >= 40` даёт `True`. **Состояние:** условие = `True`.
3. Строка с отступом присваивает значение `label`. **Состояние:** `label = "достаточно времени"`.
4. Строка без отступа находится вне `if` и выполняется при любом результате проверки. **Вывод:** `Проверка завершена`.

**Проверим прогноз для ложного условия:**

```python
minutes = 30
if minutes >= 40:
    print("Достаточно")
print("Проверка завершена")
```

**Ответ:** выводится только `Проверка завершена`. Условие ложно, поэтому пропускается строка внутри `if`. Последняя строка находится вне блока.

### Разбор ошибки

```python
if minutes >= 40
    print("Достаточно")
```

**Вопрос:** какой знак нужен, чтобы начать блок после условия?

**Ответ:** двоеточие после условия.

```python
if minutes >= 40:
    print("Достаточно")
```

Двоеточие отделяет строку условия от следующего блока с отступом.

Ложное условие не останавливает весь файл и не заставляет Python повторять проверку. Оно пропускает только своё тело. Если тело выполнилось, управление тоже возвращается к следующей строке вне блока. Повторение появится только с циклом, поэтому здесь один вход приводит к одному проходу по файлу.

## 02. else обрабатывает другой ответ

`else` означает «иначе». Это блок для случая, когда связанное с ним условие `if` ложно. У `else` нет нового условия: Python не проверяет после него второе выражение.

Если `else` нет, ложный ответ просто пропускает тело `if`, а выполнение идёт дальше. Если `else` есть, его отступ и расположение связывают его с соответствующим `if`. После одной из ветвей строки за пределами конструкции всё равно выполняются обычным порядком.

```python
is_ready = False

if is_ready:
    message = "Можно начать"
else:
    message = "Пока рано"

print(message)
```

**Проверим прогноз:** при `is_ready = False` печатается `Пока рано`. Ложный ответ переводит выполнение в `else`, связанный с этим `if`.

**Подставим ветку, которая обработает ложный ответ:**

```python
if is_ready:
    message = "Можно начать"
___:
    message = "Пока рано"
```

Варианты: `else`, `elif`, `and`.

**Ответ:** `else`. Она относится к завершённой конструкции `if` на том же уровне отступа и принимает её ложный случай.

## 03. elif проверяет следующий вариант

`elif` добавляет условие в ту же цепочку. Python читает её сверху вниз и выбирает первую истинную ветку. Если совпадений нет и `else` отсутствует, ни один блок не выполнится.

Следующее условие проверяется только после ложного ответа на предыдущее. Как только получен первый `True`, остальные условия в этой цепочке уже не рассматриваются. Поэтому порядок важен для смысла выбора, а `else` можно читать как остаток, который не подошёл ни одному условию.

```python
if minutes >= 60:
    period = "час и больше"
elif minutes >= 30:
    period = "от половины часа"
else:
    period = "меньше половины часа"
```

1. При `minutes = 75` подходит `if minutes >= 60`, поэтому значение `period` будет `час и больше`.
2. При `minutes = 45` первая проверка ложна, а `elif minutes >= 30` истинна; `period` получит `от половины часа`.
3. При `minutes = 20` обе проверки ложны, поэтому `else` задаст `меньше половины часа`.

При `minutes = 45` первая проверка ложна, а вторая истинна. Значение получает только `period` из этой ветки. После первого совпадения Python не проверяет следующие ветки цепочки.

**Вопрос:** что будет, если заменить `else` на `elif minutes < 0` при `minutes = 20`?

**Ответ:** ни одна ветка не выполнится: первые две проверки ложны, а `minutes < 0` тоже ложно. Без `else` остаточный случай может остаться без действия.

## 04. Порядок важен при пересечении условий

Порядок нужен не потому, что Python всегда требует ставить строгую проверку первой. Он важен, когда условия пересекаются и широкая проверка забирает значения более узкой категории.

Например, условие `score >= 60` принимает и 60, и 95. Значит, оно перекрывает условие `score >= 90`. Если сначала поставить широкую границу, значение 95 остановится на ней. Если сначала нужна отдельная категория для высоких результатов, сначала проверим более узкую границу.

**Сначала широкая проверка:**

```python
score = 95
if score >= 60:
    grade = "достаточно"
elif score >= 90:
    grade = "высокий результат"
```

При `score = 95` срабатывает первая ветка. До второй проверки выполнение не дойдёт.

**Сначала узкая проверка:**

```python
score = 95
if score >= 90:
    grade = "высокий результат"
elif score >= 60:
    grade = "достаточно"
```

При `score = 95` сначала проверяется узкая категория. Для границ `60` и `90` полезно проследить значения `59, 60, 61, 89, 90, 91` и записать выбранную ветку. Сверим значение перед порогом, сам порог и ближайшее целое после него: знак `>=` включает саму границу. Если первая ветка включает все значения следующей, последующая ветка недостижима.

**Верно или неверно:** любую цепочку нужно начинать с самого строгого условия, даже если её условия не пересекаются.

**Ответ:** неверно. Строгий порядок нужен, когда условия пересекаются и широкая проверка перехватывает узкую категорию. Непересекающиеся условия можно располагать по смыслу задачи.

## 05. Независимые if и одна цепочка

Два отдельных `if` проверяют разные правила независимо. Оба блока могут выполниться. Связка `if/elif/else` выбирает не больше одной ветки. Для одной взаимоисключающей категории нужна цепочка, для двух независимых признаков нужны отдельные проверки.

Представим две отдельные галочки в анкете: каждая проверка может отметить свой признак, поэтому обе могут оказаться истинными. Цепочка похожа на вопрос с выбором одного ответа: после первого совпадения остальные варианты уже не выбираются. В Python это не ручной выбор человека: результат каждой проверки вычисляется из значений, а структура определяет, сколько блоков получат управление.

На схеме сравним два маршрута. В независимых проверках каждое условие решает судьбу своего действия; в цепочке следующий вопрос задаётся только после ответа «нет» на предыдущий.

На правой стороне первая истинная проверка завершает выбор. На левой каждое правило оценивается отдельно, поэтому оба действия могут выполниться. Стрелки показывают порядок управления, а не перемещение самих значений.

**Два независимых признака:**

```python
has_ticket = True
seat_is_free = True

if has_ticket:
    print("Билет есть")

if seat_is_free:
    print("Свободное место есть")
```

При двух значениях `True` выполнятся оба блока.

**Одна категория прогноза:**

```python
weather = "rain"
if weather == "rain":
    action = "взять зонт"
elif weather == "sun":
    action = "надеть кепку"
else:
    action = "выйти без зонта"
print(action)
```

По одному прогнозу выбирается один погодный сценарий.

**Разберём ошибку:**

```python
status = "new"
if status == "new":
    message = "Новая задача"
if status == "done":
    message = "Задача выполнена"
else:
    message = "Неизвестный статус"
```

Для `status = "new"` появится не то сообщение, потому что `else` относится только ко второму `if`.

```python
if status == "new":
    message = "Новая задача"
elif status == "done":
    message = "Задача выполнена"
else:
    message = "Неизвестный статус"
```

Для одного выбора статуса нужна общая цепочка.

Здесь две проверки командного ввода были бы независимыми: наличие названия само по себе не меняет знак количества. Но расчёт разрешён только при двух положительных ответах. В знакомом условии `and` соединяет эти bool: оно истинно, когда истинны оба. Поэтому полезно различать независимые факты и правило, которое требует их одновременного выполнения.

## 06. Переменная должна получить значение на выбранном пути

Присваивание внутри ветки происходит только тогда, когда эта ветка выполнена. Если ниже используется имя, которому значение могли не присвоить, на некоторых входах возникнет ошибка.

Можно представить записку, которую кладут в лоток только на одном маршруте. Если выполнение прошло в обход, записки нет. Так же и имя получает значение только на пройденной строке присваивания. Аналогия описывает факт присваивания, а не отдельные области видимости для веток.

```python
command = "exit"

if command == "calc":
    result = 90

print(result)
```

**Вопрос:** будет ли `result` иметь значение, если `command` равен `exit`?

**Ответ:** нет. Условие ложно, блок с присваиванием пропускается. До `print` имя `result` не создаётся, поэтому такой путь завершится ошибкой.

Отступ отделяет блок выполнения, но сам по себе не создаёт новую область видимости. Если присваивание произошло внутри `if`, имя доступно ниже в той же функции или файле. Ошибка появляется не из-за «закрытой» ветки, а потому что на выбранном пути строка присваивания вообще не выполнялась.

Перед использованием имени проверим все пути. Если на каждом пути нужно получить строку, присваивание должно происходить в каждой ветке. Не будем маскировать пропуск случайным значением по умолчанию.

**Два уровня проверок:**

```python
has_ticket = True
inside_schedule = False

if has_ticket:
    if inside_schedule:
        print("Проход открыт")
    else:
        print("Сейчас вход закрыт")
else:
    print("Билет не найден")
```

Вложенный блок нужен, когда второй вопрос имеет смысл только после положительного ответа на первый. Здесь сначала находим билет и только потом проверяем расписание. Отступ внутри первого блока показывает второй уровень; внешний `else` относится к проверке билета.

Сначала мы решаем, можно ли продолжить вообще, и только внутри разрешённого пути задаём следующий вопрос. Такой порядок не даёт использовать значение для расчёта до проверки. Если оба отказа ведут к одному сообщению, его можно поместить в подходящий остаточный путь; если причины должны различаться, каждой нужен свой блок. В этом упражнении разбираем только общий отказ и не добавляем новую обработку ошибок.

## 07. Порядок классификации задачи

Перед кодом зафиксируем договор классификатора. Для каждой пары признаков нужен ровно один результат. Сначала проверяется завершённость, затем порог приоритета, а последнее сообщение принимает остаточный случай.

Здесь используем учебные входы: `is_done` принимает `True` или `False`, а `priority` заранее дан целым числом от 1 до 5. Это ограничение важно для остаточной ветки: `else` означает низкий приоритет только потому, что значения вне диапазона исключены условием. Такая карточка объясняет порядок выбора и не добавляет модель задачи в наш проект.

1. **Выполнена:** `is_done` равен `True`. Этот признак важнее любого уровня приоритета.
2. **Срочно:** задача открыта, а `priority` не меньше 4.
3. **В работе:** задача открыта, `priority` не меньше 2, но меньше 4.
4. **Низкий приоритет:** задача открыта, а `priority` равен 1.

Для проверки возьмём открытые задачи с приоритетами `1, 2, 3, 4, 5`, а также выполненную задачу с приоритетом `5`. Так проверяются оба порога и случай, где признак завершённости должен победить высокий приоритет. Мы знаем ожидаемые сообщения, но код классификатора соберём в практике.

## 08. Один управляемый запуск в main.py

В проекте первым входом будет команда. Одна цепочка выберет расчёт, естественное завершение файла или сообщение о неизвестном варианте. Только ветка расчёта запросит значения для расчёта.

1. **`calc`:** внутри этой ветки остаётся знакомый расчёт StudyHub. Перед ним проверяются непустое очищенное название и неотрицательное целое количество.
2. **`exit`:** расчёт не запускается. После сообщения программа доходит до естественного конца файла.
3. **Другая команда:** показываем честное сообщение и завершаем запуск без запроса чисел и без расчёта.

Команду читаем один раз и нормализуем уже знакомыми `strip()` и `lower()`. Внутри расчётного пути используем существующие строки ввода и формулы, не создаём второй калькулятор. Получим bool для очищенного названия и неотрицательного количества, затем одним условием проверим оба результата до расчёта. Так решение остаётся в двух уровнях вложенности. Нечисловой текст для количества пока не обрабатываем: преобразование к `int` остаётся предпосылкой текущего сценария.

Это пока не командный цикл: после выбранной ветки файл естественно доходит до конца. При `calc` мы переносим прежние строки и формулу внутрь разрешённого пути, а не пишем второй калькулятор. При `exit` и неизвестной команде запросы числа не выполняются. Следующее занятие будет повторять уже выбранное действие для последовательности.

Команда стоит перед числовым вводом, потому что сначала мы выбираем сам сценарий. Так ветки `exit` и неизвестного значения заканчиваются раньше и не ждут данные, которые им не нужны. Внутри `calc` исходная формула остаётся прежней; мы меняем место её выполнения и проверяем, что отказ не доходит ни до формулы, ни до печати результата.

**Вопрос:** в какой ветке нужен запрос количества занятий?

**Ответ:** только внутри `calc`. Остальные пути заканчиваются без числового ввода.

Ключевые правила занятия:

- `if` запускает блок только при истинном условии.
- `elif` продолжает ту же цепочку, а `else` принимает остаток.
- Независимые проверки могут выполнить несколько блоков.
- Перед использованием переменной проверяем присваивание на каждом пути.
- Отступами ограничиваем вложенность двумя уровнями.

## 09. Что мы будем делать в практике

Сначала проследим отдельные ветки и отступы, затем исправим цепочку с неверным `else` и недостижимым условием. После этого проверим, что значение создаётся на любом нужном пути, и соберём классификацию четырёх сообщений.

1. Проследим истинный и ложный вход в `if` и увидим, почему общая строка выполняется вне тела.
2. Исправим цепочку: назначим ровно одно сообщение каждому статусу и откроем отдельную категорию для верхнего порога.
3. Проверим присваивания на каждом нужном пути и зададим результат для всех вариантов команды.
4. В `main.py` сохраним прежний расчёт в `calc`, а выход, неизвестную команду и отказ проверим без вывода результата.

Мы один раз получим команду, а затем поместим прежний расчёт внутрь разрешённого пути. Для расчёта сверим название и количество до вывода результата. Для двух занятий проверим знакомый итог прежней формулы: 90 минут, 1 час и 30 минут. При отказе, выходе и неизвестной команде числовые данные не запрашиваются.

**Проверяемый итог:** один выбранный сценарий, прежний расчёт только в разрешённой ветке и объяснимый отказ при недопустимых данных. В следующем занятии цикл `for` повторит уже понятное действие для элементов последовательности.
