# Сравнения и логические правила

Научимся получать проверяемые ответы о данных и соединять их в одно понятное правило.

**Темы:** `bool` · сравнения и границы · `and` · `or` · `not` · короткое вычисление

## 00. От подготовленных данных к проверке

1. **Точка старта.** Мы умеем получать и очищать текст, хранить значения и выводить результат.
2. **Новый вопрос.** Как проверить значение и объединить несколько ответов до выбора действия?
3. **Результат.** Мы получим `bool`, проверим границы и объясним каждую часть диагностического правила.

После занятия о строках у нас есть очищенный текст и числа, с которыми можно работать. Но сам вывод значения ещё не отвечает, подходит ли оно правилу. Сначала вычислим ответ «да» или «нет»; выбор действия появится в следующем занятии.

Например, у числа можно проверить границу, у команды сравнить написание с ожидаемым, а несколько проверок объединить. В конце мы сможем показать диагностические флаги в прежнем `main.py`. Флаги сообщат о данных, но пока ничего не остановят и не изменят.

## 01. Ответ bool

Тип `bool` хранит один из двух ответов: `True` означает «да», `False` означает «нет». Такой ответ получается из вопроса и пригодится, когда мы проверяем наличие, состояние или возможность.

- `is_` задаёт вопрос о состоянии: `is_done = False`.
- `has_` задаёт вопрос о наличии: `has_access = True`.
- `can_` задаёт вопрос о возможности: `can_start = True`.

Имя помогает прочитать назначение значения, но само по себе не меняет его тип. Настоящие `True` и `False` пишутся без кавычек. В кавычках находится текст, даже если внутри написано слово `False`.

Булево значение хранит ответ, а не правило, по которому мы его получили. Например, `chairs_left = 2`, затем `has_seats = chairs_left > 0`: переменная `has_seats` получает `True`. Если позже в `chairs_left` сохранить ноль, уже полученный ответ сам не пересчитается. Мы вычислим его заново, когда снова выполним сравнение.

## 02. Сравнение задаёт вопрос

Оператор сравнения сопоставляет два значения и возвращает `True` или `False`. Он не исправляет и не преобразует сравниваемые данные.

- `==` спрашивает, равны ли значения.
- `!=` спрашивает, различаются ли значения.
- `<` проверяет, меньше ли первое значение второго.
- `<=` проверяет, не больше ли первое значение второго.
- `>` проверяет, больше ли первое значение второго.
- `>=` проверяет, не меньше ли первое значение второго.

Оператор `=` присваивает значение, а `==` сравнивает.

### Числовой текст не становится числом сам

```python
print(4 == 4)
print(4 == "4")
```

В первом сравнении обе стороны числа, поэтому ответ `True`. Во втором слева число, справа строка, и Python не превращает строку в число автоматически. Равенство здесь даёт `False`; для упорядочивания числа и строки Python сообщит об ошибке сравнения. Если число хранится текстом, преобразование нужно выполнить отдельно знакомым способом до сравнения.

При сравнении `4 < "4"` вместо bool возникает `TypeError`, ошибка из-за неподходящих типов: Python не знает, как упорядочить число и текст. Если смысл именно числовой, текст нужно отдельно преобразовать до сравнения.

Перед сравнением полезно спросить, какие значения и типы стоят по обе стороны. Внешне похожие значения не обязаны иметь одинаковый смысл: число 4 и текст «4» остаются разными данными, пока мы явно не преобразуем текст.

### Найдём причину ошибки

```python
command = " calc "
print(command == "calc")
```

**Вопрос:** почему проверка не находит команду?

- A. Оператор `==` удаляет только крайние пробелы
- B. Строки сравниваются с учётом пробелов; подготовка не выполнена
- C. Строки нельзя сравнивать

**Ответ:** B. Сравнение видит исходные пробелы. Сначала сохраним результат `strip()`, затем сравним очищенный текст.

```python
command = " calc ".strip()
print(command == "calc")  # True
```

У строк также учитывается регистр: `"Calc" == "calc"` даёт `False`. Если договор требует одинаковый регистр, нормализуем текст до сравнения, например уже знакомым методом `lower()`.

## 03. Граница и включённый диапазон

Сравним вопрос «больше четырёх?» с вопросом «не меньше четырёх?». Разница заметна ровно на границе: знак `>` исключает 4, а `>=` включает.

Представим линейку с отметкой 4: значение соответствует точке на ней, а порог обозначает черта. Выражение `priority > 4` спрашивает, правее ли точка; `priority >= 4` включает и саму черту. Аналогия помогает увидеть границу, но Python не передвигает и не округляет значение: он только вычисляет ответ для выбранного знака.

```python
priority = 4
print(priority > 4)
print(priority >= 4)
print(3 >= 4)
print(5 >= 4)
```

**Результат**

```text
False
True
False
True
```

Сначала подставим значение `priority` в каждый вопрос. В результате получаем `False`, `True`, `False`, `True`.

В диапазоне нужно проверить две границы: значение не должно быть ниже минимума и выше максимума. Пока сравним каждую границу отдельно; способ соединить ответы разберём после знакомства с логическими операторами.

**Как записать правило «не меньше четырёх», чтобы значение 4 подошло?**

```python
priority > 4
```

Этот вариант исключает граничное значение.

```python
priority >= 4
```

Этот вариант включает 4. Для порога возьмём значение ниже границы, саму границу и значение выше неё. Допустимый диапазон потребует проверить обе границы.

Порог и диапазон описывают разные договоры. Значение 6 проходит проверку `priority >= 4`, но выходит за диапазон от 1 до 5. Поэтому сначала решим, спрашиваем ли мы о минимуме или о допустимости внутри двух границ; одна проверка не заменяет другую.

## 04. Соединяем ответы через and, or и not

Одного сравнения иногда недостаточно. `and` требует, чтобы обе части были истинны; `or` требует хотя бы одну; `not` меняет один логический ответ на противоположный.

Представим список допуска с двумя независимыми пунктами, например билетом и подтверждением. `and` похоже на правило «нужны отметки в обеих строках», тогда как `or` означает «достаточно одной»; `not` меняет уже полученный ответ на противоположный. В этой аналогии пункты списка соответствуют отдельным `bool`, а правило объединения соответствует логическому выражению. Код только вычисляет ответ и сам не открывает реальную дверь.

- `and` даёт истинный ответ, когда обе части истинны.
- `or` даёт истинный ответ, когда истинна хотя бы одна часть.
- `not` даёт противоположный ответ для исходного bool.

Вернёмся к диапазону от 1 до 5. Сначала получим ответы о каждой границе, затем соединим их через `and`:

```python
priority = 4
above_minimum = priority >= 1
below_maximum = priority <= 5
within_range = above_minimum and below_maximum
print(above_minimum, below_maximum, within_range)
```

**Результат:** `True True True`. Число 4 удовлетворяет обеим границам. Для тех же двух проверок Python позволяет записать сравнения короче: `1 <= priority <= 5`. Эта запись проверяет оба соседних сравнения и даёт тот же bool, что и соединение через `and`.

Например, правило «нужны пароль и код» использует `and`. Для правила «подойдёт почта или телефон» нужен `or`. Вопрос «запись ещё не завершена?» можно выразить через `not is_done`.

Сверим все сочетания двух готовых bool. Таблица показывает, когда составной ответ истинен.

- Если `A = False` и `B = False`, то `A and B` равно `False`, а `A or B` тоже равно `False`.
- Если `A = False` и `B = True`, то `A and B` равно `False`, а `A or B` равно `True`.
- Если `A = True` и `B = False`, то `A and B` равно `False`, а `A or B` равно `True`.
- Если `A = True` и `B = True`, то оба выражения, `A and B` и `A or B`, равны `True`.

Перед записью составного правила назовём каждый вопрос отдельно. Например, «есть ли пропуск?» и «есть ли подтверждение?» дадут два промежуточных bool. Затем `and` соединит их. Так легче увидеть, какая часть привела к итоговому ответу.

Для более длинного правила будем добавлять по одной проверке. Сначала посмотрим на ответы двух частей, затем присоединим следующую и снова проверим каждую часть отдельно. Так можно объяснить не только итог, но и конкретную причину, по которой правило дало `False`.

**Верно или неверно:** `a and b` истинно, если истинны обе части.

**Ответ:** верно. Для `and` одного `True` недостаточно.

## 05. Скобки и порядок вычисления

Если в выражении встречаются несколько логических операторов, Python вычисляет их в заданном порядке: сначала `not`, затем `and`, потом `or`. Скобки явно показывают, какие части мы хотим объединить.

```python
has_ticket = True
has_invitation = False
checked = False
allowed = has_ticket or has_invitation and checked
```

Без скобок сначала вычисляется `has_invitation and checked`: `False and False` даёт `False`. Затем `True or False` даёт `True`. Если сначала сгруппировать билет или приглашение, получим `True and False`, то есть `False`.

Если правило должно означать «есть билет или приглашение, и дополнительно пройдена проверка», поставим скобки вокруг выбора билета или приглашения:

```python
(has_ticket or has_invitation) and checked
```

В практике мы будем разбирать промежуточные ответы, а не полагаться на интуицию по длинной строке.

## 06. Короткое вычисление и значения-операнды

У `and` и `or` есть короткое вычисление. В `and` ложной левой части достаточно для всего результата, поэтому правая часть не нужна. В `or` истинной левой части уже достаточно.

```python
denominator = 0
can_divide = denominator != 0 and 12 / denominator > 2
print(can_divide)
```

**Результат:** `False`.

Сначала выражение `denominator != 0` даёт `False`. Python не вычисляет деление справа от `and`, поэтому ошибки деления на ноль нет. Этот приём помогает проверять безопасное условие до операции, которая возможна не для каждого входа.

В общем случае `and` и `or` могут вернуть один из операндов, а не новый `bool`.

```python
print(0 and "готово")
print("" or "нет названия")
```

**Результат**

```text
0
нет названия
```

Первая левая часть ложна, поэтому `and` возвращает её. Вторая левая часть пуста, поэтому `or` возвращает правый операнд.

Левая часть вычисляется первой. Поэтому проверку, которая защищает правую операцию, ставим слева от `and`. Если левая часть уже даёт `False`, Python остановится на этом ответе; если для `or` слева уже есть истина, правая часть тоже не нужна. `not` устроен иначе: он возвращает противоположный булев ответ.

### Строка "False" остаётся истинной строкой

```python
label = "False"
print(not label)
```

Результат равен `False`: строка непустая и считается истинной, независимо от текста внутри. Простые значения `0` и пустая строка дают ложную оценку, ненулевое число и непустая строка дают истинную. Вызов `bool(value)` явно получает такую оценку. Строка `"False"` не становится булевым `False`.

## 07. Проверки в прежнем проекте

Теперь применим уже знакомые ввод и очистку, не переписывая расчёт StudyHub. После `strip()` можно получить `bool` для непустого названия. Для целого количества занятий можно отдельно сравнить значение с нулём.

1. **Название.** Проверяем, осталось ли что-то после очистки краёв. Сам текст и его регистр сохраняются.
2. **Количество.** Сравниваем целое число с нулём и получаем отдельный флаг.
3. **Диагностика.** Выводим оба ответа рядом с прежним результатом. Флаги ничего не запрещают и не исправляют.

Ввод количества на этом шаге предполагается корректным целым числом, как в предыдущих занятиях. Если вместо него набран произвольный текст, преобразование может завершиться ошибкой. Обработка такой ошибки и выбор другого действия будут изучаться отдельно.

Представим показание прибора рядом с расчётом: оно сообщает, что мы заметили, но не меняет работу механизма. Так же и диагностический `bool` ничего не запрещает. Чтобы по результату проверки пропустить или запустить часть кода, нам понадобится условная конструкция следующего занятия.

Отдельно разберём правило срочности карточки. У него три входа: приоритет от 1 до 5, булев признак выполнения и учебное число дней до срока. Высокий приоритет начинается с 4, незавершённость означает `is_done` равно `False`, а остаток времени положителен, когда `days_left` больше 0. Поле `days_left` задаётся только для этого примера и не добавляется в модель Planner. Для ответа «срочно» должны одновременно подойти все три проверки. Мы используем число дней только для разбора логики, а не как настоящий срок карточки.

**Вспомним:** что пока делает диагностический `bool` в `main.py`?

Он показывает результат проверки. Сам по себе он не останавливает расчёт и не выбирает ветку исполнения.

## 08. Проверим себя

### Вопрос 1

Если `raw_title = "   "`, чему равно `bool(raw_title.strip())`?

- A. `True`, потому что исходная строка непустая
- B. `False`, потому что после `strip()` строка пустая
- C. Ошибка преобразования

**Ответ:** B. Сначала `strip()` создаёт пустую строку, затем `bool()` получает её ложную оценку.

### Вопрос 2

При `lesson_count = 0` чему равно `lesson_count >= 0`?

- A. `False`, потому что занятий нет
- B. `True`, потому что ноль не меньше нуля
- C. Ошибка сравнения

**Ответ:** B. Ноль входит в диапазон неотрицательных целых чисел.

### Вопрос 3

Чему равно `is_urgent`, если `priority = 4`, `is_done = False` и `days_left = 1`?

- A. `True`, все три части правила истинны
- B. `False`, потому что `priority` должно быть больше 4
- C. `False`, потому что `days_left` должно быть равно 0

**Ответ:** A. Граница `priority >= 4` включена, запись не завершена, а до срока остаётся положительное число дней.

### Вопрос 4

Чему равно `is_urgent`, если `priority = 5`, `is_done = True` и `days_left = 1`?

- A. `True`, потому что приоритет высокий
- B. `False`, потому что правило требует незавершённую запись
- C. Ошибка, потому что `is_done` не число

**Ответ:** B. Для срочности должны одновременно подойти все проверки. При `is_done = True` часть `not is_done` ложна.

### Главное после занятия

- `bool` хранит `True` или `False`.
- Сравнение создаёт ответ и не очищает, не преобразует значения.
- `and` требует обе части, `or` допускает одну, `not` меняет bool.
- Границу и составное правило проверяем на отдельных значениях.
- Короткое вычисление может пропустить правую часть.

## 09. Что мы будем делать в практике

Сначала исследуем ответы на границах, сравнение подготовленного текста и составное логическое правило. Затем продолжим существующий проект.

1. **Исследуем границы и сравнения.** Спрогнозируем результаты для строгой и включённой границ, диапазона и подготовленных строк, затем сверим ответы Python.
2. **Соберём правило срочности.** Соединим две проверки, добавим третью и выведем промежуточные bool, чтобы увидеть причину каждого ответа.
3. **Продолжим `main.py`.** Добавим два диагностических bool рядом с прежним расчётом; они не будут выбирать действие или останавливать программу.

Для каждой работы сначала объясним ожидаемые ответы, затем сверим вывод и найдём причину расхождения. В проекте сохраним прежний расчёт и проверим название и количество занятий на обычном и граничном значениях.
