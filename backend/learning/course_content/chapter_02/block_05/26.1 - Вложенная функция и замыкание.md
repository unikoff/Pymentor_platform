# 26.1. Вложенная функция и замыкание

## 00. Вступление

В предыдущем занятии мы передавали готовые функции как значения: таблица команд хранит обработчики, а `run` вызывает выбранный обработчик после выбора команды. Теперь разберём более тонкий вариант: можно ли вернуть функцию, которая позже использует настройку, заданную раньше?

1. **Точка старта:** мы умеем определять функции, передавать параметры, возвращать значения и сохранять функцию для вызова позже.
2. **Новый вопрос:** как вернуть функцию, которая после завершения внешнего вызова всё ещё обращается к его настройке?
3. **Результат:** мы разберём вложенное определение и замыкание, а затем сравним два callback с разными настройками.

Для примеров возьмём форматирование коротких сообщений. Префикс зададим один раз при настройке, а текст сообщения будем передавать при каждом вызове. Этот путь подготавливает нас к следующему занятию, где внешняя функция настроит диагностическую обёртку. Сам Planner сейчас менять не требуется.

## 01. Внешняя функция создаёт внутреннюю

Функцию можно определить внутри другой функции. Внешняя функция задаёт контекст или настройку, а вложенная описывает действие, которому эта настройка понадобится позднее. Вложенное определение не запускает тело внутренней функции: оно создаёт функцию, доступную в оставшейся части внешнего вызова.

```python
def make_labeler(prefix):
    def label(message):
        return f"{prefix}: {message}"

    return label
```

Когда мы вызываем `make_labeler("Заметка")`, Python связывает значение `"Заметка"` с локальным именем `prefix`, доходит до `def label` и создаёт внутреннюю функцию. Тело `label` пока не выполняется: в нём ещё нет сообщения, которое нужно оформить. Параметр `message` относится к будущему вызову `label`, а `prefix` пришёл из вызова `make_labeler`.

Имя `label` объявлено внутри `make_labeler`, а не на уровне всего файла. Снаружи мы получим его, только если вернём функцию или передадим её кому-то ещё. Поэтому вложенное определение само по себе не добавляет новый обработчик в таблицу команд и не меняет интерфейс Planner. Мы используем его там, где полезно собрать действие с настройкой для отдельного будущего вызова.

Здесь полезна аналогия с небольшой мастерской печатей. Сначала мы выбираем текст на штампе, а затем получаем штамп, которым можно помечать разные карточки. Внешний вызов похож на настройку штампа, возвращённая функция служит готовым инструментом, а `message` играет роль очередной карточки. Но программа не создаёт физический предмет: аналогия лишь помогает разделить настройку и последующее действие.

## 02. Возвращаем функцию, а не её результат

У имени функции и у вызова функции разная роль. Имя `label` обозначает саму функцию. Запись `label("Готово")` запускает её тело и даёт результат в виде строки. Скобки после имени важны: они означают вызов.

```python
make_labeler("Заметка")  # результат: функция label
make_labeler("Заметка")("Проверить тему")  # результат: строка
```

В первой строке фабрика вернула действие, которое можно сохранить и вызвать позже. Во второй строке мы сразу вызываем возвращённую функцию с текстом. Фабрикой здесь называют функцию, которая создаёт и возвращает другое значение, например настроенную функцию. Это описательное название, а не отдельный синтаксис Python.

Сравним `return label` и `return label("Готово")`. В первом случае наружу выходит функция. Во втором Python немедленно вызывает `label`, получает строку и возвращает строку. Если затем написать `saved("Ещё сообщение")`, но в `saved` лежит строка, возникнет ошибка: строку нельзя вызвать как функцию. Частая причина такой ошибки: добавить скобки там, где мы хотели сохранить действие.

Перед тем как двигаться дальше, проследим этот простой пример.

```python
def make_greeting(prefix):
    def greet(name):
        return f"{prefix}, {name}!"
    return greet

morning = make_greeting("Доброе утро")
print(morning("Анна"))
```

После первой строки вызова `make_greeting` переменная `morning` содержит функцию `greet`, а не готовое приветствие. При `morning("Анна")` внутреннее тело получает новое значение `name`, формирует строку и возвращает её. Настройка и сообщение приходят в разные моменты.

Не перепутаем и `return` с печатью. `return` отдаёт значение вызывающему коду, который может сохранить его в переменную. `print` только показывает представление значения на экране; сам по себе он не передаёт вызывающему коду возвращённую функцию. Если фабрика напечатает внутреннюю функцию, но не вернёт её, присваивание результата вызова фабрики получит `None`. Тогда поздний вызов тоже не сработает, хотя имя вложенной функции было определено правильно.

## 03. Замыкание сохраняет доступ к внешнему имени

Внутренняя функция может использовать имя из внешней функции даже после того, как внешний вызов завершился. Для такого случая мы используем термин **замыкание**: внутренняя функция вместе с доступом к нужным именам окружающей области. Функция не обязана копировать все внешние переменные и объекты. Она сохраняет возможность разрешить имена, которые использует.

Вернёмся к `make_greeting`. Имя `prefix` не объявлено внутри `greet`, но Python находит его во внешней области того вызова `make_greeting`, который создал эту функцию. Позже `morning("Анна")` передаёт новое имя, а `greet` соединяет его с доступным `prefix`. Внешняя функция уже закончила работу, однако связанная с ней настройка остаётся доступной внутренней функции.

Можно представить это как карточку заказа в мастерской: на карточке указана выбранная настройка, а позже по ней выполняют работу для нового входного текста. Соответствие такое: карточка помогает вспомнить настройку, а вызов возвращённой функции приносит новые данные. Граница аналогии: в Python нет бумажной карточки, и замыкание не обязано сохранять копию каждого объекта из внешнего кода.

Это отличается от глобальной переменной. Внешнее имя здесь относится к конкретному вызову фабрики, который создал функцию. Мы не записываем префикс в общий модульный список настроек и не заставляем все функции читать одно глобальное состояние.

Чтобы проследить поиск, начнём с имени `name`: оно является параметром `greet` и получает аргумент текущего вызова. Имя `prefix` среди параметров и локальных присваиваний `greet` не задано, поэтому для него используется доступная внешняя привязка. Если бы имя не было доступно ни в функции, ни в её окружающей области, программа сообщила бы об неопределённом имени. В нашем примере нужная связь появляется потому, что мы создаём и возвращаем функцию из того вызова, где параметр настройки уже получил значение.

Проследим всю последовательность: внешний вызов получает `prefix`, создаёт `greet`, возвращает функцию и завершается. Позже отдельный вызов передаёт `name`; только тогда тело `greet` формирует строку. Мы не удерживаем внешний вызов открытым и не запускаем его заново. Доступ к нужной внешней привязке остаётся у возвращённой функции, чтобы она могла выполнить свою работу.

## 04. Вызовы фабрики создают отдельные настройки

Каждый вызов `make_labeler` создаёт собственный контекст для своей настройки. Поэтому две возвращённые функции могут выполнять одинаковый алгоритм, но использовать разные префиксы.

```python
def make_labeler(prefix):
    def label(message):
        return f"{prefix}: {message}"
    return label

notice = make_labeler("Важно")
question = make_labeler("Вопрос")

print(notice("Сохранить файл"))
print(question("Где лежит файл?"))
print(notice("Закрыть редактор"))
```

Вызов `make_labeler("Важно")` создаёт одну настроенную функцию, а вызов `make_labeler("Вопрос")` создаёт другую. Внутри первой доступно имя `prefix` со значением первой настройки, во второй со значением второй. Когда мы чередуем вызовы, каждая функция использует свою настройку. Новое сообщение каждый раз приходит через `message`; оно не заменяет префикс.

Это похоже на два одинаковых рецепта, каждый из которых заранее настроен на свою порцию соли. Мы можем готовить по ним в любом порядке, и один рецепт не перепишет настройку другого. Аналогия помогает представить независимые вызовы внешней функции; она не означает, что Python сохраняет копию исходного кода или создаёт отдельный процесс.

Полезно различить два имени настройки от двух алгоритмов. В обеих внутренних функциях выполняется одна и та же строка форматирования. Меняется не тело, а доступная ему привязка `prefix`, полученная при разных вызовах фабрики. Если бы мы просто меняли один общий внешний параметр перед каждым сообщением, результат зависел бы от такого общего изменения. Здесь же каждая функция связана со своей настройкой, поэтому порядок вызовов не смешивает префиксы.

Разделим назначение двух параметров. `prefix` служит настройкой, которая задаётся при создании callback; `message` приносит новые данные при каждом его вызове. Поэтому один настроенный callback можно использовать для многих сообщений. Это не кэш готового результата: строка формируется заново, когда получатель вызывает функцию с очередным текстом.

## 05. Замыкание не означает копирование общего списка

Сохранённый доступ к имени не равен глубокой копии всего объекта. Это особенно важно для списка: разные функции могут обращаться к одному изменяемому списку, если при создании им передали один и тот же объект.

```python
def make_reader(items):
    def read():
        return items
    return read

shared = []
first_reader = make_reader(shared)
second_reader = make_reader(shared)
shared.append("глава 5")

print(first_reader())
print(second_reader())
```

Оба вызова `make_reader` создали разные внутренние функции и разные внешние области вызова. Но параметр `items` в обоих случаях получил ссылку на один объект `shared`. Метод `append` изменил этот объект на месте, поэтому оба callback увидят добавленную строку. Здесь нет противоречия: отдельные окружения не отменяют явное совместное использование переданного списка.

Эта граница похожа на две закладки, ведущие к одной общей записной книжке. Закладки отдельные, но запись в книжку видна с обеих. Соответствие: функции имеют отдельные окружения, а `items` указывает на переданный список. Ограничение: закладки лишь образ ссылок; точные правила задаёт работа имён и объектов Python. Как и в знакомом нам примере с поверхностной копией, новый контейнер верхнего уровня не обещает независимых вложенных объектов.

Если каждой фабрике передать отдельный список, получатели увидят разные контейнеры верхнего уровня. Если сначала сделать только поверхностные копии списка с вложенными словарями, сами словари могут остаться общими. Значит, вопрос не в том, «разные ли замыкания», а в том, «на какие объекты ссылаются доступные им имена». Такой разбор помогает не приписывать замыканию копирование, которого в коде не было.

Замыкание не создаёт автоматическую копию списка, словаря или вложенных значений. Если независимость нужна, её нужно отдельно спроектировать и явно создать копию подходящего уровня. В этом занятии мы лишь определяем, какие имена ведут к какому объекту; глубокое копирование и проектирование хранилища здесь не добавляем.

## 06. Callback и замыкание отвечают на разные вопросы

Слово **callback** описывает роль функции: одна часть программы передала её другой части, чтобы та вызвала функцию в подходящий момент. Слово **замыкание** описывает свойство функции: она использует имя из внешней области, сохранившейся для позднего вызова. Поэтому функция может быть и callback, и замыканием одновременно, но callback не обязательно является замыканием.

В нашем примере `notice` можно передать коду, который форматирует сообщения по запросу. Она будет callback, потому что получатель вызовет её позже. Она также замыкание, потому что использует настроенный `prefix`. Обычная функция `print` тоже может быть переданной функцией, однако сам факт передачи не говорит, что она захватила настройку из другой функции.

В следующем занятии этот механизм подготовит диагностическую обёртку: внешняя функция получит исходную операцию и настройки, а возвращённая внутренняя функция вызовется позже. Пока мы не переходим к передаче произвольных аргументов, `nonlocal`, декораторам или перехвату ошибок. Сначала важно уверенно различать создание функции, её возврат и поздний вызов.

## 07. Что мы будем делать в практике

Практика этого занятия исследовательская и проходит в интерпретаторе. Мы используем небольшую фабрику форматирующих функций, чтобы увидеть, как настройка и сообщение попадают в разные вызовы.

1. **Создадим функцию с вложенным определением:** увидим, что внешняя настройка задаётся до будущего вызова внутренней функции.
2. **Вернём внутреннюю функцию:** получим callback, который можно вызвать отдельно, и отличим его от уже вычисленной строки.
3. **Настроим два callback:** вызовем их по очереди и объясним, почему каждый использует свой префикс.
4. **Проследим общий список:** увидим, что две отдельные внутренние функции могут обращаться к одному переданному изменяемому объекту.

В результате мы сможем объяснить порядок настройки и вызова без изменения алгоритмов Planner. Главная граница проверки: увидеть и назвать, какое имя пришло из внешней настройки, какие данные поступили при позднем вызове и осталась ли функция или общий объект общими.
