# Где редактировать практику

Для содержания и качества заданий используй [CONTENT_AUTHORING.md](../../../docs/CONTENT_AUTHORING.md). Здесь только расположение файлов и подключение.

## Структура всех курсов

Все девять курсов перенесены в отдельные Python-пакеты. Обзор и занятия каждого блока находятся вместе с файлами практики. Отдельной папки `practice` нет.

```text
planner_api/
├── __init__.py              # публичные каталоги и ID курса
├── track.json               # русское название и прежний ID загрузчика
├── block_00/
│   ├── __init__.py
│   ├── План обучения.md
│   ├── Теория месяца.md
│   └── manual.py            # OVERVIEW_PRACTICE: имена обзорных Markdown
└── block_09/                # остальные блоки устроены так же
    ├── 45 - ...md           # теория занятия
    ├── ...                  # остальные Markdown блока
    ├── __init__.py          # экспорт и проверка диапазона
    ├── manual.py            # MANUAL_PRACTICE: номер занятия → упражнения
    └── code_tasks.py        # CODE_TASKS: номер занятия → задачи редактора
```

| Блок | Номера занятий |
| --- | --- |

| 12 | 63–68 |

1. Найди номер занятия в имени Markdown.
2. Открой нужный блок. Проектную или устную работу пиши в `manual.py`; изолированную Python-задачу с автопроверкой в `code_tasks.py`.
3. Добавь или замени запись в исходном словаре: `MANUAL_PRACTICE[45]` или `CODE_TASKS[46]`. Значение всегда список. Не дублируй ключи и не создавай второе присваивание в конце файла.
4. Новое задание внутри диапазона подключается автоматически через существующие `__init__.py`. Не добавляй импорт во frontend, регистрацию в getter или путь в `SELF_CHECK_LESSONS`.
5. Для обзора используй `OVERVIEW_PRACTICE["План обучения.md"]` и другие уже существующие имена файлов.
6. При необходимости бери конструкторы из `learning.practice_helpers`. Блок не импортирует старые модули, соседний блок или `content.py`.

Прямой импорт для проверки:

```python
from learning.course_content.chapter_03 import MANUAL_PRACTICE, CODE_TASKS
from learning.course_content.chapter_03.block_09 import MANUAL_PRACTICE as block_09_manual
```

Старые `learning.rich_practice.get_manual_practice` и `learning.rich_code_tasks.get_code_tasks` работают как прежде и перенаправляют все курсы в новые каталоги. Сами карточки в этих двух файлах больше не редактируются.

## Теория и пути

Markdown и практика каждого курса распределены по `block_00` и его учебным блокам. `track.json`, `__init__.py` курса и служебный `README.md` находятся в корне пакета.

Названия папок используют `chapter_{номер}`, без пробелов и дефисов. Пакеты подключаются обычными импортами. Русские названия курса и блоков остаются в track.json и интерфейсе. `track.json.id` сохраняет прежний ID курса; не меняй его при редактировании содержания.

`source_file` содержит новый физический путь. Загрузчик восстанавливает прежний путь урока и сохраняет ID, прогресс и task ID. Реестры в `frontend/src/lessons/*/index.ts` преобразуют старые ключи компонентов в новые пути. Не переименовывай Markdown и не перемещай его при обычном редактировании текста.

## Какие форматы поддерживает платформа

Есть два интерфейса практики:

- Ручная работа: упражнения с вложенными `tasks`, понятным условием, подсказкой, полным ответом и критерием готовности. Формат смотри в методичке; новые задания не пиши через старое внешнее поле `steps`.
- Редактор: `mode="solve"` для функции с `return` или `mode="script"` для программы с выводом. Нужны условие, вход, стартовый код, скрытые тесты и внутренний `reference_code`.

Редактор не запускает FastAPI, БД или многофайловый проект. Такие работы оформляются ручной практикой. Если у занятия есть редакторные задачи, загрузчик скрывает ручные карточки: не добавляй маленький кодовый опыт так, чтобы исчезла основная проектная работа.

Существующий разбор `starter`/`tests` из Markdown и `SELF_CHECK_LESSONS` сохранён для совместимости. В перенесённом курсе это не альтернативное место для новых копий заданий. Полный ответ ручной практики открывается по запросу; скрытые тесты и эталон редактора в публичную выдачу не попадают.

## Идентификаторы и границы блоков

Папки курсов и блоков используют Python-имена: строчные латинские буквы, цифры и `_`, без пробелов и дефисов. Русские названия курса и блока остаются в метаданных и интерфейсе. `track.json.id` и `TRACK_ALIASES` сохраняют прежние публичные идентификаторы, даже когда они отличаются от имени пакета.

Новый курс или блок требует отдельного подключения: имя пакета, стабильный ID курса, диапазон, явные импорты, подпись блока в загрузчике и ключи frontend-реестра. Добавление занятия или карточки в уже подключённый блок этого не требует.

## Проверка после изменения

Из корня проекта:

```powershell
$env:PYTHONPATH = (Resolve-Path .\backend).Path
.\.venv\Scripts\python.exe -m unittest discover -s backend/tests -p test_practice_catalog_migration.py -v
```

Для редактора проверь эталон и ошибочный код через `learning.code_runner.run_python_task`. Тесты должны проверять только требования условия.

Перезапусти backend, если он не перезагружается автоматически: каталоги собираются при импорте. Проверь точное имя Markdown через прежний getter и выдачу `/learning/lessons` под допустимым тестовым доступом. Без Pro код и ручные карточки закрытых занятий пусты; это ожидаемая блокировка, а не пропавшая практика. Не меняй подписку ради проверки.

В интерфейсе проверь `practice.py`, открытие подсказки и ответа, работу редактора. Для изменения TSX или реестра также нужна проверка типов и сборка frontend. Если браузерный просмотр недоступен, прямо обозначь его как непроверенный.
