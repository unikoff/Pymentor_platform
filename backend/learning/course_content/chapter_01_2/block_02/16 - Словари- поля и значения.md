## 00. Вступление

У списка есть позиции, у tuple — фиксированный порядок, у set — уникальный состав. Для записи с несколькими именованными полями нужно находить значение по смысловой метке, а не запоминать его позицию. Перед новым механизмом коротко восстановить только те свойства прежних коллекций, которые потребуются в примерах.

1. **Точка старта:** ожидаемая по паспорту опора — знакомые list/tuple/set, чтение простых данных, принадлежность и присваивание; фактическую готовность подтвердит короткое восстановление перед новой темой.
2. **Новый вопрос:** как обратиться к одному полю записи по его имени и выбрать безопасный способ чтения, если поле может отсутствовать?
3. **Результат:** ученик создаёт и меняет словарь одной записи, выбирает чтение по договору поля и получает из словаря ключи, значения и пары.

Каждый следующий шаг отвечает на часть вопроса: сначала даёт модель ключа и значения, затем чтение и изменение поля, после — договор обязательного или необязательного поля, операции изменения и представления. Восстановление A — проверка входной опоры, а не повторное прохождение прежнего блока.

## 01. Именованное поле: ключ и значение

- Что и зачем объяснить: словарь хранит соответствия ключей и значений. Для записи материала строки-ключи обозначают поля, а значения содержат данные этих полей. Показать словарный литерал и роль фигурных скобок, двоеточия и запятых после восстановления нужной пунктуации.
- Механизм и порядок: начать с одной короткой записи; сопоставить каждую метку со своим значением. Объяснить уникальность ключа: повтор ключа в словарном литерале оставляет последнее значение; последующее присваивание тому же ключу также заменяет его, а не создаёт второе одноимённое поле. Сравнить смысл имени поля со знакомой числовой позицией в list. Сразу после примера ученик предсказывает, какое из двух значений останется у повторённого ключа.
- Пример и типичная путаница: использовать нейтральную запись учебного материала, не Task. Не читать ключ как индекс списка; не считать повтор ключа способом хранить несколько одноимённых значений.
- Опора для повторного обращения: при чтении записи найди точное имя ключа, затем связанное с ним значение; если значение заменилось, проверь, не использован ли тот же ключ повторно.
- Переход к следующему шагу: когда пара ключ–значение ясна, прочитать поле по имени и посмотреть, что происходит при записи нового значения.

## 02. Чтение и изменение по ключу

- Что и зачем объяснить: квадратные скобки с ключом читают связанное значение; присваивание через тот же ключ меняет существующее поле, а через новый ключ добавляет поле. Принадлежность в словаре проверяет ключи. Длина словаря — количество пар, а не позиция или максимальный номер ключа.
- Механизм и порядок: проследить чтение одного существующего поля, затем замену его значения и добавление другого поля. Сверить состояние словаря до и после каждой строки; отдельно проверить принадлежность имени поля. Короткое применение: ученик предсказывает значение title после замены и объясняет, почему добавление другого ключа не меняет остальные пары.
- Пример и типичная путаница: одинаковая числовая запись в list означала бы позицию, а в dict ключом является значение, переданное в скобках. Проверка принадлежности спрашивает о ключе, не о том, встречается ли такое значение среди полей. Присваивание по ключу меняет сам словарь и не создаёт независимую копию.
- Опора для повторного обращения: для получения конкретного существующего поля используй его ключ; чтобы проверить наличие, проверяй ключ; после присваивания сравни пары, а не ищи числовую позицию.
- Переход к следующему шагу: прямое чтение подходит, когда ключ обязателен. Для поля, которое может отсутствовать, сначала нужно понять его договор.

## 03. Обязательное и необязательное чтение

- Что и зачем объяснить: квадратные скобки выражают требование, что ключ существует; отсутствующий ключ приводит к KeyError. Вызов get с default возвращает значение по ключу, если ключ присутствует, и только при отсутствии ключа возвращает default. Без переданного default отсутствующий ключ даёт None.
- Механизм и порядок: сравнить запись с обязательным полем и запись с необязательным полем. Показать состояния «ключ отсутствует», «ключ есть со значением None», «ключ есть со значением False» и «ключ есть со значением 0». Проверка in различает отсутствие от сохранённого None. Показать, что get с default возвращает сохранённые None, False и 0 как есть; запасное значение используется только для отсутствующего ключа. После объяснения ученик выбирает [] или get для двух подготовленных состояний — отсутствующего subtitle и subtitle со значением None — и объясняет результат.
- Пример и типичная путаница: get не должен маскировать отсутствующее обязательное поле или опечатку в ключе. Для обязательного поля его отсутствие — ошибка данных, которую нужно заметить, а не молча заменить запасным значением. KeyError объяснить по месту возникновения без try/except.
- Опора для повторного обращения: сначала определи, обязателен ли ключ. Для обязательного используй квадратные скобки; для необязательного — get с осмысленным default. Если нужно отличить отсутствие ключа от сохранённого None, проверь наличие через in.
- Переход к следующему шагу: после выбора способа чтения рассмотреть контролируемое обновление нескольких полей и удаление поля с учётом результата операции.

## 04. Обновление и удаление полей

- Что и зачем объяснить: update записывает несколько пар в словарь и заменяет значения совпавших ключей; операция меняет исходный словарь и не возвращает новый словарь. pop удаляет поле и возвращает прежнее значение; при необходимости для отсутствующего ключа задаётся default. del удаляет поле по ключу и не передаёт удалённое значение.
- Механизм и порядок: объяснить точку вызова и скобки методов, затем начать с обновления известной записи и сравнить изменённые и сохранённые поля. Проследить удаление присутствующего необязательного поля через pop и удаление известного поля через del. Обозначить, что pop без default и del по отсутствующему ключу тоже приводят к KeyError. Короткое применение: после каждого действия ученик предсказывает итоговые пары и то, вернёт ли операция удалённое значение.
- Пример и типичная путаница: не присваивать результат update обратно имени словаря; не путать возвращаемое значение pop с эффектом изменения исходника; не ожидать возвращаемого значения от del. Не использовать запасной default для сокрытия отсутствующего обязательного поля.
- Опора для повторного обращения: для массовой записи нескольких известных пар — update; когда нужно получить удалённое значение — pop; когда нужно только убрать известное поле — del. После действия проверь и итоговые пары, и возвращаемое значение, если оно предусмотрено.
- Переход к следующему шагу: словарь можно просматривать не только по одному имени поля; сначала научиться получать его ключи, значения и пары.

## 05. Ключи, значения, пары и копия словаря

- Что и зачем объяснить: способы keys, values и items позволяют получить названия полей, их значения или связанные пары. Каждый элемент items — знакомая tuple-пара ключ–значение; получить и прочитать эти данные можно без for. Метод copy создаёт отдельный внешний словарь. Порядок отображения ключей не даёт им числовой позиции.
- Механизм и порядок: объяснить знакомую форму вызова метода через точку и скобки; получить ключи, значения и пары в записи с простыми полями. Затем сделать копию внешнего словаря, заменить в копии конкретное поле title и сравнить соответствующее поле оригинала и копии. Короткое применение: ученик выбирает, какое из представлений нужно для заданного вопроса, и предсказывает, какое значение title останется в исходнике после изменения копии.
- Пример и типичная путаница: items возвращает связанные пары ключ–значение, а не список записей для Planner. Копия отделяет внешний словарь, но не предназначена для разбора вложенных изменяемых значений: это тема следующего урока. Не обращаться к ключу по «номеру вставки».
- Опора для повторного обращения: выбери keys для названий полей, values для набора значений, items для пар; copy используй, когда нужно отдельно изменить верхний словарь. Для обязательного результата достаточно правильно получить эти данные и объяснить копию.
- Дополнительное исследование после основной практики: подробно рассмотреть, что представление keys, values или items связано с исходным словарём и может отражать последующие изменения. Сравнить его со списком, полученным через list(...), который сохраняет отдельный снимок. Это исследование не входит в критерий B и не требуется для перехода к списку вложенных записей.
- Переход к следующему шагу: применить обычное чтение полей, получение представлений и копию к одной нейтральной записи; динамическое поведение видов не является условием перехода.

## 06. Что мы будем делать в практике

**Формат и исходная опора:** короткие scripts на платформе с видимыми или описанными исходными значениями; начинаем с проверки нужных свойств знакомых коллекций, затем работаем с одной нейтральной записью материала. Общий результат — создать и изменить словарь, осмысленно прочитать обязательные и необязательные поля и объяснить полученные представления.

1. **Создать и изменить запись материала:** на подготовленной записи с ключами code, title и minutes ученик читает title и заменяет его заданной строкой; добавляет отсутствующий ключ format с указанным значением; через update меняет minutes на указанное целое и добавляет ключ level с указанным значением. Опора — блоки 01–02 и 04 после подготовки литерала и скобок. Проверяемый результат после каждого шага: title получает заданную строку; format добавлен без изменения code и minutes; update заменяет minutes и добавляет level, сохраняя остальные поля. Свободный выбор другого поля можно оставить коротким исследованием после проверки.
2. **Проверить обязательное и необязательное чтение, затем удаление:** начать с нейтральной записи материала, где title задан, subtitle отсутствует, duration равен 0, а available равен False. Квадратные скобки для title возвращают заданную строку; get для отсутствующего subtitle возвращает указанный default. После добавления subtitle со значением None тот же get возвращает None; duration и available сохраняют 0 и False. Затем pop для имеющегося subtitle возвращает None и убирает ключ, pop для отсутствующего format с default возвращает default, а del удаляет имеющийся available. Опора — блоки 02–04; до каждой операции ученик объясняет её договор. Отсутствующий обязательный title проверяется в отдельном script и даёт KeyError. Проверяемый результат: наличие ключа различено с его значением, 0/False/None не подменены default, а итоговые пары и возвращаемые значения совпадают с указанными переходами.
3. **Получить ключи, значения и пары; проверить копию:** на новой нейтральной записи ученик получает keys, values и items и читает пару title со значением; затем копирует словарь и меняет title только в копии. Опора — обязательная часть блока 05; выбор свободного поля остаётся исследованием, а в проверочной части поле title задано. Проверяемый результат: полученные данные соответствуют исходному словарю, title копии изменён, title оригинала сохранён. Дополнительно после основной проверки можно исследовать изменение представления после добавления заранее названного ключа и сравнить его со списком, созданным через list(...); этот результат не влияет на B и переход к уроку 17.

Действия идут от конкретного изменения заданных полей к выбору контракта чтения, затем к получению представлений и копированию. Для каждого основного результата известны начальные данные и ожидаемое состояние. Свободный выбор поля и исследование динамического представления выполняются только после однозначно проверяемой части. В совокупности изменения title/minutes, сохранение code, договоры get/[] и независимость копии подтверждают B; детальное поведение views не является условием завершения или перехода. Проектных возможностей для повторной проверки нет, проект не меняется.
