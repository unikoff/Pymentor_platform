## 00. Из клиента теперь виден сервер

В прошлой работе мы отправляли HTTP-запросы через Postman на готовый Echo-сервис и сохранили collection с environment в `studyhub-api/postman`. Мы видели обе стороны сообщения, но сам сервер не создавали. Теперь продолжим тот же проект: оставим клиентские файлы на месте и добавим маленькую серверную границу для StudyHub. Python-приложение получит адрес, дождётся запроса и вернёт ответ.

У этой работы три участника. FastAPI описывает приложение и его маршрут, то есть операцию по определённому адресу. Uvicorn запускает приложение как локальный HTTP-сервер. Браузер, Swagger UI или Postman отправляет запрос и показывает ответ. Эти роли похожи на меню, кухню и посетителя кафе: меню описывает, что можно заказать, кухня выполняет работу, а посетитель приносит заказ и получает результат. Техническое название связи FastAPI и Uvicorn, ASGI, разберём ниже.

В результате в подготовленной папке `studyhub-api` появится один endpoint `GET /health`, а экспорты Postman останутся в `postman/`. Сохранённые пути `/get` и `/post` относятся к Echo, поэтому в этой работе мы не направляем старые запросы на локальный сервер. Endpoint не будет работать с задачами, пользователями или базой. Его задача скромнее: подтвердить, что сервер стартовал и приложение отвечает. Мы также откроем автоматическую документацию и научимся понимать типичные ошибки запуска.

После этой главы вы сможете объяснить, почему одного файла с функцией недостаточно для HTTP-сервера, что означает команда запуска и чем отличаются «сервер не запущен», «путь не зарегистрирован» и «endpoint ответил успешно».

## 01. Что уже есть и чего не хватает

HTTP-клиент умеет сформировать запрос. В запросе есть method, URL и, если нужно, дополнительные данные. Но адрес сам по себе не создаёт программу, которая его обработает. По адресу должен ждать запущенный процесс, принимающий сетевые сообщения.

До запуска сервера файл Python просто лежит на диске. Интерпретатор не держит порт открытым только потому, что в проекте написан декоратор. Когда запускается сервер, операционная система связывает процесс с сетевым адресом и портом. Клиент может обратиться к этому адресу, пока процесс работает.

Для локального эксперимента адрес обычно выглядит так:

```text
http://127.0.0.1:8000/health
```

Разберём адрес по частям:

| Часть URL | Значение | Роль |
| --- | --- | --- |
| Схема | `http` | Протокол, по которому клиент отправляет запрос. Двоеточие и `//` отделяют схему от адреса сервера. |
| Host | `127.0.0.1` | IPv4-адрес loopback: в этой локальной настройке запрос направляется на ту же машину. |
| Port | `8000` | Порт, на котором Uvicorn принимает соединения. Если host и port не указаны в команде Uvicorn, это его значения по умолчанию. |
| Path | `/health` | Путь ресурса. FastAPI должен зарегистрировать подходящий маршрут для этого path и HTTP-метода. |

> **Части адреса.** `Host` означает адрес компьютера-сервера. `127.0.0.1` это специальный адрес, который возвращает запрос на ваш компьютер; его также называют `loopback`. `Port` означает номер сетевого входа программы. `Path` означает путь к конкретной операции внутри приложения. Эти части помогают отличить ошибку подключения от ошибки маршрута.

Порт можно представить как номер окна выдачи: компьютер один, но разные программы могут слушать разные порты. Это порт сервера, а не отдельный «порт процесса»: процесс Uvicorn занимает его, пока сервер работает.

Локальный адрес удобен для разработки. Он не означает, что приложение уже доступно ученику или пользователю в интернете. Сейчас мы проверяем код на своей машине, а публикация и настройки рабочего сервера останутся за границами этой работы.

## 02. FastAPI и объект приложения

FastAPI это Python-фреймворк для описания HTTP API. Фреймворк предоставляет готовые правила и инструменты, а разработчик задаёт конкретное поведение приложения: какие запросы принимать и какие ответы возвращать.

> **Новые слова.** `Фреймворк` это готовая основа программы: она берёт на себя общие задачи, а мы добавляем правила своего API. `Экземпляр` это конкретный объект, созданный по классу; в этом проекте им станет `app`.

Начинаем с класса `FastAPI` и создаём его экземпляр:

```python
from fastapi import FastAPI

app = FastAPI(title="StudyHub Planner API")
```

Класс можно сравнить с формой для изготовления предмета. Вызов `FastAPI(...)` создаёт конкретный объект приложения. Переменная `app` становится точкой, где мы будем регистрировать endpoint и настраивать API. Само создание `app` ещё не запускает сервер, не открывает порт и не посылает запросы.

Параметр `title` задаёт понятное название API. FastAPI использует эти сведения о приложении, когда строит документацию. Название не влияет на URL и не определяет правила обработки запросов.

### Что напечатает этот код?

```python
from fastapi import FastAPI

first = FastAPI()
second = FastAPI()

print(first is second)
```

Здесь создаются два отдельных экземпляра. Предположите, будет ли напечатано `True` или `False`, прежде чем открыть ответ в карточке.

## 03. Endpoint связывает HTTP с функцией Python

Endpoint, или маршрут, задаёт соответствие между HTTP-операцией и Python-функцией. Это сочетание метода и пути: `GET /health` и `POST /health` являются разными операциями, даже если путь совпадает.

Декоратор FastAPI регистрирует такую связь. Декоратор в Python получает функцию и добавляет к ней сведения о маршруте. В этом случае `@app.get("/health")` сообщает приложению: «Для входящего GET-запроса по пути /health используй следующую функцию».

Посмотрим на независимый пример с состоянием сервиса уведомлений:

```python
from fastapi import FastAPI

app = FastAPI()

@app.get("/status")
def read_status():
    return {"service": "notifications", "active": True}
```

Функция расположена сразу после декоратора. Она не выполняется при чтении файла сверху вниз как обычный вызов. FastAPI сохраняет информацию о маршруте, а затем вызывает функцию, когда получает подходящий запрос.

Вызов должен совпасть по двум признакам:

- method запроса равен GET;
- path запроса равен `/status`.

Если хотя бы одно условие не совпало, эта функция не становится обработчиком запроса. Например, GET на `/unknown` не найдёт этот маршрут. А POST на `/status` не совпадёт с зарегистрированным GET.

Это разные ошибки маршрутизации: если path вообще не зарегистрирован, обычно приходит `404 Not Found`; если path существует, но для него не разрешён отправленный method, приходит `405 Method Not Allowed`. Ни один из этих ответов сам по себе не означает, что Uvicorn не смог запуститься.

### Соедините части маршрута

Сопоставьте каждую часть с её ролью:

- `@app.get("/status")` сообщает HTTP-метод и path;
- `def read_status():` задаёт функцию-обработчик;
- `return {...}` описывает данные ответа.

Подумайте, какую часть пришлось бы изменить, чтобы адрес стал `/health`.

## 04. Возврат из функции превращается в HTTP-ответ

Функция endpoint возвращает значение Python. Например, словарь может описывать объект, который клиенту удобно получить в JSON. FastAPI преобразует поддерживаемые Python-значения в содержимое HTTP-ответа. Для обычного успешного ответа используется status `200 OK`.

Это не означает, что словарь сам отправил сетевые байты. Он является результатом работы функции. FastAPI формирует HTTP-ответ, а Uvicorn передаёт его обратно через соединение клиенту.

Рассмотрим независимый пример. Функция сообщает состояние службы уведомлений:

```python
def read_status():
    return {"service": "notifications", "active": True}
```

Клиент увидит JSON:

```json
{"service": "notifications", "active": true}
```

Здесь есть два разных представления одних данных. В Python коде это словарь с ключами и значениями. В HTTP-ответе это JSON body. FastAPI берёт на себя преобразование. Если бы функция вернула другой поддерживаемый тип, форма ответа была бы другой.

Название `health` означает проверку доступности. Такой endpoint часто используют разработчики и инфраструктурные системы, чтобы понять, отвечает ли приложение на простой запрос. В нашей практике маршрут вернёт короткий статус `ok`. Это докажет только, что конкретный endpoint обработал запрос. Проверка не скажет, исправны ли база данных, очередь, почта или другие внешние системы. Таких компонентов в текущем приложении ещё нет.

Поэтому не будем выдавать простую проверку процесса за полную диагностику продукта. В более сложных системах отдельно решают, какие части программы должна проверять операция доступности.

### Верно или неверно?

«Если FastAPI-функция вернула словарь, то она самостоятельно открыла порт и отправила клиенту HTTP-пакет». Объясните, где здесь смешаны разные роли.

## 05. Uvicorn принимает HTTP и вызывает приложение

Uvicorn это сервер для Python-приложений, работающих через ASGI. Он запускает процесс, принимает HTTP-соединения и передаёт запросы приложению. Когда FastAPI сформировал ответ, Uvicorn отправляет его клиенту.

ASGI задаёт общий интерфейс между Python web-приложением и сервером. Это как стандартный разъём: приложению не обязательно знать внутреннее устройство каждой сетевой программы, а серверу не нужно понимать бизнес-логику StudyHub. На этом этапе достаточно помнить направление:

> **Что означает ASGI.** Полное название: *Asynchronous Server Gateway Interface*, «асинхронный интерфейс связи сервера и приложения». Сейчас важна не внутренняя механика, а роль общего разъёма между Uvicorn и FastAPI. Асинхронное выполнение мы будем изучать позже; в этом уроке функция маршрута может быть обычной `def`.

Когда приходит запрос, сервер передаёт приложению сведения о соединении и сообщении. Приложение формирует ответ через тот же интерфейс. Не нужно сейчас запоминать внутренние функции ASGI. Важно, что FastAPI и Uvicorn могут взаимодействовать через общий контракт, а не через детали реализации друг друга.

```text
браузер или Postman
  → HTTP request
Uvicorn
  → вызов ASGI-приложения
FastAPI endpoint
  → результат функции
Uvicorn
  → HTTP response
браузер или Postman
```

FastAPI и Uvicorn не конкурируют за одну и ту же обязанность. Если FastAPI описывает правило «GET /health возвращает статус», это ещё не означает, что порт уже слушается. Если Uvicorn слушает порт, это не означает, что в приложении зарегистрированы все нужные маршруты.

Мы запускаем сервер из командной строки:

```powershell
python -m uvicorn app.main:app --reload
```

`python -m uvicorn` просит выбранный интерпретатор Python запустить установленный модуль Uvicorn. Так проще не перепутать Python и Uvicorn из разных окружений.

Аргумент `app.main:app` делится двоеточием:

- слева `app.main` это путь к Python-модулю `app/main.py`;
- справа `app` это имя объекта FastAPI внутри этого модуля.

Последний аргумент `--reload` включает перезапуск после изменения файла. Это удобно во время разработки. Для рабочего сервера, которым пользуются другие люди, режим автоматической перезагрузки не заменяет полноценную настройку запуска.

## 06. Почему важна текущая директория

Python ищет файлы с кодом по путям поиска. Когда мы запускаем Uvicorn с записью `app.main:app`, сервер должен найти пакет `app`, внутри него модуль `main.py`, а затем переменную `app`.

> **Слова Python.** `Модуль` это файл с кодом Python, например `main.py`. `Пакет` это папка, из которой можно импортировать модули; здесь это `app/`. `Импортировать` означает найти и загрузить код по имени. Запись `app.main:app` в команде запуска указывает, какой модуль загрузить и какой объект взять из него.

Для нашего проекта структура будет такой:

```text
studyhub-api/
  README.md
  requirements.txt
  postman/
    http-lab.collection.json
    echo.environment.json
  app/
    __init__.py
    main.py
```

Команду запуска нужно выполнять из папки `studyhub-api`. Тогда `app.main` читается как «найди пакет app в текущем проекте, затем модуль main». Файл `__init__.py` явно обозначает папку как Python-пакет и помогает новичку видеть структуру импорта без неявных правил.

Если запустить ту же команду из родительской папки или из `app`, Python будет искать модули относительно другого места. В результате сервер может не найти `app.main`. Это не HTTP-ошибка и не ошибка самой функции endpoint. Запрос ещё не дошёл до приложения: сервер не смог импортировать его объект.

В нашей команде есть `--reload`. Если импорт не удался, дочерний серверный процесс завершится, но процесс-наблюдатель может оставить терминал занятым. После чтения ошибки нажмите `Ctrl+C`, дождитесь возврата приглашения командной строки и только затем меняйте папку и запускайте сервер снова.

В записи импорта две части, разделённые двоеточием:

```text
модуль: app.main  -> файл app/main.py
объект: app       -> переменная приложения внутри модуля
```

Три частые ситуации не нужно смешивать:

| Наблюдение | Что это обычно означает |
| --- | --- |
| Uvicorn не стартовал и сообщает об ошибке импорта | неверная папка запуска, имя модуля или переменная приложения |
| Браузер сообщает, что соединение отклонено | по адресу и порту никто не слушает, либо сервер уже остановлен |
| Сервер вернул HTTP 404 | соединение состоялось, но такой path не зарегистрирован |
| Сервер вернул HTTP 405 | path существует, но отправленный method для него не разрешён |
| Сервер вернул 200 и JSON | запрос совпал с маршрутом, функция завершилась успешно |

Например, если у нас есть только `GET /health`, запрос к `GET /` получит 404. Это ожидаемо. Мы не объявляли маршрут для корня. Если же отправить `POST /health`, path существует, но для него объявлен только GET, поэтому FastAPI вернёт 405. Оба ответа полезны для диагностики: клиент связался с сервером, но запрос не соответствует объявленному маршруту.

## 07. Swagger UI и OpenAPI появляются из описания API

Когда приложение зарегистрировало маршрут, FastAPI может подготовить описание его HTTP-контракта. Это описание следует стандарту OpenAPI. В нём перечисляются доступные пути, методы, параметры и формы данных, которые известны приложению.

Swagger UI это веб-интерфейс, который показывает такое описание и позволяет вручную отправить запрос. В стандартной настройке FastAPI он доступен по адресу `/docs`. Для нашего локального сервера это `http://127.0.0.1:8000/docs`. Отдельный JSON-документ OpenAPI обычно доступен по `/openapi.json`.

> **Кнопки документации.** `Try it out` означает «подготовить пробный запрос»: после нажатия можно задать данные. `Execute` означает «отправить запрос». Оба действия относятся к интерфейсу Swagger UI, а не к коду маршрута.

Это не ещё один сервер и не вручную написанная страница. FastAPI использует зарегистрированные маршруты и известные сведения о приложении, чтобы сформировать описание API. Swagger UI читает его и показывает операции человеку.

Для текущей работы мы используем `/docs` как удобный клиент:

1. открываем маршрут `GET /health`;
2. нажимаем `Try it out`;
3. запускаем запрос;
4. сравниваем status и JSON response с ожиданием.

Swagger полезен, чтобы исследовать API и увидеть, что сервер сейчас считает своим контрактом. Он не гарантирует, что правила приложения правильные, и не заменяет автоматические тесты. На рабочем сервере доступность интерактивной документации настраивают осознанно: публичная документация раскрывает устройство API, поэтому её включение зависит от продукта и политики безопасности.

Пока у нас один маршрут без входных данных. Поэтому документация будет короткой. Когда позже появятся параметры, схемы и request body, FastAPI сможет показать их в описании. Сейчас не нужно заранее изучать эти темы, чтобы проверить `GET /health`.

## 08. Что мы будем делать в практике

В начале практики собственного сервера ещё нет, но папка проекта уже подготовлена. В прошлой работе в `studyhub-api/postman` появились экспорты collection и environment. Сохраним их и продолжим проект: создадим виртуальное окружение `.venv`, а приложение поместим в пакет `app`. Окружение отделит библиотеки этого проекта от пакетов других Python-программ. Команда `python -m pip` установит FastAPI и Uvicorn в активное окружение.

> **Файлы и команда.** `.venv` это папка отдельного окружения Python для этого проекта. `pip` это инструмент установки пакетов; запись `python -m pip` запускает его через выбранный Python. `README.md` это инструкция для человека. `requirements.txt` это список пакетов для повторной установки. Эти файлы выполняют разные роли.

Внутри приложения появится объект `app` и один маршрут `GET /health`. Этот маршрут вернёт словарь со статусом `ok`. Uvicorn запустит приложение из корня проекта. Это разделение позволит отдельно увидеть код маршрута и процесс, который принимает HTTP.

Затем мы проверим результат снаружи приложения. Сначала откроем `/health` и сверим status и JSON. После этого вызовем тот же маршрут через `/docs`. Наконец, безопасно запустим команду из неправильной папки, увидим ошибку импорта, остановим процесс-наблюдатель и восстановим правильный запуск. Сбой нужен не ради поломки проекта, а чтобы научиться отличать ошибку старта от HTTP-ответа.

В конце сохраним команду запуска в `README.md` и создадим `requirements.txt`. Это список библиотек, который помогает установить зависимости проекта заново на другой машине. Сам каталог `.venv` обычно не сохраняют в Git, системе хранения изменений проекта: он содержит установленные файлы, зависящие от компьютера и ОС. Если проект находится в Git, для `.venv` обычно добавляют правило в `.gitignore`. Этот файл перечисляет пути, которые Git должен пропускать. Настройка Git в эту практику не входит.

Команда `python -m pip freeze` показывает установленные пакеты и их версии. Знак `>` в командной строке сохраняет этот список в файл. Такой список помогает повторить установку, но не заменяет понятную инструкцию: другой человек должен ещё знать, из какой папки выполнять команды.

Готовый артефакт будет небольшим, но воспроизводимым:

- каталог `studyhub-api` с сохранёнными Postman-экспортами в `postman/`;
- модуль приложения `app/main.py`;
- один проверяемый endpoint `GET /health`;
- команда запуска и указание правильного каталога в `README.md`;
- `requirements.txt`, чтобы установить зависимости в новом окружении.

Мы намеренно не добавляем список задач, создание данных, проверку структуры данных, базу, авторизацию или публикацию рабочего сервера. Следующая работа расширит уже запущенное приложение маршрутами только для чтения. Для этого важно сначала надёжно научиться запускать сервер и проверять ответ, не смешивая запуск сервера с обработкой данных.

### Карта ролей

- FastAPI описывает объект приложения и маршрут.
- Функция endpoint формирует данные результата.
- Uvicorn принимает HTTP и передаёт запрос приложению.
- Браузер или Swagger UI действует как клиент.
- Файл зависимостей помогает восстановить окружение проекта.

## 09. Самопроверка перед переходом к коду

Закройте теорию и попробуйте ответить без подсказки:

1. Почему строка `app = FastAPI()` сама по себе не запускает сервер?
2. Что означает левая часть и правая часть записи `app.main:app`?
3. Чем отличается ошибка импорта при старте от HTTP 404?
4. Почему GET к `/` может вернуть 404, хотя GET к `/health` работает?
5. Что именно доказывает ответ `{"status": "ok"}` и чего он не доказывает?
6. Какую роль выполняет `/docs` и откуда FastAPI получает сведения для этой страницы?
7. Почему `--reload` полезен в разработке, но не подходит как план запуска рабочего сервера для пользователей?
8. Чем отличаются 404 для незарегистрированного path и 405 для неподдерживаемого method у существующего path?

Если ответы смешивают FastAPI и Uvicorn, вернитесь к цепочке request-response. Если вы понимаете роли, можно переходить к практике и собрать первый локальный сервер самостоятельно.
