## Границы и передача дальше

Обязательны нейтральные состояния суммы и счётчика, условный счёт, одновременное накопление нескольких итогов, сравнение кандидата максимума после первого числа, пустой/отрицательный/неупорядоченный наборы, исправление сброса прежнего результата. `max()` можно **упомянуть после** освоения собственного алгоритма только для сравнения; он не заменяет обязательный проход. Не требовать `break`, `continue`, `while`, вложенные циклы или новые библиотеки. В занятие 10 передаётся способность проследить состояние после шага и итог после завершения `for`.

## 00. Вступление: раньше видели элементы, теперь нужен ответ

Запланировать первую связанную группу для MAIN (`LinkedNotes variant="connected"`):

1. **Точка старта:** прежний `for` показывает каждый элемент списка и заканчивается после последнего; у пустого списка проходов нет.
2. **Новый вопрос:** как после этого ответить «сколько всего минут?», «сколько маршрутов завершено?» и «какая длительность самая большая?», если переменная цикла содержит только текущее значение?
3. **Результат:** создаём хранимое состояние, меняем его в нужные моменты и объясняем результат даже при пустых данных.

После группы объяснить связь: цикл обеспечивает последовательный доступ, переменная результата сохраняет историю уже просмотренных элементов. На визуале «до прохода → текущий элемент → обновление состояния → после цикла» показать направление данных; ученик предсказывает, какая величина переживёт переход к следующему элементу. Не демонстрировать решение будущей финальной задачи.

## 01. Сумма: значение до, обновление внутри, итог после

**Что и зачем.** `total` означает сумму **уже обработанных** чисел. `total = 0` нужно написать один раз **до** `for`. Внутри `total = total + minutes` читает прежний итог справа и сохраняет новый слева; `total += minutes` — сокращённая запись того же сложения. `print(total)` после цикла печатает **один итог**, а внутри цикла показал бы промежуточные итоги. На пустом списке обновлений нет, `total` остаётся `0`.

**Независимый пример и первая попытка.** В MAIN использовать `steps = [4, 0, 3]`, не тренировочные `route_minutes`. Пошаговая таблица «текущее / было / стало»: после 4 — 4, после 0 — 4, после 3 — 7. Скрыть последнюю строку на момент прогноза; затем ученик самостоятельно предсказывает итог для `[2, 5]` и `[]`, объясняет ноль. **Различающий случай:** ошибочное `total = 0` внутри `for` уничтожает предыдущее накопление, даже если два первых шага выглядели правдоподобно.

**Опора на возврат:** «общая величина → 0 до цикла → предыдущее + текущее в теле → один вывод после». Следующая ступень меняет вопрос: сколько элементов, независимо от их величины?

## 02. Счётчик: за элемент прибавляем единицу

**Механизм.** `count = 0` до цикла, `count += 1` на **каждом** проходе. Счётчик отражает число встреченных элементов, поэтому не складывает строки и не прибавляет числовое значение элемента. У трёх элементов сумма может быть 12, но количество всё равно 3. `len` для целого списка возможен, однако проход нужен для следующего условного счётчика.

**Независимый пример:** `stops = ["Север", "Юг", "Центр"]` — счётчик `0 → 1 → 2 → 3`; сопоставить с суммой чисел `[5, 5, 2]`, равной `12`. Ученик самостоятельно предсказывает счёт для `["А", "А"]`, `["А"]`, `[]` и проверяет, что смена текста не меняет количество. **Типичная ошибка:** `count = 1` до обхода даёт лишний элемент, особенно заметный на пустоте. **Опора:** «число элементов → старт 0 → +1 за элемент». Переход: иногда считаем только элементы, подходящие условию.

## 03. Условный счётчик: проверка в каждом проходе

**Механизм.** `if record["completed"]:` проверяет заранее известное булево поле текущего словаря (его чтение не меняет запись). `completed_count += 1` с дополнительным отступом выполняется **только при `True`**. При `False` цикл всё равно идёт к следующей записи. Общий счётчик и условный отвечают на разные вопросы.

**Другой набор:** `visits = [{"completed": False}, {"completed": True}, {"completed": False}]`. Трасса «поле / условие / счётчик после»: `False/нет/0`, `True/да/1`, `False/нет/1`. Ученик прогнозирует два завершённых из `[True, True, False]` и ноль из `[False, False]`, затем объясняет, почему второй результат не означает пустой список. **Различающий ошибочный случай:** перенести увеличение за пределы `if` — получится количество всех записей. **Опора:** «0 до цикла → `if` в теле → +1 только в ветке». Переход: можем обновлять сразу несколько независимых ответов.

## 04. Сумма и два счётчика за один проход

**Сначала три отдельных вопроса:** сколько минут у **всех** маршрутов, сколько маршрутов всего, сколько завершено? До `for` создать три нулевых состояния. В теле на каждой записи добавить минуты и увеличить общее количество, под `if completed` увеличить только количество завершённых. `print` для каждого итога — после цикла, в согласованном порядке. Маршрут с нулём минут учитывается как одна запись.

**Независимая трасса для MAIN:** `records = [{"minutes": 3, "completed": True}, {"minutes": 0, "completed": False}, {"minutes": 5, "completed": False}]`; после каждой записи значения (сумма, всего, завершено): `(3,1,1) → (3,2,1) → (8,3,1)`. Предложить прогноз середины до открытия таблицы, затем ученик сам прослеживает один незавершённый маршрут на 4 минуты и пустой список. **Ошибка:** если все три обновления положить под `if`, потеряются минуты и общее число незавершённых. **Опора:** «каждому вопросу — своё состояние и правило обновления». Переход: с максимумом отличается начальное состояние.

## 05. Максимум: нет кандидата, первый кандидат, сравнение

**Ключевой механизм до работы ученика.** `best` — наибольшее из **уже просмотренных** чисел. Перед просмотром ни одного кандидата нет: `best = None`. В теле `if best is None:` принимает первое число **без сравнения с `None`**. Только отдельная ветка `elif value > best:` сравнивает числа и заменяет кандидата на большее. Иначе сохраняем старого. `elif` обеспечивает, что числовое сравнение не происходит в первом проходе; не вводить ещё непояснённое комбинированное `or`.

**Независимая трасса:** `heights = [-7, -2, -5]`, состояния `None → -7 → -2 → -2`. Содержательный визуал «кандидата нет → первый → новый больший → прежний остаётся»; спросить, почему это `-2`, а не `0` или последнее `-5`. Далее позитивный набор `[3, 9, 4]`: максимум в середине. Ученик самостоятельно прогнозирует `best` после каждого элемента для `[-4]`, `[6,2,6]`, `[]` и объясняет, что `print(best)` печатает `None` на пустом списке.

**Различающий ошибочный случай:** `best = 0` неверен для всех отрицательных чисел, а `best = value` на каждом проходе оставляет последнее число. **Опора:** «`None` означает отсутствие кандидата; первый элемент становится им; заменить только при `>`». Переход: проверить механические ошибки накопления на новых наборах.

## 06. Пустота, сброс и неверный отступ

**Развести результаты:** на `[]` сумма и обычный/условный счётчик равны **числу** `0`, максимум равен **отсутствию кандидата** `None`. На одном отрицательном элементе сумма и максимум равны ему, счёт зависит от условия. На отрицательном наборе `best = 0` запрещён, поскольку ноль мог вообще не встречаться. Если значение не превосходит кандидата, кандидат не меняется; это сохраняет максимум в середине списка.

**Диагностика до исправления:** в неверном цикле `total = value` для `[3, 8, 2]` состояния становятся `3 → 8 → 2`: прежняя сумма стирается, итог `2` вместо `13`. Ученик указывает строку и заменяет присваивание **обновлением с прежним итогом**; затем самостоятельно проверяет `[5, 2] → 7` и `[] → 0`. Ещё два мини-прогноза с разным назначением: что будет, если старт суммы внутри `for`, и сколько строк появится, если `print` внутри `for`. В MAIN использовать последовательность «прогноз → объяснение трассы → исправление → новый ввод», а не серию одинаковых True/False.

**Опора для возврата:** короткая таблица «остался последний → заменяли вместо прибавления; появились лишние строки → вывод в теле; отрицательный максимум стал 0 → неверный первый кандидат». Готовый `max` упомянуть только факультативно после ручной проверки, без требования в заданиях.

## 07. Перенос: условие «не ниже порога» и независимые ответы

**Подготовка к финалу, без решения финала.** `threshold` — переданное платформой число, `value >= threshold` означает «значение равно порогу **или** больше». Это уже известное сравнение в условном счётчике из 03; сумма **всех** чисел и максимум **всех** чисел не фильтруются порогом. На `values = [-3, 0, 4]` и `threshold = 0` подходят `0` и `4`, счёт `2`; общая сумма равна `1`, максимум `4`.

**Самостоятельная маленькая подготовка:** ученик для `[2, -1, 2]`, `threshold = 2` заранее составляет таблицу из трёх ответов (сумма `3`, подходящих `2`, максимум `2`). После смены порога на `3` неизменны сумма/максимум, счёт становится `0`. Объяснить, почему так. Затем **словами**, без готового кода, наметить три переменные до `for`, три правила обновления и три строки после; вернуться при затруднении к разделам 01, 03, 05. Седьмая задача начинается из практически пустого редактора: ни каркас `for`, ни места инициализации ученику не выдавать.

**Семь обязательных задач** `CODE_TASKS["9.1"]`, каждая — платформенный `script` с заранее заданными входами, stdout и автопроверкой. 2. **Задания 3–4: условие и три итога.** Для `routes` с `completed` дописать `if` и обновлять `completed_count` только при `True`; различить отсутствие завершённых от отсутствия записей. 3. **Задания 5–6: максимум и ремонт накопления.** Для `measurements` самостоятельно дописать ветки `if best is None` / `elif value > best` внутри подготовленного `for`, проверить `[4,9,6] → 9`, `[-8,-3,-6] → -3`, `[-4] → -4`, `[] → None`. Затем найти причину неверного `total = value`, исправить её и проверить `[3,8,2] → 13`, `[5,2] → 7`, `[] → 0`. Вернуться к 05–06.
4. **Задание 7: полностью самостоятельная сборка.** Платформа задаёт `measurements` (целые, включая отрицательные и 0, список может быть пуст) и `threshold` (целое). Без каркаса ученик выбирает **собственные** состояния/их начало, пишет `for` и проверки, не меняет список и печатает **ровно три строки**: общая сумма; количество `value >= threshold`; максимум всего списка (или `None`). Отличающие проверки: `[0,4,2]` при пороге `2` → `6/2/4`; `[-8,-3,-6]` при `-6` → `-17/2/-3`; `[]` → `0/0/None`; `[7]` при `8` → `7/0/7`; `[2,9,1,4]` при `4` → `16/2/9`. В MAIN до самостоятельной попытки **не показывать** финальную программу на этих именах.

После группы связать шаги: от одной операции в готовом цикле к выбору нескольких состояний и условий без каркаса. **Подсказки открываются после попытки** и возвращают к принципу в соответствующем разделе, не подменяют самостоятельное составление программы. Промежуточные входы и примеры теории отличаются от итоговых тестов; каждый запуск заново получает данные и не наследует предыдущий результат.

**Предметная приёмка P4 / передача в MAIN:** ученик различает сумму и счёт, фиксирует старт до прохода, обновление внутри, вывод после; понимает включённый порог `>=`, ноль и пустоту, кандидата `None`, отрицательный максимум и не последний максимальный элемент. Будущую MAIN-подачу планировать с реальными прогнозами, трассами и визуалами состояния не реже чем после двух соседних читаемых абзацев; избегать цепочек однотипных карточек. Сильную исходную прогрессию **шесть тренировок → седьмая самостоятельная** сохранить.
