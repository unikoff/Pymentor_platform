## 01. Первая проверка `while`: цикл может не начаться

- **Задача раздела:** научиться читать форму `while условие:` и объяснять, когда и сколько раз выполнится тело. Переход от знакомого `if`: `if` один раз проверяет условие и идёт дальше, `while` после тела **возвращается к новой проверке**. Сравнение проводится на одних значениях с наблюдаемым различием, не как абстрактная таблица ключевых слов.
- **Механизм до применения:** Python проверяет условие *до* входа в тело; при ложном условии тело не исполняется ни разу; при истинном выполняется всё тело с отступом, затем проверка повторяется на **текущих значениях переменных**. После ложной проверки выполняется следующий оператор **за циклом**. Показать расположение двоеточия, отступов и операторов внутри/после `while`.
- **Независимый пример теории (убывающий заряд):**

  ```python
  charge = 2
  while charge > 0:
      print(charge)
      charge = charge - 1
  print("готово")
  ```

  В явной трассе: проверка `2 > 0` → печать `2`, новое `charge = 1`; проверка `1 > 0` → печать `1`, новое `charge = 0`; проверка `0 > 0` → ложь и `готово`. Исходное `charge = 0` даёт лишь `готово`; исходное `1` даёт одну печать и выход. Это **три разных маршрута**, а не утверждение «цикл всегда срабатывает».
- **Первое действие ученика:** до запуска по изменённым значениям `charge = 3` и `charge = -1` обозначить проверки и полный вывод, затем проверить прогноз в редакторе; ответ объяснять значением **перед** проверкой, а не числом строк кода. Для самостоятельной практики будет другой пример с возрастанием и иной границей.
- **Опора при ошибке:** показать указатель «проверка → тело → изменение → проверка» и отдельно, куда исполнение идёт, когда ответ ложный. Не объяснять остановку временем или «когда Python посчитает достаточно».
- **Содержательная вставка MAIN:** схема с одним возвращающимся ребром и развилкой «истина/ложь», ученик выбирает следующий шаг при `charge = 0` до раскрытия стрелки. Между описаниями и схемой/прогнозом — максимум два читаемых абзаца.

## 02. Четыре вопроса о конечности: начало, условие, изменение, выход

- **Задача раздела:** отделить факт повторения от *доказательства*, что оно закончится. Сохранить сильное правило прежнего плана: **(1) где начнём, (2) пока что продолжаем, (3) что изменяем, (4) как достигнем остановки**. Проверять ответы до запуска, а не после зависания.
- **Механизм:** состояние — значения переменных, влияющих на условие. Если условие `position < limit`, движение `position = position + 1` приближает к ложному условию при фиксированной границе и конечном стартовом целом числе; если `remaining > 0`, шаг `remaining = remaining - 1` приближает к нулю. Движение в противоположную сторону или отсутствие изменения не даёт такого аргумента. Проговорить, что прогресс нужен **на каждом повторяющемся пути**, а `break` является самостоятельным способом выхода.
- **Различающий пример:** при `position = 0`, `while position < 3` и прибавлении единицы значения перед проверкой будут `0, 1, 2, 3`; тело выполнится для первых трёх. Если оставить внутри только `print(position)` и не менять `position`, сравнение `0 < 3` останется истинным, и код бесконечно повторяет ту же печать. **Дефектный вариант не запускать**; сначала на бумаге записать два последовательных одинаковых состояния, объяснить причину и предложить исправление.
- **Первое действие ученика:** в короткой трассе `position = 1`, `limit = 4` выбрать, где должен стоять шаг, назвать значения перед проверкой и прогнозируемое завершение. На другом случае `position = 4` объяснить ноль проходов. Проверка — объяснение из четырёх вопросов, затем безопасный запуск исправленного варианта.
- **Типичная ошибка:** «в теле есть изменение какой-то переменной, значит цикл конечен». Контрпример: менять `total`, когда условие зависит только от неизменного `position`; попросить указать именно переменную в условии.
- **Вставка MAIN:** таблица трассы `значение до проверки / условие / выполняемое действие / новое значение` с заполнением одной пропущенной строки самим учеником. Визуал нужен, чтобы увидеть неподвижное состояние без реального зависания.

## 03. `while` и список: сначала граница, затем индекс

- **Задача раздела:** перенести модель состояния на знакомый список. Для `for item in items` Python сам выбирает следующий элемент; при `while` ученик ведёт номер позиции сам. Сопоставить два коротких прохода по одним данным и одинаковый вывод: различается **ответственность за продвижение**.
- **Механизм:** начать с `index = 0`; проверять `index < len(items)` **прежде**, чем читать `items[index]`; после чтения сдвигать индекс на единицу. `len(items)` — количество элементов, а последний допустимый индекс на единицу меньше длины. Условие `index <= len(items)` неверно для обычного доступа: при `index == len(items)` индекса уже нет. Не вводить новые методы или техники итерации.
- **Независимый пример теории (метки полок):**

  ```python
  labels = ["верх", "низ"]
  index = 0
  while index < len(labels):
      print(labels[index])
      index = index + 1
  ```

  Трасса: `0 < 2` → «верх» → индекс 1; `1 < 2` → «низ» → индекс 2; `2 < 2` → ложь. Для `labels = []` проверка `0 < 0` сразу ложна: ни чтения, ни ошибки. Для `index = len(labels)` сразу ноль проходов.
- **Первое действие ученика:** прогноз на другом списке `labels = ["А", "Б", "В"]` при `index = 1`: какие значения появятся и на каком значении индекса цикл кончится? Затем самостоятельно исправить в **текстовой** трассе условие `<=` на безопасное, объяснить разницу на пустом списке и при достижении границы, после этого запускать исправленный код.
- **Возврат при затруднении:** рисунок `0 | 1 | ... | len-1` и отдельная позиция `len` уже *за* списком; понятие `index` и `len` взяты из планируемой A занятия 6.1, но безопасность чтения закрепляется здесь.
- **Вставка MAIN:** линия ячеек с подсветкой индекса и «за пределом»; прогноз последнего шага до изменения подсветки. Это одна проверка границы, без соседней карточки с тем же вопросом.

## 04. `while True`: выход по достижимому `break`

- **Задача раздела:** понять, чем принципиально отличается цикл с условием перед телом от намеренно постоянного `True`. Только после конечных циклов 01–03 показать, что `while True` **сам по себе никогда не станет ложным**; предусмотреть явный `break`, путь к нему и состояние на этом пути.
- **Механизм:** знакомый из занятия 10 `break` завершает ближайший цикл, в том числе `while`; строки после `break` в теле не выполняются, далее программа идёт за циклом. В `while True` достижимый `break` — часть правильной конструкции, но запись `if ...: break` без возможности стать истинной **не обеспечивает выхода**.
- **Независимый пример теории (попытки до границы):**

  ```python
  attempt = 0
  while True:
      if attempt == 2:
          break
      print(attempt)
      attempt = attempt + 1
  print("конец")
  ```

  Трасса: при `attempt = 0` печать `0`, при `1` печать `1`; при `2` условие `break` истинно, поэтому печати `2` нет, за циклом печать «конец». При старте `attempt = 2` выход происходит до первой печати тела. Пояснить, что первоначальный `True` выполняет вход, но выход может случиться в самом первом проходе.
- **Первое действие ученика:** на примере с `attempt = 1` самостоятельно предсказать печать и точку выхода; в подозрительной версии, где строка увеличения удалена, **без запуска** найти недостижимый `break` и восстановить продвижение. Различить этот случай и обычный `while attempt < 2` на том же стартовом состоянии.
- **Переход:** в настоящем script остановка может наступить по двум причинам: получен сигнал `stop` или достигнут конец подготовленного списка. Перед усложнением нужен ещё один механизм — `continue` и его влияние на обновление состояния.
- **Вставка MAIN:** мини-трасса с «до `break` / после `break` / после цикла» и единственный вопрос на предсказание первого выполненного оператора при изменённом старте.

## 05. `continue` и все пути продвижения

- **Задача раздела:** перенести знакомое по 10 значение `continue` в **`while`** и устранить опасную ошибку: пропуск остатка тела может пропустить и изменение переменной. В `for` продвижение к следующему элементу происходило автоматически; в `while` этого нет.
- **Сначала самостоятельная простая трасса:**

  ```python
  step = 0
  while step < 4:
      step = step + 1
      if step == 2:
          continue
      print(step)
  ```

  Вывод: `1`, `3`, `4`. На `step == 2` печать пропущена, но увеличение **уже произошло**; следующая проверка выполняется при 2. Если переставить увеличение после `if ...: continue`, то при `step == 2` прогресс остановится. До запуска ошибочного варианта показать два одинаковых состояния и предложить безопасный порядок строк.
- **Затем композиция с подготовленными сигналами:** в script есть список слов `next`, `skip`, `stop`; до чтения `signals[index]` необходимо обработать `index == len(signals)` или другой безопасный контроль конца списка. Объяснить **впервые здесь**, как соединяются четыре независимых решения: конец данных → `break`; чтение очередного сигнала; обновление `index` **до** любого `continue`; `skip` → `continue`, `stop` → `break`, `next` → обычное действие. Не скрывать новое правило под готовым решением итогового упражнения. Сигналы — элементы готового списка, клавиатурного `input` нет.
- **Контрольная учебная трасса без готового script:** на сигналах `["next", "skip", "stop", "next"]` ученик помечает значение индекса *до чтения* и *после продвижения*, какое действие пропущено при `skip`, на какой записи случается `stop`, почему последнее `next` не обработано. Затем отдельно рассматривает `[]` (выход по концу до чтения), `["skip"]` (после пропуска дошли до конца) и `["next"]` (конец без `stop`).
- **Опора при ошибке:** таблица двух возможных выходов и каждого пути из тела: `next` ведёт к новому чтению, `skip` ведёт к новой проверке без полезного действия, `stop` завершает, конец списка запрещает чтение. Для продолжения нужна смена `index` *перед* веткой `skip`; один и тот же сигнал нельзя обрабатывать бесконечно.
- **Вставка MAIN:** развилка на схеме «конец / next / skip / stop» с указателем индекса, затем одно задание на поиск опасного пути; карточки с однотипными вопросами подряд не требуются.

## 06. Безопасная диагностика и проверка остановки

- **Смысл:** перед любым сомнительным запуском ученик составляет короткую трассу: значения переменных, проверка условия, выход `break` либо следующее состояние. Повторение того же состояния при истинном условии без другого достижимого выхода — повод **не запускать**, а исправить логику. Остановка не доказывается количеством напечатанных строк или самим наличием слова `break`.
- **Проверяемые случаи:** первоначально ложное условие (`0` проходов), один проход, несколько проходов, граница равна старту, пустой список, указатель на границе, `skip` перед концом и отсутствие `stop`. Для `while True` явно ответить: что ограничивает просмотр, где `break` и как мы обязательно попадём к нему при конечном списке.
- **Первое действие ученика:** без запуска разобрать две короткие дефектные трассы: (а) индекс не изменяется на пути `skip`; (б) чтение `signals[index]` сделано до проверки конца. Предложить изменение порядка и объяснить, какой новый граничный случай становится безопасным; только затем проверить исправленный script.
- **Вставка MAIN:** один осмысленный «найди состояние, которое повторяется» и мини-таблица крайних случаев. Ритм подачи: **не более двух читаемых абзацев подряд между содержательными визуалами или интерактивами**; визуал должен помогать предсказать, проследить либо исправить, без декоративных вставок и цепочек из одинаковых вопросов.
