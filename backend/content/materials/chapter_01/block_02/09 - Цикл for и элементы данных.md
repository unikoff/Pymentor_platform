## 00. Вступление

Ученик уже встречал отдельные значения и коллекции; теперь нужно вывести каждое значение списка, не переписывая `print` для каждой позиции. Начать с `[10, 30, 50]` и вопроса «Как вывести всё, если завтра элементов станет четыре?». Сначала объяснить один повторяемый блок, не начинать с индексов или `range`.

1. **Точка старта:** подготовленный список с различимыми значениями и знакомое чтение одного элемента.
2. **Новый вопрос:** как последовательно получить очередное значение и выполнить для него одно действие?
3. **Результат:** script с простым конечным обходом, где можно назвать текущий элемент, значение переменной цикла и наблюдаемый вывод.

Пояснить связь: ученик прослеживает прямой проход по списку, **сам пишет** такой же цикл на других данных, затем переносит механизм на знакомую строку. Далее разбирает `range` для известного числа повторений, применяет числа как позиции, после этого выбирает обход словаря и читает список записей. Накопление итогов остаётся за границами занятия. В MAIN у ключевых переходов запланировать содержательные трассы/визуалы и короткие прогнозы «что будет в переменной / что напечатается»; вставка должна помогать освоить новый механизм, а не просто разбивать текст.

## 01. Как выполняется один цикл for

- **Механизм до первого применения.** На подготовленном `[10, 30, 50]` разобрать `for item in values:`: `for` начинает проход, имя `item` **на каждом проходе получает одно очередное значение**, `in values` задаёт источник. Двоеточие завершает заголовок; дополнительный одинаковый отступ отмечает строки тела. Показать в объясняющем примере **полный синтаксис с отступом**:

  ```python
  values = [10, 30, 50]
  for item in values:
      print(item)
  print("Готово")
  ```

  Первая команда печати исполняется трижды, вторая — только после завершения цикла и ровно один раз. Отступ в последней строке отсутствует: иначе это было бы уже другое поведение. Практика далее использует другие данные и собственный код ученика.
- **Трасса наглядно.** Проход 1: `item = 10` → вывод `10`; проход 2: `item = 30` → `30`; проход 3: `item = 50` → `50`; затем вне тела `Готово`. Визуал выделяет текущую строку и элемент. До запуска изменённого `[4, 9]` ученик предсказывает две строки значений и одну строку завершения; проверяет прогноз на выводе.
- **Пустота и имя.** При `values = []` тело ни разу не выполняется, но команда вне тела по-прежнему исполняется. Если до цикла `item` не существовало, пустой `for` не создаёт это имя. После непустого цикла оно может хранить последний элемент, однако чтение его после **пустого** источника приведёт к ошибке (или к устаревшему значению, если имя уже существовало); не использовать его как гарантированный результат цикла. Имя не является индексом автоматически.
- **Опора и переход.** Четыре вопроса для повторения: откуда берём → что попало в имя → что происходит с отступом → что выполняется после блока. После прогноза по пустому/непустому источнику дать самостоятельно написать простой цикл; `range` ещё не нужен.

## 02. Прямой обход списка и символов строки

- **Первое самостоятельное написание.** После разобранного примера ученик получает **другие** значения `[7, 7, 2]`, выбирает имя переменной и сам пишет заголовок `for`, отступ и печать каждого значения, затем добавляет одно сообщение **после** цикла. Не давать готовый цикл, где осталось изменить надпись. Прогноз для трёх элементов с повтором отличает обход каждого вхождения от выбора уникальных значений. На `[]` в теле нет вывода, на `[6]` он один, строка после цикла остаётся одной в обоих случаях.
- **После списка — строка.** Напомнить, что уже знакомая строка состоит из символов в порядке их следования. В отдельном объясняющем примере разобрать `for letter in "кот":` и печать `letter`: `"к"`, `"о"`, `"т"` поступают по одному символу. Пустая строка `""` даёт ноль проходов; повторы символов остаются отдельными проходами. Только после демонстрации ученик **сам составляет** цикл по другой короткой строке и прогнозирует результат для пустой. Индексы строк здесь не нужны.
- **Опора и переход.** Для обоих источников: «текущий элемент → имя → действие → вывод». Два одинаковых значения означают два исполнения тела. Ученик уже пишет прямой `for` по новым данным; затем вводится `range` как иной источник чисел, пока без обращения к списку по позициям.

## 03. range: повторяем известное число раз

- **Зачем:** иногда нужно выполнить одно действие заданное число раз без готового списка значений. `range` задаёт последовательность целых чисел, которую может обходить `for`; переменная цикла получает очередное **число**, пока ещё не индекс другого источника. Не называть `range` готовым списком.
- **Механизм до примера.** Сначала одна граница: `range(4)` даёт `0, 1, 2, 3`, **не включая** `stop=4`; `range(0)` не даёт ни одного числа. Затем форма с началом: `range(2, 5)` даёт `2, 3, 4`, `range(3, 3)` — пуст. Во всех случаях по умолчанию шаг +1. Отрицательный шаг и его запись здесь не нужны.
- **Прогноз → наблюдение → собственный код.** На объясняющем `range(3)` и `print("Сигнал")` показать: переменная получает `0, 1, 2`, но на экран трижды выходит **одинаковая** строка, поскольку тело не использует число. На новых границах ученик прежде запуска перечисляет числа, затем пишет свой `for` на пять одинаковых сообщений; проверяет отдельно `range(0)` и `range(4, 6)`. Локальный критерий — число строк и отсутствие исполнения при пустом диапазоне, без счётчика.
- **Опора и переход.** Для `range` записать start, stop, получаемые числа и число проходов. Если start не меньше stop при шаге +1, тело не выполнится. Лишь после самостоятельного предсказания числового обхода показать, что эти числа могут стать позициями списка.

## 04. Значение элемента и его позиция

- **Смысл выбора раньше синтаксиса.** Для `values = [10, 30, 50]` прямой `for item in values:` даёт данные `10`, `30`, `50`. Если требуется назвать **место** каждого значения, нужна позиция. До нового заголовка напомнить освоенные на 6.1 `len(values)` как число элементов и `values[index]` как чтение значения по позиции. Теперь можно объяснить `for index in range(len(values)):`: `range` даёт позиции `0, 1, 2`, а доступ к значению происходит отдельной операцией `values[index]`.
- **Наглядный разбор двух путей.** Сопоставить трассы «`item` → 10, 30, 50» и «`index` → 0, 1, 2 → `values[index]` → 10, 30, 50». В визуале индекс расположен над соответствующим элементом. На `[10, 10]` позиции 0 и 1 различаются, хотя значения одинаковые. При пустом списке `len(values) == 0`, `range(0)` пуст и попытки чтения по несуществующей позиции нет. Позиция — не само значение, не постоянный ID и не обязательно номер для пользователя.
- **Самостоятельное применение.** На новом списке из двух текстовых значений ученик пишет цикл для вывода каждой позиции **рядом** с её значением. Затем выбирает, какой из двух вариантов короче для задачи «вывести только значения», и объясняет почему. Готовый индексный заголовок в практическом задании не предлагать. Исходный список не менять.
- **Опора и переход.** Вопрос: «Нужно само значение или место, на котором оно стоит?» По умолчанию для значения прямой обход; индексный только при реальной потребности в позиции. После этого перейти к уже знакомому словарю.

## 05. Ключи, значения, пары словаря и список записей

- **Три источника, по одному.** На `record = {"title": "Книга", "pages": 20}` сначала напомнить, что `for key in record:` получает `"title"`, потом `"pages"`; прямой обход словаря даёт **ключи**, а не значения. Если нужны только значения, знакомый из 8 метод `record.values()` даёт `"Книга"` и `20` по одному значению на проход. Если нужна связь ключа и значения, `record.items()` даёт пары `(ключ, значение)`. **После** объяснения пары показать `for key, value in record.items():`: одна пара распаковывается в два имени точно так же, как в 7.2. Запятая в заголовке не запускает второй цикл.
- **Сопоставление для выбора.** Три содержательные колонки на одной записи: ключи → `title, pages`; значения → `Книга, 20`; пары → `title: Книга`, `pages: 20`. Перед собственным кодом ученик выбирает источник по условию «нужны названия полей / только значения / название вместе со значением» и объясняет получаемое имя. Пустой `{}` не даёт ни одного прохода. Если порядок вывода проверяется, данные — литерал словаря с заданным порядком записи полей (Python сохраняет порядок вставки); ключ и значение одного поля нельзя рассоединять.
- **Затем — внешний список записей.** Напомнить B занятия 8.1: `cards = [{"title": "A"}, {"title": "B"}]` — список, **каждый его элемент** является словарём. Объяснить один проход: переменная `card` получает целую запись, `card["title"]` читает знакомое поле. Затем проследить все записи. Для печати одного поля каждой записи хватает **одного прямого `for`**, не нужны `items`, вложенный цикл или изменение словаря. Если список пуст, тело не выполняется; одинаковые значения полей в двух разных записях выводятся дважды.
- **Первое собственное действие и опора.** На другом словаре ученик сам выбирает источник и составляет цикл для ключей, значений или пар, после чего на другом списке записей пишет собственный обход с чтением нужного поля. В обоих случаях опора одна: «источник → что получает переменная за проход → что печатается». Нельзя считать успешным простое узнавание заранее готового цикла. Дальше — объединённая самостоятельная практика с новым набором нейтральных данных.

## 06. Что мы будем делать в практике

**Формат и исходная опора:** обязательны короткие **scripts на платформе** с заранее видимыми исходными значениями и наблюдаемым stdout, как в паспорте 9 (rev `5120da6c`). `input()` не нужен. До выдачи подтвердить базовое чтение списка (B6.1), распаковку пары (B7.2), ключи/представления словаря (B8), чтение поля записи (B8.1); это планируемая опора, не подтверждённое достижение конкретного ученика. Для проверки именно `for` не выдавать готовый цикл: стартовый код может содержать **только исходные данные** и краткую формулировку требуемого вывода. Автопроверяемый результат — строки stdout в порядке обхода; в каждом задании явно задавать, нужна ли строка после цикла, и не оценивать произвольные имена переменных.

Общий результат — серия собственных scripts: прямой `for` по значениям и строке → `range` без индексов → `range` для позиций → выбор ключей/значений/пар → прямой обход списка записей. На каждом шаге проверяется **созданный** учеником заголовок/тело, а не отредактированное сообщение в готовом решении.

1. **Первый `for` своими руками (01–02).** **Вход/объект:** подготовленный список целых значений `[12, 12, 7]`, ни одного готового заголовка `for`. **Опора:** B6.1 (чтение списка; проверить перед выдачей), объяснённый механизм `for` из 01. **Действие ученика:** написать `for` с переменной текущего элемента и печатью самого элемента, затем одну строку «Готово» без отступа; перед запуском назвать значения переменной и число выполнений. **Локальный результат:** три строки чисел в заданном порядке и одно «Готово». **Различающий случай:** для `[]` только «Готово», для `[5]` — одна строка числа и «Готово»; два одинаковых элемента не должны сливаться в один. После пустого списка не просить печатать не созданную переменную цикла.
2. **Тот же механизм на строке (02).** **Вход/объект:** заранее известная строка `"дом"`, затем `""` и `"мама"`; это другой сюжет, чем объясняющее `"кот"`. **Опора:** строка как последовательность знакома ранее, прямой `for` освоен на шаге 1. **Действие:** самому написать цикл, который печатает по одному символу на строку, назвать значение переменной на каждом проходе. **Локальный результат:** три отдельные строки символов для `"дом"`; без вывода для пустой строки. **Различающий случай:** для `"мама"` четыре строки, включая повторные «м» и «а», без попытки получить индекс символа.
3. **Заданное число действий через `range` (03).** **Вход/объект:** задача вывести одинаковую метку ровно пять раз; затем отдельно границы 0 и `(4, 6)`. **Опора:** прямой `for` освоен, обе формы `range` и исключённый `stop` разобраны в 03. **Действие:** написать новый цикл по `range`, не создавая фиктивный список или накопитель; до запуска перечислить числовые значения источника. **Локальный результат:** пять одинаковых строк при `range(5)`; ноль при `range(0)`; две при `range(4, 6)`. **Различающий случай:** не выводить `5` как шестое значение, не считать `6` третьим числом в последнем диапазоне; объяснить, почему `start=stop` даёт пустой обход.
4. **Позиция вместе со значением (04).** **Вход/объект:** список `['чай', 'сок']`, затем `[]`; требуется показать именно позицию рядом со значением. **Опора:** B6.1 (`len` и чтение `values[index]`, проверить перед выдачей), `range` из шага 3. **Действие:** самостоятельно построить цикл по позициям и обратиться к элементу по текущему индексу, получив пары `0 — чай`, `1 — сок`; затем объяснить, почему прямой `for` предпочтителен, если нужны только значения. **Локальный результат:** две строки с **разными позициями** и соответствующими данными. **Различающий случай:** `[]` даёт ни одной строки и не вызывает чтение по индексу; при двух равных значениях позиции остаются разными. Проверка отделяет индекс от содержимого.
5. **Выбор обхода словаря (05).** **Вход/объект:** нейтральный `{'color': 'blue', 'size': 'small'}` и затем `{}`; требуется отдельно имена полей, отдельно значения и в третьем script — пары «ключ: значение». **Опора:** B8 (словарные представления) и B7.2 (распаковка пары), проверить перед выдачей; формы цикла объяснены в 05. **Действие:** самому выбрать `record`, `record.values()` или `record.items()` и написать соответствующий заголовок с одной либо двумя переменными, вывести требуемое. **Локальный результат:** ключи `color`, `size` для первого требования; значения `blue`, `small` для второго; точные связи `color: blue`, `size: small` для третьего. **Различающий случай:** `{}` не печатает строки; нельзя путать обход значений с обходом ключей и нельзя выводить ключ от одной пары со значением другой.
6. **Перенос на список готовых записей (05).** **Вход/объект:** `cards = [{'name': 'Лена'}, {'name': 'Ася'}, {'name': 'Лена'}]` и затем `[]`; нужно вывести одно известное поле **каждой** записи. **Опора:** B8.1 — чтение `record['name']` из списка словарей (проверить перед выдачей) и прямой `for` шагов 1–2. **Действие:** самому написать единственный прямой цикл по внешнему списку, выбрать имя текущей записи и вывести её поле `name`; исходные коллекции не изменять. **Локальный результат:** три строки в исходном порядке: «Лена», «Ася», «Лена». **Различающий случай:** две записи с равным полем дают **две** строки, пустой список — ноль; не требуется ни `items()`, ни вложенный цикл, ни счётчик. Это проверяет перенос механизма на записи, а не знание следующего урока.

Действия выполняются в указанном порядке: каждый новый источник появился **после** объяснения. При ошибке в шаге 3 вернуться к таблице `start/stop` в 03, при ошибке позиции — к двум трассам из 04, при смешении ключей и значений — к трём колонкам 05. В MAIN использовать трассы и сопоставления как осмысленные визуальные опоры между читаемыми абзацами (не более двух последовательных абзацев без содержательного интерактива или визуала); конкретные интерфейс, проверочные данные и подсказки остаются за этапом 3. Подсказка не должна раскрывать готовый цикл, который ученик обязан написать сам.

**Итоговый критерий всей практики:** на незнакомом коротком списке и знакомом типе записи ученик без готового шаблона пишет корректный `for`, предсказывает значение переменной и число проходов, отличает элемент от позиции, объясняет обе формы `range` и подбирает словарное представление по вопросу задачи. Мини-проверка переноса: поменять входные записи и предсказать новый вывод до запуска; это продолжение шага 6, не отдельный проект. Для каждого сценария видны результат обычного и различающего входа. Накопители и готовые решения занятия 9.1 не нужны.
