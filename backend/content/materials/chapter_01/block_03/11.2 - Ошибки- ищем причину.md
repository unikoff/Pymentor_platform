## Последовательность объяснения для MAIN

### 00. От знакомого вызова к неожиданному результату

Стартовая ситуация: один знакомый вызов функции даёт ожидаемое значение, а изменённый ввод — остановку или неверное число. **Связанная группа «Точка старта → Новый вопрос → Результат»:** знакомые функции и данные → как выяснить, что произошло → найти причину, изменить минимум, проверить старые данные. После группы коротко пояснить: «красный текст» помогает только когда программа остановилась; логический дефект обычно приходится искать сравнением с договором. Первое предсказание о результате простого вызова — перед новыми терминами.

### 01. Не все ошибки выглядят одинаково

Объяснить три случая на **независимых от обязательных задач** мини-сюжетах. 1) Пропущенная закрывающая скобка в `print(7`: Python разбирает текст программы и сообщает `SyntaxError` до начала её исполнения; нельзя обещать, что *любая* синтаксическая ошибка укажет точно на виновный символ. 2) Деление `10 / divisor` при `divisor = 0`: синтаксис правилен, но операция прерывается исключением `ZeroDivisionError`. 3) Скидка, посчитанная по неверному порогу: программа завершается, однако число нарушает явно заданное правило; traceback нет. Ученик сравнивает для каждого «программа начала работать? есть исключение? совпадает с ожидаемым?»; итог — верный выбор способа диагностики. Возвратная опора: исключение — событие прерывания текущего выполнения, «ошибка результата» определяется договором.

**Вставка MAIN:** одна таблица «синтаксис / выполнение / логика» с тремя разными наблюдаемыми следствиями; после неё одно предсказание для нового простого фрагмента, чтобы закрепить различение, без повторной карточки.

### 02. Как прочитать traceback

Сначала разъяснить на отдельном небольшом вызове `outer() → inner()`, где `inner` получает ноль в знаменателе: строки `File ... line ... in ...` показывают путь вызовов и конкретные исполнявшиеся строки, самая нижняя строка содержит тип и текст исключения. Начинать с нижней строки для вида сбоя, затем искать ближайшую **собственную строку кода** и двигаться по цепочке вызовов к полученному входу. Не путать «нижняя строка traceback» со строкой кода, где впервые появилась неправильная величина; вывод платформы может включать служебные кадры. Подготовить понятия кадра вызова, строки кода и переданного аргумента *до* просьбы их назвать. В примере на листе ученика отдельно показать вход, фактическое значение и операцию; первопричину нельзя выводить из одного лишь имени `ZeroDivisionError`.

**Первое самостоятельное действие:** дан короткий фрагмент и его traceback для нового входа; ученик помечает тип, собственную строку остановки, значение аргумента и какую операцию следует проверить. Моментальный критерий — эти четыре элемента согласованы с показанным вызовом, без угадывания правки. **Учебный визуал:** читаемая схема «вызов → вызов → строка остановки → тип/сообщение», с выделением кадров именно из этого примера; далее обычный текст связывает её с диагностикой.

### 03. Что значат знакомые типы исключений

Объяснить смысл и необходимое наблюдение через знакомые операции, **не через заучивание типов**: `NameError` — обращение к имени, которого нет в доступной области; `TypeError` — операция с неподходящими типами (например, сложение текста с числом); `ValueError` — тип значения подходящий для операции, но само значение неприемлемо (например, `int("три")`); `IndexError` — индекс списка вне границ; `KeyError` — отсутствует запрошенный ключ словаря; `ZeroDivisionError` — делитель равен нулю. Для `ValueError` заранее напомнить изученное `int` и сравнить с `TypeError`, не обобщать «все неверные значения — ValueError». Ни один случай не требует обработчика `except`. Локальное действие — на новом фрагменте сопоставить тип исключения, известное значение и проверку («какое имя/тип/индекс/ключ/делитель?»). Критерий — обоснование по операции и фактическим данным, а не по цвету сообщения.

**Вставка MAIN:** одна компактная сопоставительная схема «операция — вход — тип»; после неё ученик сам объясняет два различающихся случая, например `list[0]` на пустом списке и `dict["x"]` при отсутствии ключа.

### 04. Строка, на которой упало, может быть невиновна

Независимый пример: функция создаёт карточку с обязательным полем `name`, другая читает `card["name"]`; нарушенное при создании имя поля проявляется ошибкой при чтении. Ввести **контракт данных** как договор о том, какие поля обязательно существуют. Сначала ученик прослеживает созданный словарь и строку чтения, затем предлагает *проверить создателя* до правки потребителя. На различающем готовом словаре чтение уже работает — его поведение нужно сохранить. Не выдавать замену на `.get(...)` за исправление: отсутствие обязательного поля тогда лишь скрыто значением по умолчанию. Это опора для практики 1, где будут **другие** имена полей.

**Вставка MAIN:** схема «создатель → запись → читатель» с показанным несовпадением ключей; краткое объяснение после визуала отделяет место проявления от причины.

### 05. Результат вычислили, но `return` потеряли

Вернуться к занятиям 11 и 11.1: `print` показывает, `return` передаёт, а завершение функции без `return` возвращает `None`. На новом нейтральном сюжете с двумя ветвями `if` ученик сначала наблюдает путь, который возвращает число, затем другой, где число вычислено, но функция закончилась без передачи результата. Сравнить промежуточное значение внутри функции и то, что действительно получила вызывающая сторона; возможный `TypeError` появляется позднее, при арифметике с `None`. Указать отдельные критерии: прежний рабочий путь продолжает возвращать число, второй тоже возвращает ожидаемое число, без подстановки константы в вызывающий код. Это подготавливает практику 2 с другим вычислением.

**Вставка MAIN:** короткая трассировка двух ветвей с местом `return` и значением у вызывающего кода. После неё самостоятельный прогноз для ветви, не попавшей в первый пример.

### 06. Без исключения тоже бывает дефект

Объяснить проверку логики через **явный договор**: например, в список попадают оценки строго выше 3, а код отбирает и тройки. Сравнить 2, 3 и 4, чтобы увидеть границу и отсутствие исключения, и только после этого обсудить минимальную правку условия. Затем ученик самостоятельно выбирает диагностический ввод для нового правила («включая границу» против «строго»), предсказывает и сверяет число подходящих элементов. Разбор теории не содержит конкретных данных или порога третьей практической задачи.

**Вставка MAIN:** таблица «входное значение → ожидается/факт → причина расхождения»; затем объяснение, зачем нужен граничный пример наряду с обычным.

### 07. Цикл диагностики и регрессионная проверка

Собрать навыки в ясную последовательность: **1. воспроизвести** сбой на исходных данных; **2. записать** ожидаемое и фактическое; **3. прочитать** traceback, если есть, либо проследить вычисление; **4. назвать** конкретную гипотезу о причине, отделив её от строки проявления; **5. сделать** минимальную правку; **6. проверить** проблемный, ранее рабочий и нужный граничный случай. Термины *bug* = дефект программы, *debug* = поиск и проверка причины, *regression* = прежний рабочий результат испортился после правки. Не вводить `try/except` и внешний debugger: здесь диагностика через код, данные и вывод.

**Первое применение полного цикла:** новый короткий пример из теории даёт видимый сбой; ученик формулирует проверяемую гипотезу и объясняет, чем подтвердит или опровергнет её без немедленного показа решения. Возвратная опора для практики — шесть вопросов выше и различение «где видно?»/«почему возникло?». Нельзя формулировать в теории гипотезу о виновной функции четвёртой задачи.

## Практика

В четвёртой исходный код и требования задают результат, но не называют виновную функцию. Подсказки идут по шагам и открываются только после собственной попытки. Задания уже существуют в `backend/content/materials/chapter_01/block_03/code_tasks.py` под ключом `"11.2"` (только чтение); MAIN соотносит план с их условием, сохраняя саму практику отдельной работой.

### Практика 1. Данные создали неправильно, а ошибка проявилась при чтении

- **Вход:** дан готовый `script` с `make_points(value)`, `read_points(record)` и тремя вызовами; заранее известный договор: у переданной записи обязателен ключ `points`. Один готовый словарь уже читается успешно, два других создаёт функция. Не требовать придумывать синтаксис словаря заново.
- **Объект:** запись после создания, обращение по ключу в читающей функции и вывод трёх вызовов.
- **Опора:** 02 (чтение строки исключения), 03 (`KeyError`), 04 (причина в создателе, обязанность поля), прежние словари из блока 2.
- **Самостоятельно:** запустить и воспроизвести исключение; указать последнюю собственную строку, фактические ключи записи и источник несоответствия; исправить только место нарушения договора и объяснить, почему уже рабочий вызов менять нельзя. В стартовом коде показаны функции, но не выделена правильная строка.
- **Локальный критерий:** вывод по порядку `4`, `8`, `0`, каждое на отдельной строке; готовый словарь по-прежнему читается; никакой запасной ответ вместо обязательного поля не появляется. Отличающий случай — созданное значение `0`: ключ существует, его значение нулевое и потому нельзя спутать отсутствие ключа с нулём.
- **Помощь только при затруднении:** вернуть к сверке ключей созданного словаря и выражения чтения; не заменять диагноз готовой правкой до собственной попытки.

### Практика 2. Один путь возвращает число, другой — нет

- **Вход:** готовый `script` с `add_bonus(value)` и `show_total(value)`; для 4 и 0 есть договор итогового вывода `8` и `4`. Один путь работает, на другом исполнение останавливается.
- **Объект:** значение, которое выходит из `add_bonus` после двух разных ветвей, и вычисление в `show_total`. Вызывающая функция и правильная арифметика остаются на месте.
- **Опора:** 02–03 (тип и место исключения), 05 (`return`, неявный `None`, ветви), материал 11 о результате функции при подтверждённой A.
- **Самостоятельно:** до правки предсказать, какое значение получает вызывающий код при каждом входе; указать путь с потерянным результатом; изменить только причину, не подставляя заранее готовый ответ в `show_total`.
- **Локальный критерий:** оба вызова завершаются выводом `8` и `4`; значение `4` из прежнего положительного пути сохранено в вычислении, а ноль обрабатывается как самостоятельный путь. Отличие — программа уже умеет считать нужное число в одной ветви, но ещё не передаёт его наружу.
- **Помощь:** вернуть к табличке «значение внутри → значение у вызывающего кода» из 05; не предлагать `try/except` и не скрывать `None` константой.

### Практика 3. Исправный запуск с неверным счётчиком

- **Вход:** готовый `script` со списками длительностей и циклом `count_long_sessions`; подходят элементы **не меньше 20 минут**. Программа завершается, но некоторые результаты противоречат договору.
- **Объект:** условие допуска элемента к счётчику; цикл, возврат и четыре вызова сохраняются.
- **Опора:** 01 (ошибка без исключения), 06 (граничные примеры), 07 (ожидание/факт/перепроверка), прежнее сравнение и накопление из блока 2.
- **Самостоятельно:** сформулировать правило словами, вручную оценить 19, 20 и 21, сопоставить его с существующим условием, выбрать минимальную правку; затем запустить весь набор вызовов.
- **Локальный критерий:** по порядку `2`, `0`, `2`, `0` для `[8, 22, 0, 31]`, `[0, 14, 19]`, `[20, 27]`, `[]`. Явно проверить включение 20, отсутствие подходящих и пустой список; не менять исходные списки.
- **Помощь:** напомнить разницу между «больше» и «не меньше» на новом числе, не писать условие вместо ученика.

### Практика 4. Неизвестная ошибка отчёта по книгам — контроль самостоятельности

- **Вход:** `script` с двумя известными по назначению операциями — отбор доступных книг и сумма страниц **переданного набора**. Платформа передаёт `books`: список словарей с `pages` (целое число от нуля) и `available` (булево значение). Код должен вывести **три строки:** число доступных книг, сумму страниц доступных книг, сумму страниц всех книг. Исходный список остаётся неизменным. Для доступной книги на 12 страниц и недоступной на 90 ожидаются `1`, `12`, `102`. Это описание ожидаемого, а не места дефекта.
- **Объект:** текущие значения, промежуточная отобранная коллекция, аргументы вызовов и вывод программы. Функции и логика отбора/суммы могут оказаться рабочими; прежде чем менять любую из них, сравнить их входы с договором.
- **Опора:** 01 и 06 (логическая ошибка без исключения), 02 (анализ пути данных), 07 (гипотеза/минимальная правка/регрессия); `return`/списки/словари/функции — запланированные B предыдущих занятий с обязательным подтверждением перед выдачей. История и примеры 04–06 **не** раскрывают структуру ошибки этого отчёта.
- **Самостоятельно, без маркировки виновной функции:** 1) воспроизвести неверный вывод; 2) письменно/в поле заметки зафиксировать `ожидание → факт → предположение → способ проверить`; 3) проследить, какие значения проходят через отбор и вычисление суммы; 4) выбрать **одно причинное исправление** и обосновать его, не подгоняя ответ под фиксированные числа; 5) заново проверить прежнее поведение на новых наборах. Исходный `script` показывает законные вызовы и базовые функции, но не содержит комментария «исправь здесь» или готовой гипотезы.
- **Локальный критерий:** для `[{pages:12, available:True}, {pages:90, available:False}]` (здесь фигурная запись — предметная схема словарей, реальный синтаксис Python с кавычками) строки `1 / 12 / 102`; для смешанного `12 (True), 90 (False), 8 (True)` — `2 / 20 / 110`. Проверить также **нет доступных**: `0 / 0 / 7` на одной недоступной 7; **все доступны**: `2 / 8 / 8` на доступных 3 и 5; **пусто**: `0 / 0 / 0`; поздняя доступная после нуля — `1 / 14 / 14`. Это проверка общего договора для *произвольного* переданного набора; нельзя заменить функцию суммы частной формулой или зафиксировать числа вывода.
- **Помощь дозированно:** первая подсказка возвращает к **первой расходящейся строке** и фактическим входам; вторая — к различию наборов, соответствующих каждому показателю; третья допускается после попытки и уточняет контракт частей отчёта. Не показывать ученику заранее итоговое исправление и не превращать самостоятельную задачу в копию примера из 04.

### Небольшой перенос после основной практики (дополнительный)

На новом коротком traceback функции, не использующей книги/длительности/баллы, ученик указывает собственную строку проявления и один способ проверить источник неверного значения. **Критерий:** отдельно названы место проявления, гипотеза о причине и проверочный ввод. Это устное/текстовое закрепление, не пятая обязательная `script`-задача и не зависимость следующего урока.

## Приёмка и границы

Исправление сохраняет сумму произвольного переданного набора. Пустой, полностью доступный, недоступный и смешанный наборы различают правильную причину и маскировку симптома. Подсказки служат восстановлению затруднившего шага и открываются после собственной попытки. В самостоятельных работах исходные данные и договор результата заданы явно; конкретный алгоритм и расположение состояний не подставляются в стартовый код. Новые конструкции языка вне указанной опоры не требуются.

**Суммарная приёмка B:** после трёх тренировок на разных причинах ученик *без указания виновной функции* успешно диагностирует четвёртый случай, объясняет `ожидание → факт → причина → минимальная правка`, демонстрирует вывод на смешанном и различающих наборах и сохраняет общее поведение функций и исходный `books`. Если исправлены только заранее разобранные ошибки или отчёт верен на одном вводе, B пока не доказана. MAIN не должен подсказать решение через заголовок, подсветку или готовый участок корректировки.

**Ритм будущей MAIN:** максимум два идущих подряд читаемых абзаца без *содержательного* интерактива или учебного визуала; плановые вставки 01–07 служат предсказанию, трассировке, сравнению, диагностике и объяснению причины. Между визуалами/интерактивами нужна смысловая связка; не вставлять подряд дублирующие карточки ради формального лимита. Две обязательные связные группы запланированы в 00 и 08; текст после каждой раскрывает их вывод.

**Передача:** B 11.1 готовит локальные имена, аргументы и результат для диагностики, но статус реального освоения ещё подлежит проверке. Следующее занятие 12 переносит знакомый запуск к установленному Python и VS Code; среда и debugger в 11.2 не обязательны.
