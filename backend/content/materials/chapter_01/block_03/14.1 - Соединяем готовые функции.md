2. **Новый вопрос:** как каждый вызов получает свои данные и возвращает значение, которое можно использовать дальше, не смешивая вычисление с показом на экране?
3. **Результат:** собственная `calculate_study_minutes(durations)` и две карточки задач в коротком демо: три готовые функции соединены результатами, сумма вызвана отдельно.

Связь ступеней для MAIN (`LinkedNotes variant="connected"`): «знакомый цикл → значение из функции → передача между функциями → наблюдаемый вывод». Не изображать сумму как четвёртый шаг создания карточки: это **отдельный** расчёт. ## 01. Проверяем исходный `main.py` и договоры готовых функций

- **Зачем:** дать новичку точное состояние работы: продолжаем его `main.py`, а не пишем вторую фабрику или новый проект. Перед фактическим занятием преподаватель проверяет отдельные вызовы трёх функций по B занятия 14; отсутствие любой из них — сигнал восстановить прежний результат.
- **Напоминание договоров:** `normalize_title(title)` удаляет пробельные символы только по краям строки (`strip()`), внутренние пробелы и регистр сохраняются; `create_task(task_id, title, priority)` возвращает *новый* словарь с `id`, `title`, `priority`, `is_done=False`; `format_task(task)` возвращает строку `[id] title | приоритет: priority | состояние` (`не завершена` или `выполнена`). Фабрика принимает заранее подготовленные положительный `id`, непустое название и целый приоритет 1–5; проверки ввода сюда не добавляем.
- **Независимый пример перед новым механизмом:** `normalize_title("  Конспект  ")` возвращает `"Конспект"` (внешняя строка с пробелами остаётся прежней). На готовом словаре с `is_done=False` `format_task` возвращает текст, но сам его не печатает; показать рядом значение возвращённой строки и то, что находится в консоли *до* внешнего `print`.
- **Первое действие ученика:** до редактирования объяснить на двух отдельных вызовах, где аргумент, где результат, и предсказать, изменится ли исходная строка/словарь. Верный признак: название с сохранёнными внутренними пробелами, неизменённая запись и отсутствие вывода от самой функции. При затруднении вернуться к занятиям 11, 13.2 и 14; нельзя объявить A освоенной по одному наличию имени `def`.
- **Роль подачи MAIN:** один содержательный визуал «вход → функция → возвращённое значение» рядом с различием «получить строку»/«напечатать строку», затем краткий прогноз. Не строить пока итоговую композицию — сначала разберём, как возникает новое возвращаемое значение суммы.

## 02. Добавляем знакомое накопление в функцию

- **Новое применение знакомого механизма:** имя `calculate_study_minutes(durations)` задаёт функцию с одним параметром — именем списка *внутри вызова*. При вызове с переданным списком каждый элемент означает целое количество минут, а `return` возвращает одно число вызывающему коду. Здесь повторно не учим `def` и `for`, а связываем их смысл с новым результатом.
- **Порядок, который надо объяснить до записи в проект:** внутри функции `total` получает 0 **один раз в начале каждого вызова**; `for` последовательно берёт из `durations` очередное число и прибавляет его к `total`; `return total` расположен **после** цикла на уровне его внешнего отступа. Поэтому после завершения прохода сохраняется сумма *всех* элементов, а один вызов не наследует `total` из другого.
- **Независимый пример для объяснения (другие данные, чем в практике):** на маршруте прогулки три отрезка по 8, 12 и 5 минут. Наблюдаем состояние `total`: до прохода 0, после первого числа 8, после второго 20, после третьего 25; только теперь результат 25 возвращается наружу. Аналогия «складываем длины участков» помогает понять накопление, но реальный цикл использует числа из списка и точный порядок исполнения, а не рисует дорогу.
- **Ошибка с различающим случаем:** при `total = minutes` вместо прибавления результат для [8, 12, 5] окажется 5, а при инициализации `total = 0` внутри `for` предыдущие 8 и 12 потеряются. При `return` внутри `for` выйдем после первого элемента и получим 8. Один элемент не различает все эти ошибки, поэтому нужен случай с несколькими значениями.
- **Первое действие ученика:** на новом маленьком списке `[4, 9, 2]` без готового решения заполнить трассу «значение элемента → `total` до → `total` после» и объяснить, где должен быть `return`. Наблюдение: 0 → 4 → 13 → 15, результат 15; если итог 2 или 4, по схеме найти пропущенный шаг. В MAIN дать небольшую трассировку с пустыми ячейками, а не четыре подряд информационные карточки.
- **Опора для практики:** форма «один параметр-список → локальный ноль перед `for` → изменение суммы в цикле → возврат после него»; следующий раздел проверит, работает ли правило без единой итерации.

## 03. Проверяем пустой вход и независимость вызовов

- **Почему пусто — это допустимый результат, а не ошибка:** если `durations == []`, тело `for` ни разу не выполнится, но созданный *перед* циклом `total` уже равен 0; до `return` управление доходит в любом случае. Для `[13]` результат 13; для `[13, 7, 4]` — 24. Не нужно дополнительное условие `if durations`: существующий алгоритм покрывает пустой список.
- **Независимость повторных вызовов:** сравнить `calculate_study_minutes([6, 4])` → 10, затем `calculate_study_minutes([3])` → 3, затем повторное `[6, 4]` → 10. Визуал — три отдельные рамки вызовов с собственным начальным `total = 0`; рамки не передают сумму друг другу. Это вторая наглядная опора, отличная от «участков пути»: имя локальной переменной существует заново в каждом выполнении, рисунок не означает три одновременно выполняющихся вызова.
- **Граница побочных эффектов:** функция *читает* элементы списка и не меняет его (`append`, присваивание по индексу и другие операции над ним тут не нужны); не читает `input()`, не печатает и не обращается к общей сумме. `print(calculate_study_minutes(...))` допускается **снаружи** функции, чтобы увидеть её результат, но `print(total)` внутри сам по себе не заменяет `return`.
- **Первое самостоятельное действие:** предсказать результаты трёх вызовов с `[]`, `[5]`, `[5, 5, 1]`; обосновать, почему повторный `[5]` снова даёт 5. Дополнительно решить, будет ли исходный список `[6, 4]` прежним после вызова: да, потому что в механизме нет операции его изменения. Короткое сравнение «возврат/печать» и изменение списка использовать как **разные** когнитивные проверки, не дублирующие трассу суммы.
- **Опора/переход:** пустой вход → 0; каждый вызов начинает с 0; `return` сохраняет результат для дальнейшего кода. Теперь используем тот же принцип передачи результата на готовых функциях, не переписывая их.

## 04. Применяем композицию на двух записях

- **Новый смысл — композиция значений:** вызов функции вычисляет **результат**, а промежуточное имя позволяет сохранить его и отдать следующей функции. Это похоже на эстафету: каждый этап получает результат предыдущего; граница аналогии — в Python мы передаём полученный объект аргументом следующего вызова и не обязаны менять общую переменную. Прежде чем показать код, сопоставить тип ожидаемого входа и результата: `normalize_title` принимает и возвращает строку, `create_task` принимает подготовленные `id`, строку названия и приоритет 1–5 и возвращает словарь, `format_task` получает словарь и возвращает строку.
- **Наблюдаемая цепочка на независимом примере:** сырой заголовок `"  Прочитать раздел  "` → очищенное `"Прочитать раздел"`; вместе с `id=7` и `priority=3` он попадает в новую запись `{"id": 7, "title": "Прочитать раздел", "priority": 3, "is_done": False}`; затем formatter возвращает `[7] Прочитать раздел | приоритет: 3 | не завершена`. Отдельный вызывающий код печатает **эту** строку. Для MAIN показать одну схему со стрелками и значениями под ними, а не набор абстрактных логотипов функций.
- **Синтаксис, который нужно разобрать до самостоятельного склеивания:** `clean_title = normalize_title(raw_title)` — переменная слева хранит *результат вызова*; `task = create_task(7, clean_title, 3)` передаёт второй аргумент как строку, а `card = format_task(task)` — словарь. Внешний `print(card)` отвечает только за показ. Объяснить, что сначала вычисляется правая часть присваивания, затем имя слева получает её результат, и сопоставить три аргумента с тремя параметрами. Для самостоятельной работы P3 даст **другие данные и оставит ученику запись всей последовательности**.
- **Различающая ошибка:** `format_task(clean_title)` вместо `format_task(task)` передаёт строку там, где ожидается словарь; `print(task)` показывает словарь, но не строку карточки; `print(normalize_title)` печатает представление функции вместо результата её вызова. При забытой очистке по краям карточки остаются нежелательные пробелы. Сравнить на схеме *что именно* лежит под каждым именем перед следующим шагом.
- **Первое действие ученика:** получить не готовый код, а три подписи «что вернулось / куда подходит / что увидим» для альтернативного заголовка с краевыми пробелами и id=8, priority=4. Ученик сам выбирает, какую из трёх промежуточных величин печатать для точной карточки, и объясняет несовпадение строкового/словарного аргумента. Критерий — очищенное название, отдельный словарь, возвращённая строка без лишних пробелов на краях названия.
- **Опора/переход:** три последовательных возвращаемых значения образуют **одну** карточку; чтобы показать две, повторяем композицию на втором наборе данных, не меняя контракты функций.

## 05. Оставляем компактное демо

- **Зачем минимальное демо:** оно подтверждает договоры, не заменяя их реализацию или будущую команду меню. В конце `main.py`, после определений, лежат два подготовленных набора `id/title/priority` для отдельных вызовов и **отдельный** список минут. Сумма вычисляется самостоятельно; у каждой задачи своя цепочка очистка → фабрика → formatter → внешний вывод. Четвёртая функция `calculate_study_minutes` не обрабатывает словари задач.
- **Что демонстрация обязана показать:** две строки в точном формате `[id] title | приоритет: priority | состояние`, соответствующие *разным* словарям с `is_done=False`, и отдельное число минут; порядок вывода определён в демо и должен быть воспроизводим. Ни `normalize_title`, ни `create_task`, ни `format_task`, ни суммирование не печатают сами. Сохранить прежние определения функций, удалить старый `Hello world` и дублирующие демонстрации, не добавлять `tasks`, `run`, `calc`, `input()` или чтение файла.
- **Небольшой прогноз после механизма:** если второму подготовленному заголовку добавить пробелы с обеих сторон, изменится ли готовая строка после очистки? Нет. Если поменять у второй задачи приоритет с 2 на 5, что именно в строке изменится? Только часть `приоритет: ...` при остальных одинаковых данных. Эти прогнозы показывают контракт, а не знание новой команды.
- **Для MAIN:** перед переходом к практике дать содержательное сравнение «две независимые цепочки задач + отдельная сумма», затем предложить ученику отметить на схеме четыре места вызова функций. Сокращение демо показывать на диффе до/после как осмысленное упрощение, без повторных декоративных карточек.
