## 00. Вступление

Ученик уже встречал Python-код и видел, как платформа показывает результат. Теперь нужно понять, что меняется, когда тот же код запускается на своём компьютере.

1. **Точка старта:** знакомые выражения и разбор простых ошибок в платформенной среде; планы 11–15.1 задают этот маршрут, но прохождение и практика ученика пока не подтверждены.
2. **Новый вопрос:** какие программы и места ввода нужны, чтобы выполнить знакомый код локально, и как понять, почему запуск не сработал?
3. **Результат:** проверить или установить Python 3.12 и VS Code, выполнить знакомый код и уверенно различать Python-оболочку и PowerShell.

Сначала разделяем роли редактора, интерпретатора и терминала; затем разбираем файлы и пути, проверяем установку, учимся входить в Python-оболочку и выходить из неё, после чего запускаем знакомый код выбранным интерпретатором. Это подготовка среды: история проекта начнётся на следующем занятии.

## 01. Проверяем поддержку Python в VS Code

- Что и зачем объяснить: VS Code редактирует файл, расширение Microsoft Python добавляет поддержку Python-команд и запуска, а установленный интерпретатор исполняет код. Расширение не устанавливает Python.
- Механизм и порядок: открыть Extensions view и найти Microsoft Python. Сначала проверить, что расширение установлено и включено; если его нет — установить из официального Marketplace и затем проверить статус. Появившиеся команда `Python: Select Interpreter` или выбор интерпретатора в строке состояния служат наблюдаемым признаком поддержки.
- Пример и типичная путаница: установленное расширение при отсутствии Python-интерпретатора не запускает программу; наличие VS Code также не подтверждает наличие расширения.
- Первое самостоятельное действие: ученик самостоятельно находит расширение и показывает статус Installed/Enabled; если устанавливал его, после установки находит команду выбора интерпретатора. Результат — поддержка Python в редакторе доступна и видна.
- Переход к следующему шагу: выбрав роли инструментов, ученик готовит путь к короткому сохранённому файлу.

## 02. Файл, папка и путь запуска

- Что и зачем объяснить: `.py` — расширение файла с Python-кодом; папка группирует файлы, а путь указывает, где искать нужный файл. Терминал работает относительно текущей папки, поэтому одинаковая команда может найти файл в одном месте и не найти в другом.
- Механизм и порядок: сначала различить имя файла и путь к нему, затем текущую папку и адрес файла; показать просмотр/смену папки и зачем брать путь с пробелами в кавычки. До команд объяснить названия и эффект действий.
- Пример и типичная путаница: открытая вкладка VS Code не задаёт текущую папку PowerShell. Расширение `.py` не является командой запуска и не выбирает версию Python.
- Первое самостоятельное действие: по схеме папок ученик находит указанный файл и объясняет, какая текущая папка нужна для его запуска; результат — путь указывает на файл, а не просто на название открытой вкладки.
- Опора для повторного обращения: при проблеме запуска проверить имя и расширение файла, его папку, текущую папку терминала и кавычки в пути с пробелами.
- Переход к следующему шагу: имея представление о файле и терминале, можно проверить, установлен ли нужный исполнитель.

## 03. Проверяем установленный Python 3.12

- Что и зачем объяснить: версия Python — свойство установленного интерпретатора. Версию устанавливаем отдельной проверкой в PowerShell; это команда оболочки, а не Python-код. Launcher и PATH зависят от ОС; их внутреннее устройство здесь не изучаем.
- Механизм и порядок: проверить наличие версии 3.12; сравнить ожидаемую версию с отсутствующим Python или неподходящей версией; только при необходимости пройти официальный путь установки. Уточнить, что наличие VS Code и расширения не подтверждает наличие интерпретатора.
- Пример и типичная путаница: «команда не найдена» означает, что оболочка не нашла исполняемую команду; это отличается от ошибки внутри уже запущенного Python. Не устранять это запуском текста команды в Python-оболочке.
- Первое самостоятельное действие: ученик читает результат проверки и решает, достаточно ли подтвердить текущую установку или нужно продолжить официальную установку; результат — найденный Python 3.12 либо конкретно определённый шаг, которого не хватает.
- Опора для повторного обращения: версию подтверждает вывод проверки установленного Python, а не только название ярлыка или редактора.
- Переход к следующему шагу: теперь можно сравнить оболочку, в которой вводятся команды системы, с оболочкой, которая принимает выражения Python.

## 04. PowerShell и Python-оболочка

- Что и зачем объяснить: PowerShell запускает команды программ и работает с папками; Python-оболочка с приглашением `>>>` вычисляет выражения Python. Введённый текст интерпретируется разными программами в зависимости от приглашения.
- Механизм и порядок: показать вход в интерактивный Python после проверки установленной версии, знакомые выражения, отображение результата выражения, присваивание результата имени и отдельный `print`; затем объяснить выход обратно в PowerShell. Развести автоматическое отображение результата оболочкой и печать, выполняемую кодом.
- Пример и типичная путаница: команда смены папки не является выражением Python; выражение Python не является командой PowerShell. Присваивание в оболочке может не показать значение, хотя оно сохранено; автоматический показ выражения не доказывает, что функция вызвала `print`.
- Первое самостоятельное действие: ученик выбирает правильную оболочку для знакомого системного действия и знакомого выражения, выполняет выражение и возвращается в PowerShell; результат — верное приглашение до и после каждого действия.
- Опора для повторного обращения: сначала прочитать приглашение (`>>>` или PowerShell), затем вводить выражение либо системную команду; для выхода из Python-оболочки использовать объяснённое действие выхода.
- Переход к следующему шагу: понимание оболочек подготовило запуск уже сохранённого файла из VS Code выбранным Python.

## 05. Запускаем файл кнопкой Run Python File in Terminal

- Что и зачем объяснить: единственный основной способ запуска в этом уроке — кнопка `Run Python File in Terminal` в правом верхнем углу редактора. Она запускает активный файл с выбранным в VS Code интерпретатором и открывает для этого встроенный терминал.
- Механизм и порядок: сначала через `Python: Select Interpreter` выбрать установленный Python 3.12 и увидеть выбранную версию в строке состояния; затем сохранить короткий пример на знакомых конструкциях и нажать `Run Python File in Terminal`. После запуска проверить `python --version` в том же интегрированном терминале, который открыл и активировал выбранную среду: это проверяет версию `python`, доступную при запуске файла. Кнопка использует выбранный интерпретатор, а среда автоматически активируется в терминале, согласно [документации VS Code](https://code.visualstudio.com/docs/python/run) и [описанию выбора среды](https://code.visualstudio.com/docs/python/environments). Не использовать для этой проверки отдельное окно PowerShell.
- Пример и типичная путаница: после запуска связанный терминал показывает Python 3.11, а строка состояния редактора — выбранный Python 3.12. Первым делом убедиться, что команда версии выполнена именно в терминале, открытом кнопкой запуска; затем сверить выбранную версию в строке состояния. Если проверка была в другом окне PowerShell, повторить её в терминале запуска. Если там остаётся 3.11 — заново выбрать Python 3.12 и повторить запуск; PATH не менять.
- Первое самостоятельное действие: ученик выбирает Python 3.12, запускает файл указанной кнопкой, проверяет версию в связанном терминале и запускает пример с другими знакомыми данными. Результат — версия в терминале совпадает с выбранной, а вывод меняется по входным данным.
- Опора для повторного обращения: `Python: Select Interpreter` задаёт выбранную версию; `Run Python File in Terminal` запускает файл с ней; `python --version` проверяется в том же терминале. При несовпадении сначала проверить, что это терминал запуска, затем сверить выбор в редакторе.
- Переход к следующему шагу: успешный запуск одним способом позволяет отдельно классифицировать командную ошибку, неверный путь и ошибку Python.

## 06. Различаем проблемы запуска

- Что и зачем объяснить: недоступная команда, неверный путь и исключение Python возникают на разных этапах. Прежняя диагностика из занятия 11.2 помогает сравнить ожидание, сообщение и место возникновения, но её освоение в новой карте нужно подтвердить.
- Механизм и порядок: сначала определить, ответила ли оболочка или уже запустился Python; затем понять, нашла ли система файл; только после запуска разбирать тип/сообщение Python и строку собственного кода. Исправлять минимальную причину, не менять сразу несколько слоёв.
- Пример и типичная путаница: сообщение PowerShell о неизвестной команде не является `NameError` Python; отказ найти файл не означает синтаксическую ошибку; traceback появляется после запуска кода и разбирается средствами прежнего урока.
- Первое самостоятельное действие: ученик классифицирует короткие подготовленные сообщения по слою и называет первое место проверки. В различающем случае связанный терминал показывает 3.11, а строка состояния VS Code — выбранный 3.12; сначала он проверяет, что версию считали именно в терминале запуска файла, затем сверяет выбранный интерпретатор и повторяет проверку там. Результат — источник расхождения найден до любых изменений PATH.
- Опора для повторного обращения: команда не найдена — проверить установку/доступность команды; путь не найден — файл и текущую папку; traceback — тип, сообщение и собственную строку Python.
- Переход к практике: все действия практики используют уже объяснённые команды, файл и критерии результата; Git и создание проекта не требуются.

## 07. Что мы будем делать в практике

**Формат и исходная опора:** локальная среда компьютера; начинаем с проверки Python 3.12, VS Code и расширения Microsoft Python. Используем знакомые выражения и короткий сохранённый пример занятия. Пример не становится проектом и не сохраняется как `main.py`.

Общий результат — ученик подтверждает или безопасно устанавливает нужные инструменты, знает разницу между PowerShell и `>>>`, выполняет знакомый пример выбранным Python и различает основные категории проблемы запуска.

1. **Проверить редактор и интерпретатор:** исходное состояние компьютера неизвестно; опора — блоки 01 и 03. Ученик проверяет, что VS Code установлен и открыт; в Extensions view находит Microsoft Python и проверяет статус Installed/Enabled. Если редактора или расширения нет, устанавливает отсутствующее из официального источника и повторяет проверку. Затем проверяет Python 3.12 и при необходимости проходит официальный путь установки. Критерий — VS Code открыт, расширение видно как установленное и включённое, наличие Python 3.12 подтверждено выводом проверки.
2. **Найти рабочую папку и перейти между оболочками:** исходное состояние — PowerShell после проверки; опора — блоки 02 и 04. Ученик находит текущую папку, вводит знакомое выражение в Python-оболочке, сопоставляет автоматический результат с выводом программы, выходит в PowerShell и выполняет объяснённую команду оболочки. Критерий — он правильно называет активное приглашение и выбирает место ввода.
3. **Запустить сохранённый пример локально:** исходное состояние — выбранный Python 3.12 и предоставленный короткий файл с уже знакомыми конструкциями; опора — блоки 01, 02 и 05. Ученик выбирает интерпретатор через `Python: Select Interpreter`, запускает файл только кнопкой `Run Python File in Terminal`, затем выполняет `python --version` в том же интегрированном терминале. Критерий — версия в терминале совпадает с выбранной версией редактора, файл запускается, вывод соответствует входным данным. Не создавать репозиторий или проект.
4. **Разобрать проблему запуска:** исходное состояние — три коротких случая ошибок запуска и один различающий случай версий; опора — блок 06 и планируемая диагностика занятия 11.2. Ученик различает недоступную команду, неверный путь, ошибку Python и ситуацию, когда версия связанного терминала отличается от выбранной в редакторе. Сначала он проверяет, что версию считал в терминале запуска файла, затем сверяет выбранный интерпретатор. Критерий — источник расхождения установлен до изменения настроек системы; Git и debugger не требуются.

Паспорт требует запуск сохранённого файла из VS Code, но краткий список практики не задаёт сам пример. Для этапа 3 подготовить один короткий файл только со знакомыми конструкциями; он служит материалом урока, не становится проектом и не заменяет `main.py` занятия 12.1.

Последовательность ведёт от проверки инструментов к выбору места ввода, запуску файла и локальной диагностике. Обычный случай — выбранный Python 3.12 запускает знакомый файл; различающие случаи — нужного инструмента нет, команда введена не в той оболочке, указан неверный путь, Python выдаёт traceback или связанный терминал показывает версию, отличную от строки состояния редактора. В последнем случае сначала проверяется, что версию считали в терминале запуска файла. Если инструменты уже есть, установку не повторяют.

Итоговый критерий практики: ученик сам выбирает, где выполнить системную команду и где Python-выражение, подтверждает локальный Python 3.12, запускает знакомый файл единственной указанной кнопкой, сверяет версию в связанном терминале и объясняет первый шаг проверки при трёх типах ошибок запуска и расхождении версий. Следующий урок получит только готовую локальную среду; создание StudyHub и Git-истории начинается там.
