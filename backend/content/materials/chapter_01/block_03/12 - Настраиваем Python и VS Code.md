## 01. Кто исполняет код и где он хранится

- **Задача:** перенести известное «написал выражение → получил результат» с платформы на свой компьютер. Платформа предоставляла исполнитель и место ввода; локально их нужно различить: установленный **интерпретатор Python** выполняет код, **VS Code** редактирует и сохраняет текст, **расширение Microsoft Python** помогает редактору найти интерпретатор и дать команду запуска. Расширение не устанавливает Python. **Терминал** — окно для команд; это ещё не интерактивная Python-оболочка.
- **Файл и путь до действия:** файл `example.py` — сохранённый текст Python, `.py` — часть имени, показывающая тип файла; папка объединяет файлы, путь задаёт местонахождение. На схеме двух папок `Documents/example.py` и `Downloads/example.py` показать, что одно имя ещё не означает один и тот же файл. Условное имя не является создаваемым проектом. Нажатие Save сохраняет изменения на диск; несохранённая вкладка сама по себе не становится запускаемым файлом.
- **Пример для объяснения:** один и тот же `print(2 + 3)` на платформе и в сохранённом `.py` даёт `5`, если интерпретатор действительно выполнил код; сам редактор ничего не вычисляет. Отличить печать кодом от текста, подсвеченного редактором. Визуал MAIN: три роли «файл в VS Code → команда расширения → интерпретатор → вывод терминала»; ученик указывает, на каком шаге появляется `5`.
- **Первая самостоятельная попытка:** дать рисунок папки с двумя `.py` и одним `.txt`; попросить выбрать файл Python и назвать полное местонахождение. Поменять местами одинаковые имена в двух папках; ученик объясняет, почему путь нужен. Критерий — он указывает конкретную папку и `.py`, не предполагая запуск по виду вкладки.
- **Опора/переход:** редактор ≠ интерпретатор; имя ≠ путь; сохранение ≠ исполнение. Теперь нужен способ проверить реальный Python на компьютере — команда в терминале.

## 02. PowerShell: приглашение, текущая папка и команды

- **Новая среда перед первыми командами:** на Windows PowerShell — оболочка, где вводят команды компьютеру и получают текст ответа. Встроенный терминал VS Code может показывать тот же PowerShell, но имеет своё состояние. Приглашение вида `PS C:\Users\Student>` означает готовность PowerShell принять команду; символы приглашения не перепечатывают. Терминал можно открыть в VS Code через **Terminal → New Terminal**; вне VS Code — через поиск PowerShell в меню Пуск. Настоящее приглашение зависит от настроек.
- **Путь и эффект команд — сначала смысл, потом ввод:** текущая папка — место, относительно которого ищутся относительные пути. `Get-Location` показывает её, `Set-Location <путь>` переводит в другую **существующую** папку, `python --version` просит доступный под именем `python` интерпретатор напечатать версию. Для пути с пробелами приводить форму `Set-Location "C:\My Files"` только как пример при условии, что папка существует; кавычки удерживают части пути вместе. Не объяснять устройство PATH/launcher и не требовать системной перенастройки.
- **Независимый опыт/различающий случай:** на схеме `PS C:\Users\Student>` → `Get-Location` показывает `C:\Users\Student`; переход в существующую учебную папку меняет приглашение/вывод. Открытая вкладка редактора **не гарантирует** такую же текущую папку в отдельно открытом PowerShell. Визуал MAIN: две рядом стоящие строки — путь открытого файла и текущая папка терминала; ученик предсказывает, может ли относительный путь найти файл.
- **Первая самостоятельная попытка:** ученик находит приглашение PowerShell, выполняет `Get-Location`, называет текущую папку; из двух показанных путей выбирает, какой можно передать `Set-Location`, и объясняет роль кавычек при пробелах. Если папки нет, переход не выполняется: это ошибка пути, а не Python. Опора для возврата — приглашение → команда → ответ → место, откуда её запустили.
- **Переход:** команда `python --version` теперь понятна по роли; можно проверить существующую установку и установить отсутствующую безопасным официальным способом.

В PowerShell из 02 выполнить `python --version`: число вида `Python 3.12.x` подтверждает версию того интерпретатора, который сейчас доступен **именно по имени `python`** в этом терминале. `Python 3.11.x`, `command not found`/`is not recognized`, предложение Microsoft Store и отсутствие ответа нужной версии — разные варианты, требующие проверки установки, а не ввода команды как Python-кода.

Название кнопок и вариант настройки запуска могут зависеть от установщика/ОС; нет требования вручную редактировать PATH, переустанавливать чужие версии или удалять другие Python. - **Расширение после редактора:** открыть VS Code → Extensions (кнопка боковой панели или Ctrl+Shift+X), найти **Python** от **Microsoft**; если доступно — проверить `Installed`/`Enabled`, иначе установить из официального [Marketplace](https://marketplace.visualstudio.com/items?itemName=ms-python.python). Команда `Python: Select Interpreter` (через Ctrl+Shift+P) позволяет найти установленный интерпретатор; здесь лишь показать её, окончательный выбор — в 05. Имя расширения не подтверждает версию самого Python.
- **Пример/ошибка:** Microsoft Python установлено, а список интерпретаторов пуст или `python --version` даёт 3.11 — расширение работает, но Python 3.12 ещё нужно найти/установить. Два наблюдаемых свидетельства проверяются отдельно: `Installed/Enabled` и версия реального исполнителя. Визуал MAIN: один экран с подписанными статусами расширения, второй — вывод версии; ученик предсказывает, что будет отсутствовать, если установлен только редактор.

Если нет прав на установку, записывает конкретный блокирующий экран/сообщение и обращается к владельцу устройства; отсутствие прав не объявлять ошибкой знаний.

## 04. PowerShell и Python-оболочка

- **Два разных режима одного окна:** из приглашения `PS ...>` команда `python` запускает интерактивный интерпретатор **при условии, что это нужный установленный Python 3.12**; появившееся `>>>` — приглашение вводить выражения Python. `Get-Location` и `python --version` вводятся только при `PS ...>`, а `2 + 3` — при `>>>`. В реальном интерфейсе приглашения могут выглядеть иначе; определяющим остаётся `>>>`.
- **Механизм вывода до сравнения:** в REPL отдельное выражение `2 + 3 * 2` автоматически показывает `8`; строка `result = 2 + 3 * 2` сохраняет значение без автоматического показа, следующее `result` показывает его; `print(result)` выводит `8` уже явным вызовом `print`. В `.py` простое выражение само по себе не печатается, поэтому в файле потребуется `print`. Комментарий MAIN/визуал: небольшая таблица «ввод → что видно → кто вывел», ученик предсказывает пустую строку после присваивания.
- **Выход до попытки:** `exit()` при `>>>` заканчивает Python-оболочку и возвращает приглашение PowerShell; после выхода `Get-Location` вновь становится командой оболочки. Если `python --version` показывает не 3.12, в учебном пути сперва завершить настройку по 03; при наличии Python Launcher на Windows допустимо проверить `py -3.12 --version` и войти через `py -3.12` (это команды PowerShell для выбора установленной версии, не код Python; детали launcher вне занятия). Не утверждать, что `python` безусловно выбирает интерпретатор VS Code.
- **Отдельный пример и различение:** показаны `PS> Get-Location`, `PS> python`, `>>> 10 + 5`, `>>> exit()`; подписи поясняют, что `PS>`/`>>>` — приглашения, их не набирают. Путаница: `>>> Set-Location ...` — попытка выполнить системную команду внутри Python; `PS> result = 5` — ввод Python-кода в другую оболочку.
- **Первая самостоятельная попытка:** после объяснения ученик предсказывает, какие строки покажут результат для `6 + 4`, `value = 6 + 4`, `value`, `print(value)`; проверяет это в `>>>`, затем выходит и выполняет `Get-Location` в PowerShell. Критерий — прогноз совпал с наблюдением, выбранное приглашение названо до каждой команды и возвращение подтверждено. При сбое опора на таблицу и повтор с `7 + 4`.
- **Переход:** теперь понятны команда, выражение и `print`; пора сохранить знакомый код в `.py` и выполнить его из редактора.

## 05. Запускаем файл кнопкой Run Python File in Terminal

- **Роль кнопки:** основной способ исполнения сохранённого `.py` в этом уроке — `Run Python File in Terminal` (кнопка запуска в редакторе VS Code с открытым `.py`). Команда должна запустить **текущий сохранённый файл** выбранным интерпретатором. В отличие от REPL, обычный файл не показывает результат голого выражения автоматически; используем знакомый `print`. Не обучать параллельно `python path/to/file.py` как второму обязательному способу.
- **Подготовка без проекта:** из 03 открыть Ctrl+Shift+P → `Python: Select Interpreter`, выбрать именно установленную **3.12** по версии/пути; если её нет в списке, вернуться к проверке установки. В VS Code выбрать **File → New Text File** (или Ctrl+N), ввести разобранный пример `count = 2` и `print(count + 3)`, затем **File → Save As** (при первой Ctrl+S редактор также предложит сохранение): выбрать **существующую доступную папку** (например, Documents) и имя `lesson12_check.py` (не `main.py`). Проверить, что в заголовке вкладки видно это имя и нет индикатора несохранённого изменения. Это один временный файл для опыта, не проект/репозиторий; его дальнейшая судьба не влияет на StudyHub.
- **Пример наблюдения и содержательная вставка MAIN:** до клика спросить, покажет ли одна строка `count = 2` что-либо и какой вывод даст `print(count + 3)`; затем нажать только `Run Python File in Terminal`, увидеть `5`. Сопоставить «имя и папка сохранённого файла → путь в команде запуска → вывод `5`». При изменении только `count` на `4` ученик предсказывает `7` и проверяет повторным запуском. Если текст изменён, снова сохранить: иначе может исполниться прежнее содержимое.
- **Проверка выбора, не подмена механизмов:** в **том же** терминале запуска выполнить `python --version` при приглашении PowerShell и объяснить, что это версия **команды `python` в терминале**, а не неопровержимое свидетельство того, каким исполняемым файлом воспользовалась кнопка. Для запуска выбранного Python VS Code может указывать полный путь к `python.exe`, в то время как `python` в текущем терминале ссылается на другую установленную версию. При расхождении 3.11/3.12 сверить активный терминал, выбранную 3.12 и **команду запуска файла**, показанную терминалом; при необходимости повторно выбрать интерпретатор и запустить. Для точного подтверждения исполнения по спорному случаю **после объяснения** показать диагностическую вставку **трёх отдельных строк** в том же файле: `import sys`, затем `print(sys.version)` и `print(sys.executable)`. Команда `import` подключает встроенный модуль стандартной библиотеки `sys`; его `version` сообщает версию исполняющего код Python, `executable` — путь к нему. Строки выводит **сам запущенный файл**, поэтому они отличают фактический исполнитель от команды `python` оболочки. В обычной работе диагностические строки не нужны. Не требовать изменения PATH.
- **Отдельная первая самостоятельная проверка:** ученик выбирает 3.12, сохраняет одиночный файл со знакомым `print`, предсказывает два вывода на разных значениях, запускает кнопкой, сверяет `python --version` **в связанном терминале** и при несовпадении доказывает реальную версию через объяснённые диагностические строки. Критерий — **файл действительно исполняет выбранный Python 3.12**, оба предсказания совпадают; несовпадение только терминальной команды фиксируется как состояние окружения, а не ложная ошибка запуска.
- **Опора/переход:** `Select Interpreter` выбирает Python для кнопки, сохранение фиксирует текст файла, `Run Python File in Terminal` запускает его; `python --version` отдельно описывает команду в терминале. Следующий шаг — локализовать реальные сбои по месту возникновения.

## 06. Различаем проблемы запуска

- **Три разных этапа:** (1) PowerShell ещё не нашёл названную программу (`python` не распознана) → проверка установки/команды из 03; (2) Python запустился, но ему передали несуществующий путь к файлу (`can't open file`, `No such file or directory`) → имя, сохранение, папка/путь из 01–02; (3) Python открыл файл, но код дал traceback (`NameError` и строка исходника) → вернуться к проверенной диагностике B 11.2. Сообщение + место возникновения важнее догадки «Python сломан».
- **Независимое сравнение:** три коротких условных фрагмента терминала без лишних правок ОС: «терминал не знает `python`», «интерпретатор не нашёл `lesson12_chek.py`», «в исполняемом файле `NameError: name 'unknown_name' is not defined`». Показать сначала вопрос «кто ответил?» и затем «какое имя/путь/строка неверны?». Неправильный путь не требует менять код, traceback не лечится переустановкой VS Code.
- **Различающий случай 3.11 против 3.12:** `python --version` в связанном терминале выдаёт 3.11, строка состояния VS Code — выбранный 3.12. Это ещё не доказывает неправильный запуск кнопкой. Ученик проверяет, что терминал действительно тот, изучает показанную команду запуска и при необходимости временно печатает `sys.version`/`sys.executable` **из запущенного файла** (объяснено в 05). Если файл исполняет 3.12, исправлять нечего; если исполняет 3.11, заново выбрать интерпретатор и запустить. Ни в одном из случаев не менять глобальный PATH наугад.
- **Первая самостоятельная попытка:** по четырём подготовленным сообщениям ученик записывает `кто сообщил → какая первая проверка → какого результата жду после одной исправленной причины`; затем классифицирует изменённое имя файла и новую строку `NameError` без готовой подсказки. Проверяемое различие — не спутал проблему выбора Python для кнопки с версией команды в отдельной оболочке.
- **Переход к практике:** соответствующие объяснения и безопасные возвраты уже есть в 01–06; Git, отладчик и системные настройки не нужны. В MAIN вставить рядом с этой развилкой один учебный разбор «сообщение → слой → первая проверка», а не несколько одинаковых тестов на узнавание.

## 07. Что мы будем делать в практике

**Обязательный формат паспорта:** локально проверить или при необходимости установить Python 3.12, VS Code и поддержку Microsoft Python; поработать с терминалом/интерактивной Python-оболочкой; запустить знакомый Python-код локально. На старте неизвестно, какие программы уже стоят. Для опыта допускается ровно один **непроектный** временный `.py` в существующей папке; **нет** репозитория, отдельного пробного проекта или `main.py`. Формат — наблюдаемые локальные действия и осмысленное объяснение, без автоматической проверки платформой.

**Цель:** самостоятельно установить, *что именно выполняет код*, правильно выбрать место ввода, получить два предсказанных вывода из выбранного Python 3.12 и локализовать неисправность без случайной перенастройки системы. Подготовка B 11/11.2 — планируемая: до практики проверить два микрошага из точки A и при необходимости восстановить их в прежних объяснениях.

1. **Проверка среды (01–03).** Вход: текущий компьютер неизвестен, даны официальные ссылки и значение `Python 3.12.x` как целевой пример. **Сам:** открыть VS Code, найти в Extensions расширение Python именно Microsoft, посмотреть статус; в PowerShell распознать приглашение, выполнить `python --version` и решить, какого компонента не хватает. При необходимости установить только отсутствующее и повторить соответствующий шаг; если `python` указывает на другую версию, посмотреть наличие 3.12 в выборе интерпретатора VS Code, не делать вывода о её отсутствии только по одной команде. **Наблюдение:** редактор открывается, расширение Installed/Enabled, Python 3.12 доступен для выбора; вывод терминала записан как отдельный факт. **Различающий случай:** установлен редактор и расширение, но нет 3.12 — следующий шаг именно установка интерпретатора; запрет установки из-за прав — чёткий внешний блокер. Возврат — 01 и 03.
2. **Папка и две оболочки (01–02, 04).** Вход: PowerShell и доступная 3.12; ученик выбирает существующую папку, а не создаёт проект. **Сам:** выполнить `Get-Location`, назвать текущую папку, при необходимости перейти в другую **существующую** папку объяснённой `Set-Location` с кавычками при пробелах; войти в Python-оболочку (`python` при подтверждённой 3.12 либо объяснённая форма `py -3.12`), до ввода предсказать результаты `9 + 2`, `answer = 9 + 2`, `answer`, `print(answer)`; сравнить наблюдения и выйти `exit()`. **Наблюдение:** выражение отображается, присваивание не печатает значение, `print` выводит его; после выхода снова работает `Get-Location`. **Различающий случай:** предложить `Set-Location` при `>>>`: ученик останавливается, называет неверную оболочку и возвращается к `PS ...>` вместо попыток «чинить Python». Возврат — 02, 04.
3. **Свой сохранённый файл и запуск (01, 03, 05).** Вход: доступная папка и установленный Python 3.12; разобранный независимый пример из 05 уже показан. **Сам:** создать в существующей папке **один** `lesson12_check.py` с двумя знакомыми строками присваивания и `print` (числа и имя выбрать самостоятельно), сохранить; до запуска записать ожидаемый вывод. Через `Python: Select Interpreter` выбрать 3.12, нажать `Run Python File in Terminal`, сравнить результат с прогнозом; изменить одно число, **сохранить** и повторить тем же способом. **Наблюдение:** два вывода соответствуют двум разным предсказаниям; результат появляется от исполнения файла, не от подсветки в редакторе. **Различающий случай:** несохранённое изменение или неверная папка/имя файла — ученик проверяет сохранение, путь и команду запуска; не создаёт второй файл/проект. Возврат — 01, 05.
4. **Версия и источник расхождения (03, 05–06).** Вход: файл уже успешно запущен в интегрированном терминале. **Сам:** при приглашении PowerShell в том же терминале выполнить `python --version`, сопоставить с выбранной 3.12 и показанной командой запуска. При отличии терминального `python` от выбранной версии воспользоваться **разобранной в 05** временной диагностикой через `sys.version`/`sys.executable` **в том же файле**, затем сохранить и запустить снова кнопкой. **Наблюдение:** определена версия и путь *фактического исполнителя файла*; если это 3.12, задание выполнено даже при `python --version = 3.11`, потому что терминальная команда не обязательно выбирает тот же исполняемый файл. **Различающий случай:** если `sys` показывает 3.11, сначала исправить выбор интерпретатора в VS Code и снова проверить запуск. Возврат — 05–06; PATH/launcher не перенастраиваются.
5. **Диагностика на новом примере (02, 06 + планируемая B 11.2).** Вход: четыре подготовленных **текстовых фрагмента**, запуск реальной поломанной системы не нужен: команда PowerShell не найдена, Python не нашёл `.py`, traceback `NameError` в файле, терминальный `python` сообщает другую версию при фактически выбранном 3.12. **Сам:** для каждого назвать ответившую программу, первый проверяемый факт и единственное минимальное исправление/решение «ничего исправлять не надо». Затем без подсказки классифицировать изменённое имя `lesson12_chek.py` и новую строку ошибки в коде. **Наблюдение:** причины разделены по слоям, а смена версии только в терминале не записана как автоматическая поломка запуска. Возврат — 01–03, 05–06 и, для traceback, 11.2.

Между читаемыми абзацами располагать по смыслу схемы пути, предсказание вывода, сравнение приглашений и разбор ошибочного сообщения; максимум два подряд читаемых абзаца без содержательной вставки. Не размещать подряд декоративные схемы или карточки с повторяющимся ответом: каждая вставка требует нового решения или объяснения ученика.
