# 13.2. Название задачи и Git

> Внутренний план занятия. Согласован с теорией и практикой после методического ревью главы.

## Результат

Добавить normalize_title и понять независимость рабочего файла, index и commit на одном небольшом изменении.

## Опора до занятия

Strip, функции с return, собственный опубликованный проект, status, add, commit и push.

## Последовательность теории

1. Основной путь: функция, проверка, обычный diff, staged diff, поздняя правка, снятие staging без удаления текста и сохранение результата.
2. Определение функции и strip кратко восстанавливаются как знакомые средства.
3. Менторский путь вынесен в отдельный закрытый маршрут: подготовка develop до редактирования, публикация ветки и PR после проверки.
4. Самостоятельный режим не требует новой ветки, PR или ожидания ментора.

## Практика

- Общие пять задач: исходное состояние, функция, запуск и diff, сравнение версий, итоговый staging и публикация.
- До правки выбирается один режим. Самостоятельный критерий — проверенный commit в настроенной ветке; менторский — опубликованная develop и проверенный PR base main / compare develop.

## Приёмка и границы

Пустое, обычное и пробельное название; сохранение регистра и внутренних пробелов. Git-проверка различает рабочую и подготовленную версии без потери текста.

Подсказки служат восстановлению затруднившего шага и открываются после собственной попытки. В самостоятельных работах исходные данные и договор результата заданы явно; конкретный алгоритм и расположение состояний не подставляются в стартовый код. Новые конструкции языка вне указанной опоры не требуются.
