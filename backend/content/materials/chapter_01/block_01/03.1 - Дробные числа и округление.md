Сначала на делении восстановить знакомое `число / число → результат`, затем последовательно перейти к `float` → `round` → преобразованиям текста → отличию `int` → причинам ошибок. ## 01. Дробное значение и его тип

- **Зачем и первые слова:** `int` — тип целых значений (`4`), `float` — числовой тип, в котором возможна дробная часть (`4.5`), но и целое по величине число может иметь тип `float` (`4.0`). В записи Python десятичная часть отделена **точкой**, не запятой. Тип описывает, с каким видом значения работает программа; величина и её единица («метры», «час») задают смысл расчёта. `float` — число, не текст в кавычках.
- **Механизм на независимом сюжете:** отмерили `5` километров за `2` часа. После `distance_km = 5`, `hours = 2`, `speed = distance_km / hours` имя `speed` связано с `2.5` км/ч. Напомнить по шагам: справа от `=` вычисляется выражение, затем имя получает результат; `print(speed)` показывает `2.5`, а `print(type(speed))` — `<class 'float'>`. Объяснить запись вызова `type(значение)`: встроенная команда возвращает описание типа, `print(...)` показывает его; ученик не пишет собственную функцию.
- **Различающий случай:** `8 / 2` выводит `4.0`, и тип всё равно `float`, хотя делится без остатка; сравнить с целым литералом `4` и `type(4)` → `<class 'int'>`. В смешанном выражении `2 + 0.5` получается `2.5`: целое и дробное число допустимо складывать. Сначала предсказать **значение**, затем **тип** — это два самостоятельных ответа.
- **Граница точности:** некоторые дроби `float` хранятся приближённо: например, `print(0.1 + 0.2)` может показать `0.30000000000000004` в обычном Python. Это следствие представления числа в памяти, а не ошибка складывания и не правило «каждый float неверен». Здесь не объясняем двоичные разряды и не требуем точного сравнения дробей; для понятного результата понадобится округление.
- **Первое самостоятельное действие:** перед запуском предсказать число и тип для `9 / 2` и `8 / 2`, затем проверить их через `print` и `type`, сказать, в каком случае дробная **часть** исчезла, но тип остался. **Визуал MAIN:** пары «запись → значение → тип» для `4` / `4.0`; после схемы — прогноз без готовой карточки ответа. **Опора при возврате:** «есть кавычки? / или целый литерал? что показывает type?». Далее возникает практический вопрос: сколько знаков дроби оставить в ответе человеку.

## 02. Округление как числовая операция

- **Потребность → форма → результат:** измерение `3.276` метра неудобно сообщать с тремя знаками. Встроенный вызов `round(3.276, 2)` возвращает `3.28`: первое значение в скобках — **что** округляем, второе после запятой — **сколько цифр оставить после десятичной точки**. Вызов сначала вычисляет переданное выражение, затем отдаёт новое округлённое число; исходная переменная не меняется, если отдельно не присвоить ей результат. `print(round(...))` только показывает значение. Разобрать скобки и запятую до первой попытки с двумя аргументами.
- **Разные формы без скрытого синтаксиса:** `round(3.276, 1)` → `3.3`; `round(3.276, 2)` → `3.28`. С `float` и указанным вторым аргументом результат имеет тип `float` (`round(7.0, 2)` → `7.0`). Без второго аргумента `round(3.276)` → `3` типа `int`. Это отдельная форма вызова, **не требование** делать округление до целых в основной практике. Округление не превращает значение в строку с обязательными нулями: `round(7.0, 2)` выводится как `7.0`, а не `7.00`.
- **Округлять итог, а не промежуточную величину:** в независимом примере три равные доли одного литра: `round((1 / 3) * 3, 2)` → `1.0`, а `round(1 / 3, 2) * 3` → `0.99`. Сначала назвать последовательность действий («разделить, умножить, округлить» или «разделить, округлить, умножить»), затем предсказать разницу. Это простая демонстрация возможного накопления ошибки раннего округления, не универсальная формула для денег или физических измерений.
- **Первое самостоятельное действие:** для `7 / 6` предсказать округление результата до одного и двух знаков (`1.2` и `1.17`), проверить вывод, назвать единицу выбранной величины и объяснить, почему нельзя дописывать нули к *числовому* результату ради красивой строки. **MAIN:** схемой показать две очередности арифметики; затем дать интерактив на **предсказание различия**, а не второй вопрос «что делает round».
- **Опора и граница:** «что округляем → на каком этапе → сколько знаков → какое число получилось». Не включать `2.5` и другие ровно пограничные половины в обязательный контроль: у Python есть специальные правила таких случаев и нюансы `float`, но B требует понимания обычного округления. Дальше ученик встречает запись числа **в кавычках**: её сначала нужно преобразовать, чтобы вычислять.

## 03. Явное преобразование подходящих значений

- **Зачем:** `'8'` и `'8.25'` в кавычках — текст (`str`), даже если похожи на числа. Его нельзя автоматически считать числовой величиной. `int(значение)` создаёт целое число из подходящей записи; `float(значение)` создаёт дробное числовое значение. Встроенные имена и круглые скобки — тот же вид вызова, что и у `round`. `str(число)` действует в обратную сторону: создаёт **текст**, который удобно показывать, но из него нельзя напрямую складывать числа.
- **Независимый пример и порядок:** на условных ценниках из подготовленного текста `label_whole = '8'`, `label_fraction = '8.25'` сначала показать `type(label_fraction)` → `str`; затем `whole = int(label_whole)` → `8` типа `int`, `part = float(label_fraction)` → `8.25` типа `float`; лишь потом `print(part + 1)` → `9.25`. Ученику проговорить, что кавычки исчезли из типа результата и новое значение *создано* преобразованием; исходный текст сохранился в своём имени.
- **Различающие записи:** `float('8')` допустим → `8.0`; `int('8.25')` выдаёт `ValueError`, потому что `int` не разбирает десятичную **строку**. Выражение `int(float('8.25'))` допустимо → `8`, но удаляет дробную часть; назначение этого шага разберём в 04. `float('8,25')` не принимает десятичную запятую; исходные учебные записи использовать с точкой. `str(8.25)` даёт `'8.25'` типа `str` — это направление в текст.
- **Первое самостоятельное действие:** прогнозировать тип и результат `float('4.75') + 1` (`5.75`, `float`) и `int('4') + 1` (`5`, `int`), затем проверить в редакторе; отдельно выбрать, почему `'4.75'` не следует передавать прямо в `int`. **MAIN:** на схеме отделить три объекта «текст → команда преобразования → число», после — короткая **трассировка изменения типа**, а не повтор прогноза из 02.
- **Опора и переход:** «кавычки → исходный тип → допустима ли запись → вызываем `int`/`float` → тип нового значения → арифметика». Неподходящий текст требует исправления записи или корректного выбора преобразования, а не случайной подмены ожидаемого числа. Теперь надо разобраться, что именно случилось с дробной частью после `int(float(...))`.

## 04. Преобразование к int и округление — разные решения

- **Зачем различать:** `round` приближает число к выбранной разрядности; `int` создаёт целое число и **отбрасывает дробную часть по направлению к нулю**, даже если эта часть велика. Смысл вопроса определяет выбор: нужна приблизительная величина или намеренно отброшенные доли? Встроенные вызовы уже объяснены в 02 и 03.
- **Механизм через разные знаки:** `int(4.8)` → `4`, тогда как `round(4.8)` → `5`; `int(-4.8)` → `-4`, тогда как `round(-4.8)` → `-5`. На числовой прямой показать направление **к нулю** для `int`, и к ближайшему целому для этих примеров `round`; значения `4.8` и `-4.8` не являются спорными пограничными случаями. `round(4.8, 0)` → `5.0` типа `float`, если нужен именно вызов с числом знаков; `round(4.8)` → `5` типа `int`.
- **Не путать с прошлым уроком:** `//` при отрицательных числах округляет частное **вниз**, к меньшему числу, поэтому его правило отличается от отбрасывания дробной части в `int`. Понятие из урока 3 используется только для проверки одной ошибки; не повторять деление и остаток заново.
- **Первое самостоятельное действие:** для `2.9` и `-2.9` ученик до запуска выбирает `int` или `round`, предсказывает результаты, указывает различие типов у `round(2.9)` и `round(2.9, 0)`, затем проверяет. **MAIN:** визуал числовой прямой плюс **объяснение выбора операции** для нового отрицательного числа, чтобы не дублировать предсказание из 02.
- **Опора и переход:** «хочу отбросить часть → `int`» / «хочу ближайшее число или указанную точность → `round`». Когда вместо результата возникает ошибка, сначала определить, не передали ли неподходящий текст или не попытались ли вычислять со строкой.

## 05. Две причины ошибки: текст и несовместимые типы

- **Два разных вопроса при остановке:** `ValueError` при `float('два')` значит, что текст нельзя прочитать как ожидаемое число; `TypeError` при `'3.5' + 2.0` значит, что операция сложения получила здесь несовместимые типы `str` и `float`. Объяснить, что это имена *видов ошибки* из сообщения Python; появившаяся ошибка останавливает текущий скрипт, а исправление выполняется **в коде** перед новым запуском. Никакой обработки исключений пока не требуется.
- **Независимые фрагменты и исправления:** для `float('2,5')` причина — запятая вместо точки: исправленная запись `'2.5'` даёт `2.5`. Для `print('3.5' + 2.0)` причина — попытка сложить текст с числом: `print(float('3.5') + 2.0)` даёт `5.5`. Третий короткий контраст `int('3.5')` тоже `ValueError`, но теперь запись с точкой допустима как float, и ошибка в **выборе преобразования**, а не в отсутствии числа. Не сводить все ошибки к одному рецепту.
- **Первое самостоятельное действие:** без запуска сопоставить `float('нет')`, `int('6.7')`, `'6.7' + 1.0` с видом ошибки и причиной; затем в каждом случае назвать минимальную содержательную правку, которая сохраняет смысл «получить числовое значение для сложения». В MAIN после пары иллюстраций дать **диагностику по сообщению и типам**, а не ещё одну карточку на синтаксис `float`.
- **Опора для возврата:** «найди строку падения → проверь кавычки и требуемый тип → проверь, допускает ли текст нужную числовую запись → исправь источник или вызов → повтори запуск и проверь число и тип». Перед практикой связать путь целиком: вычислить `/` → округлить готовый ответ → преобразовать текст там, где это действительно нужно → отличить целое усечение от округления → устранить причину ошибки.

## 06. Что мы будем делать в практике

**Формат и договор:** четыре коротких независимых `script` в редакторе платформы: ученик вводит или дописывает код, запускает его и смотрит `stdout` (текст, который показывает `print`). Исходные числа и строки даём заранее: `input()` и проект не нужны. Для каждого шага предусмотрены исходный случай и маленькая проверка переноса; изменение входов не требует новых команд. Образцы в теории используют другие данные, поэтому готовое выражение из примера нельзя просто переписать как ответ.

1. **Скорость и момент округления (опора: 01–02).** **Вход:** `distance_km = 10` и `hours = 3`; `hours` положительно. **Объект:** скорость в км/ч — число после деления расстояния на время; для контроля можно также получить расстояние обратно, умножив скорость на время. **Стартовый код:** только эти два присваивания и указание вывести скорость и её тип, без выражения для B. **Самостоятельно:** написать деление, выбрать `round` до двух знаков **после полного вычисления скорости**, вывести округлённую скорость и её тип; отдельно сравнить возврат расстояния с округлением скорости до умножения и после умножения. **Локальная проверка:** `3.33` км/ч типа `float`; при возврате `3.33 * 3` выходит `9.99` км, тогда как округление `(10 / 3) * 3` в конце даёт `10.0` км. **Различающий случай:** заменить на `distance_km = 8`, `hours = 2` → скорость `4.0` типа `float`, несмотря на целую величину. Ученик объясняет, почему тип остался `float` и почему для контрольного расчёта нельзя заранее обрезать точность. Не требовать оформления единиц в строке программой: единицы заданы в условии.
2. **Сложить массы из двух текстовых записей (опора: 03 с возвратом к 01).** **Вход:** `base_kg = '4'` и `extra_kg = '2.75'` — подготовленные строки с массой в килограммах. **Объект:** суммарная масса как число, допускающее дробную часть. **Старт:** два исходных присваивания и места для вывода, без вызовов преобразования и суммы. **Самостоятельно:** установить исходный тип через `type`, выбрать преобразование для целой записи и для десятичной записи, сложить полученные **числа**, показать типы после преобразования и тип суммы. **Локальная проверка:** исходные значения — `str`; после преобразования соответственно `int` и `float`; итог `6.75` кг типа `float`. **Различающий случай:** заменить `extra_kg` на `'2'`, по-прежнему преобразовать его как десятичное числовое значение → итог `6.0` кг типа `float`; объяснить, почему `int('2.75')` непригоден и зачем при сумме нельзя оставлять кавычки. Числа и типы показываются обычным `print`, форматирование ещё не изучается.
3. **Выбрать отбрасывание или округление (опора: 04, использует 02–03).** **Вход:** сначала `amount = 2.9`, затем отдельным запуском `amount = -2.9`; это математическая величина без предметного ограничения вроде «числа коробок». **Объект:** два разных результата для одной величины — часть без дроби и ближайшее целое. **Старт:** только `amount` и требование вывести оба результата с типами; готовых вызовов нет. **Самостоятельно:** выбрать между `int` и `round` под каждую цель, записать оба вызова, перед запуском предсказать числа; дополнительно проверить форму `round(amount, 0)` и её тип. **Локальная проверка:** для `2.9` — `2` и `3`; для `-2.9` — `-2` и `-3` (все четыре результата имеют тип `int`); `round(-2.9, 0)` → `-3.0` типа `float`. **Различающий случай:** словами объяснить, почему `int(-2.9)` движется к нулю и почему известное `//` при отрицательном результате подчиняется другому правилу. Проверка оценивает обоснованный выбор операции, а не только цифру.
4. **Диагностика двух отдельных остановок (опора: 03 и 05).** **Вход:** первый скрипт состоит из двух строк: `weight = float('6,25')` и `print(weight)`; второй, отдельный, — из `total = '1.25' + 4.0` и `print(total)`. **Объект:** число, прочитанное из записи массы, и сумма чисел; запускать фрагменты отдельно, чтобы первая ошибка не скрывала вторую. **Старт:** эти ошибочные фрагменты без пояснений или готовых исправлений. **Самостоятельно:** предсказать вид ошибки каждого случая (`ValueError` или `TypeError`), прочитать сообщение после запуска, указать проблемную строку и причину; внести минимальное смысловое исправление и повторно запустить. **Локальная проверка:** оба скрипта завершаются без ошибки и показывают соответственно `6.25` и `5.25` типа `float`. **Различающие случаи:** текст `'6.250'` с точкой также преобразуется в число, а `'1.25' + 5.0` остаётся ошибкой типов, пока текст не превращён в число; ученик объясняет это до нового запуска. Не требовать `try/except` или намеренно угадывать иной вход вместо исправления источника ошибки.

**Итоговая B-проверка для MAIN:** без подсказки с выражением ученик на изменённых входах (1) получает дробную величину с понятной единицей, округляет **окончательный** ответ и называет числовой тип; (2) превращает подходящий числовой текст в значение и использует его в арифметике, объясняя различие `str`/`int`/`float`; (3) аргументирует выбор `round` либо `int` в том числе на отрицательном числе; (4) определяет и исправляет причины `ValueError` и `TypeError` в двух независимых случаях. Каждый пункт можно проверить сразу после соответствующего скрипта; ответы на новые данные требуют выбора действия самим учеником. В MAIN разрешены диагностические подсказки «посмотри кавычки / порядок вычислений / тип», но не готовая конструкция итогового выражения.

**Передача дальше:** отдельный проект и проверка старых проектных возможностей не требуются. В занятие 4 передаются проверенные числа и типы, готовые для объяснения текстового сообщения. Запись прежней f-строки в журнале относится к прежнему маршруту и не подтверждает её освоение учеником текущей главы; её новый механизм остаётся предметом следующего занятия.
