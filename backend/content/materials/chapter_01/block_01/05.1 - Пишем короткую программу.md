Показать знакомую ситуацию: в редакторе платформы есть несколько строк Python, которые при запуске выполняются по порядку сверху вниз; `print(...)` показывает результат. По отдельности ученик уже пробовал текст, числа и проверки; теперь соединяет их, чтобы получить понятный отчёт из данных задачи. Если фактическое прохождение прежних уроков не подтверждено, это проектный вход, а не утверждение об ученике.

1. **Точка старта:** умеем записывать значения в имена, вычислять выражения и показывать их с помощью `print` (планируемая B занятий 1–5).
2. **Новый вопрос:** как из обычного описания понять, какие данные нужны, что делать первым и как не потерять правильный тип или единицы?
3. **Результат:** самостоятельно написанный короткий `script` (несколько выполняемых сверху вниз строк кода), который печатает расчёт и два отдельных логических ответа.

Смысл связки: значения задаются в начале, промежуточные результаты создаются из них, а `print` лишь показывает уже вычисленное. В этом уроке выбор действия по условию пока не пишем: обе проверки всегда вычисляются и выводятся. **Первый прогноз:** до запуска двух знакомых строк присваивания и `print` ученик указывает, какое значение будет показано, затем сверяет с выводом. Для MAIN — короткая схема «исходные значения → новые значения → экран» с прогнозом между частями, не декоративная карточка.

## 01. Из описания — к данным, вычислениям и выводу

- **Понятие и зачем:** текст задачи — ещё не программа. Сначала разделяем его на «что уже дано», «что надо получить» и «какие шаги нужны между ними». В итоговой задаче дано название с пробелами по краям, число предметов как текст, длительность одного предмета как число, допустимое общее время в тех же единицах, дополнительное поле `None`. Никаких данных из `input()` не запрашиваем: они уже записаны в условии, а в коде появятся как присваивания.
- **Порядок:** 1) переписать данные вместе с их смыслом и единицами; 2) выписать ожидаемые выходы (чистое название, общее время, сообщение, два ответа `True`/`False`); 3) стрелками отметить зависимости: текстовое количество нужно превратить в число *до* умножения; расчёт должен появиться *до* сообщения и сравнения; отсутствие проверяется отдельно. Пропуск шага заметен до написания кода.
- **Независимый пример:** для вывески «`  Библиотека  `» задача просит убрать только пробелы вокруг названия и вывести текст. Дано значение `"  Библиотека  "` (`str`), ожидаемый выход — `"Библиотека"`; не следует угадывать количество книг или добавлять арифметику. **Наглядная опора 1:** три колонки «дано → сделать → показать»; колонки лишь помогают спланировать, Python не создаёт их автоматически.
- **Первая попытка:** дать мини-условие «`"  Кружок "` → название для бейджа без краевых пробелов». Ученик сам распределяет вход, нужное преобразование и видимый результат, затем сравнивает с коротким разбором; он ещё не обязан собирать весь скрипт. Типичная ошибка — считать вход и очищенный результат одной и той же строкой. Опора при возврате: «дано / требуется / зависит от». **Переход:** дальше закрепим, какими именами обозначить данные и когда нужен `int`.

## 02. Имена, типы и промежуточные результаты

- **Зачем имена:** имя — подпись для значения; полезно дать отдельное имя каждому новому результату. `title_text` и `title_clean` могут обозначать исходный текст и результат его очистки, а `count_text` и `count` — текст количества и целое число. Важно не название конкретного имени, а тип значения и то, что с ним делаем; `=` сохраняет новое значение справа под именем слева.
- **Как работают знакомые операции:** `"  Афиша  ".strip()` убирает пробелы **по краям**, возвращает новую строку и не изменяет прежний `str`; внутри текста пробелы остаются. `int("4")` получает целое `4` (`int`) из текста, содержащего корректную запись целого числа; `"4"` и `4` выглядят похоже, но имеют разные типы. `int("четыре")` не является допустимым преобразованием; в практике по условию дан корректный числовой текст, обработка ошибок не нужна.
- **Независимый разбор по строкам:** `label = "  Афиша  "` → `clean_label = label.strip()`; потом отдельно `visitors_text = "4"` → `visitors = int(visitors_text)`. Показать значения и типы **до/после** (строка осталась строкой, преобразованное количество стало числом); не соединять эти примеры в готовое решение будущего отчёта. **Наглядная опора 2:** рядом две пары «сырое → обработанное», с типами; это схема значений, а не обещание, что изменение одного имени автоматически исправляет другое.
- **Первая попытка:** на `label = "  Музей "`, `tickets_text = "7"` ученик записывает свои два присваивания с `.strip()` и `int`, до запуска предсказывает значения `"Музей"` и `7`, затем выводит их через `print`; отдельно объясняет, почему старое `label` осталось с пробелами. Опора: `.strip()` — новый `str`, `int(...)` — новое число из подходящего текста. Типичная ошибка — пытаться умножать число на исходный текст количества, рассчитывая получить числовой итог: строка при умножении на целое **повторяется**, а не превращается в нужное количество. **Переход:** только после преобразований задаём арифметическую формулу.

## 03. Расчёт и проверки без ветвления

- **Этап 1 — вычислить число:** единицы говорят, какое действие верно. Если есть `3` коробки и `5` карандашей в каждой, `3 * 5` даёт `15` **карандашей**, а не коробок. В будущем задании количество умножают на длительность одной единицы, чтобы получить общую длительность; бюджет должен быть в **тех же минутах**. Исходное число и результат — разные значения. **Первый прогноз:** ученик выбирает между `3 + 5` и `3 * 5` для независимого примера, объясняет единицы и проверяет результат. Типичная ошибка — сложить количество с длительностью или сравнить минуты с часами.
- **Этап 2 — сделать понятный вывод:** сначала сохранить расчёт в отдельном имени, затем собрать знакомую f-строку, например `pages = 8`, `message = f"Прочитано страниц: {pages}"`, `print(message)`. Фигурные скобки подставляют **значение** переменной, текст снаружи — подпись; без `f` скобки остались бы буквальным текстом. После объяснения ученик сам пишет сообщение про `books = 2` и предсказывает вывод «Книг: 2». `print` только показывает, а не вычисляет впрок; дальнейшие сравнения используют числовую переменную.
- **Показать сборку нескольких строк до полной задачи:** короткий **самостоятельный учебный образец другого сюжета** — `topic = "  Выставка  "` → `ready_topic = topic.strip()` → `message = f"Тема: {ready_topic}"` → `print(message)`. В MAIN расположить эти четыре команды одна под другой, по очереди проследить `"  Выставка  "` → `"Выставка"` → `"Тема: Выставка"` и только затем вывести сообщение. Попросить до запуска предсказать вывод после замены исходного названия на `" Парк "`. Это пример **сборки**, а не готовый отчёт со временем, бюджетом и `None`; арифметику и два флага ученик позднее добавит сам по смыслу отдельного условия.
- **Этап 3 — два независимых ответа:** `bool` — логический тип, который хранит результат вопроса `True` («да») или `False` («нет»). На отдельном примере `used_minutes = 8`, `limit_minutes = 8` выражение `used_minutes <= limit_minutes` отвечает «уложились **включительно** в лимит?» и даёт `True`. На `9` при том же лимите — `False`, на `7` — `True`. Выбор `<=` зависит от фразы «не больше», знак `<` ошибочно исключил бы равенство. Для другого независимого случая `comment = None`, `has_no_comment = comment is None` даёт `True`; если `comment = ""` или `comment = 0`, проверка даёт `False`. Оба результата — `bool`, проверка `None` не меняет значение и **не** включается в арифметику.
- **Первая самостоятельная попытка после объяснения:** ученик на знакомых числах `current = 10`, `max_allowed = 10` выбирает знак для «не превышает», до запуска объясняет граничный `True`; затем подставляет `11` и проверяет `False`. На отдельных значениях `extra = None`, `extra = ""` прогнозирует два результата `extra is None`. Сопоставить не только ответы, но и вопросы: предел чисел и отсутствие необязательного поля. Ошибки: перепутать `=` с `<=`, принять пустую строку за отсутствие или решить, что `True` запускает какое-то действие; ветвления пока нет.
- **Опора и переход:** последовательность для B — «сохранить число → составить f-строку → отдельно вычислить сравнение и `is None` → показать все результаты через `print`». Для MAIN — схема «ветки данных к двум булевым вопросам», в которой ветки обозначают **независимые вычисления**, а не конструкцию `if`; короткий прогноз на границе завершает схему. Теперь нужно научиться проверять такой код строка за строкой.

## 04. Проследить программу и исправить один дефект

- **Что значит проследить:** на каждой строке ответить «какое значение было», «каким стало новое значение и какого оно типа», «что напечатает `print`». Простая таблица с именами и значениями фиксирует ход сверху вниз: Python берёт значение имени **в момент выполнения** строки; запись нового значения сама по себе ничего не печатает.
- **Независимый разобранный дефект:** для сюжета про книги `books = 3`, `pages_per_book = 5`, `total_pages = books + pages_per_book`, `print(total_pages)` исходный код выводит `8`, хотя по смыслу нужно `15` страниц. Пройти значения `3`, `5`, `8`, обнаружить первое расхождение **на операции**, затем заменить сложение на умножение и проверить `15`. Не выдавать этот код как решение задания с длительностью и бюджетом; он показывает только способ локальной диагностики.
- **Типичная путаница и различающий случай:** не исправлять `print(total_pages)` на `print(15)` — тогда новые входы не изменят правильный ответ. Поменять количество книг с `3` на `4`: после правильного изменения операции выйдет `20`, после зашитого числа останется `15`. Вторая ошибка — исправлять последний вывод, когда неверное значение появилось раньше.
- **Первое действие:** на другом коротком фрагменте с уже знакомыми данными и одной неверной операцией ученик **до запуска** указывает первое расходящееся значение, предсказывает фактический вывод, меняет только проблемную строку и проверяет новый случай. Опора: таблица «строка → новое значение/тип → ожидаемый экран»; поддержка разбора снимается после одной демонстрации. **Переход:** исправленная программа ещё должна выдержать новые данные и точную границу.

## 05. Проверить перенос на изменённых данных

- **Зачем второй запуск:** число в тексте может случайно совпасть с правильным ответом на одном наборе. Проверка на изменённых входах показывает, откуда берётся результат. Менять только присваивания **исходных данных**, формулу и выбранный знак не подгонять под ответ.
- **Различающие случаи:** для `total = 12`, `limit = 12` ответ `total <= limit` — `True`; если `limit = 11`, ответ `False`, при `limit = 13` снова `True`. До запуска назвать ответ и почему граница включена. Для `note = None` `note is None` истинно; при `note = ""` ложно; пустой текст нельзя считать тем же, что отсутствие. **Наглядная опора:** три точки «ниже / ровно / выше» на числовой оси с одним знаком `<=`; порог показывает лишь сравнение чисел, не выбор дальнейшего действия.
- **Первая попытка:** ученик сам составляет мини-таблицу прогноза для другой пары целых чисел и трёх границ, затем проверяет её в редакторе. На отдельном знакомом фрагменте меняет `None` на обычный текст и объясняет, почему ответ изменился; не использует `if`. Если результаты расходятся, возвращается в раздел 03 (какой вопрос задаём) и 04 (где впервые стало неверно).
- **Опора для итоговой практики:** «данные и единицы → новые значения и типы → числовой расчёт → вывод и две независимые проверки → прогноз на границе». Переход к практике: ученик переносит эту цепь на **другой сюжет**, выбирает имена, операции и порядок сам. Подготовка проверки отсутствия зависит от подтверждения B занятия 5 перед фактической выдачей.

## 06. Что мы будем делать в практике

**Формат и исходная опора:** обязательная кодовая работа — короткие последовательные `script` в редакторе платформы, с записью кода и запуском. Ученик видит поле для кода, кнопку запуска и область вывода (занятие 1); стартовые значения берёт из текста задания. Для первого шага выдан маленький **свой** скрипт с одной ошибкой, для итогового — **только данные и требуемый вывод**, без готовой цепочки вычислений и конструкций. Самостоятельность предполагает планируемую B занятий 1–5 и её проверку перед выдачей; в частности, `is None` из занятия 5. Локальный проект, `input()`, файлы, ветвления и запоминание результата между запусками не нужны.

**Предметный договор итоговой работы:** небольшой отчёт о времени повторяющихся занятий. Условие даёт, например, название `"  Разминка  "`, число повторений текстом `"3"`, длительность одного повторения числом `20` **минут**, бюджет `60` **минут**, дополнительную заметку `None`. Это только входные значения, не готовый алгоритм. Ученик самостоятельно получает очищенное название, количество как `int`, общее время **в минутах**, отдельный логический ответ «уложились в бюджет?» (`<=`, граница входит) и другой ответ «заметка отсутствует?» (`is None`). **Наблюдаемый контракт вывода:** четыре смысловые строки в порядке: очищенное название; подписанный понятный f-строкой итог с числом минут; `True`/`False` для бюджета; `True`/`False` для отсутствия. Конкретные имена переменных свободны; текстовая подпись может быть собственной, если будущая проверка не требует фиксированный stdout. Для чисел выше предусмотрены итог `60`, флаги `True` и `True`; эти ожидаемые значения служат автору MAIN для проверки смысла, а не раскрываются заранее ученику как решение. Значение `None` не участвует в умножении.

1. **Найти и исправить локальную ошибку → чистое название действительно выведено.** *Вход/объект:* короткий отдельный `script` с текстом `"  Музыка "`, верно вычисленным очищенным названием и одной строкой вывода, которая ошибочно показывает исходную строку. *Опора:* 02 (`.strip()` возвращает новое значение), 04 (первая строка расхождения, прогноз). *Самостоятельно:* указать, почему видны пробелы, выбрать, что исправить, и изменить одну строку. *Локальный критерий:* после запуска печатается `"Музыка"` без краевых пробелов; после смены входа на `" Кино  "` печатается `"Кино"`. Это задание **не** из будущего итогового отчёта и не копирует разобранную ошибку с арифметическим знаком.
2. **Разложить новое условие → составить собственный порядок из зависимостей.** *Вход/объект:* только пять данных и четыре требуемые смысловые строки отчёта о времени из договора выше, пока без готового вычислительного кода. *Опора:* 01 (таблица «дано → сделать → показать») и 02–03 (тип и порядок). *Самостоятельно:* назвать исходные и производные значения, для каждого указать тип и единицы, порядок преобразования текста количества, вычисления общего времени, сборки сообщения и **двух независимых** проверок. *Локальный критерий:* полученная цепочка сначала создаёт нужные значения, затем использует их; число `"3"` остаётся исходным текстом, расчёт работает с числом `3`, значение `None` отделено от числовой ветки. Способ проверки — сверить собственную схему с зависимостями, не выдавая ещё код решения.
3. **Написать полный отчёт → увидеть четыре результата на исходных данных.** *Вход/объект:* чистый редактор и те же пять присваиваемых исходных значений из условия; промежуточные строки и имена создаёт ученик. *Опора:* 02 (очистка и `int`), 03 (умножение с единицами, f-строка, `<=`, `is None`) и 04 (пошаговая проверка). *Самостоятельно:* написать весь последовательный `script` с промежуточными значениями и четырьмя выводами; до запуска объяснить, что станет `str`, `int` и `bool`. *Локальный критерий:* название без краевых пробелов, итог в минутах совпадает с произведением, f-строка содержит **вычисленное**, а не зашитое число, оба флага показаны независимо и без `if`. Для приведённого входа расчёт `60` минут, оба флага истинны. Допустимые имена свободны; контракт строк фиксирует смысл и порядок, точную подпись будущий MAIN согласует с типом проверки.
4. **Перенести на новые данные → предсказать и проверить границу.** *Вход/объект:* собственный готовый скрипт из шага 3, меняются **только исходные данные**: другой текст названия, количество `"4"`, длительность `12` минут, лимит сначала `48`, потом `47` минут; заметка сначала `None`, затем `""`. *Опора:* 04–05 (трассировка и граничные случаи), 03 (`<=` и `is None`). *Самостоятельно:* до запуска предсказать новое очищенное название, число `48`, итоговый тип и два флага; запустить каждый изменённый случай и объяснить причину различий. *Локальный критерий:* при бюджете `48` сравнение истинно, при `47` ложно; при заметке `None` ответ об отсутствии истинный, при пустом тексте ложный. Формула не меняется, результат следует из входов, а не из вручную переписанного `print(48)`.

Первые действия дают диагностику одной ошибки и собственный **план** перед кодом; по этому плану ученик строит программу с минимальной подсказкой и затем доказывает, что она обрабатывает новые входы. Если ошибка обнаружена, вернуться ровно к объяснению 02, 03 или 04 и исправить исходную причину. Для MAIN список образует связанную группу «действие → наблюдение» с объяснением после неё; интерактивные прогнозы в 01, 03 и 05 должны проверять **разные** операции мысли (разметка условия, граничный выбор, перенос), а не три подряд одинаковых ответа.

**Итоговый критерий всей практики:** ученик самостоятельно пишет и объясняет короткий `script`, включая преобразование количества, арифметику с минутами, динамическое сообщение, включённую границу и явную проверку `None`; на новом наборе данных прогнозирует результат и объясняет, почему он меняется. Итог объединяет исправление ошибки, свой код и проверку границы; конструкций будущего занятия 6 не требуется.
