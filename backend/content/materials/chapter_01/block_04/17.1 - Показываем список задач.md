## 00. Вступление

Пользователь ввёл `add`, задача попала в `tasks`, но после `list` он не видит её карточку. Что должна сделать уже существующая функция `show_tasks`, если задач нет? А если их две? Начинаем с наблюдения двух состояний, затем меняем только показ.

1. **Точка старта:** `run` хранит один список `tasks`; `add` наполняет его, `list` вызывает `show_tasks(tasks)`.
2. **Новый вопрос:** как пройти по всем словарям и вывести готовые карточки, не меняя список и номера задач?
3. **Результат:** `list` объясняет пустоту или показывает каждую запись в исходном порядке.

Порядок понятен заранее: сначала решить пустой случай, затем разобрать один шаг цикла, после него соединить `format_task` с `print` и проверить источник `id`. В основной функции появится только чтение и вывод.

## 01. Одна функция — одна ответственность

- **Объяснение:** команда `list` уже есть в `run`, а `show_tasks(tasks)` уже получает список аргументом. Изменяем **одно существующее определение**; второе `def show_tasks` создало бы путаницу, какое определение действует. `add` меняет список, `show_tasks` только читает его и показывает результат.
- **Независимый пример:** «коробка с карточками»: передали пустую коробку — сообщаем, что показывать нечего; передали две карточки — читаем обе. Аналогия касается выбора поведения, но в Python решение определяют `len`, `for` и вызовы функций.
- **Прогноз ученика:** для `[]` и для списка с одной записью выбрать ветвь показа и назвать ожидаемое количество карточек; для непустого входа пока не показывать готовую реализацию.
- **Для MAIN:** схема `run → show_tasks(tasks) → экран` с вопросом «где находится общий список и кто его изменяет?». После схемы коротко связать её с конкретным местом в `main.py`.
- **Переход:** сначала разберём случай нулевой длины.

## 02. Пустой список и `return`

- **Объяснение механизма:** `for` по `[]` делает ноль проходов и сам по себе ничего не сообщает пользователю. Поэтому до цикла проверяем пустоту (`len(tasks) == 0`), печатаем понятное сообщение и выполняем `return`. Здесь `return` завершает **только вызов** `show_tasks`; управление возвращается в меню `run`. Он не завершает Python и не удаляет `tasks`.
- **Независимый контраст:** сравнить функцию, которая напечатала «Нет записей» и вернулась вызывающему коду, с командой `exit` пользовательского меню: в первом случае меню продолжает работать, во втором завершается `run`. Не представлять пустоту как исключение.
- **Прогноз и проверка:** до правки ученик предсказывает результат нулевого цикла, после добавления пустой ветви вызывает `list` при старте и вновь получает приглашение меню. Спросить: «Почему после сообщения не нужен поиск задачи или второй `print`?».
- **Для MAIN:** небольшая развилка «0 записей → сообщение → возврат в меню / есть записи → обход»; ученик указывает, какой путь выполняется. Далее объяснить, что непустая ветвь продолжает работу после условия.

## 03. Прямой `for`: очередной словарь, а не номер

- **Короткое повторение знакомого:** в независимом примере `labels = ["чай", "вода"]` и `for label in labels: print(label)` выводится сначала «чай», затем «вода». Переменная `label` принимает **значение элемента**, не его позицию. Для пустого `labels` тело ни разу не выполнится.
- **Перенос к задачам:** `tasks` — список словарей, поэтому `for task in tasks` в каждом проходе даёт **один словарь задачи целиком**. Для двух задач — два прохода в том же порядке; никаких копий, `enumerate`, второго цикла или сортировки.
- **Первая попытка:** на двух карточках с разными названиями ученик самостоятельно называет содержимое `task` в первом и втором проходах и прогнозирует число вызовов форматтера.
- **Для MAIN:** визуальная трасса из двух ячеек списка со стрелкой текущего элемента; попросить передвинуть стрелку ко второму элементу и назвать словарь. Затем перейти от словаря к строке карточки.

## 04. `format_task` возвращает, `print` показывает

- **Объяснение механизма:** готовый `format_task(task)` принимает **один словарь** и возвращает **одну строку карточки** с полями задачи. Сам по себе вызов не печатает её. `show_tasks` отвечает за цикл и вывод: на каждой итерации получает строку форматтера и передаёт её `print`. Знакомые `card = format_task(task)` и `print(card)` показывают две разные операции; можно обсудить эквивалентность `print(format_task(task))`, не раскрывая всю готовую `show_tasks`.
- **Конкретный случай:** при двух записях форматтер вызывается дважды, `print` показывает две полные карточки; одна карточка может занимать несколько строк — считать нужно **карточки/вызовы**, а не экранные строки. Статус и приоритет форматирует прежняя функция, их правила здесь не переписываются.
- **Прогноз и ошибка:** предложить варианты «только `format_task(task)`» и «`print(format_task(task))`»; ученик объясняет, в каком варианте карточка появится на экране и почему. При ошибке вернуться к разнице `return` и `print` из A.
- **Для MAIN:** цепочка с реальными подписями «словарь → строка → экран», где ученик выбирает недостающий шаг; после неё показать связь с телом существующего цикла.

## 05. `id` принадлежит записи; показ не меняет данные

- **Объяснение:** `id` — поле словаря, присвоенное при создании задачи. Место в `tasks` и значение `id` могут не совпадать. Прямой `for` сохраняет порядок **элементов списка**, а `format_task` читает `id` **из каждого элемента**. Ничего не нумеруем заново, не сортируем и не меняем `is_done`.
- **Различающий пример:** в специально переданном списке первая запись имеет `id=20`, вторая `id=3`. Следовательно, первой появляется карточка с номером 20, второй — с номером 3. Показ «1, 2» выдаёт позиции за номера; показ «3, 20» означал бы неразрешённую сортировку.
- **Самостоятельный перенос:** ученик предсказывает порядок для отдельной пары `id=8`, `id=2`, а затем объясняет, почему два вызова `list` подряд должны дать одинаковые карточки при отсутствии изменений через `add`.
- **Для MAIN:** сравнение двух колонок «позиция в списке / `task["id"]`» с указанием правильного источника числа. После этого — переход к самостоятельному изменению одной `show_tasks` в основном StudyHub. Не ставить рядом вторую карточку с тем же вопросом: достаточно одной трассы и отдельного переноса в практику.

## 06. Что мы будем делать в практике

**Формат и исходная опора:** работа в основном локальном StudyHub с ожидаемой B занятия 17: `run` содержит один `tasks`, команда `add` добавляет записи, `list` вызывает существующую минимальную `show_tasks(tasks)`, `format_task(task)` готов и возвращает строку. Это **планируемый checkpoint**: перед выдачей практики подтвердить его запуском, а при расхождении восстановить версию после 17. Опоры: `for` из занятия 9, словарь и formatter из 14, команды и список из 17; их фактическое освоение проверяется вопросами в точке A.

Мы самостоятельно расширим показ списка, проверим пустое и непустое состояние, затем убедимся, что чтение не ломает прежние команды и карточку.

1. **Проверить исходное состояние и исправить пустой путь.** В знакомом `run` подтвердить вызов `list`, действие `add` и временный вывод старой `show_tasks` (опора занятия 17 и блока 01). В **существующей** функции самостоятельно записать условие пустого списка, понятное сообщение и выход именно из `show_tasks` по механизму блока 02. В новом запуске `list` без `add` выдаёт **одно** сообщение о пустоте, затем меню снова принимает команду; в файле по-прежнему одно определение `show_tasks`.
2. **Самостоятельно написать непустой обход.** Опираясь на независимый пример `for` в блоке 03 и разделение `format_task`/`print` в блоке 04, ученик сам составляет цикл **внутри той же функции** и показывает возвращаемую formatter строку для каждого словаря. После первого `add` команда `list` показывает **одну** полную карточку; после второго — **две**, с названиями, приоритетами, состояниями и действительными `id` в порядке `tasks`. Если строка карточки многострочная, считать карточки, а не строки терминала. Запустить `list` ещё раз: значения и порядок совпадают без новых `add`.
3. **Проверить отличие `id` от позиции.** После выхода из `run` в уже знакомой интерактивной сессии создать готовой фабрикой две **временные** записи с `id=20` и `id=3`; передать их списком в `show_tasks` именно в этом порядке (блок 05). Ученик сам объясняет вывод: сначала карточка `20`, затем `3`. Вариант `1, 2` означал бы подмену `id` позициями, `3, 20` — лишнюю сортировку. Это различающий случай, недоступный при обычных последовательных `add`.
4. **Проверить чтение без изменения и прежние команды.** В той же интерактивной сессии через знакомый `print` сравнить **оба временных словаря и их порядок до и после** `show_tasks`: значения не изменились; повтор вывода из шага 2 служит дополнительным наблюдением, но сам по себе не доказывает отсутствие мутации. Отдельно вызвать готовый `format_task` для тестовых записей со статусами `False` и `True` (для второго случая поменять `is_done` лишь во временном словаре), проверить оба отображения, не добавляя `done` и не изменяя общий `tasks` из `run`. В основном `run` снова испытать `add`, неизвестную команду и `exit`: эти ветви продолжают работать (опоры 04–05 и прежняя B занятия 17).
5. **Проверить и сохранить свой результат.** Через знакомые `git status`/`git diff` увидеть изменение только существующей `show_tasks`, отсутствие второго `def` и изменений меню; по ранее изученному Git-маршруту сделать осмысленный commit/push. Практический результат — сохранённая версия с работающими пустым и непустым показом и сохранёнными прежними командами.

Каждый следующий шаг проверяет новую часть B: пустой запуск — ранний выход, одна и две задачи — самостоятельно написанный цикл и вывод каждой строки formatter, отдельная пара `20, 3` — порядок и подлинный `id`, сравнение данных до/после — отсутствие записи в список. При затруднении возвращаться к соответствующему блоку 01–05, не показывая готовую реализацию всей `show_tasks`. Если фактический вход не совпадает с B занятия 17, практику начинают только после восстановления правильного checkpoint, а не с поздней версии HEAD.

Итог B подтверждён, когда одна существующая функция показывает пустое состояние или все текущие задачи, корректно отображает каждую запись и не меняет общий список. Ранее работающие add, нормализация команды, неизвестная команда и выход продолжают работать. Поиск по id остаётся следующей темой.
