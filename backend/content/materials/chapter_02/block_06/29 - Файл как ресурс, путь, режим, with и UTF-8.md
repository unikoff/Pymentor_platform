## 01. Путь задаёт расположение, файл содержит данные

- **Что объяснить до опыта:** значение переменной живёт во время работы процесса, а записанный на диск файл может остаться после выхода. Папка содержит файлы и другие папки; путь указывает **где искать**, а содержимое — **что прочитать**. Создать строку с именем файла ещё не означает создать сам файл.
- **Механизм простыми шагами:** у абсолютного пути есть начальная точка в файловой системе; относительный адрес вроде `notes/today.txt` отсчитывается от **cwd** — текущей рабочей папки запущенного процесса. Место, где сохранён `lesson.py`, само по себе не меняет cwd. Смена cwd при том же относительном имени может выбрать другой файл.
- **Подача MAIN:** учебная схема из двух cwd и одной одинаковой относительной строки; ученик сначала указывает конечные адреса, затем схема раскрывает две разные папки. Это проверяет причинную связь, а не запоминание слова «относительный».
- **Независимый пример для разбора:** два запуска из папок `demo` и `demo/archive` обращаются к `notes/today.txt`. Перед открытием ученик показывает пальцем на две разные итоговые папки, объясняет, что строка пути одинакова, а адрес разный. Это пример **адресации**, без записи Planner и без необходимости знать `Path`.
- **Первое действие / локальный критерий:** по нарисованным двум деревьям папок определить, какой `today.txt` будет выбран; объяснить, почему файл, записанный на диск, не исчезнет вместе с переменной Python. Не путать «файл отсутствует» с «файл пуст».
- **Опора и переход:** сначала выясняем cwd, затем соединяем части адреса, затем проверяем, существует ли нужная папка. Следующий раздел вводит инструмент для этих действий.

## 02. Path строит адреса и помогает выбрать каталог

- **Зачем:** строковую склейку `"папка/" + имя` сложно читать и переносить между системами. `from pathlib import Path` даёт готовый инструмент стандартной библиотеки: `Path("drafts") / "idea.txt"` соединяет части **пути**, но файл от этого не появляется. `Path` — объект готовой библиотеки, писать собственный класс не требуется.
- **Порядок операций и незнакомый синтаксис:** `Path.cwd()` показывает текущую рабочую папку; `path.parent` даёт папку адреса `path`; `path.resolve()` показывает абсолютный адрес. В сохранённом модуле `__file__` — его путь, поэтому `Path(__file__).resolve().parent` позволяет строить адрес **от папки модуля**, независимо от cwd. В интерактивной консоли `__file__` обычно не определён: для первого опыта там достаточно `Path.cwd()`. `/` между объектом `Path` и строкой — операция соединения частей пути, а не деление чисел.
- **Папка раньше файла:** перед записью в выбранную учебную подпапку создают родительский каталог через `path.parent.mkdir(parents=True, exist_ok=True)`. Объяснить каждую часть: `parent` выбирает папку; `parents=True` разрешает создать промежуточные папки; `exist_ok=True` не считает ошибкой уже существующую папку. Это действие создаёт **каталог**, но не текстовый файл; путь `path` ещё нужно открыть для записи.
- **Независимый пример:** из `demo/lesson.py` получить адрес `demo/examples/draft.txt` двумя мысленными способами — от текущего cwd и от папки модуля. До сравнения вывести предполагаемые адреса; если cwd равен другой папке, относительная запись разойдётся с модульной. `resolve()` не проверяет, что файл существует или что разрешён доступ.
- **Первое действие / критерий:** ученик по двум значениям cwd объясняет, какой путь останется постоянным при запуске одного и того же сохранённого модуля из разных папок; после разбора предсказывает `parent` и указывает, что именно создаёт `mkdir`.
- **Граница с Planner:** позже один рабочий путь задаст `app.main` относительно корня проекта, передаст его хранению; `app.cli` не меняет cwd и не изобретает второй адрес. Правила поиска пакета при `python -m ...` — отдельная тема импорта, их нельзя приписывать `resolve()`.
- **Переход:** после выбора адреса и подготовки папки можно открыть реальный ресурс.

## 03. Открытый файл — ресурс с ограниченным временем жизни

- **Новая сущность:** `Path` хранит адрес; `path.open(...)` **пытается** получить файловый объект, через который выполняют `read()` или `write(...)`. Метод — доступная операция готового объекта; новый собственный класс здесь не появляется. `read()` возвращает обычную строку; `write(text)` принимает строку и возвращает число записанных символов, а не прочитанный текст.
- **Порядок на независимом примере:** для уже существующего `demo/examples/draft.txt` показать `with path.open("r", encoding="utf-8") as file:`, внутри `text = file.read()`, после блока `print(text)`. По отступу объяснить границу времени жизни: внутри `file.closed == False`; снаружи `file.closed == True`, а `text` всё ещё доступен. `encoding` назван как настройка преобразования текста; его смысл подробно в 05.
- **Почему нужен `with`:** файл — ограниченный системный ресурс. После **успешного открытия** блок `with` закроет его при обычном выходе и при исключении **внутри** блока; отдельный вызов `file.close()` в учебном пути не нужен. Если `open` не сработал, блок ещё не начался — `with` не превращает ошибку в пустой текст.
- **Подача MAIN:** пошаговая трассировка `open → read → выход из with` с двумя наблюдаемыми состояниями — `file.closed` и ранее прочитанной строкой. Спросить прогноз **перед выходом**, затем показать состояние после; второе такое же голосование не требуется.
- **Первое действие / критерий:** объяснить разницу между `text` и `file`, предсказать значения `file.closed` до и после выхода; проверить, что прочитанная строка доступна после закрытия. Ошибочная попытка чтения из уже закрытого `file` — повод вернуться к границе `with`, а не переоткрывать его случайно.
- **Ограничение:** `with` закрывает ресурс, но не делает запись атомарной и не восстанавливает стёртое содержимое при ошибке.
- **Переход:** способ открытия задаёт, можно ли читать, заменять или дописывать данные.

## 04. Режим r, w или a определяет действие

- **Различение по намерению:** `"r"` — читать **существующий** файл, не создавая его; `"w"` — создать или **сразу при открытии обнулить** прежний файл; `"a"` — создать при отсутствии или дописать **в конец** существующего. В `"w"` нельзя получить прежнее содержимое через `read()`; `"a"` сам не добавляет пробел или перевод строки.
- **Независимый мысленный опыт:** в `draft.txt` уже записано `старое`. Перед выполнением `with ...open("w")` спросить о состоянии файла **сразу после открытия, ещё до `write`** (он пуст), затем после `write("новое")` (только `новое`). При `"a"` и `write("!")` получится `старое!`, если исходно снова было `старое`. Начальное состояние для двух опытов указано явно, чтобы сравнение было честным.
- **Первое действие / критерий:** для трёх ситуаций ученик сам выбирает режим и обосновывает сохранность текста: прочитать известное, заменить черновик полностью, добавить короткую заметку. Различающий случай — открыть существующий файл через `"w"` и **ничего не записать**: объяснить, почему результат уже пустой.
- **Подача MAIN:** одно сравнение «старое содержимое → выбранный режим → итог» для `w` и `a` с предварительным прогнозом ученика; затем случай «открыли `w` без `write`» как проверка переноса, а не повторный вопрос о названии режима.
- **Опора:** `w = заменить содержимое`, `a = дополнить`, `r = получить существующее`. Будущий полный JSON-снимок нельзя «сохранить» посредством накопления нескольких полных документов через `a`. Нужные пользовательские данные не используем для экспериментов с `w`.
- **Переход:** режим решает судьбу прежних данных; кодировка решает, какие символы вернутся при чтении.

## 05. UTF-8 связывает символы и байты файла

- **Что происходит:** строка Python содержит символы, файл на диске хранит байты. При текстовой записи Python **кодирует** строку в байты, при чтении **декодирует** их в строку. Аргумент `encoding="utf-8"` в обоих `open(...)` задаёт одинаковое правило; его указывают явно, в том числе при работе с кириллицей.
- **Отдельный разбор до практики:** на коротком `draft.txt` показать путь одного символа «Я»: строка → запись UTF-8 → байты → чтение UTF-8 → та же строка. Не требовать знания числовых кодов байтов. Пояснить, что `print(text)` показывает уже декодированные символы и что перевод строки `"\n"` — самостоятельный символ строки, не автоматически добавляемый `write`.
- **Первое действие / критерий:** ученик предсказывает, что после записи и чтения текста «Ёж и чай» с одинаковой кодировкой получит точно ту же строку; указывает, что несовпадение кодировок способно дать неверные символы **или** `UnicodeDecodeError`. Ошибка пути и неправильный режим этим не исправляются.
- **Опора и переход:** `path` выбирает **где**, режим — **что делаем**, `encoding` — **как понимаем текст**. Дальше рассмотрим отказ, когда открыть ресурс не удалось.

## 06. Отсутствие файла и отказ доступа — разные ситуации

- **Разделить три состояния:** существующий пустой файл читается через `"r"` как пустая строка `""`; отсутствующий файл при `"r"` даёт `FileNotFoundError`; существующий файл без разрешения на операцию может дать `PermissionError`. Два последних случая — отказ открыть ресурс, а не содержимое файла. Доступ зависит от ОС и разрешений, поэтому не требовать специально ломать права на учебной машине.
- **Порядок объяснения:** определить путь → попытаться открыть → только при успехе войти в `with` → прочитать. Показать на небольшом сценарии чтения имени `missing.txt`, что ошибка возникает **до** чтения строки. Если ошибка внутри уже открытого `with`, ресурс закроется при выходе; это отдельная ситуация.
- **Первое действие / критерий:** по трём наблюдениям (`""`, `FileNotFoundError`, `PermissionError`) ученик объясняет, был ли файл открыт, и почему нельзя возвращать `""` для любой ошибки. Обработку ошибки доступа он здесь только **объясняет**; реализация `StorageError` и политика первого запуска Planner принадлежат занятию 30.2.
- **Переход:** все части будущего опыта известны: безопасный адрес, открытие, режим, кодировка и проверка результата.

## 07. Что мы будем делать в практике

**Формат:** И — исследование в редакторе/интерпретаторе; для сравнения с `__file__` нужен **сохранённый** маленький учебный модуль, для первых проб достаточно интерпретатора. Исходная опора — строки, импорт, `print` (A) и объяснения 01–06. Технически предоставляются только инструкция выбрать безопасную учебную папку и исходные строки, **не готовая программа с выполненным опытом**. Никакого `data/tasks.json`, рабочего файла Planner, `save_titles` или второго приложения.

**Цель и маршрут самостоятельных действий (вход → объект → опора → своё действие → немедленный результат):**

1. **Назвать безопасный адрес и подготовить папку.** Вход: сохранённый учебный модуль в известной папке; объекта с данными ещё нет. Опора: 01–02 (`cwd`, `Path`, `parent`, `mkdir`). Ученик сам задаёт отдельную подпапку `pymentor_file_lab` **рядом с этим модулем**, формирует адрес `note.txt`, сначала предсказывает и затем выводит его абсолютное расположение, создаёт только учебный каталог. **Проверка:** папка существует там, где предсказано; сам `note.txt` ещё не создан. Различение: создание каталога не означает создание файла.
2. **Записать и прочитать кириллицу.** Вход: пустая учебная папка и выбранный `note.txt`; объект — этот файл и полученная строка. Опора: 03–05 (ресурс, `with`, `"w"`/`"r"`, UTF-8). Ученик **сам** пишет два отдельных блока `with` для записи выбранной короткой русской строки и последующего чтения, сохраняет результат в переменную и выводит её после закрытия. **Проверка:** строка совпадает с записанной посимвольно, `file.closed` после блока истинен, полученная строка доступна. Различение: `read()` возвращает текст, файловый объект после выхода нельзя использовать для новых операций.
3. **Выбрать между заменой и добавлением.** Вход: `note.txt` уже содержит текст из шага 2; объект — его содержимое после каждой операции. Опора: 04. Ученик до запуска записывает два **разных** прогноза, затем открывает **только учебный файл** в `"w"` для другой строки, читает результат; отдельно открывает его в `"a"` и добавляет короткий фрагмент с осознанно выбранным разделителем, снова читает. **Проверка:** после `w` старого текста нет, после `a` новое не исчезает, а присоединяется в точном порядке. Различение: повторный `w` не накопит две записи; без `"\n"` перенос строки не возникнет сам.
4. **Сравнить два источника адреса при разных cwd.** Вход: тот же сохранённый модуль, две существующие рабочие папки; объект — **вычисленные адреса**, без записи в них. Опора: 01–02. Ученик из двух cwd запускает **тот же модуль по заранее известному пути**, сравнивает вывод `Path.cwd() / "pymentor_file_lab" / "note.txt"` и пути от `Path(__file__).resolve().parent`, объясняет расхождение/совпадение. **Проверка:** адрес относительно cwd меняется с cwd, модульный путь остаётся прежним; учебный `note.txt` в модульной папке не повреждён. Не обещать, что `python -m app.main` работает из произвольной cwd: поиск пакета объясняется отдельно.
5. **Различить отсутствие и ограничение доступа.** Вход: заведомо не созданный `missing.txt` в учебной папке и известный `note.txt`; объект — результат попытки открыть выбранный адрес. Опора: 03 и 06. Ученик сначала прогнозирует, потом пробует открыть `missing.txt` с `"r"` и называет `FileNotFoundError`; объясняет по предложенному случаю с запрещённым доступом `PermissionError`, **не меняя права файлов**. **Проверка:** отличает отказ открытия от пустой строки существующего пустого файла; не объявляет `with` обработчиком ошибки, не подменяет все сбои пустым результатом. Повторное чтение `note.txt` подтверждает, что основной учебный файл цел.

После каждого шага учащийся формулирует **почему** наблюдается результат, сверяясь с соответствующим разделом. Суммарная B достигнута, когда он может найти путь независимо от cwd, записать/прочитать кириллицу, объяснить влияние `w/a/r`, закрытие и тип отказа **по собственному наблюдению**. Дополнительный перенос (не условие перехода): предсказать судьбу файла, если открыть его через `"w"` и выйти из `with` без `write`.
