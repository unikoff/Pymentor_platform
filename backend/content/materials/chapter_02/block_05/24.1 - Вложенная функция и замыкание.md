## 00. Вступление

В предыдущем занятии мы передавали готовые функции как значения: таблица команд хранит обработчики, а `run` вызывает выбранный обработчик после выбора команды. Теперь разберём более тонкий вариант: можно ли вернуть функцию, которая позже использует настройку, заданную раньше?

1. **Точка старта:** в занятии 24 запланировано научиться сохранять callback без скобок; перед использованием этого навыка подтвердим выполненную таблицу и поздний вызов в Planner.
2. **Новый вопрос:** как вернуть функцию, которая после завершения внешнего вызова всё ещё обращается к его настройке?
3. **Результат:** мы разберём вложенное определение и замыкание, а затем сравним два callback с разными настройками.

Для примеров возьмём форматирование коротких сообщений. Префикс зададим один раз при настройке, а текст сообщения будем передавать при каждом вызове. Этот путь подготавливает нас к следующему занятию, где внешняя функция настроит диагностическую обёртку. Сам Planner сейчас менять не требуется.

## 01. Внешняя функция создаёт внутреннюю

Функцию можно определить внутри другой функции. Внешняя функция задаёт контекст или настройку, а вложенная описывает действие, которому эта настройка понадобится позднее. Вложенное определение не запускает тело внутренней функции: оно создаёт функцию, доступную в оставшейся части внешнего вызова.

```python
def outer():
    def inner():
        return "готово"
    return inner

saved = outer()       # функция создана и возвращена, но "готово" ещё не получено
print(saved())        # готово
print(saved())        # готово: внутреннюю функцию можно вызвать снова
```

Прочитаем код по порядку: (1) определение `outer` только сообщает Python, что делать при вызове; (2) `outer()` создаёт `inner` и возвращает **саму функцию** в `saved`; (3) лишь `saved()` выполняет тело `inner` и получает строку `"готово"`. Поэтому на экран выводятся две одинаковые строки, а при `saved = outer()` ничего не печатается. Отступ показывает, что `inner` определена внутри `outer`. Здесь ещё нет сохранённой настройки: пока мы изучаем создание и отдельный вызов.

Имя `inner` объявлено внутри `outer`, а не на уровне всего файла. Снаружи мы получим его, только если вернём функцию или передадим её кому-то ещё. Поэтому вложенное определение само по себе не добавляет новый обработчик в таблицу команд и не меняет интерфейс Planner. Мы используем его там, где полезно собрать действие для отдельного будущего вызова.

**Первая попытка:** до запуска зачеркнуть два `print(saved())` и предсказать, будет ли вообще вывод; затем вернуть их и проверить. Изменить в `inner` строку на `"начато"`, **заново выполнить определение `outer` и строку `saved = outer()`**, вызвать `saved()`. Это проверяет, что мы получаем результат при вызове внутренней функции, а не при создании внешней.

## 02. Возвращаем функцию, а не её результат

У имени функции и у вызова функции разная роль. Имя вложенной функции обозначает саму функцию. Например, запись `greet("Анна")` запускает её тело и даёт результат в виде строки. Скобки после имени важны: они означают вызов.

Фабрикой здесь называют функцию, которая создаёт и возвращает другое значение, например настроенную функцию. Это описательное название, а не отдельный синтаксис Python. После определения фабрики можно сравнить возврат функции с немедленным вызовом возвращённой функции.

Сравним `return greet` и `return greet("Анна")` внутри фабрики приветствий. В первом случае наружу выходит функция. Во втором Python сразу вызывает `greet`, возвращает готовую строку и завершает фабрику. Если сохранить результат второго варианта в `saved`, а затем написать `saved("Ещё сообщение")`, возникнет `TypeError`: в `saved` лежит строка, а не функция. Это разные моменты вызова и разные типы результата.

Перед тем как двигаться дальше, проследим этот простой пример.

```python
def make_greeting(prefix):
    def greet(name):
        return f"{prefix}, {name}!"
    return greet

morning = make_greeting("Доброе утро")
print(morning("Анна"))  # Доброе утро, Анна!
print(morning("Игорь")) # Доброе утро, Игорь!
```

При `make_greeting("Доброе утро")` параметр `prefix` получает настройку, а `return greet` отдаёт функцию в `morning`. Позже `morning("Анна")` передаёт аргумент параметру `name` и возвращает строку. `morning("Игорь")` использует прежний `prefix` с новым именем. Здесь **два этапа**: сначала создаём функцию, затем вызываем её сколько потребуется; запись из нескольких пар скобок подряд пока не нужна.

**Различающий опыт:** временно заменить только `return greet` на `return greet("Анна")`, заново определить `make_greeting` и выполнить `saved = make_greeting("Привет")`. Вызов `saved("Игорь")` теперь выдаст `TypeError`, потому что `saved` содержит `"Привет, Анна!"`. Вернуть `return greet`, заново определить фабрику и убедиться, что тот же поздний вызов работает. Не заменять возврат на `return greet(name)`: в момент работы фабрики её параметра `name` ещё нет.

Не перепутаем и `return` с печатью. `return` отдаёт значение вызывающему коду, который может сохранить его в переменную. `print` только показывает представление значения на экране; сам по себе он не передаёт вызывающему коду возвращённую функцию. Если фабрика напечатает внутреннюю функцию, но не вернёт её, присваивание результата вызова фабрики получит `None`. Тогда поздний вызов тоже не сработает, хотя имя вложенной функции было определено правильно.

## 03. Замыкание сохраняет доступ к внешнему имени

Внутренняя функция может использовать имя из внешней функции даже после того, как внешний вызов завершился. Для такого случая мы используем термин **замыкание**: внутренняя функция вместе с доступом к нужным именам окружающей области. Функция не обязана копировать все внешние переменные и объекты. Она сохраняет возможность разрешить имена, которые использует.

Вернёмся к `make_greeting`. В момент `make_greeting("Доброе утро")` появляется внешний параметр `prefix`; в момент `morning("Анна")` появляется параметр внутренней функции `name`. Хотя первый вызов уже закончился, `greet` всё ещё может использовать `prefix` из **своего** внешнего вызова. Это и есть новая часть по сравнению с `outer/inner` из раздела 01.

Самостоятельно отметим источники имён прямо в коде: `prefix` берётся из внешнего вызова `make_greeting(...)`, а `name` — из текущего `morning(...)`. Для этого `greet` не нужен глобальный префикс: у возвращённой функции есть доступ к собственной внешней привязке. Если бы `greet` не использовала `prefix`, одной вложенности было бы недостаточно, чтобы назвать её замыканием над `prefix`.

**Проверка понимания:** ещё до запуска `morning("Оля")` назовите значения `prefix` и `name` и предскажите строку; затем выполните вызов. Если ответ неверен, найдите в коде **два разных вызова**, которыми эти параметры были получены. Чередование **двух** настроенных функций проверим уже в разделе 04, на другом наборе данных.

## 04. Вызовы фабрики создают отдельные настройки

Каждый вызов фабрики создаёт собственный контекст для своей настройки. Поэтому две возвращённые функции могут выполнять одинаковый алгоритм, но использовать разные значения внешнего параметра. Покажем механизм на другом сюжете, прежде чем самостоятельно писать текстовый форматтер.

```python
def make_multiplier(factor):
    def multiply(number):
        return factor * number
    return multiply

double = make_multiplier(2)
triple = make_multiplier(3)

print(double(4))
print(triple(4))
print(double(5))
```

Вызов `make_multiplier(2)` создаёт одну настроенную функцию, а вызов `make_multiplier(3)` — другую. Внутри первой доступно имя `factor` со значением первой настройки, во второй — со значением второй. При чередовании получится `8`, `12`, `10`: выбор второй функции не перенастроит первую. Число каждый раз приходит через `number`; оно не заменяет множитель. Этот **числовой** пример независим от предстоящего самостоятельного форматтера `make_labeler(prefix)`.

Сравним не только ответы, но и причину: `double` и `triple` используют **одно тело** `multiply`, однако были созданы **двумя вызовами** `make_multiplier`. Поэтому они сохранили доступ к разным привязкам `factor`; вызов `triple(4)` не меняет настройку `double`. Аналогия — два одинаковых калькулятора с разными установленными множителями, но Python не запускает отдельные процессы для этих функций.

В числовом примере `factor` задаётся **один раз при создании**, `number` передаётся **при каждом вызове**. В самостоятельном текстовом форматтере такую же пару составят `prefix` и `message`. Замыкание хранит доступ к настройке, а не готовые ответы: результат заново вычисляется для каждого нового аргумента.

**Первая попытка:** самостоятельно добавить `quadruple = make_multiplier(4)`, предсказать результаты `double(7)`, `quadruple(7)`, `double(2)` и проверить порядок. Критерий: первый callback сохранил множитель `2`, новый получил `4`. Если ответы смешались, найти, в каком вызове создавался каждый callback, и повторить с числами `3` и `6`.

## 05. Замыкание не означает копирование общего списка

Сохранить доступ к внешнему имени — **не значит создать копию объекта**. Например, две функции могут читать и изменять один список, если при создании каждой передали именно этот список. Для понимания достаточно уже знакомых ссылок и `append`; способы копирования изучать здесь не нужно.

```python
def make_appender(items):
    def add(value):
        items.append(value)
        return items
    return add

shared = []
first_add = make_appender(shared)
second_add = make_appender(shared)

print(first_add("глава 5"))
print(second_add("глава 6"))
```

Оба вызова `make_appender(shared)` создали разные функции, но **аргумент был одним и тем же объектом**. Параметр `items` обеих функций ссылается на `shared`. Первая печать покажет `['глава 5']`, вторая — `['глава 5', 'глава 6']`: каждый `append` изменяет общий список на месте. В практике мы напишем **другую** функцию `make_reader`, которая будет только читать список после изменений снаружи.

Эта граница похожа на две закладки, ведущие к одной общей записной книжке. Закладки отдельные, но запись в книжку видна с обеих. Соответствие: функции имеют отдельные окружения, а `items` в обоих окружениях указывает на переданный `shared`. Граница аналогии: важны реальные ссылки на объекты, а не сами «закладки».

Если создать `left = []` и `right = []` и передать их разным функциям, изменение `left` не появится в `right`. Два вывода `[]` до изменений не доказывают независимость: доказательством будет добавление элемента только в один список и сравнение результатов. Замыкание само по себе ничего не копирует.

**Первая попытка:** перед `first_add("глава 7")` предсказать, что изменится в `shared`, выполнить вызов и проверить; затем создать `other = []` и **самостоятельно** настроить callback для него. После добавления в `other` вывести `shared` и `other`. Критерий: новый callback изменил только свой отдельный список; два старых по-прежнему ссылаются на общий.

## 06. Callback и замыкание отвечают на разные вопросы

Слово **callback** описывает роль функции: одна часть программы передала её другой части, чтобы та вызвала функцию в подходящий момент. Слово **замыкание** описывает свойство функции: она использует имя из внешней области, сохранившейся для позднего вызова. Поэтому функция может быть и callback, и замыканием одновременно, но callback не обязательно является замыканием.

Посмотрим на получателя функции, используя уже созданную в разделе **04** `double`:

```python
def apply_once(callback, number):
    return callback(number)

print(apply_once(double, 3))  # 6
```

При создании `double = make_multiplier(2)` внешний параметр `factor` получил значение `2`. Позднее `apply_once` получает саму функцию `double`, а не результат `double(3)`, и вызывает её с числом `3` ровно один раз. Здесь `double` — **callback по роли у `apply_once`** и **замыкание по доступу к `factor`**. Обычную функцию без внешней настройки тоже можно передать получателю: роль callback сама по себе не доказывает наличия замыкания.

В следующем занятии этот механизм подготовит диагностическую обёртку: внешняя функция получит исходную операцию и настройки, а возвращённая внутренняя функция вызовется позже. Пока мы не переходим к передаче произвольных аргументов, `nonlocal`, декораторам или перехвату ошибок. Сначала важно уверенно различать создание функции, её возврат и поздний вызов.

**Контроль перед практикой:** до запуска самостоятельно предсказать результаты `apply_once(double, 5)` и `apply_once(triple, 5)`, заменить один callback другим в вызове получателя и сверить `10` и `15`. Указать отдельно, **кто вызывает функцию**, **откуда пришёл `factor`** и **откуда пришёл `number`**. Если результат перепутан, вернуться к примеру из раздела **04** и строке `callback(number)` здесь: значение `5` не перенастраивает множитель.

## 07. Что мы будем делать в практике

**Обязательный формат:** самостоятельное исследование и запись Python-кода **в интерпретаторе**, без изменений `main.py` Planner. Для ученика нужны консоль Python, известные `def`, параметры, `return`, присваивание, списки и `append`. Прежде чем выдать практику, проверить подтверждение A из раздела «Точка A», особенно завершённую таблицу callback занятия 24; если предыдущая B ещё не достигнута, сначала закончить её. Заданный в теории числовой `make_multiplier` остаётся **учебным примером**, а решение текстовой фабрики ученик записывает самостоятельно.

1. **Разберём вложенный `def` и время выполнения → отличим функцию от значения.**
   - **Вход и объект:** работающий `outer/inner` раздела **01** и консоль; `saved = outer()` и `saved()` уже разобраны, а код будущего `make_labeler` не выдан.
   - **Опора:** разделы **01–02** с отступом у вложенного `def`, поздним вызовом и различием `return inner` / `return inner(...)`.
   - **Самостоятельно:** с нуля написать свою маленькую пару внешней и вложенной функций с другой возвращаемой строкой, сохранить возвращённую функцию, вызвать её дважды и сверить прогноз. Затем изменить `return inner` на `return inner()` и заново создать `saved`, прежде чем пробовать `saved()`.
   - **Наблюдение:** в первом варианте `saved` — вызываемая функция, во втором — готовая строка и `saved()` вызывает `TypeError`. **Различающий случай:** заменить `return inner` на `print(inner)` без последующего `return` — на экране виден объект функции, но в `saved` окажется `None`. Если прогноз не совпал, проверить в разделе **02**, что именно возвращается из внешней функции.
2. **Самостоятельно построим `make_labeler(prefix)` → получим настраиваемый callback.**
   - **Вход и объект:** пустая консоль/редактор интерпретатора; контракт: внешняя функция получает `prefix`, вложенная `label(message)` возвращает строку вида `"{prefix}: {message}"`, внешняя **возвращает функцию без вызова**. Готового тела целевой функции в starter нет.
   - **Опора:** разделы **01–03** о параметре внешнего вызова, областях видимости, отступах, `return` и позднем вызове; независимый `make_greeting`.
   - **Самостоятельно:** определить обе функции с нужными параметрами, вернуть вложенную, получить один настроенный callback и использовать его для **двух разных** сообщений.
   - **Наблюдение:** один префикс повторяется, сообщения различаются, настройка передана только в момент создания. **Различающий случай:** `return label("тест")` создаёт сразу строку (и последующий вызов этой строки даст `TypeError`); `return label(message)` внутри фабрики обращается к ещё не заданному там `message` и даёт `NameError`. Исправить возврат на `return label`, проверить на третьем сообщении.
3. **Настроим два независимых callback → чередование не смешивает префиксы.**
   - **Вход и объект:** самостоятельно написанная фабрика шага 2, имена `notice` и `question`, настройки `Важно` и `Вопрос`, два разных сообщения.
   - **Опора:** раздел **04**, отдельные окружения фабрики и числовой независимый пример с множителями.
   - **Самостоятельно:** создать две функции и написать своего простого получателя `deliver(callback, message)`, который **один раз вызывает** переданную функцию с `message` и возвращает её результат (аналог `apply_once` из **06**, без готового тела `deliver`). Через `deliver` передать `notice` с первым сообщением, `question` со вторым и снова `notice` со вторым; заранее записать прогноз всех трёх строк. Сравнить один вызов через `deliver` с прямым вызовом того же `notice`.
   - **Наблюдение:** ожидаемый порядок `Важно: <первое>`, `Вопрос: <второе>`, `Важно: <второе>`; прямой вызов и вызов через получателя возвращают одинаковую строку. **Различающий случай:** повторная передача `notice` после `question` не наследует префикс `Вопрос`, а `deliver` сам не содержит ни одного из префиксов. Проверить альтернативный порядок на третьей фразе; если смешались, вернуться в **03–04**, если результат оказался `None`, проверить `return` получателя по **06**.
4. **Проверим границу замыкания на списке → отличим окружение функции от копии объекта.**
   - **Вход и объект:** чистая консоль и `shared = []`; самостоятельно создаваемый `make_reader(items)` на основе механизма `make_appender` из раздела **05**; изменения Project Planner не допускаются.
   - **Опора:** раздел **05**, доступ к `items` и возврат того же списка через вложенную функцию, планируемая B **22/22.1** с условием проверки в точке A.

После этого создать два **разных** списка и по одному reader для каждого; добавить новое значение только в первый список и заранее предсказать результаты обоих reader.
   - **Наблюдение:** оба reader общего контейнера видят изменение; при разных контейнерах значение видно только первому reader. **Различающий случай:** два пустых списка сначала могут выглядеть одинаково при печати, поэтому их независимость доказывает именно изменение одного из них, а не начальный вывод `[]`. Повторить общий случай после второго `append` и объяснить, какая ссылка остаётся общей.
5. **Проверим учебный кодовый контракт → наблюдаемая B при выдаче автозадания.**
