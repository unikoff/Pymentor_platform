## 00. Вступление

В предыдущем занятии мы передавали готовые функции как значения: таблица команд хранит обработчики, а `run` вызывает выбранный обработчик после выбора команды. Теперь разберём более тонкий вариант: можно ли вернуть функцию, которая позже использует настройку, заданную раньше?

1. **Точка старта:** в занятии 24 запланировано научиться сохранять callback без скобок; перед использованием этого навыка подтвердим выполненную таблицу и поздний вызов в Planner.
2. **Новый вопрос:** как вернуть функцию, которая после завершения внешнего вызова всё ещё обращается к его настройке?
3. **Результат:** мы разберём вложенное определение и замыкание, а затем сравним два callback с разными настройками.

Для примеров возьмём форматирование коротких сообщений. Префикс зададим один раз при настройке, а текст сообщения будем передавать при каждом вызове. Этот путь подготавливает нас к следующему занятию, где внешняя функция настроит диагностическую обёртку. Сам Planner сейчас менять не требуется.

## 01. Внешняя функция создаёт внутреннюю

Функцию можно определить внутри другой функции. Внешняя функция задаёт контекст или настройку, а вложенная описывает действие, которому эта настройка понадобится позднее. Вложенное определение не запускает тело внутренней функции: оно создаёт функцию, доступную в оставшейся части внешнего вызова.

```python
def outer():
    def inner():
        return "готово"
    return inner
```

Когда мы вызываем `outer()`, Python доходит до `def inner` и создаёт внутреннюю функцию. Её тело пока не выполняется: строка `"готово"` будет получена лишь при позднем вызове возвращённой функции. Здесь ещё нет внешней настройки: этот независимый пример показывает только вложенность, отступы и момент создания. Дальше добавим параметр внешней функции, который пригодится внутренней.

Имя `inner` объявлено внутри `outer`, а не на уровне всего файла. Снаружи мы получим его, только если вернём функцию или передадим её кому-то ещё. Поэтому вложенное определение само по себе не добавляет новый обработчик в таблицу команд и не меняет интерфейс Planner. Мы используем его там, где полезно собрать действие для отдельного будущего вызова.

Здесь полезна аналогия с мастерской печатей: вложенный `def` похож на изготовление инструмента, а отдельный вызов вернувшейся функции — на использование изготовленного инструмента. В следующих примерах мы сможем добавить на инструмент настройку. Граница аналогии: функция — выполняемый код, а создание инструмента не запускает его работу.

**Первая попытка:** взять `outer`, самостоятельно присвоить результат её вызова имени `saved`, предсказать, в какой момент появится строка `"готово"`, затем вызвать `saved()` и сверить. Изменить возвращаемую строку на `"начато"` и повторить; если `saved` оказался `None`, сверить отступы и `return inner`, затем воспроизвести случай с другим текстом.

## 02. Возвращаем функцию, а не её результат

У имени функции и у вызова функции разная роль. Имя вложенной функции обозначает саму функцию. Например, запись `greet("Анна")` запускает её тело и даёт результат в виде строки. Скобки после имени важны: они означают вызов.

Фабрикой здесь называют функцию, которая создаёт и возвращает другое значение, например настроенную функцию. Это описательное название, а не отдельный синтаксис Python. После определения фабрики можно сравнить возврат функции с немедленным вызовом возвращённой функции.

Сравним `return greet` и `return greet("Анна")` внутри фабрики приветствий. В первом случае наружу выходит функция. Во втором Python немедленно вызывает `greet`, получает строку и возвращает строку. Если затем написать `saved("Ещё сообщение")`, но в `saved` лежит строка, возникнет ошибка: строку нельзя вызвать как функцию. Частая причина такой ошибки: добавить скобки там, где мы хотели сохранить действие.

Перед тем как двигаться дальше, проследим этот простой пример.

```python
def make_greeting(prefix):
    def greet(name):
        return f"{prefix}, {name}!"
    return greet

morning = make_greeting("Доброе утро")
print(morning("Анна"))
saved_greet = make_greeting("Доброе утро")  # результат: функция greet
print(make_greeting("Доброе утро")("Анна"))  # результат: строка
```

После первой строки вызова `make_greeting` переменная `morning` содержит функцию `greet`, а не готовое приветствие. При `morning("Анна")` внутреннее тело получает новое значение `name`, формирует строку и возвращает её. Настройка и сообщение приходят в разные моменты.

**Первая попытка:** до исполнения предсказать тип результата `make_greeting("Привет")` и значение его отдельного вызова с именем `Игорь`. Самостоятельно создать новое имя для возвращённой функции и вызвать его дважды с разными именами. Оба результата содержат одно приветствие и разные имена; если вместо функции сохранена строка, проверить `return greet` без скобок и повторить с приветствием `Здравствуйте`.

Не перепутаем и `return` с печатью. `return` отдаёт значение вызывающему коду, который может сохранить его в переменную. `print` только показывает представление значения на экране; сам по себе он не передаёт вызывающему коду возвращённую функцию. Если фабрика напечатает внутреннюю функцию, но не вернёт её, присваивание результата вызова фабрики получит `None`. Тогда поздний вызов тоже не сработает, хотя имя вложенной функции было определено правильно.

## 03. Замыкание сохраняет доступ к внешнему имени

Внутренняя функция может использовать имя из внешней функции даже после того, как внешний вызов завершился. Для такого случая мы используем термин **замыкание**: внутренняя функция вместе с доступом к нужным именам окружающей области. Функция не обязана копировать все внешние переменные и объекты. Она сохраняет возможность разрешить имена, которые использует.

Вернёмся к `make_greeting`. Имя `prefix` не объявлено внутри `greet`, но Python находит его во внешней области того вызова `make_greeting`, который создал эту функцию. Позже `morning("Анна")` передаёт новое имя, а `greet` соединяет его с доступным `prefix`. Внешняя функция уже закончила работу, однако связанная с ней настройка остаётся доступной внутренней функции.

Можно представить это как карточку заказа в мастерской: на карточке указана выбранная настройка, а позже по ней выполняют работу для нового входного текста. Соответствие такое: карточка помогает вспомнить настройку, а вызов возвращённой функции приносит новые данные. Граница аналогии: в Python нет бумажной карточки, и замыкание не обязано сохранять копию каждого объекта из внешнего кода.

Это отличается от глобальной переменной. Внешнее имя здесь относится к конкретному вызову фабрики, который создал функцию. Мы не записываем префикс в общий модульный список настроек и не заставляем все функции читать одно глобальное состояние.

Чтобы проследить поиск, начнём с имени `name`: оно является параметром `greet` и получает аргумент текущего вызова. Имя `prefix` среди параметров и локальных присваиваний `greet` не задано, поэтому для него используется доступная внешняя привязка. Если бы имя не было доступно ни в функции, ни в её окружающей области, программа сообщила бы об неопределённом имени. В нашем примере нужная связь появляется потому, что мы создаём и возвращаем функцию из того вызова, где параметр настройки уже получил значение.

Проследим всю последовательность: внешний вызов получает `prefix`, создаёт `greet`, возвращает функцию и завершается. Позже отдельный вызов передаёт `name`; только тогда тело `greet` формирует строку. Мы не удерживаем внешний вызов открытым и не запускаем его заново. Доступ к нужной внешней привязке остаётся у возвращённой функции, чтобы она могла выполнить свою работу.

**Первая попытка:** на уже разобранной `make_greeting` самостоятельно создать две функции с приветствиями `Добрый день` и `Добрый вечер`; до запуска спрогнозировать результат чередования первой, второй, затем снова первой с новыми именами. Проверить, что повторный вызов первой не получил настройку второй; если приветствия смешались, проверить, какая фабрика создала каждую переменную, и повторить с другими именами.

## 04. Вызовы фабрики создают отдельные настройки

Каждый вызов фабрики создаёт собственный контекст для своей настройки. Поэтому две возвращённые функции могут выполнять одинаковый алгоритм, но использовать разные значения внешнего параметра. Покажем механизм на другом сюжете, прежде чем самостоятельно писать текстовый форматтер.

```python
def make_multiplier(factor):
    def multiply(number):
        return factor * number
    return multiply

double = make_multiplier(2)
triple = make_multiplier(3)

print(double(4))
print(triple(4))
print(double(5))
```

Вызов `make_multiplier(2)` создаёт одну настроенную функцию, а вызов `make_multiplier(3)` — другую. Внутри первой доступно имя `factor` со значением первой настройки, во второй — со значением второй. При чередовании получится `8`, `12`, `10`: выбор второй функции не перенастроит первую. Число каждый раз приходит через `number`; оно не заменяет множитель. Этот **числовой** пример независим от предстоящего самостоятельного форматтера `make_labeler(prefix)`.

Это похоже на два одинаковых калькулятора, в одном из которых заранее настроен множитель два, а в другом — три. Мы можем использовать их по очереди, и работа второго не перепишет настройку первого. Аналогия помогает представить независимые вызовы внешней функции; она не означает, что Python создаёт отдельный процесс для каждой функции.

Полезно различить две настройки от двух алгоритмов. В обеих внутренних функциях выполняется одно и то же умножение. Меняется не тело, а доступная ему привязка `factor`, полученная при разных вызовах фабрики. Если бы мы просто меняли один общий множитель перед каждым действием, результат зависел бы от такого общего изменения. Здесь же каждая функция связана со своей настройкой, поэтому порядок вызовов не смешивает множители.

Разделим назначение двух параметров. В числовом примере `factor` задаётся при создании функции, а `number` передаётся при каждом вызове. В будущем форматтере ту же роль играют `prefix` и `message`. Поэтому один настроенный callback можно использовать для многих сообщений. Это не кэш готового результата: ответ формируется заново, когда получатель вызывает функцию с очередными данными.

**Первая попытка:** самостоятельно добавить `quadruple = make_multiplier(4)`, предсказать результаты `double(7)`, `quadruple(7)`, `double(2)` и проверить порядок. Критерий: первый callback сохранил множитель `2`, новый получил `4`. Если ответы смешались, найти, в каком вызове создавался каждый callback, и повторить с числами `3` и `6`.

## 05. Замыкание не означает копирование общего списка

Сохранённый доступ к имени не равен глубокой копии всего объекта. Это особенно важно для списка: разные функции могут обращаться к одному изменяемому списку, если при создании им передали один и тот же объект.

```python
def make_appender(items):
    def add(value):
        items.append(value)
        return items
    return add

shared = []
first_add = make_appender(shared)
second_add = make_appender(shared)

print(first_add("глава 5"))
print(second_add("глава 6"))
```

Оба вызова `make_appender` создали разные внутренние функции и разные внешние области вызова. Но параметр `items` в обоих случаях получил ссылку на один объект `shared`. Первый вызов `add` добавляет `"глава 5"`, второй — `"глава 6"` в тот же список, поэтому после обоих вызовов `shared` содержит обе главы. Здесь нет противоречия: отдельные окружения не отменяют явное совместное использование переданного списка. В практике будет **другая функция**: `make_reader` будет только читать общий список, который изменяют снаружи.

Эта граница похожа на две закладки, ведущие к одной общей записной книжке. Закладки отдельные, но запись в книжку видна с обеих. Соответствие: функции имеют отдельные окружения, а `items` в обоих окружениях указывает на переданный `shared`. Граница аналогии: важны реальные ссылки на объекты, а не сами «закладки».

Если вместо общего `shared` передать каждой фабрике свой новый список `[]`, изменения первого списка не появятся во втором. Проверять нужно **объект, переданный при создании**, а не количество вызовов фабрики. Замыкание не копирует список автоматически; способы копирования и вложенные контейнеры здесь не рассматриваем.

**Первая попытка:** после работы примера с `make_appender` предсказать, что вернут `first_add("глава 7")` и `second_add("глава 8")`; выполнить вызовы и проверить общий список. Затем **самостоятельно** создать третий callback на отдельном `other = []`, изменить только `other` и сравнить объекты. Критерий: первый и второй callback добавляют в исходный `shared`, третий — только в `other`. Если результат неожидан, проследить передачу объекта в `items` и повторить с другим названием главы.

## 06. Callback и замыкание отвечают на разные вопросы

Слово **callback** описывает роль функции: одна часть программы передала её другой части, чтобы та вызвала функцию в подходящий момент. Слово **замыкание** описывает свойство функции: она использует имя из внешней области, сохранившейся для позднего вызова. Поэтому функция может быть и callback, и замыканием одновременно, но callback не обязательно является замыканием.

Посмотрим на получателя функции, используя уже созданную в разделе **04** `double`:

```python
def apply_once(callback, number):
    return callback(number)

print(apply_once(double, 3))  # 6
```

При создании `double = make_multiplier(2)` внешний параметр `factor` получил значение `2`. Позднее `apply_once` получает саму функцию `double`, а не результат `double(3)`, и вызывает её с числом `3` ровно один раз. Здесь `double` — **callback по роли у `apply_once`** и **замыкание по доступу к `factor`**. Обычную функцию без внешней настройки тоже можно передать получателю: роль callback сама по себе не доказывает наличия замыкания.

В следующем занятии этот механизм подготовит диагностическую обёртку: внешняя функция получит исходную операцию и настройки, а возвращённая внутренняя функция вызовется позже. Пока мы не переходим к передаче произвольных аргументов, `nonlocal`, декораторам или перехвату ошибок. Сначала важно уверенно различать создание функции, её возврат и поздний вызов.

**Контроль перед практикой:** до запуска самостоятельно предсказать результаты `apply_once(double, 5)` и `apply_once(triple, 5)`, заменить один callback другим в вызове получателя и сверить `10` и `15`. Указать отдельно, **кто вызывает функцию**, **откуда пришёл `factor`** и **откуда пришёл `number`**. Если результат перепутан, вернуться к примеру из раздела **04** и строке `callback(number)` здесь: значение `5` не перенастраивает множитель.
