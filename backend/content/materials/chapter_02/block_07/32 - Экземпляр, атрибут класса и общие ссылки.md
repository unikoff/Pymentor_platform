После триады противопоставить присваивание нового значения **имени атрибута** и изменение **уже найденного списка**. Далее объяснить причины этого различия; сравнение не должно предполагать, что ученик уже знает атрибут класса.

## 01. Кому принадлежит атрибут
- **Сначала понятия:** атрибут — значение, доступное по имени после точки. `self.title = title` в `__init__` создаёт/меняет поле **текущего экземпляра**. `section = "Python"` с отступом внутри тела класса задаёт атрибут **класса**. Вызов класса создаёт экземпляр; из атрибута класса не создаются автоматически отдельные копии для каждого экземпляра.
- **Короткий сквозной пример теории**, отличный от будущего практического `Bookmark`:

  ```python
  class ReadingCard:
      section = "Python"

      def __init__(self, title):
          self.title = title

  first = ReadingCard("Списки")
  second = ReadingCard("Функции")
  print(first.section, second.section)  # Python Python
  print(first.title, second.title)      # Списки Функции
  ```

  Пошагово повторить два запуска `__init__`: `self` поочерёдно указывает на создаваемые `first` и `second`; `section` при этом записан в классе один раз. Разделить вопрос «где значение **записано**?» от «откуда оно **прочитано**?».
- **Первая попытка:** после `first.title = "ООП"` ученик до запуска предсказывает `second.title` и объясняет, почему поле второго экземпляра не изменилось. Затем проверяет и при ошибке возвращается к двум вызовам конструктора.
- **Наглядность и предел:** один шаблон карточки и две заполненные карточки показывают общее описание и индивидуальные поля; картинка не описывает устройство памяти и не объясняет ещё общий изменяемый список.
- **Переход:** как `first.section` вообще доступен, если `__init__` его не записывал?

## 02. Поиск атрибута и собственное присваивание
- **Механизм до прогноза:** для **простого** поля `first.section` Python сначала проверяет собственный атрибут `first`; если его нет — читает `ReadingCard.section`. Сложные дескрипторы и `property` не рассматриваем.
- **Сравнение последовательных состояний** на прежнем `ReadingCard`:

  ```python
  first.section = "ООП"
  print(first.section)        # ООП
  print(second.section)       # Python
  print(ReadingCard.section)  # Python
  ```

  Присваивание `first.section = ...` создаёт/меняет собственное значение экземпляра, которое **перекрывает** класс при чтении через `first`. Значение класса не удалено и не заменено. **Различающий случай:** после `ReadingCard.section = "Алгоритмы"` чтение `second.section` изменится, а `first.section` останется «ООП».
- **Самостоятельная проверка:** ученик заполняет прогнозную таблицу «first / second / класс» до присваивания, после записи в экземпляр и после записи в класс; затем запускает. При неверном ответе выясняет, есть ли собственное поле `section` у выбранного объекта.
- **Граница:** «перекрыл» — это правило **выбора при чтении**, а не удаление значения класса. Эта запись отличается от вызова `append`, при котором не присваивают атрибуту новую ссылку.
- **Переход:** что меняется, когда найденное через класс значение — изменяемый список?

## 03. Общий изменяемый атрибут
- **Перед кодом:** `notes = []` в теле класса создаёт один список. `a.notes.append("важно")` **мутирует найденный список**; `a.notes = []` создаёт **новое поле** конкретного экземпляра и новый список. Две операции имеют разный эффект для `b.notes`.
- **Независимый разбор**, чтобы практика не содержала готового исправления:

  ```python
  class Draft:
      notes = []

  a = Draft()
  b = Draft()
  a.notes.append("важно")
  print(b.notes)  # ['важно']
  a.notes = []
  a.notes.append("личное")
  print(a.notes)  # ['личное']
  print(b.notes)  # ['важно']
  ```

  После каждого действия назвать **владельца поля** и отдельно **объект списка**. Общее наблюдение возникает из общих ссылок, не из автоматической синхронизации объектов.
- **Исправление механизма:** когда список нужен каждому отдельно, убрать `notes = []` из тела класса, поместить `self.notes = []` внутрь `__init__` и создать **новую** пару экземпляров. Тогда `a.notes.append(...)` не влияет на `b.notes`. Общее **неизменяемое** обозначение `section` оставлять на уровне класса допустимо.
- **Микровопрос с проверкой:** после `a.notes = []` спросить до запуска, будет ли `b.notes` пустым. Ошибка «тоже пустой» означает путаницу переназначения и мутации; вернуть к разделу 02.
- **Вторая наглядность:** две карточки могут указывать на одну «коробку» с заметками; при `self.notes = []` каждая получает свою коробку. Аналогия не утверждает конкретное устройство памяти.
- **Переход:** один и тот же объект может иметь и несколько **имён переменных**, без общего поля класса.

## 04. Два имени и два экземпляра
- **Сначала правило:** `alias = first` связывает новое имя с **тем же экземпляром**, без вызова `__init__`. `other = ReadingCard("Списки")` вызывает класс снова и создаёт **отдельный** экземпляр. `is` отвечает «тот же объект?», а `==` — «равны ли выбранные значения?». В этом примере сравниваем строки `title`, а не экземпляры классов с неописанным `__eq__`.

  ```python
  first = ReadingCard("Списки")
  alias = first
  other = ReadingCard("Списки")
  print(first is alias)              # True
  print(first is other)              # False
  print(first.title == other.title)  # True
  alias.title = "Словари"
  print(first.title, other.title)    # Словари Списки
  ```

- **Самостоятельный прогноз:** до запуска ученик объясняет три сравнения и изменение через `alias`, указывая, где конструктор вызывается повторно. Признак понимания: два объекта могут иметь одинаковое содержимое, а два имени — один объект.
- **Граница:** присваивание `alias` не является ни копированием, ни созданием нового экземпляра. Обычная `Task` пока не обещает сравнение по равенству всех полей.
- **Переход:** ссылки на одни экземпляры могут храниться в **разных внешних списках**.

## 05. Поверхностная копия и ссылки внутри списка
- **Напоминание формы из блока 5:** `copies = cards.copy()` создаёт **новый внешний список** со ссылками на прежние элементы. Сами экземпляры не копируются, `deepcopy` пока не нужен.
- **Два независимых наблюдения:** при `cards = [first, other]` и `copies = cards.copy()` выражение `cards is copies` ложно (разные контейнеры), а `cards[0] is copies[0]` истинно (один экземпляр). `copies[0].title = "Повторение"` меняет поле элемента, поэтому новое значение видно через `cards[0]`. Напротив, `copies.append(ReadingCard("Новая"))` увеличит длину **только copies**.
- **Отличающий случай:** `copies[0] = other` заменяет элемент внешнего списка `copies`, но `cards[0]` продолжит указывать на `first`. Перед каждым действием ученик помечает, что меняет: «состав внешнего контейнера» либо «состояние общего объекта-элемента».
- **Мини-проверка:** дать `cards is copies`, `cards[0] is copies[0]`, значение поля после мутации и длины после `append`; ученик сначала предсказывает все четыре факта, затем сверяет. Не считать правильный единственный `True` доказательством понимания.
- **Переход:** проверить те же причины на **другом классе**, чтобы отделить понимание от запоминания вывода `ReadingCard`.
