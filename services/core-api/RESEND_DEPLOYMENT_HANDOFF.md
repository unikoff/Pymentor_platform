# Resend: подготовка подключения к сайту

## Что проверено

12 ноября 2026 года домен `knowi.ru` подтверждён в Resend. Для отправки выбран
адрес `support@knowi.ru`. Локальный Core с изолированной SQLite-базой отправил
письма подтверждения и восстановления через SMTP Resend: оба получили статус
Delivered в кабинете Resend, и владелец тестового ящика подтвердил их получение
во входящих. Приложение на работающем сайте при этом не изменялось.

На тестовом компьютере STARTTLS на порту 587 не ответил, а порт 2587 прошёл
STARTTLS и фактическую отправку. Доступность порта на сервере нужно проверить
отдельно. Первые два тестовых письма были отправлены ранее загруженным процессом
со старым названием Pymentor в теме; исходные шаблоны обновлены на knowi.

## Настройки для будущего окружения

Без секретов в Git, образах, логах и открытых файлах настроек:

```text
PYMENTOR_SMTP_HOST=smtp.resend.com
PYMENTOR_SMTP_PORT=2587
PYMENTOR_SMTP_USERNAME=resend
PYMENTOR_SMTP_FROM=support@knowi.ru
PYMENTOR_SMTP_STARTTLS=1
PYMENTOR_EMAIL_PUBLIC_URL=<проверенный HTTPS URL платформы>
```

Через защищённое хранилище окружения отдельно передаются:

- `PYMENTOR_SMTP_PASSWORD` — Resend API key, ограниченный отправкой и доменом;
- `PYMENTOR_EMAIL_TOKEN_SECRET` — отдельный случайный постоянный секрет подписи
  длиной не менее 32 байт. Он не должен меняться при каждом запуске приложения.

Локальный тестовый сервер хранит ключ только в памяти. Для будущего развёртывания
нужен доступный ключ в защищённом хранилище; не следует считать его сохранённым
только потому, что локальная проверка прошла.

## Перед выпуском

1. Установить фактический источник GitOps и целевой профиль; текущий локальный
   набор изменений ещё не является развёрнутой версией. Подготовить релизный
   образ с изменениями спринта и способ применения миграции `verified`.
2. Добавить в актуальный манифест безопасную передачу двух секретов и обычных
   SMTP-настроек. В локальном Helm-шаблоне `deployment-core.yaml` сейчас явно
   подключены только `DATABASE_URL` и учётные данные бота; почтовые секреты
   туда пока не подключены. Не записывать значения ключей в манифест.
3. Проверить исходящее SMTP-соединение с сервера, HTTPS URL страницы платформы,
   сохранность базы и способ отката до развёртывания. Для SQLite с несколькими
   процессами нужен общий лимит запросов на прокси, как указано в README.
4. После отдельного согласования выпуска применить изменения и проверить письмо,
   ссылку подтверждения и восстановление на контролируемом тестовом аккаунте.

Адрес `support@knowi.ru` выбран как отправитель. Приём ответов на него требует
отдельно настроенного почтового ящика или переадресации; Resend-проверка домена
сама по себе такой ящик не создаёт.
