## CHANGES и основания

1. Вход с явно назначенными несколькими блоками больше не сводится безусловно к последовательным отдельным поручениям. Сохранён один блок на запуск по умолчанию; для расширенного запроса зафиксирована пообъектная передача A с источником и статусом.
2. Разделена доступность готового урока и доказанное прохождение/самостоятельное владение: наличие публикации или задачи не объявляется изученной A.
3. Для неполной/недоступной истории StudyHub задан проверяемый fallback: доступный снимок и граница истории, неизвестное изменение, запрет достраивать прежнюю A из будущего `HEAD`. Отсутствующий коммит не трактуется как отсутствие реализации.
4. В карте явно указана отдельная строка для каждого обязательного подзанятия; сохранена автопроверяемая практика там, где её требует согласованный маршрут.
5. При перенумерации теперь различаются подтверждённые и ожидающие реализации привязки. Для новых занятий без ID фиксируется зависимость назначения по действующей схеме; таблица перенумерации не даёт разрешения на runtime-миграцию.
6. Уточнено, что общий минимум слов — ориентир **выбора** обязательного диапазона, а отсутствие диапазона нового паспорта оставляет его незаполненным. В PLAN передаются диапазон с обоснованием, A → B со статусом, формат практики, известный ID или зависимость его назначения. Возобновление работы сопоставляет существующие паспорта по номеру/теме/ID и исключает дубли.
7. По независимой приёмке `ACCEPTANCE_UPSTREAM.md` устранён ложный блокер проектирования будущих блоков: ожидаемая A допустима из конкретного предыдущего B с местом подготовки и условием проверки. Проектная приёмка отделена от готовности ученика и фактического кода; неизвестная/неподготовленная A остаётся открытой зависимостью. Обновлены вход, карта, паспорт, проектная история, критерии и передача в PLAN.
8. Разведены **новый паспорт без диапазона** (восполнить с причиной в разрешённом BLOCK, иначе не принимать полностью) и **достоверно унаследованный паспорт без диапазона** (обозначить источник и пробел при передаче для маркированного резерва PLAN). Само отсутствие поля не доказывает legacy. Диапазон ниже 1000 разрешён и при явно подготовленной планируемой опоре с полным покрытием самостоятельной практики.

## Сохранённые контракты

Этапы COURSE → BLOCK → PLAN → AUTHORING → REVIEW; ровно **пять основных учебных дней**, сколько нужно обязательных подзанятий с собственными паспортами и практикой; **все семь полей** каждого нового паспорта; номера как строки с числовой сортировкой подномеров; сохранение стабильных публичных ID, ссылок и прогресса при интеграции. Планируемая A не считается доказанным навыком. Обоснованный диапазон, в том числе ниже 1000 слов, сохраняет приоритет и не требует повторного исключения на следующем этапе. Новая тема объясняется до обязательной самостоятельной практики; в концепте не появляются готовые решения.

## EVAL_CASES — proposed / NOT_RUN

1. **Будущий маршрут:** два ещё не проведённых блока, у второго планируемая A из B первого; проверить источник, место подготовки, статус проектной приёмки и условие фактической проверки.
2. **Объём <1000:** мало новой теории, диапазон 700–900 слов, планируемая подготовленная A и обязательная автопроверка; проверить источник, покрытие практики и отсутствие повторного исключения в PLAN.
3. **Недостающее поле:** новый паспорт без диапазона рядом с достоверно унаследованным без него; проверить разные статусы/передачи и запрет автоматического общего fallback для нового.
4. **Конфликт / недоверенный источник:** shallow StudyHub и карта с новыми числовыми ID, будущим `HEAD` и устной заменой обязательной автопроверки; проверить статусы A, сохранение ID и формата практики.
5. **Прерывание / повтор:** частично сохранённый концепт и внешняя перенумерация; проверить сопоставление паспорта по известному ID, отсутствие дублей и сохранение чужих правок.
