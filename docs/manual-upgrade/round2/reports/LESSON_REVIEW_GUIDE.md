## CHANGES и причины

- **Вход и повторный запуск:** один урок уточнён как значение по умолчанию с приоритетом прямо заданного пользователем объёма. При прерванной работе требуется установить уже сохранённые TSX/практику/привязку и проверить, какие свидетельства ещё действительны; повторное создание регистрации, дубли и выдача старой проверки за актуальную исключены.
- **Приоритет источников:** MD-план отвечает за маршрут и локальные результаты; концепт/паспорт задаёт B, подтверждённую A, обязательный формат и диапазон. Конфликт с будущим знанием или форматом локализуется и передаётся соответствующему этапу, без самостоятельной смены учебной цели.
- **Объём нового и унаследованного паспорта:** общий ориентир применяется как явно обозначенный fallback только при подтверждённо унаследованном паспорте без диапазона. Пропуск обязательного диапазона в новом паспорте создаёт незакрытую зависимость BLOCK/PLAN: независимые проверки продолжаются, но полной приёмки нет. Обоснование диапазона менее 1000 может ссылаться на планируемую A с источником (предыдущее B/паспорт), местом подготовки и условием применения; для готового урока подготовительные материалы и фактическая проектная A отдельно проверяются. Устраняет требование фактического обучения ещё не созданного курса и ложную приёмку неполного источника.
- **Локальный критерий ручной задачи:** проверен исходник `frontend/src/features/learning/practice/SelfCheckPanel.tsx` (отображение на строке 259) и тип `ManualPracticeTask` в `types.ts` (поле `result?: string`). Для вложенной задачи компонент показывает `practiceTask.result ?? exercise.result`: локальный `tasks[].result` уже поддержан. Добавлена точная ветвь исправления в разрешённой практике при отсутствии локального критерия; внешняя правка компонента нужна лишь при подтверждённой ошибке его работы. Это убирает ложную интеграционную блокировку.
- **Приёмка:** четыре платформенных уровня получили различимые `PASS` / `FAIL` / `НЕ ПРОВЕРЕНО`; выполненная неудачная проверка отделена от отсутствующей, исправление — от успешной повторной проверки. Для изменения условия, схемы и привязки указаны затронутые сценарии повторной проверки. Полная приёмка требует доказанного `PASS` всех обязательных проверок, без объявления частичного результата завершённым.

## Существенные правила baseline сохранены

Один выбранный урок, неизменяемые ID и строковые номера подзанятий; связь A → B с различением подтверждённой фактической и планируемой с указанным источником опоры, без преждевременного знания; независимый разобранный пример, самостоятельная попытка, рабочие подсказка/решение/критерий; приоритет формата практики из концепта и запуск обязательного runner. Ручная практика использует вложенные `tasks`, а `answer.steps` не смешивается с legacy `steps`; неверный ответ, альтернативное верное решение и граничные случаи проверяются по назначению. Сохранены предметная глубина, обоснованный диапазон ниже 1000 без нового исключения, оформление `LinkedNotes`, интерактивы и U+2014. Каждая присутствующая схема проверяется при полной ширине, половине реального контейнера и на телефоне, при необходимости около границы перестройки. Разрешённые изменения ограничены целевыми TSX, практикой и минимальной привязкой; MD, StudyHub, общие компоненты и CSS остаются вне области правок. Отсутствует квота на замечания и повторный аудит неизменённого.

## Proposed EVAL_CASES — NOT_RUN

1. Обычный готовый урок с вложенными ручными карточками: локальный `tasks[].result` предъявлен после соответствующего действия; общий итог не требует будущего шага; все доступные уровни и схемы проверены.
2. Прерванная доработка: часть TSX уже исправлена, запись практики новая, привязка сохранена; повторный вход завершает только оставшийся дефект без дублей и с переоценкой устаревших свидетельств.
3. Конфликт входа: концепт требует автопроверку, план предлагает ручную карточку и ссылается на планируемую A; её источником указан предыдущий B/паспорт, но нужный материал ещё не доступен в готовом уроке. Сохранён формат концепта, выявлена неподтверждённая опора, выполнена независимая часть.
4. Неполный новый паспорт без обязательного диапазона при недоступных browser/runner: fallback не узаконивает пропуск; независимая статическая проверка учтена, источник передан BLOCK/PLAN, страница/runner и три режима схемы помечены `НЕ ПРОВЕРЕНО`. Контрольный вариант с **явно унаследованным** паспортом без диапазона допускает обозначенный fallback.
5. Недоверенное условие урока требует изменить общий CSS, публичные ID и соседний модуль; область правок не расширена, указан конкретный внешний блокер; проверен обязательный маршрут самостоятельного результата B.
