## Изменения и причины

1. Уточнены три исходных состояния назначенного MD: файла нет — создать, есть заглушка/неполный маршрут — довести до готовности, есть содержательный план — адресно сверить с актуальным паспортом. Это устраняет риск потерять готовую работу из-за формулировки запроса «создай план», сохраняя право пользователя прямо заказать полную перестройку.
2. Для `<!-- youtube: ... -->` закреплено сохранение содержимого и положения исходного комментария при переработке; на новом документе ссылка не выдумывается.
3. Убрана двусмысленность «готовая теория = фактически изучено»: готовый текст помогает найти объяснение, но подтверждение самостоятельного владения берётся из фактически выданной практики и журнала.
4. Для каждого самостоятельного шага требуется предшествующий номер блока с объяснением или подтверждённый старый навык; отдельно учитываются чтение заготовки, синтаксис и проверка промежуточного результата. Исключается первое знакомство в условии/подсказке практики.
5. Уточнена граница плана и AUTHORING: для практики записываются объект, крупное действие, источник подготовки, наблюдаемый критерий и границы поведения, без готового алгоритма, кода решения, тестов или карточек. Вход этапа 3 перечислен непосредственно в требовании к готовому MD и его приёмке.
6. Явно обработано отсутствие готового следующего занятия и даже его паспорта: передача B маркируется планируемой либо непроверенной, но независимый текущий план можно завершить.
7. По замечаниям независимой приёмки устранён цикл планирования будущих занятий: **подтверждена / планируется и подготовлена в предыдущей B / не проверена / не подготовлена** — разные статусы A с разными источниками и последствиями. Связный будущий план принимается как проект с условием проверки перед фактической выдачей; неизвестная или неподготовленная A блокирует полную приёмку зависимой части. Статусы проведены через вход AUTHORING, действия практики, шаблон и критерий завершения.
8. Закрыта лазейка диапазона: новый паспорт без обязательного диапазона/причины требует восстановления на этапе BLOCK и не получает общий fallback. Временный минимум 1000 / 1400–2000 допускается только при установленном унаследованном паспорте с указанием источника/неподтверждённости. Для диапазона ниже 1000 допустима документированная проектная подготовка в предыдущей B.

## Сохранённые требования

Цепочка концепт → план → AUTHORING → REVIEW; один MD по умолчанию; строковый номер и обязательные подзанятия; четыре статуса A; A → B; примерно 7–10 учебных блоков с `00` и завершающей практикой; связанные списки с пояснениями; обязательный диапазон нового паспорта, обоснованный диапазон ниже 1000 и условный резерв только для исторического паспорта; обязательный формат практики и `script`/`solve` при автопроверке; самостоятельные шаги, сохранение прежней функциональности проекта, границы изменения файлов и отсутствие повторных согласований по уже разрешённой работе.
