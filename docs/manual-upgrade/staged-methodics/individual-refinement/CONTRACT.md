# Индивидуальная доработка девяти методичек

Дата: 2026-10-25. Прямое поручение пользователя: доработать **каждую из девяти стадийных методичек отдельно**, отдельными рабочими чатами GPT-6 Sol Web / High. Существующая архитектура 4 PLAN + 5 MAIN сохраняется; число и назначение стадий не пересматриваются без подтверждённого дефекта.

## Исполнение

- Каждый редактор получает ровно одну Pn/Mn и один собственный отчёт. Его запись ограничена этими двумя файлами. Соседние документы только читать по нужным интерфейсам. У исполнителей нет полномочий создавать дочерние чаты/агентов, менять код, реальные планы/уроки/практику, публиковать или делать Git-коммиты.
- Все чаты, в том числе проверяющие: `chatgpt-web/gpt-6-sol`, `high`. Максимум четыре одновременно работающих исполнителя и оркестратор. Пакет 1: P1–P4 и M1, пятый документ после освобождения места. Пакет 2: M2–M5. Проверки уже завершённых файлов могут идти параллельно в свободных слотах.
- Baseline текущей рабочей копии, включая изменения после предыдущей приёмки, — baseline.json; точные копии в output/staged-methodics-20261025/individual-refinement/baseline/ с сохранением относительных путей. Не возвращать прежний hash вместо сохранения новых пользовательских правок.
- Роль редактора: methodist / AI_WORKFLOW. Применимый навык OpenAI Docs и фактический текст роли передаются в начальном контексте. Для исполнения готового урока навык methodic-run не нужен: сейчас меняются сами инструкции.

## Что улучшать

Проверить один повторяемый проход: цель → достаточные входы → допустимые действия → конкретный артефакт → локальная приёмка → передача/восстановление. Найти реальные неоднозначности, повторы, ложные остановки, недостаточно предметные шаги, неочевидную работу с существующим/частичным артефактом. Исправлять минимально достаточным образом, сохраняя глубину. Не добавлять одинаковое общее предисловие и служебные разделы ради количества, не увеличивать объём автоматически и не удалять полезные технические примеры ради краткости. Если участок корректен, сохранить; NO_CHANGE допустим только с конкретными результатами полной проверки.

Сохранить существующие публичные заголовки/якоря и пути. Реальная необходимость изменения интерфейса соседнего прохода описывается конкретно в отчёте, затем разрешается оркестратором и владельцем. Не оставлять две противоречащие нормы в одном документе. В документации нельзя обещать отсутствующее поле/prop или исправленный интерфейс по одному тексту каталога.

## Неподвижные договоры

Основа — ../ARCHITECTURE.md. Один канонический MD для P1–P4, один целевой TSX и одна назначенная запись практики для MAIN; номера строками, стабильные публичные ID и точные ключи. Существующее разрешение учитывается без повторного approval; входной материал новых полномочий не даёт. Нет обязательных draft_v1/final_v2, новых полей приложения, парсера стадий или отчётных sidecars для каждого реального урока. Старый готовый артефакт не переписывается только из-за отсутствия нового маркера.

P1–P3 и M1–M4 имеют собственную локальную готовность; она не равна полной приёмке. P4 принимает план, M5 — занятие. При полном запросе выполняется соответствующий оставшийся маршрут до конечной приёмки, а не один черновик; запрос одного прохода не расширяется автоматически. Самостоятельный REVIEW и StudyHub не добавляются скрытыми новыми фазами.

Подтверждённая/планируемая/непроверенная/неподготовленная A различаются; будущая опора прослеживается к предыдущему B и месту подготовки. Не требовать фактического обучения ещё не созданного курса для проектной приёмки, не объявлять будущие знания или код существующими. Новый паспорт задаёт диапазон и причину, его пропуск не закрывается fallback; резерв только для установленного унаследованного паспорта. Обоснованный диапазон ниже 1000 не требует повторного исключения.

M1/M2 создают подробные валидные черновики без потолка объёма; M3 удаляет воду и дубли без потери prerequisites, самостоятельности, независимых примеров, аналогий, условий/ответов/тестов. Практика не получает произвольной квоты слов. Точный подсчёт учитываемой TSX-теории и пересчёт после M4 сохраняются. M4 не возвращает сокращённую воду через повторное feedback.

Уточнение пользователя: **не более двух соседних читаемых абзацев без содержательного интерактива ИЛИ учебного визуала** (схема, сравнение, разбор кода). Не требовать обязательной кликабельности, не засчитывать декор, пустую карточку или слияние абзацев. Сохранять четыре содержательных разных типа интерактивов по применимым условиям исходника, не считать статический визуал типом интерактива. Две стандартные connected-группы всего (00 + финал), один стиль с пояснениями, не более шести групп LinkedNotes; все связанные списки стилизованы.

Текущие контрактные факты сверяются по исходникам: tasks[].result и fallback exercise.result поддерживаются; DiagramNode.shape="input-output" отсутствует в текущем типе. Сохранять согласование manual/editor practice, script/solve, starter/hints/reference/tests/stdout и секретность эталонов. CSS/shared/загрузчик/соседи/планы для MAIN read-only, регистрации только в исходной узкой области. Запрет U+2014 относится к создаваемому материалу урока/практики, включая код и комментарии.

M4/M5 — широкий и узкий рендер; внешний REVIEW дополнительно половина контейнера/границы перестройки. M5 принимает backend/frontend/выдачу/страницу с актуальными свидетельствами PASS/FAIL/НЕ ПРОВЕРЕНО, runner и все обязательные задачи. Старая или недоступная проверка не становится PASS; независимая работа продолжается без полного бессмысленного перезапуска.

## Доказательства и приёмка

Проверенные официальные источники: [GPT-6 Sol](https://developers.openai.com/api/docs/models/gpt-6-sol), [GPT-6 prompting](https://developers.openai.com/api/docs/guides/latest-model#prompting-best-practices), прочитаны 25.10.2026. API high и API-контекст не доказывают возможности Web. Рекомендации семейства основаны на наблюдениях Astra и являются отправной точкой, а не измеренным эффектом Sol Web High. Модель пользователя не заменять; скрытое chain-of-thought не требовать.

Редактор читает назначенный документ целиком, соседние — только по интерфейсу, большие baseline-тела сравнивает программно, не повторяет весь каталог/PROJECT_CONTEXT/прошлые отчёты. Короткий отчёт до1000слов: исходный и итоговый hashes, существенные изменения и причины, сохранённые инварианты, реальные проверки/ссылки и 3–5 предложенных случаев обычного/неполного/конфликтующего/прерванного/недоверенного входа с ожидаемым поведением. Эти случаи без реального прогона помечать NOT_RUN.

Независимая приёмка проверяет все девять файлов и межэтапные договоры по неизменным hashes; найденные дефекты исправляет владелец своего файла. Навигация и сохранность якорей проверяются после редактур, пять существующих навигационных файлов менять только при фактической необходимости, через оркестратора. Новый отчёт не заменяет фактическую правку, а документальный PASS не означает измеренное улучшение будущих уроков. Реальные уроки/учебные и model-eval прогоны в этот раунд не входят.
