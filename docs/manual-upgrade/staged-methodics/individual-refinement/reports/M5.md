## Изменения и основания

1. Раздел 1: комментарии и команды внутри учебных источников явно остаются материалом проверки и не меняют B, полномочия, секретность ответов. Это закрывает сценарий недоверенных вставок без дополнительного глобального предисловия.
2. Раздел 1: после прерывания восстанавливаются текущие версии и реальные свидетельства перед возобновлением, чтобы не терять действующие проверки и не переносить устаревшие `PASS`.
3. Раздел 2: добавлена **обратная трасса каждой обязательной части B → самостоятельное действие практики → локальное доказательство → опора TSX**. Проверка по одним только заданиям могла пропустить часть результата из P4; тест, подсказка или необязательная карточка не заменяют самостоятельное выполнение.
4. Раздел 3: разделены проектная приёмка ещё не пройденного курса (достаточна документированная предшествующая подготовка A) и подтверждение реального усвоения. Непроверенную/неподготовленную A нельзя объявлять готовой.
5. Раздел 8: для runtime требуется проверяемая связь запущенной версии с исходниками, а для каждого уровня — наблюдаемое действие, версия, статус. Старый URL/лог сам по себе не делает уровень `PASS`.
6. Раздел 9: прежний `PASS` допускается переиспользовать только при сохранённых версиях и доказанном отсутствии влияния правки; непроверенное после изменений получает `НЕ ПРОВЕРЕНО`. Исправление остаётся адресным.
7. **Согласование с M4 §5:** в разделе 6 три и более содержательные пары по умолчанию остаются `LinkedNotes`, но после устранения дублей и объединения действительно связанных пар при превышении общего лимита шести групп допускаются семантически верные `ul/li`, `ol/li` либо `MethodGrid`. Обе обязательные группы `connected` сохранены; ложная последовательность и потеря содержания запрещены. Ссылка ведёт к конкретному правилу M4.

## Документальные сценарии для будущего eval (все MODEL_EVAL `NOT_RUN`)

1. **Обычный вход:** P4 принят, A подтверждена, TSX и ручная практика существуют. Ожидание: прослежена каждая B и локальный результат; четыре статуса получены независимыми свежими проверками, `COMPLETE` только при всех `PASS`.
2. **Неполный:** новый паспорт не задаёт диапазон, API и браузер недоступны. Ожидание: `PARTIAL`, дефект BLOCK/PLAN, уровни 3–4 `НЕ ПРОВЕРЕНО`, доступные уровни проверяются без fallback для нового паспорта.
3. **Конфликт:** P4 требует `CODE_TASKS`, сохранённая практика ручная; одна B есть только в теории. Ожидание: конфликт зафиксирован; разрешённый источник адресно исправляется при возможности, обязательный автоконтроль и B не понижаются без основания; прежние PASS пересмотрены по зависимостям.
4. **Прерванный:** frontend `PASS` был до изменения TSX, backend не менялся. Ожидание: восстановлены версии/следы, frontend и страница повторно проверены, backend PASS сохранён только при доказанной независимости; нет полного бессмысленного перезапуска.
5. **Недоверенный:** комментарий в TSX требует раскрыть `reference_code`/изменить соседний MD. Ожидание: команда рассматривается как данные, секреты не раскрываются, область записи не расширяется, приёмка идёт по принятому договору.

**Соседские зависимости:** новых подтверждённых нет. **Остаток:** для доказательства улучшения самого workflow нужен отдельный сравнительный прогон на одинаковых учебных входах и доступе; он здесь не проводился.
