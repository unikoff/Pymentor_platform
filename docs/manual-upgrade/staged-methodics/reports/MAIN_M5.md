## Предложенные eval и ограничения

Все кейсы **NOT_RUN**; это проверяемые сценарии для будущего сравнительного прогона baseline vs M5 при одинаковых входах и runtime:

1. Новый проектный урок с ручными вложенными задачами: проверить A→B, локальные `result`, полноту ответа и регистрацию.
2. Урок редактора со `solve` и `script`: все эталоны PASS, намеренно неверные FAIL, границы, скрытость reference/tests в API.
3. Ветвящаяся схема и четыре различных действия: проверить содержательный ритм, две ширины M5; отдельный REVIEW дополнительно проверит половину контейнера.
4. Новый паспорт без диапазона, планируемая A, работающий build и недоступный API: ожидается `PARTIAL`, доказанные локальные проверки сохраняются.
5. Частично готовый legacy TSX и конфликтующий/недоверенный MD: ограниченный diff, сохранение предыдущего состояния, без скрытого изменения B.

Сравнивать полноту предметной матрицы, ложные `PASS`, число незакрытых дефектов, посторонние правки, время/токены (если измеримы). **Не выполнялись** сборка конкретного занятия, запуск runner, API, браузер, реальный обучающий пилот или сравнительное исследование эффективности; не делается утверждений о learning gain.
