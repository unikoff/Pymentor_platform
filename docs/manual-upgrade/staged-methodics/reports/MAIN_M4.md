## Проверка фактических компонентов и исправленные ошибки источника

- `DiagramNodeShape` сейчас содержит только `process | terminator | decision | database | subprocess`. Старый §8 перечислял несуществующий `shape="input-output"`: в новой таблице он отмечен **неподдерживаемым** и не используется в положительном JSX-примере; менять `diagrams.tsx` не нужно.
- `Diagram`, `DiagramFlow`, `DiagramArrow`, `DiagramBranches/Branch`, `DiagramLane/Group`, `DiagramExchange`, `DiagramNote/Legend/Track` сверены по реальным сигнатурам; `Diagram` уже создаёт `figure`/`figcaption`, соединитель скрывает лишь декоративную стрелку через `aria-hidden`. В новой методике нет выдуманного `aria-describedby` как prop этих компонентов. Поддерживаемая адаптация контейнера присутствует в `diagrams.css`.
- `LinkedNotes` реально принимает `variant="cards" | "connected"` и `items` с `title/description`. `MethodGrid.rows` принимает пары `ReactNode`. `StepThrough` использует нулевой индекс `steps[].line`; `CodeSequence` имеет реальный `incorrectExplanation` с обращением «Проверьте» по умолчанию. Пример `BugHunt` проверен по `code`, `question`, `options`, `correctIndex`, `explanation`, `fix`.
- При первичной проверке соседних ссылок не существовали `03_CONTENT_EDIT.md` и `05_LESSON_ACCEPTANCE.md`; при повторной **M5 уже создан**, и его ссылка разрешается. Осталась одна временно неразрешённая ссылка `03_CONTENT_EDIT.md` (документ параллельно пишется). Оба пути **точно** заданы принятой архитектурой; интегратору проверить наличие M3 после завершения пакета.
- Сохранённое руководство M4 не содержит U+2014. Реальные локальные сборки/браузерные проверки **уроков** не запускались: этот этап создавал текст воспроизводимой методики, не TSX-занятие.
