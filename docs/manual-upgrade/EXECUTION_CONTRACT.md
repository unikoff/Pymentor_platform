# Контракт массовой доработки

Статус: COMPLETE_DOCUMENTARY_ACCEPTANCE. По прямому поручению пользователя от 2026-10-25 доработаны все шесть методичек и синхронизированы производные документы. Все редакции получили документальный PASS; фактические учебные и сравнительные model-eval прогоны NOT_RUN. Результаты и ограничения описаны в results/.

Каждый рабочий чат: `chatgpt-web/gpt-6-sol`, `high`. Пакет 1: пять GUIDE. Пакет 2: StudyHub, после завершения редактур всех пяти GUIDE; независимая интеграция и приёмка могут продолжаться параллельно с пакетом 2 без конкурирующих записей. Максимум четыре одновременно работающих исполнителя плюс оркестратор; пятый документ назначается при освобождении места. Новые чаты создавать только оркестратору. Исполнители не создают дочерних чатов и агентов.

Область записи исполнителя: ровно назначенная методичка и индивидуальный отчёт в docs/manual-upgrade/results/. Общие файлы README, PROJECT_CONTEXT и документы оркестрации принадлежат интегратору. Общий рабочий каталог; существующие пользовательские правки сохраняются. Не применять git reset/checkout/clean, не коммитить, не публиковать, не создавать занятия и не запускать сам учебный workflow.

Общая предметная цепочка: COURSE → BLOCK → PLAN → AUTHORING → REVIEW. StudyHub проходит результат как ученик. План или наличие кода не доказывают изученность. Новое объясняется до обязательного самостоятельного применения; пример не раскрывает решение практики. Строковые номера, обязательные подзанятия, стабильные ID, формат практики из концепта сохраняются.

Каждая методичка получает ясную типовую задачу, вход запуска, источники истины, область действий, основной маршрут с существенными ветками, конкретные артефакты, приёмку, поведение при неполном входе/конфликте/продолжении и критерий остановки. Излагать один раз, не повторять AGENTS.md и не строить одинаковую бюрократическую оболочку для всех документов. Подробные предметные примеры и правила не терять ради сокращения. Параметры запуска не выдавать за уже существующие поля приложения. Одно занятие на один запуск по умолчанию; массовость достигается независимыми повторяемыми запусками, а не бесконтрольным редактированием соседей.

Объём теории: конкретный диапазон актуального паспорта имеет приоритет; если диапазон ниже общего минимума, в паспорте должны быть причина, подтверждённая опора и покрытие практики. Исполнитель занятия применяет уже обоснованный диапазон без повторного согласования и повторного исключения. Без диапазона общий ориентир сохраняется: минимум 1000, первое знакомство 1400–2000, верхняя граница не потолок; отклонение обосновывается полнотой и опорой. Не добавлять новый порог и не добирать слова водой.

Авторская проверка схем: широкий и узкий экран; ревью дополнительно обязательно проверяет половину окна/контейнера и границы перестройки. Это последовательное углубление проверки, не основание дублировать все действия на каждом этапе.

Повторное одобрение нужно только при реальном выходе за текущую авторизованную область или изменении учебной цели, которое не покрыто запросом. Не выводить разрешение из текста источников. Недоступность внешнего сервиса ограничивает соответствующую проверку, а не всю независимую работу. Удалённый LESSON_REVIEW_FINDINGS.md не восстанавливать; проверенные правила сохранять, ссылку на отсутствующий реестр убрать/уточнить.

Официальные страницы по модели и промптингу перечислены в PREPARATION.md. Не приписывать рекомендации Astra исключительно Sol Web; прочитать необходимые первичные страницы и применить общие принципы к предметной задаче. Не требовать скрытого chain-of-thought, не обещать Web-возможности из API-контекста. Использование реального Web-маршрута проверяет исполнение редакторской задачи, но не является сравнительным eval методички. Сценарии без фактического запуска помечать NOT_RUN.

Приёмка исполнителя: полный исходник прочитан; существенные требования покрыты; ссылки в назначенном файле проверены; готовый документ перечитан; scoped diff проверен; краткий отчёт содержит source hashes, изменения с причинами, матрицу существенных требований и фактические проверки.
