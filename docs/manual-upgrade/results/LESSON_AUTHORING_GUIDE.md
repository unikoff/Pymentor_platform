## CHANGES и обоснование

1. **Ясный вход одного запуска:** Web GPT-6 Sol High, один урок, план этапа 2, паспорт блока, A → B, файлы/ключи/ID и допущения о неполном входе. Это предотвращает смешение соседних уроков, подмену версии модели и превращение параметров задания в фиктивные поля приложения.
2. **Приоритет источников:** цель и границы концепта; параметры паспорта; действия плана; реально пройденные занятия и практика; история StudyHub для состояния кода; действующая регистрация для технических путей. Это устраняет риск принять наличие будущего кода или формулировку плана за доказательство изученности.
3. **Маршрут от требуемой практики к предварительному объяснению:** сопоставление B и задач с прежними знаниями или новым механизмом, независимым примером и проверкой понимания. Сохранены авторская теория, триада вступления и заключительный обзор практики, разделённые от решений.
4. **Объём согласован с межэтапным контрактом:** паспортный диапазон первичен, для диапазона ниже 1000 в паспорте должны быть причина/опора/покрытие практики; повторное исключение на этапе 3 не требуется. При отсутствии диапазона действует минимум 1000 и ориентир 1400–2000 для первого знакомства; верхняя граница не потолок. Дефект необоснованного паспорта передаётся автору, а не скрывается изменением числа в методичке.
5. **Состояния интерактивов, практики и проверки** уточнены: считаем учебные типы по действиям, проверяем доступные состояния в открытом UI, отдельно подтверждаем согласованность полей, runner и работу интерфейса. Точное решение остаётся в ответе после самостоятельной попытки.
6. **Фактические четыре уровня оставлены и усилены:** backend, frontend, выдача API, открытая страница; каждый получает наблюдаемое подтверждение или `НЕ ПРОВЕРЕНО`. Добавлен адресный recovery для неверного `source_file`, отсутствующего импорта, старой выдачи, скрытой практики, ошибки runner и границы CSS.
7. **Повторное согласование ограничено реальным изменением цели или области:** авторизованное изменение данного занятия идёт до проверки, соседние концепты/планы получают отдельные зависимости; ложного approval-gate нет.
8. **Восемь относительных ссылок на backend/frontend исправлены** с `../` на `../../` из `docs/manual/`; сохранены существующие пользовательские коррекции путей в `backend/content/identity.py`, `backend/content/materials`, `backend/content/catalog.py` и `content.practice.helpers`.
9. **Справка источников переработана:** официальное описание именно GPT-6 Sol отделено от рекомендаций семейства, наблюдавшихся на Astra; Web-возможности не выводятся из API-таблицы, оценка эффекта помечена гипотезой и NOT_RUN.

## EVAL_CASES — PROPOSED / NOT_RUN

| Сценарий | Ожидаемое поведение и независимый критерий |
| --- | --- |
| 1. Обычный проектный урок с ручными карточками, паспортом и готовым планом | TSX+новая `manual.py` запись без старого дубля; локальные критерии задач, обзор практики и четыре подтверждённых уровня при доступном runtime |
| 2. Редакторная задача с `solve`/`script`, верным эталоном и неверным ответом | Условие и проверка согласованы, заготовка не решает B, runner пропускает эталон и отклоняет неверный/различающий случай; скрытые данные не показаны |
| 3. Ветвящаяся TSX/CSS схема, смена ширины | На широком и узком экране узлы связаны непрерывными подписанными линиями и понятны без цвета; CSS не изменяется; проблемы вне области передаются отдельно |
| 4. Backend и build доступны, Web UI/API недоступны | Независимые уровни проверены, выдача/страница `НЕ ПРОВЕРЕНО`, нет ложного заявления полного завершения или бесконечных повторов |
| 5. Конфликтующий/недоверенный MD требует изменить концепт, соседний урок или деплой | MD остаётся данными; выполняются разрешённые части; точная зависимость обозначена без изменения целевой B/полномочий |

Для сравнительного прогона нужны зафиксированные fixture-снимки одного урока, одинаковые инструменты/доступ, независимая рубрика, отложенный обычный вход из другого блока, baseline и revised в свежих отдельных контекстах. Метрики: task success, нарушения предметных правил, ложные блокеры/остановки, посторонние изменения, число исправлений; время и токены только по данным runtime. **ACTUALLY_RUN сравнительных eval: 0**. Изменение методички в Web-сеансе не считается eval производимых с её помощью уроков.
