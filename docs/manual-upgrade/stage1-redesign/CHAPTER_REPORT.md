## 2. Отличия и причины

| Изменение по сравнению с прежним COURSE | Почему необходимо | Граница/компромисс |
| --- | --- | --- |
| Четыре явно размеченных прохода **C1–C4**, каждый с входом, сохранённым результатом и локальной проверкой | Даёт повторяемый маршрут для одной главы и не требует широкого повторного аудита после каждого блок-автора | Всё сохраняется **в одном COURSE**, нет промежуточных отдельных методичек/баз данных. |
| Нормированный `FRAME_ACCEPTED`, `FRAME_VERSION`, `B_AGREED` | Исключает четыре параллельных проектирования по несовместимым гипотезам | Статусы — документация координации, **не** machine-readable поля приложения; при нерешённом существенном споре о B остаётся DRAFT. Прямое поручение в его границах достаточно для принятия B без нового approval. |
| Интерфейсы BLOCK_1…4 одинаковой формы, с входом, границами, собственным проверяемым выходом, продуктом и нагрузкой | Позволяет стартовать 4 локальных BLOCK без ожидания предыдущего черновика | Не указывает все занятия, номера, word ranges каждого урока, готовый PLAN. |
| Реестр пяти переходов **A→1→2→3→4→B**, с поставщиком, статусом, подготовкой, проверкой и ремонтом | Не допускает «план прежнего блока = проверенная A» и фиксирует ответственность за предпосылку | После локальных блоков фактические стыки всё равно повторно проверяет 03. |
| Двунаправленная трассировка и поиск **первого необеспеченного действия** | Локализует скачок сложности, отсутствие практики или поздний ввод знания | Не предлагает выдуманную шкалу сложности и не подменяет подробный урок. |
| Развилки новая/частично освоенная/имеющая только код или материалы/конфликт/восстановление | Устраняют неявное смешение факта обучения, состояния проекта и проектной цели | Некритичную неопределённость допускают только с указанной проверкой до обязательного использования. |

**Адресная корректировка от 25.10.2026:** прежняя формула C1 п. 5 требовала выставлять `B_PROPOSED` и заново утверждать B даже при прямом поручении спроектировать новую главу. Теперь поручение в заданных пределах явно обосновывает `B_AGREED`; C1, C4, шаблон `COURSE.md` и развилки согласованы. Повторное решение требуется лишь при выходе за установленную цель/границы, неразрешённом существенном противоречии или пользовательском checkpoint. Ранее согласованную B нельзя менять незаметно.
