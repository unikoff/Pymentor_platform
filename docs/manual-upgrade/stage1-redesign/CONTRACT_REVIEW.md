## 2. Что в исходном контракте уже работает

1. COURSE различает заданный вход аудитории, проверенное освоение, запланированное и неизвестное; B описывает через понимание, самостоятельное действие и наблюдаемый результат; маршрут проверяет вперёд и назад. Согласованную B нельзя незаметно заменить при переработке (COURSE, §§2–4, 7).
2. BLOCK требует карту **всех** занятий, семь содержательных полей **каждого** паспорта, проверяемую практику и передачу предыдущего B как **условной планируемой A**, если занятия ещё не проведены (BLOCK, §§0–5).
3. Структурный инвариант: в блоке ровно **пять основных учебных дней**, каждый может иметь обязательные самостоятельные подзанятия. Номера сквозные по курсу, хранятся строкой / парой чисел, публичные ID сохраняются отдельно от отображаемой перенумерации (BLOCK, §3).
4. Формат практики определяется образовательной задачей и обязательным договором; проект, интерпретатор/редактор и обоснованный устный разбор не взаимозаменяемы произвольно. Проект сохраняет накопленные возможности. Практика должна проверять **собственное действие**, а не просмотр готового решения (BLOCK, §§2–3).
5. Новый паспорт содержит **числовой диапазон видимой теории и предметное основание**; общий ориентир от 1000, для первого знакомства обычно 1400–2000 слов не является обязательной квотой вместо паспорта. Обоснованный диапазон ниже 1000 допустим. Только установленный по происхождению legacy-паспорт без восстановимого диапазона получает маркированный резерв в PLAN (BLOCK, §3; P1, §3; P4, §3).
6. P1 уже принимает в качестве входа точный паспорт, A/B/границы/формат/диапазон, а P4 проверяет полную подробную траекторию объяснения и каждого шага практики; принимать вместо них паспорт как подробный план нельзя (P1, §§1–5; P4, §§2–6).

Следствие для новой методики: существующие нормы **перенести без ослабления**, добавив проверяемую сквозную связность и диагностику посильности. Повторное перечисление общих запретов из AGENTS.md не повышает предметное качество.

## 4. Предлагаемый контракт связности без расширения паспорта до PLAN

### 4.1. Два прохода по одной цепочке результата

**Сверху вниз:**

`A главы → B каждого из четырёх блоков → B конкретного занятия/подзанятия → своё обязательное действие → наблюдаемый результат и критерий`.

**Снизу вверх:** каждое обязательное действие имеет доказуемый выход; каждый выход нужен B своего занятия; совокупность выходов занятий покрывает B блока; совокупность результатов четырёх блоков покрывает B главы. Обязательное действие, не связанное с B, либо получает обоснованную подготовительную роль/перенос, либо становится необязательным/убирается **в пределах согласованной цели**. Удалять обязательную B потому, что её забыли в карте, нельзя.

На каждом уровне хранить связи **на понятия и самостоятельные действия**, а не только на номера тем. Номер/название помогает найти паспорт, но не доказывает наличие механизма. Одно действие может опираться на несколько подготовленных механизмов; один ранее изученный механизм может поддержать несколько следующих действий. В графе таких зависимостей не должно быть циклов и ссылок на будущее, если новое знание не объясняется и не отрабатывается до первого обязательного действия **в текущем занятии**.

### 4.2. Семь полей паспорта: минимальная достаточная микроконцепция

| Существующее поле BLOCK | Что необходимо удержать в нём | Что обязан достроить stage 2, а не паспорт |
| --- | --- | --- |
| 1. Тема и назначение | Один ключевой учебный вопрос, роль именно в этом месте главы/блока и зависимость от соседнего шага. | Вступление, конкретная педагогическая формулировка, переходы между разделами. |
| 2. Точка A | Необходимые для обязательных действий знания и состояние проекта; для каждого существенного элемента статус, источник, номер/результат-поставщик, конкретное место подготовки и условие проверки планируемой опоры. | Доказательная сверка фактически выданной теории/практики, полный учёт состояний и заготовки для задач. |
| 3. Точка B | Формулировка «ученик объяснит X, **сам построит/изменит/исследует Y**, получит наблюдаемое Z»; уровень самостоятельности. | Детальные шаги, промежуточные результаты всех упражнений, договор входов и ошибок. |
| 4. Необходимые темы | Ключевые механизмы в порядке первого появления: известный, впервые объяснить **здесь до практики**, отложенный; особые предпосылки для самостоятельного Y. | Доказательные примеры на другом сюжете, пояснения, аналогии, типовые заблуждения и подробная траектория теории. |
| 5. Основная практика | Обязательный **буквальный формат**, стартовая опора, собственные операции ученика, общий продукт, ключевой различающий случай и проверяемое поведение; не готовое решение. | Последовательные упражнения, тексты условий, локальные проверки каждого шага, подробная обратная связь. |
| 6. Выход и переход | Как одним или несколькими наблюдениями проверяется B; что остаётся работающим/освоенным **как планируемый результат**; какое следующее занятие его потребляет либо почему маршрут заканчивается. | Полная сверка предыдущего/следующего MD и условия реальной выдачи. |
| 7. Диапазон видимой теории | Конкретные границы в словах, основание из новых механизмов, опоры и практики; для обоснованного диапазона ниже 1000 — явная причина и покрытие каждого обязательного действия. | Детальная развёртка и фактический подсчёт написанной теории в соответствующем следующем этапе. |

Пример уровня **паспорта**, без создания учебного материала: «Ученик на незнакомом списке **сам пишет цикл и условие** для отбора элементов, показывает результат для случая с совпадениями и без совпадений. Обход и ветвление либо подтверждены предыдущими самостоятельными действиями, либо вводятся **в этом занятии до** самостоятельного отбора; объяснение готового фильтра не заменяет код ученика». Это точнее «изучить фильтрацию», но ещё не P2/P3: отсутствуют готовые объяснения, пошаговый шаблон задания, ответ и тесты.

**Важное различие:** «не встречалось до занятия» не означает «неподготовленная обязательная практика», если текущий урок **раньше первого использования** учит механизму, даёт небольшой управляемый пример, после чего требует собственное действие. Неподготовленная A — это отсутствие и прежней опоры, и такой внутрисессионной подготовки. Паспорт не должен выдумывать факт освоения даже при грамотно спроектированном будущем объяснении.

### 4.3. Проверка каждого ребра, а не только документов

Для перехода `поставщик → потребитель` ответить на четыре вопроса в самом связанном COURSE/BLOCK (или в рабочей сверке без отдельного обязательного файла):

1. **Что передаём?** Точное умение/конкретный результат, его источник (глава, блок, номер занятия **строкой**) и статус: подтверждён фактом, планируется, не проверен, не подготовлен. Существование готового проекта и самостоятельное умение ученика проверяются **раздельно**.
2. **Где формируем?** Предыдущее занятие содержит до передачи необходимое объяснение, собственное пробное/основное действие и наблюдаемый выход. Если новый механизм вводится в текущем занятии, указываем порядок «ввод → управляемая проба → самостоятельное действие», без ложной ссылки на прежнее освоение.
3. **Чем проверяем?** Назван результат, доступный сразу после самостоятельного действия, на нормальном и при необходимости различающем случае; для будущего маршрута — дополнительное условие подтверждения перед фактической выдачей потребителя.
4. **Что происходит при провале?** Назвать точную точку ремонта и повторно проверить затронутую цепочку, не переписывая автоматически соседние файлы вне разрешённого объёма.

Проверить все типы границ: `A главы → первый BLOCK`; внутри каждого из четырёх блоков **каждую** соседнюю пару основных занятий/обязательных подзанятий; `BLOCK 1→2`, `2→3`, `3→4`; `последнее занятие BLOCK 4 → итоговая B главы`. Если это **последний** предусмотренный блок или последнее занятие, не требовать фиктивного следующего паспорта; проверить терминальный результат и явно обозначить конец маршрута. Если продолжение предусмотрено, но паспорт отсутствует, указать «передача дальше не проверена» с зависимостью; не объявлять весь маршрут закрытым.

Готовность будущей последовательности — **документально проверенная планируемая связность**, а не доказательство реального learning gain. Фактическая выдача и ученическое освоение проверяются отдельно при реализации.

## 5. Диагностика и адресное устранение скачков сложности

Трассировать **от наиболее трудного самостоятельного обязательного действия назад** до реально подготовленных знаний. Затем мысленно пройти **вперёд глазами начинающего**: исходный объект → известные понятия → первый пример/проба → собственная операция → локальный видимый результат → следующая операция. На каждом переходе спрашивать: «что должен знать, что впервые объяснено, что уже делает самостоятельно, что должен вывести без обучения?».

| Симптом / вероятная причина | Как доказать на концепте | Локальное исправление и повторная проверка |
| --- | --- | --- |
| Незнакомый синтаксис, понятие или состояние возникает только в основной задаче. | У обязательной операции нет предыдущей/внутрисессионной опоры с первым объяснением и применением. | Поставить механизм и управляемую пробу раньше первого использования; если не помещается — дать обязательное подзанятие или перераспределить материал между днями/блоками. Повторно проверить источник и переход. |
| Между примером и самостоятельной сборкой несколько ещё несвязанных операций. | Ученик должен одновременно самостоятельно придумать новый алгоритм и освоить новый синтаксис; промежуточный результат не указан. | Разделить на посильную микропробу отдельного механизма, перенос на изменённый случай, затем соединение. Не превращать последовательность в готовое решение основной задачи. |
| Стартер уже содержит обещанное в B действие. | Если убрать/заменить одну строку, итоговый смысл реализуется готовой заготовкой. | Оставить технический каркас, а ключевую конструкцию/решение поручить ученику; проверить, что именно **своё действие** подтверждает B. |
| «Планируемая A» есть только названием в предыдущем паспорте. | Нет конкретного предыдущего объяснения, самостоятельной практики и наблюдаемого результата. | Детализировать подготовку на уровне предыдущего паспорта либо перенести ввод в текущий до практики; оставить будущую проверку факта освоения. |
| Слишком много принципиально новых механизмов на одном переходе. | Невозможно указать отдельную безопасную пробу и проверяемое применение ключевых операций до общей B. | Изменить порядок/разложение на обязательные подзанятия, перераспределить дни/соседние блоки, сохранив пять основных дней, границы и итоговую B. |
| Проектная практика предполагает ещё не существующий компонент или ломает прежний инвариант. | Нет подтверждённого снимка проекта на A либо требуемой планируемой операции поставщика; отсутствует проверка сохранения прежних функций. | Установить версию входного проекта, подготовить компонент вовремя, явно включить проверку сохранности в ожидаемый результат. |
| Действие описано, но ученик не может узнать, получилось ли. | Нет видимого выхода/различающего случая; ожидаемое «понял» недоступно наблюдению. | Заменить непроверяемую формулировку конкретным ответом/поведением/объяснением причины и повторить трассировку B назад. |

**Правило ремонта:** назвать первое разорванное ребро, его причину, наименьшую допустимую правку и все непосредственно затронутые переходы; повторно проверить эти переходы **и соответствие итоговой B**, а не проходить всю систему без причины. Если локальная правка не устраняет зависимость, подниматься на границу занятия, блока, главы. Нельзя менять согласованную B или менять чужие исходники только для получения PASS; такой конфликт фиксируется как требующий решения владельца.

**Оценивание без «магической шкалы».** Не вводить баллы «сложность 1–10», искусственные максимумы нового материала или непроверенные обещания минут. Вердикт для конкретного перехода — `ПОДГОТОВЛЕН`, `УСЛОВНО ПОДГОТОВЛЕН` (будущий поставщик назван, перед выдачей нужна проверка), `НЕ ПРОВЕРЕН`, `РАЗОРВАН`, с конкретным основанием и действием. `УСЛОВНО ПОДГОТОВЛЕН` может быть принят для **проектирования будущего** при полноте источников/контроля, но не приравнивается к фактическому освоению.

## 6. Контрольные точки будущего workflow и передача PLAN

| Контроль | Минимальное наблюдаемое основание готовности | Если не готово |
| --- | --- | --- |
| Концепт главы перед детализацией | Подтверждённая/явно условная A с источниками, проверяемая B, границы и карта **четырёх заказанных** блоков; для каждого — вклад в B, промежуточный проверяемый выход и известная зависимость; ни одной необоснованной критической предпосылки. | Сохранить проект и независимую часть; назначить источник/подготовку/решение точно по проблемной строке, не считать согласованную цель изменённой. |
| Очередной BLOCK после одного универсального маршрута | Собственный A→B согласуется со строкой COURSE; ровно пять основных дней, полный маршрут обязательных подзанятий; все семь полей паспорта каждого занятия; внутриблочные рёбра и формат/диапазон доказуемы документально. | Исправить локальный концепт в разрешённой области; конфликт с уже готовым соседом передать на общую сверку, не считать целую главу готовой. |
| После **четырёх** проходов блока | Существуют четыре полных и принятых **как концепты** BLOCK; все три межблочных стыка, начало и терминальный результат закрыты; нет пропущенных паспортизированных подзанятий, пересечений несовместимых ID или обязательной B без действия и проверки. | Статус общеглавной передачи — `NOT_READY_FOR_STAGE2`, с точным списком дефектов; принятые независимые BLOCK сохранить. |
| Передача в отдельный stage 2 | Для каждого занятия номер строкой, идентичность/публичный ID или явная зависимость, паспортные A/B, источники статусов A, место подготовки и условие проверки, обязательный формат, диапазон **с причиной**, границы и передаваемый результат. | Новый паспорт без диапазона/причины не получает PASS; доказанный legacy без восстановимого диапазона передаётся маркированно по действующему правилу P1/P4. |

Нельзя заменять этот выход укороченной схемой без готовых паспортов: stage 2 строит **подробный PLAN** и отдельно принимает его через P4. Решение `READY_FOR_STAGE2` означает готовность **проектных источников**, не существование принятых MD-планов и не работу платформы.

## 9. CHANGES, SOURCE_EVIDENCE, LIMITATIONS

**CHANGES:** предложены: обязательная готовность главы до BLOCK; ровно четыре последовательных применения одного универсального блока в этом workflow; микроконцепция внутри семи существующих полей; двунаправленный контроль «глава ↔ блок ↔ занятие ↔ собственное проверяемое действие»; проверка каждого ребра, отдельная финальная сверка четырёх блоков; локальная диагностика скачков сложности. **SOURCE_EVIDENCE / актуальность:** локальные тексты COURSE/BLOCK и P1/P4 прочитаны 25.10.2026; SHA действующих трёх файлов stage 1 соответствует [контрольной описи](baseline.json). **LIMITATIONS:** это документальное проектное ревью.
