Прежняя формула «согласованная или явно обозначенная предложенная B» заменена строгим `B_AGREED` с одним из двух достаточных оснований: установленная цель либо конкретизация по прямому поручению **в заданных границах**. Если пользователь поручил спроектировать главу/B и цель принята внутри этих границ, повторное одобрение человеком **не требуется** и F3 применяет остальные предметные критерии. `B_PROPOSED` означает действительное нерешённое решение — выход за мандат, существенный конфликт либо явный checkpoint; независимые проверки продолжаются, но итог `CHAPTER_STAGE1_INCOMPLETE` до разрешения. Это устраняет ложный gate, не разрешая скрытую смену ранее установленной B. Иные разделы методички не перерабатывались.

**Предметные иллюстрации (документальные, не проведённые прогоны):** (а) поручение «спроектируй проверяемую B этой главы в данных границах» → `COURSE` содержит основание прямого мандата и `B_AGREED` → при остальных 4/4, N/N и стыках возможен `CHAPTER_STAGE1_ACCEPTED` **без нового запроса к человеку**; (б) блок предлагает заменить ранее согласованную B за пределами поручения, или источники цели существенно конфликтуют → остаётся `B_PROPOSED`, записывается точная зависимость и `CHAPTER_STAGE1_INCOMPLETE`, сохраняя независимые проверки.

**Дополнительная проверка на циклы:** зависимость `COURSE → BLOCK×4 → F1/F2/F3 → отдельный PLAN` не требует локального ожидания готового соседнего блока; будущий поставщик берётся из принятой рамки. Дефекты возвращаются по конкретному ребру и владельцу, а изменение рамки отменяет только устаревшие подтверждения затронутых ветвей. Это не гарантия числа итераций, а правило конечного критерия готовности.
