# Beta-инструменты stage 1 — 25.10.2026

Не менять цели курса, реальные концепты, уроки, пути/ID в рабочем контенте или запускать следующий stage.

- Beta-Skill stage 1: `.agents/skills/pymentor-stage1-beta/SKILL.md`. Общий `pymentor-stage-batch` и его stage 2/3 маршруты сохранить. Причина отдельной beta-точки входа: во время запуска обнаружен активный preflight, имеющий общую область записи в Skill stage 2/3; одновременно этот файл не редактировать. Возможное объединение после обкатки является будущей задачей, не текущим действием.
- Локальные новые профили: `.codex/agents/pymentor-chapter-worker.toml` (`pymentor_chapter_worker`) и `pymentor-block-worker.toml` (`pymentor_block_worker`). Обоим `model="chatgpt-web/gpt-6-sol"`, `model_reasoning_effort="high"`. Глава: C1–C4 и отдельно назначенная интеграция F1–F3; блок: B1–B4 одного файла, повторяемый четырьмя исполнителями. Нет рекурсивной диспетчеризации.
- README/AGENTS/RUN_TEMPLATE stage 1 обозначают beta, ссылаются на реальный Skill и профили, сохраняют один COURSE + четыре BLOCK + все N паспортов, максимум5 активных Web во всей среде, отдельный оркестратор и один владелец файла.
- Авторская цель в мандате не требует нового approval. Проектная готовность не равна фактическому обучению. Не запускать автоматически stage 2/3.
- Номер, название и положение занятия в отображаемом маршруте могут меняться. Не выводить стабильную идентичность, public ID или прогресс из названия/номера; сохранять существующие ID и пути. В текущем каталоге Pymentor ID хешируется из канонического source path через таблицы identity aliases, поэтому перенос/переименование физического пути требует отдельной миграции и проверки прогресса. При переименовании/перенумерации вести явное old→new соответствие и проверять ссылки. Вставка/удаление/перестановка требует пересобрать маршрут и перепроверить A→B, сложность и связи COURSE↔BLOCK. Схемы регистрации и миграции не менять в этом beta-наборе.
- Не смешивать legacy и новые планы: у существующего урока ожидаемый, но неподтверждённый `lesson_id` означает `BETA_GAP: LESSON_IDENTITY_UNVERIFIED`; у нового ещё не созданного урока корректная отметка — «ID требует назначения по действующей схеме», с владельцем/этапом будущего mapping, без выдумывания ID и без автоматического блокирования Stage 1.
- Делегирование: native spawn — `agent_type`, `model`, `reasoning_effort`; create_thread — `model`, `thinking`, переданные инструкции роли, без выдуманного agent_type. Проверять живой каталог/результат; файл профиля не доказывает загрузку runtime.
- Глобальный config.toml, текущие stage 2/3, реальная COURSE/BLOCK/платформа и три методички не меняются. При реальном запрете записи в проектные .agents/.codex сохранить кандидаты в audit drafts и передать конкретную ошибку оркестратору; не обходить ограничения.
- Проверка beta: валидатор Skill, TOML/ссылки, сохранность stage2/3, независимые сценарии маршрутизации без реальной генерации главы; видимость профилей и read-only smoke только если runtime позволяет. Отмечать NOT_VERIFIED при отсутствии подтверждения, не заявлять промышленную проверку или экономию.
