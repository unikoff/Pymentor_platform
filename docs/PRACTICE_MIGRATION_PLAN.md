# Перенос практики к занятиям

План для модели-исполнителя. Меняем расположение файлов и подключение, не содержание заданий.

**Реализация завершена:** все девять курсов, обзорные материалы и блоки переведены на эту структуру. Все прежние каталоги практики доступны через обычные импорты. Проверки и известные ограничения указаны в отчёте Codex. План сохраняет правила для поддержки и новых переносов.

## 1. Целевая структура

Теория и практика лежат вместе в папке блока. Отдельной папки `practice` нет.

```text
backend/learning/
├── rich_practice.py              # прежние getters и экспорты
├── rich_code_tasks.py            # прежние getters и экспорты
├── practice_helpers.py           # общие конструкторы и проверки
└── course_content/
    ├── __init__.py               # пустой
    └── planner_api/
        ├── __init__.py           # сборка каталогов курса
        ├── track.json            # прежний id, русское title, порядок
        ├── README.md
        ├── block_00/
        │   ├── __init__.py
        │   ├── План обучения.md
        │   ├── Теория месяца.md
        │   └── manual.py         # OVERVIEW_PRACTICE
        └── block_09/             # так же block_10, block_11, block_12
            ├── __init__.py
            ├── 45 - ...md
            ├── ...              # остальные Markdown блока
            ├── manual.py        # MANUAL_PRACTICE
            └── code_tasks.py    # CODE_TASKS
```

Правила:

1. Папки курсов и блоков являются Python-пакетами: строчные латинские буквы, цифры и `_`, начало с буквы. Без пробелов и дефисов. Блоки называются `block_00`, `block_09` и так далее.
2. Русские названия остаются в Markdown, метаданных и интерфейсе. Markdown-файлы не переименовывай ради импортов. Ограничение относится к папкам Python-пакетов, а не ко всем папкам проекта.
3. `__init__.py` использует явные обычные импорты. Не нужны `importlib`, `exec`, поиск пакетов по диску или изменение `sys.path`.
4. Один файл на вид практики внутри блока, не файл на каждую карточку. Пустой вид практики содержит пустой словарь, а не выдуманное задание.
5. Корневой `course_content/__init__.py` не импортирует все курсы.

У каждого блока одно физическое место хранения: рядом лежат его Markdown и Python-файлы практики. Не создавай отдельный `practice/`, копии каталогов, символические ссылки или дополнительный загрузчик ради обхода обычных импортов.

## 2. Форматы файлов

| Файл | Экспорт |
| --- | --- |
| Обычный `manual.py` | `MANUAL_PRACTICE: dict[int, list[dict[str, Any]]]` |
| `code_tasks.py` | `CODE_TASKS: dict[int, list[dict[str, Any]]]` |
| `block_00/manual.py` | `OVERVIEW_PRACTICE`, ключи: прежние имена обзорных файлов |
| `block_NN/__init__.py` | Два словаря и проверка диапазона |
| `block_00/__init__.py` | Только обзорный каталог |
| `<курс>/__init__.py` | ID, алиасы, обзор и два собранных каталога |

Пример `block_09/__init__.py`:

```python
from learning.practice_helpers import validate_block
from .manual import MANUAL_PRACTICE
from .code_tasks import CODE_TASKS

validate_block(45, 50, MANUAL_PRACTICE, CODE_TASKS)
__all__ = ["MANUAL_PRACTICE", "CODE_TASKS"]
```

Пример сборки курса:

```python
from learning.practice_helpers import merge_lesson_maps
from . import block_09, block_10, block_11, block_12
from .block_00 import OVERVIEW_PRACTICE

TRACK_ID = "HTTP, API и FastAPI - Planner API"
TRACK_ALIASES = (TRACK_ID,)
MANUAL_PRACTICE = merge_lesson_maps(
    block_09.MANUAL_PRACTICE, block_10.MANUAL_PRACTICE,
    block_11.MANUAL_PRACTICE, block_12.MANUAL_PRACTICE,
)
CODE_TASKS = merge_lesson_maps(
    block_09.CODE_TASKS, block_10.CODE_TASKS,
    block_11.CODE_TASKS, block_12.CODE_TASKS,
)
__all__ = [
    "TRACK_ID", "TRACK_ALIASES", "OVERVIEW_PRACTICE",
    "MANUAL_PRACTICE", "CODE_TASKS",
]
```

Обычный импорт:

```python
from learning.course_content.planner_api import MANUAL_PRACTICE, CODE_TASKS
```

Общие функции не импортируют курсы и `content.py`. Это предотвращает циклические импорты.

Содержимое карточек остаётся в прежнем формате. Перенос не является переходом на новый шаблон заданий: старые поля, шаги, подсказки и ответы сохраняются без изменений. Общие конструкторы используй из `practice_helpers.py`, не копируй их в каждый курс.

## 4. Сначала сохрани исходное состояние

1. Проверь `git status`. Исходник: текущая рабочая папка со всеми пользовательскими правками, не HEAD.
2. Сохрани типизированный снимок всех 27 каталогов, констант ID и алиасов, результатов getters, полного `TRACKS`, ревизий задач и `CONTENT_REVISION`.
3. Зафиксируй байты Markdown и прежние `source_file`. Подготовь сравнение до редактирования.
4. Снимки содержат ответы и скрытые тесты: храни их вне Git в отдельной временной папке. Сохраняй типы, числовые ключи и порядок списков.
5. Запусти затронутые тесты и отдельно запиши уже существующие ошибки.

## 5. Сохрани идентичность при переименовании

1. В `track.json.id` сохрани прежний ID из загрузчика. Не подставляй короткое имя пакета. У некоторых курсов ID загрузчика отличается от основной константы каталога; оба прежних значения и алиасы должны остаться рабочими.
2. До перемещения добавь точное соответствие нового пути Markdown прежнему пути в `content.py::LESSON_SOURCE_ALIASES`. Дополняй существующую карту, не заменяй её: записи уже перенесённых курсов должны остаться.
3. Используй прежний путь для хеша lesson ID и старых служебных настроек. `source_file` должен содержать новый физический путь.
4. Сохрани порядок занятий и русские подписи модулей. Учитывай ID из метаданных при фильтрации файлов и назначении подписей. В интерфейсе не должны появиться технические названия вроде `block_09` вместо названия блока.
5. Обнови frontend-реестр курса под новые физические пути. Каждый Markdown должен выбирать свой прежний TSX-компонент.
6. Проверь относительные ссылки и изображения: после добавления уровня `block_NN/` им может понадобиться ещё один `../`. Исправляй только путь, не текст занятия.
7. Найди проверки, привязанные к прежнему имени папки, и переведи их на стабильный ID курса. Особенно проверь доступ и нумерацию первого курса: переименование не должно изменить бесплатные занятия, доступ по аккаунту или Pro. Меняется способ определения курса, не политика доступа.

Пример метаданных переименованного курса:

```json
{
  "id": "HTTP, API и FastAPI - Planner API",
  "title": "HTTP, API и FastAPI: Planner API",
  "tagline": "HTTP, Pydantic, CRUD, роутеры и тесты FastAPI",
  "order": 3
}
```

Для другого курса сохраняй его собственные прежние значения. `planner_api` является именем пакета, а не новым публичным ID.

Стабильные lesson ID, task ID и ревизии задач не меняются. Общий `CONTENT_REVISION` при смене `source_file` меняется ожидаемо. Не обновляй снимок, чтобы скрыть другое расхождение.

## 6. Переноси один полный курс за раз

1. Переименуй папку курса в Python-имя и разложи Markdown по блокам. Убедись, что загрузчик сохранил все занятия и ID.
2. Для выделения каталогов используй AST и исходные фрагменты, не регулярные выражения: учебные строки могут содержать `def` и другие конструкции.
3. Перенеси элементы по числовым ключам в `manual.py` и `code_tasks.py` своего блока. Обзор переносится по строковым ключам в `block_00/manual.py`.
4. Не применяй `strip`, `dedent` или нормализацию к строкам стартового, эталонного кода и тестов. Если после объявления есть вычисления или изменения словаря, сохрани их зависимости.
5. Подключи блоки через `__init__.py` и сравни собранные каталоги со снимком.
6. Переключи только прежние экспорты этого курса:

```python
# rich_practice.py
from learning.course_content import planner_api as _planner_api

PLANNER_API_TRACK = _planner_api.TRACK_ID
PLANNER_API_OVERVIEW_PRACTICE = _planner_api.OVERVIEW_PRACTICE
PLANNER_API_PRACTICE = _planner_api.MANUAL_PRACTICE

# rich_code_tasks.py: отдельный такой же импорт _planner_api
PLANNER_API_TRACK = _planner_api.TRACK_ID
PLANNER_API_CODE_TASKS = _planner_api.CODE_TASKS
```

7. Удали старые объявления каталогов этого курса, но сохрани публичные имена. Не оставляй второе присваивание, которое перекроет импорт.
8. Расширяй тесты миграции на каждый переносимый курс: проверка одного курса не доказывает корректность остальных. После текущего переноса проверь его целиком и общую совместимость платформы.

Все курсы из таблицы уже перенесены. Не меняй структуру соседнего курса при обычном добавлении карточки: существующие импорты, frontend и getters уже подключены.

## 7. Контракты и запреты

- `merge_lesson_maps(*catalogs)` сохраняет порядок обхода и ссылки на списки; повторный номер вызывает `ValueError`, даже для равных значений.
- `validate_block(first, last, *catalogs)` проверяет каждый вид независимо: `type(key) is int`, включительный диапазон, пустой словарь допустим.
- Ручные и редакторные данные могут иметь один номер. Сохрани прежний приоритет: кодовые задачи скрывают ручные карточки.
- Сохрани getters, обработку обзоров, алиасы, разбор номера filename и возврат `[]` для неизвестного ключа. Отсутствующий ожидаемый пакет не маскируй пустыми задачами.
- Старые вспомогательные имена доступны через импорты из `practice_helpers.py`. Не добавляй случайные экспорты `*_CODE_TASKS`: тесты собирают такие каталоги через `vars`.
- Не меняй условия, ответы, подсказки, тесты, номера, порядок карточек, режимы, проверяющий движок, подписки, БД, зависимости или чужие правки.
- Не добавляй задания и не исправляй содержание заодно с переносом. Без отдельного запроса не коммить, не пушь и не запускай деплой.

## 8. Проверки и завершение

Из корня проекта:

```powershell
$env:PYTHONPATH = (Resolve-Path .\backend).Path
.\.venv\Scripts\python.exe -m unittest discover -s backend/tests -p test_practice_catalog_migration.py -v
.\.venv\Scripts\python.exe -m unittest discover -s backend/tests -v
git diff --check
```

Для Python/TSX также проверь обычные импорты и сборку frontend. Не меняй tracked-сборку ради проверки: результат можно направить во временный `outDir`.

Сначала запускай целевые проверки. Общую проверку выполняй после завершения курса; уже существующие ошибки отчитай отдельно, не исправляй содержание практики ради зелёного результата.

Сравни со снимком:

1. Все каталоги, ID, алиасы и результаты getters. Значения и порядок списков совпадают.
2. Все занятия и задачи загрузились; их ID, task revisions, доступ, видео и содержимое практики сохранены.
3. Меняются только согласованные физические пути и относительные ссылки. Другие курсы не изменились.
4. Нет ложных курсов из `__pycache__`. Метаданные сохраняют старый ID курса.
5. Все редакторные эталоны проходят тесты, неверный код не засчитывается. В API не появились скрытые тесты или `reference_code`.
6. Frontend-реестр покрывает все новые пути. Ручная практика, подсказки, ответы и редактор работают под допустимым тестовым доступом. Недоступную браузерную проверку обозначь отдельно.
7. В перенесённых курсах нет старых копий практики, отдельных папок `practice` и динамической загрузки через `importlib`. Прежние публичные экспорты ведут к новым каталогам, а не к оставшимся дубликатам.

Уже запущенный backend может держать старые импорты в памяти. Проверка исходников не подтверждает обновление работающего сервера. При проверке локального приложения убедись, что оно загрузило новые пути и ревизию; если нужен недоступный перезапуск, явно укажи это ограничение. Продакшен в рамках переноса не трогай.

Обнови `CONTENT_AUTHORING.md` и `course_content/README-практика.md` под реальное расположение файлов. Удаляй лишнюю оболочку только после переноса всех исходников и проверки точных путей; предпочитай восстановимое перемещение.

Перенос завершён, когда у блока одно место редактирования теории и практики, обычные импорты работают, совместимость и сравнение подтверждены. Итог содержит фактические проверки и оставшиеся ограничения.
