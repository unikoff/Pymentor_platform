# Массовое выполнение Stage 2/3

Процедура для явно заданного одного stage и массива. Исходный чат управляет до конца. Один автор — одно занятие через P1–P4 либо M1–M5. Аудит, опись и интеграция — ограниченные служебные задания, без второго оркестратора. Инфраструктурные правки сами уроки не запускают.

Coordinator работает автономно и не рассчитывает на ответ пользователя в ходе запуска. Он сам разрешает обычные пробелы по каноническому концепту, принятым планам и сопоставимым урокам: выбирает минимальный обратимый вариант, не меняющий B, предпосылки или обязательный формат, и фиксирует только существенное допущение с источником в существующем RUN. Рутинные вопросы не задаются. Если нет безопасного решения или конфликт затрагивает цель/права, отмечается только минимальный набор зависимых ID; независимая очередь продолжается, RUN содержит точное решение, нужное от пользователя, без блокировки массива.

Не размножай одинаковые длинные промпты в контексте Coordinator. Ссылка вместо содержимого допустима при подтверждённом доступе исполнителя к файлам; роль и skill загружаются согласно действующему маршруту. Без доступа передай необходимые инструкции и факты явно. Сжатие вывода не должно скрыть FAIL, blocker, права записи или критерии готовности.

Helper: `python scripts/build_dispatch.py --stage 2 --lesson-id LESSON_ID --assignment contract.json --policy-file effective-policy.json --output dispatch.json`. В `scope` — пути/разрешения и нужный контекст одного урока, в `acceptance` — ожидаемое действие/проверка, а не абстрактное «сделай хорошо». Файл policy — фактический effective `pool`, не файл session override. Helper ничего не запускает. Для Stage 3 меняется `--stage 3`.

Задай ориентир первого сохранённого смыслового результата исходя из объёма урока. Обычно первичное чтение и выбор исправления не должны превращаться в самостоятельный многочасовой этап. Это ориентир для диагностики, не автоотмена и не обязательные отчёты по таймеру. Если прогресса нет, исполнитель сообщает реальный blocker/следующий конкретный шаг, а не начинает новый общий аудит. Разделяй задержку модели/транспорта, длительную команду и время редактирования; не приписывай всё агентскому reasoning.

Если иное не обосновано объёмом, ориентир для обычного REWORK — первый сохранённый смысловой результат в течение 10–15 минут доступной работы после чтения входов. При отклонении сообщается одно исключение с причиной и следующим результатом, без периодических отчётов. Это не гарантия скорости модели, таймер убийства агента или освобождения неизвестного слота.

## Содержательная работа и короткая локальная сдача

Автор сам проходит все P/M-проходы, сохраняя один результат. REWORK: достаточные источники → исходный учебный дефект → ранняя смысловая правка → улучшенная практика/объяснение → проверка переноса. CREATE не требует вымышленного «до». Хорошие части сохраняются; количество строк diff и число компонентов не доказывают качества.

Читай материалы и стандарты по необходимости один раз, перечитывай изменённое или недостающий фрагмент. Нельзя сначала строить полное досье, дополнительный план проверок и формальный handoff, откладывая доступное изменение. P/M — проходы над содержанием, а не отдельные чаты, коммиты или отчёты.

P4 принимает MD локально без требований будущего TSX. В Stage 3 автор завершает предметный M5 и доступные локальные проверки, возвращает LOCAL_READY при ожидании общей среды/интеграции. LOCAL_READY не увеличивает N_accepted и не означает COMPLETE. Освободившийся слот используется для отдельного автора следующего урока; нет ожидания окончания пятёрки или общей сборки каждым автором.

Сдача: lesson ID, состояние, пути/версия, один показательный смысловой результат/KEEP, проверки и остаток. Ориентир несколько строк с evidence-ссылкой; не фиксированный набор новых таблиц. При обязательном нерешённом входе — PARTIAL/BLOCKED только затронутого урока, с точным основанием и предпочтительным безопасным решением; остальные уроки и завершённые стадии продолжаются. Не выдумывай приёмку и не останавливай весь массив ради уточнения.

## Проверки один раз там, где они доказывают результат

Общий файл имеет одного владельца на короткую запись/интеграцию. Нельзя удерживать lease всё время редактирования и проверки урока. Другие авторы возвращают точные дельты; один владелец интегрирует их без конкурентной перезаписи. Сохраняются чужие правки, IDs, source_file, ключи, закрытые решения/тесты.

Автор выполняет быстрые адресные проверки изменённого материала. **Полная сборка, широкий backend-suite, общий API smoke и запуск browser/runner среды не выполняются отдельно каждым автором и после каждого прохода.** Один назначенный интегратор выполняет общие проверки на сохранённом итоговом наборе, переиспользуя тот же build/server/browser для всех уроков.

Четыре обязательных уровня M5 остаются:
1. Backend: корректные объекты/ключи/ID/практика каждого урока; общий запуск может покрывать несколько уроков.
2. Frontend: TypeScript/build и регистрации итогового набора; один успешный запуск на тот же набор вместо N сборок.
3. API: реальная выдача и доступ каждого затронутого урока, без утечки закрытого; общий сценарий должен перечислять покрытые IDs.
4. Страница/runner: каждый урок на широкой/узкой ширине, содержательные интерактивы и все обязательные задачи с верным/неверным и релевантным граничным вводом. Общая среда одна; факт проверки одного урока не покрывает соседний.

Результат общей проверки хранится в RUN одной записью: действие, итог, версия/набор зависимостей, покрытые lesson IDs. Поурочная запись ссылается на него. Совпадение версий/зависимостей и покрытия обязательно; чужой старый PASS или наличие файла не доказательство. Не требуется запускать всё повторно лишь потому, что общий тест начал другой исполнитель. После изменения повтори затронутые проверки; несвязанный PASS сохраняется только при подтверждённой независимости.

Команды имеют разумный timeout по типу проверки. Таймаут/Access denied/недоступная среда → одна ограниченная диагностика, exact repro, ответственный и BLOCKED/НЕ ПРОВЕРЕНО. Повтор допустим после конкретного изменения условий, не ради получения зелёного статуса. Пока среда заблокирована, продолжай независимое содержательное редактирование; финальный COMPLETE запрещён.

## Приёмка, исправления, завершение

Root принимает краткий итог и покрытие N/N один раз; не повторяет предметную проверку за автором и интегратором. Углубляется только при противоречии, FAIL, пропущенном обязательном критерии или явном запросе. Не назначает отдельного reviewer на каждый урок по умолчанию.

Дефект возвращается своему владельцу: файл/ключ → наблюдаемая ошибка → ожидаемый результат → затронутая проверка. После исправления проверяется именно она; повторный провал той же природы требует уточнить вход/диагноз, а не полного перезапуска stage. Короткий project-local вывод нужен только для повторяемой причины, не новый регламент на каждый случай.

Один [RUN_TEMPLATE](RUN_TEMPLATE.md): N и scope, назначения/worker IDs, урок→артефакт→состояние, общие checks/coverage, существенные допущения и blockers. Поурочные строки — единый источник истины для итоговых N/N и gate; не веди вторые расходящиеся списки в исключениях/сводках. Без per-pass SHA и многословных журналов. Ожидание по завершениям, не статусные ping. Неизвестный исход spawn сначала сверяется; переназначать только подтверждённый незавершённый остаток после terminal, не по таймауту.

### Возобновление после прерывания

При новом ходе, compaction или возврате после остановки считай `RUNNING` в RUN последней записью, а не текущей liveness. За один проход сверь точный ID каждого назначенного worker с фактическим состоянием чата. Сверь путь/версию принадлежащего ему артефакта и незакрытые критерии; обнови строку RUN. Не запускай проверку всех материалов заново.

- В wait передавай только точные ID, подтверждённые активными непосредственно перед вызовом. Вызов без получателей не является ожиданием; сначала запроси/получи состояние конкретных worker ID.
- Если worker завершён или прерван, проверь его артефакт. Готовый результат сохрани и продолжай с нужной приёмки; если результата нет или он частичный, переназначь только остаток этого урока. Назначай отдельного исполнителя на один lesson ID.
- Если фактическое состояние неизвестно, не жди повторно и не дублируй назначение: один раз разреши неопределённость через доступный источник статуса/артефакта. Если состояние так и не подтверждено, отметь `DECISION_REQUIRED`/`BLOCKED` только для затронутого урока и продолжай независимую очередь.
- После wait без события повторяй ожидание только если проверено, что указанные исполнители всё ещё активны. Не создавай циклы пустого wait и повторяющиеся сообщения «без изменений».

Ожидай нескольких подтверждённо активных исполнителей одним event wait и реагируй сразу на завершение. Это не барьер для следующих уроков. Дельты передавай интегратору по готовности; после сбоя сначала установи, перенесён ли конкретный ключ, затем исправь только незавершённое. Если сверка показывает несовпадение, сохраняй дефект и повторяй затронутую проверку. Общую итоговую проверку и все четыре PASS M5 сохраняй.

PLAN_ACCEPTED требует P4. COMPLETE Stage 3 требует предметного M5 и четырёх PASS с покрытием конкретного урока на итоговой версии. STAGE_COMPLETE требует все N принятых, интеграцию и отсутствие обязательных FAIL/BLOCKED/НЕ ПРОВЕРЕНО. Иначе STAGE_INCOMPLETE с точным остатком. Если пользователь явно перечислил несколько stage в порядке выполнения, после полного gate текущего массива продолжай следующий запрошенный stage без вопроса/подтверждения; не запускай неназванные stage или публикацию.
