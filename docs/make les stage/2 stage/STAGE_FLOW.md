# Stage 2 — рабочий маршрут

[Общий стандарт](../STAGE_COMMON_STANDARD.md) определяет запуск, сохранность и качество. Один пользовательский форк выполняет Stage 2 ровно одного занятия, сохраняет один MD-план и останавливается. Не создавай исполнителей или отчёты на каждый шаг.

## Вход

Установи одно занятие или подзанятие, его паспорт, целевой MD и разрешённую запись. Восстанови назначение по последнему актуальному поручению, не по старой очереди родительского чата. Для существующего урока сверь идентичность; новый runtime ID не выдумывай. Адресно прочитай паспорт, цели/ограничения главы и блока, источники необходимых опор и ближайшие переходы. При пробеле расширяй чтение до первоисточника. Планируемая опора не означает освоение.

## P1–P4 в одном задании

1. [P1 — рамка](01_PLAN_FRAME.md): сформулируй B и каркас единого MD, ссылаясь на паспорт и общие условия вместо их копирования.
2. [P2 — объяснение](02_THEORY_ROUTE.md): спроектируй порядок понятных объяснений и независимых примеров, подготовку новых механизмов до применения.
3. [P3 — практика](03_PRACTICE_ROUTE.md): задай старт, собственное действие, результат и подготовившую опору; уточни существенные ошибки и критерии.
4. [P4 — приёмка](04_PLAN_ACCEPTANCE.md): пройди путь по плану, сверь паспорт и переходы, исправь дефекты и прими окончательный MD.

План должен быть достаточен автору Stage 3, без подробной черновой теории и решений задач. Число разделов, задач и визуалов определяется смыслом. Для насыщенной практики учитывай последовательность новых действий, первую пробу, промежуточный результат и отладку. Оформление визуалов реализуется на Stage 3; здесь нужна их учебная функция.

## Итог и продолжение

PLAN_ACCEPTED относится только к актуальному плану после P4. Укажи путь принятого плана этого занятия и точные остатки. После прерывания продолжай незавершённый P по текущему MD; отдельный RUN обычно не нужен. Не переходи к следующему уроку. TSX, build, API, страница и runner не являются приёмкой Stage 2.

Stage 3 запускается отдельно без обязательной смены чата. Существующие планы и ссылки служат передачей; автоматического перехода нет. При возобновлении продолжай фактически незавершённое своего занятия. Правила сохранности при параллельных форках определены общим стандартом.
