# AGENTS.md: Stage 2, один план

Применяй [общие правила](../AGENTS.md), [STAGE_FLOW](STAGE_FLOW.md) и [README](README.md). Один пользовательский форк выполняет одно конкретное занятие: полный P1–P4 в том же чате. Полные [P1](01_PLAN_FRAME.md), [P2](02_THEORY_ROUTE.md), [P3](03_PRACTICE_ROUTE.md), [P4](04_PLAN_ACCEPTANCE.md) обязательны перед соответствующей работой; краткие файлы и skill не заменяют их содержание.

Точка входа: [stage-2-lesson-plan](../../../.agents/skills/stage-2-lesson-plan/SKILL.md). Форки создаёт пользователь. Последнее поручение задаёт цель; старые очереди, подтверждения и назначения из истории не являются текущей задачей. Запрос изменить инструкции не запускает создание занятия. Модель и полномочия определяет текущий запуск.

Ученические заголовки и текст теории не содержат вшитых номеров занятий: называй занятие или тему либо используй стабильную навигацию, поскольку нумерация может меняться. Это не относится к номерам разделов 00/01, техническим lesson ID, путям, порядку, прогрессу и маршрутам.

**Обязательные правила текста.** В создаваемом или перерабатываемом плане и передаваемых в MAIN ученических формулировках не используй символ U+2014 (длинное тире). Перестрой предложение или используй другую подходящую пунктуацию. В тексте для ученика, включая теорию, практику, подсказки и обратную связь, не ссылайся на занятия по номеру: вместо «в занятии 41» пиши «в предыдущем занятии» только при подтверждённом соседстве, иначе называй изученную тему. Номера и ID сохраняются в служебной идентификации, именах файлов, ссылках источников и учёте. Числа, необходимые для объяснения или примера, не являются номерами занятий. Если защищённый от изменения фрагмент содержит U+2014, зафиксируй конфликт и не утверждай прохождение проверки, пока он не разрешён.

- Установи паспорт COURSE/BLOCK, A с источниками, B, формат, глубину и один разрешённый MD. При недостаточном входе назови зависимость, не выполняй Stage 1 вместо неё.
- Последовательно выполни P1–P4 без отдельного сообщения, отчёта, агента или копии MD на шаг. Обычные пробелы разрешай по источникам; существенный конфликт цели/опоры не меняй за пределами поручения, продолжай независимую работу над этим планом.
- **До записи выбери CREATE, REWORK или RESUME** по состоянию реального целевого файла. При REWORK диагностируй наблюдаемые пробелы A → B, порядок предпосылок и доказательность самостоятельной практики; составь короткий план адресных улучшений. Не превращай P1–P4 в четыре одинаковые повторные проверки. Если доказанных дефектов нет, сохрани хорошие разделы (`KEEP`), не подменяй содержательную работу квотой изменений.
- **Результаты проходов различны:** P1 — корректная рамка цели и крупных действий; P2 — проверяемая последовательность объяснений, независимых примеров и первых применений; P3 — самостоятельные действия с локальными критериями, реальным ростом самостоятельности и различающими случаями; P4 — итоговый учебный путь плюс сравнение дефектов и улучшений при переработке. У P4 должно быть содержательное доказательство результата, а не только отметки чек-листов.
- Планируя подачу для MAIN, выбирай интерактивы и визуалы по учебной функции, без квоты абзацев. Проверь длинные текстовые фрагменты и повторяющиеся карточки; объяснение, сравнение или действие должны подготавливать самостоятельную практику.
- Сохраняй строковый номер, ID, исходное имя, YouTube-комментарий побайтно и на прежнем месте. Не создавай копии плана по проходам.
- A имеет статус и источник; планируемая A прослеживается к месту подготовки и не объявляется освоенной. Глубина теории обосновывается предметно; числовой диапазон и fallback не обязательны.
- Чат самостоятельно проверяет **сохранённый** MD по P4: концепт/проект, объяснения до действий, самостоятельность, критерии практики, соседние переходы, ясность и отсутствие заглушек. При REWORK показывает компактно `было → дефект → стало → наблюдаемый учебный результат` **по существенным исправлениям**, при CREATE — покрытие B, при KEEP — проверенное основание сохранить исходное. Runtime ещё не созданного занятия не требуется.
- Пиши только целевой MD. Сохраняй идентичность, соседние материалы и чужие правки; форк не изолирует файлы или Git. Не очищай чужой diff и не меняй паспорт молча.
- STAGE_COMPLETE / PLAN_ACCEPTED только после P4 сохранённого плана; иначе STAGE_INCOMPLETE с остатком. Итог по [шаблону](../START.md#итоговый-ответ), без N-описи блока и обязательного журнала. При прерывании достаточно одного краткого RUN.
- После результата остановись: Stage 3 и другое занятие запускаются отдельно. Не возобновляй прежний batch-маршрут и не назначай новых чатов.
