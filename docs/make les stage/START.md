# Запуск Stage 1–5

Выбери один Stage, курс и объём работы. Каждый этап запускается отдельно; сквозной цепочки разных Stage и автоматического перехода между этапами нет. Stage 5 последовательно проходит весь назначенный диапазон внутри главы одним чатом. В Stage 2/3 один форк получает ровно одно занятие и один Stage. Внутренние шаги сохраняются и выполняются в этом чате без отдельных сообщений на каждый. Общие требования — в [стандарте](STAGE_COMMON_STANDARD.md).

| Stage | Вход | Результат и маршрут | Skill |
| --- | --- | --- | --- |
| 1: концепция | Цель главы, предшествующие опоры и ограничения | COURSE и BLOCK с паспортами; [C → B → F](1%20stage/STAGE_FLOW.md) | pymentor-stage1-beta |
| 2: планирование | Принятый паспорт Stage 1 | Один MD-план на занятие; [P1–P4](2%20stage/STAGE_FLOW.md) | pymentor-lesson-stage |
| 3: создание | Принятый план Stage 2 | Теория, практика, визуалы и приёмка; [M1–M5](3%20stage/STAGE_FLOW.md) | pymentor-lesson-stage |
| 4: экспертная доработка | Готовые занятия | Находки, адресные исправления и проверка; [методичка](4%20stage/LESSON_REVIEW_GUIDE.md) | pymentor-lesson-review |
| 5: ученическое прохождение | Готовые занятия, проект и прежние знания | Последовательный проект, знания и ревью; [методичка](5%20stage/STUDYHUB_WORKFLOW.md) | pymentor-learner-run |

Связь Stage 1 → 2 → 3 задают сохранённые артефакты, а не память предыдущего чата. Следующий запуск читает нужный паспорт/план по ссылке и проверяет актуальность; переписывать всю главу или создавать отдельное досье передачи не нужно. Ограничение на проверку или исправление только части занятия сохраняется.

## Примеры отдельных запусков

- **Stage 1:** «Используй $pymentor-stage1-beta. Создай концепцию главы {глава, цель, блоки} и выполни её приёмку. Stage 2 не запускай».
- **Stage 2:** «Используй $pymentor-lesson-stage. Только Stage 2: {курс, глава, блок, занятие}. По действующему паспорту выполни P1–P4, сохрани и прими один MD-план. После этого остановись».
- **Stage 3:** «Используй $pymentor-lesson-stage. Только Stage 3: {курс, глава, блок, занятие}. По принятому плану выполни M1–M5, исправь найденное, проверь практику и полностью осмотри итоговый урок локально. После этого остановись».
- **Stage 4:** «Используй $pymentor-lesson-review. Проверь и доработай {курс, занятия}, сохрани IDs и перепроверь исправления». Для одного ревью добавь «без правок».
- **Stage 5:** «Используй $pymentor-learner-run. Пройди {глава, версия, занятия по порядку} в `C:\Project Python\studyhub-learning`, код `project/`, ветка `chapter/{NN}/v{N}`. Собери практику и знания, недостатки курса запиши в локальный review.md. Указанные программы заменяй доступным CLI/API/агентом без обязательного Computer Use, проверяй результат и кратко отмечай замену. Продолжай весь диапазон без команды «дальше». Коммит каждого занятия и push своей ветки после блока, а перед проверкой опубликованного SHA/clone — раньше без нового подтверждения. Main не изменяй, итоговый SHA передай на приёмку».

Для Stage 5 уже разрешена помощь одного субагента `gpt-6.1-terra / medium` на конкретное затруднение после двух неудачных попыток или зацикливания без новых данных. Используй короткую консультацию по методичке, затем продолжай тем же исходным чатом.

## Запуск через форки

Создай форк вручную и передай одно из поручений Stage 2/3 выше. Цель устанавливается по последнему актуальному поручению, а не по старой очереди в истории. Паспорт и принятый план находятся в файлах проекта: копировать весь контекст главы в сообщение не требуется. Форк завершается после своего занятия, не назначает другие уроки и не создаёт новые чаты. Правила общих файлов при параллельных форках — в [общем стандарте](STAGE_COMMON_STANDARD.md).

## Специализированная работа

- [pymentor-lesson-theory](../../.agents/skills/pymentor-lesson-theory/SKILL.md): создать теорию своего занятия на M1 с сохранением содержательных требований прежних методичек.
- [pymentor-lesson-practice](../../.agents/skills/pymentor-lesson-practice/SKILL.md): создать практику своего занятия на M2 с ясными полями и полным разбором.

- [pymentor-lesson-visual](../../.agents/skills/pymentor-lesson-visual/SKILL.md): создать или доработать конкретный учебный визуал; остаётся частью заданного Stage.
- [pymentor-block-visual-review](../../.agents/skills/pymentor-block-visual-review/SKILL.md): осмотреть блок или набор по реальным страницам; не заменяет полное ревью Stage 4.

Дополнительные роли frontend/visual используются при полезном и разрешённом делегировании, без обязательного отдельного исполнителя на урок. methodic-run и course-practice нужны только для соответствующего поручения, не как обязательная цепочка skills.

Для продолжения прерванной работы используй существующую краткую запись; для одного занятия отдельный [RUN](RUN_TEMPLATE.md) обычно не нужен. Итог сообщает сохранённые результаты, реально выполненные проверки и конкретный остаток. PLAN_ACCEPTED относится к плану; полная приёмка занятия требует фактических содержательных, визуальных и технических проверок.
