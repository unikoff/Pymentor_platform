# AGENTS.md — Stage 1 BETA

Область: **только** проектирование одной главы и четырёх её глобально пронумерованных блоков по прямому поручению. Изменение этих инструкций не запускает реальную главу. В корневом чате явно прочитать [`$pymentor-stage1-beta`](../../../.agents/skills/pymentor-stage1-beta/SKILL.md), [README](README.md), [RUN_TEMPLATE](RUN_TEMPLATE.md), затем перед проходами — тексты [01/C](01_CHAPTER_CONCEPT.md), [02/B](02_BLOCK_CONCEPT.md), [03/F](03_CHAPTER_ACCEPTANCE.md). При записи в `docs/concept/` AGENTS этой папки **не гарантированно автозагружается**: исполнителям передавать применимое содержимое, а не только ссылки.

- **Маршрут:** `C1→C4` один раз в `COURSE.md` до `FRAME_ACCEPTED` → `B1→B4` **ровно четыре раза**, по одному `BLOCK_N.md`, до 4/4 `BLOCK_LOCAL_READY` → `F1→F3` по пяти сохранённым MD, включая адресные повторные проверки. Только `CHAPTER_STAGE1_ACCEPTED` и полная предметная приёмка дают `STAGE_COMPLETE`.
- **Роли:** [`pymentor_chapter_worker`](../../../.codex/agents/pymentor-chapter-worker.toml) владеет COURSE при C, а при отдельном назначении интеграцией F; [`pymentor_block_worker`](../../../.codex/agents/pymentor-block-worker.toml) владеет **одним** назначенным BLOCK, четыре независимых назначения. Рецензент пишет замечания владельцу; RUN пишет оркестратор. Один файл — один активный писатель. Наличие TOML не доказывает регистрацию роли в runtime.
- **Web:** все делегаты, reviewer и integrator — только `chatgpt-web/gpt-6-sol` / `high`; подтвердить фактический маршрут, конфигурацию и ID инструментом. **Не более пяти активных Web/browser turns во всей среде**, включая чужие задачи; оркестратор вне лимита. Native `spawn_agent` имеет `agent_type/model/reasoning_effort`; `create_thread` — `model/thinking/prompt/target`, **без** `agent_type`. При незарегистрированной роли допустима честно обозначенная передача текста TOML через поддерживаемый маршрут; без проверенного Web/High — конкретный `BLOCKED`, без скрытой замены модели.
- **Вход и журнал:** установить курс, главу, порядок четырёх глобальных номеров, канонические пути, A/B и источники, разрешённую область записи. Один `docs/stage-runs/<run-id>/RUN.md` для пяти MD, версий рамки, владельцев, очереди, статусов C/B/F и **полной N-описи**. При возобновлении читать тот же RUN, diff, последние версии и активные задания, не дублировать исполнителей и не терять чужие правки.
- **Предмет:** ровно пять основных учебных дней в каждом блоке плюс **все обязательные подзанятия**; у каждого отдельный паспорт и **семь смысловых полей** (в том числе практика/критерий, диапазон видимой теории **с причиной**). Новый паспорт без диапазона не готов; legacy-исключение требует источника. A со статусом/источником; планируемая предыдущая B — ещё не факт обучения; новое объяснить и безопасно опробовать до самостоятельного применения. `N_expected` не снижать при дефектах, номера хранить строкой, прежние публичные ID сохранять.
- **Идентичность:** `display_number`, `title`, название/порядок блока и позиция урока могут меняться; `lesson_id` бери **из авторитетной реализации**, где `_stable_lesson_id()` хеширует `_lesson_identity_source()` от относительного source path с учётом алиасов (`backend/content/identity.py`, `backend/content/catalog.py`). ID независим от позиции, **но зависит от канонического пути**. Вести mapping прежний→новый номер/title ↔ существующий lesson_id ↔ canonical identity source / alias ↔ физический путь. При разбиении «03» на «03.1–03.3» сохранять ID/пути существующих уроков. Для **нового запланированного занятия**, у которого ещё нет runtime `lesson_id`, допустима запись в паспорте **«ID требует назначения по действующей схеме»** с владельцем реализации и этапом проверки/создания mapping при включении в каталог; это **не Stage 1 blocker и не BETA_GAP**. Обычный путь сохранять: физический перенос/переименование может изменить хеш и `lesson_id`. При необходимом переносе отдельно уполномоченный владелец реализации должен добавить/проверить alias/identity mapping и миграцию прогресса; Stage 1 фиксирует потребность, но не выполняет её, не меняет файлы, routes, progress ID или схему. При вставке/удалении/перестановке пересобрать последовательность, prerequisite/A→B, возрастающую сложность, COURSE↔BLOCK, N-паспорта и три межблочных перехода; чистый display rename — только корректировка отображения и ссылок по mapping. `BETA_GAP: LESSON_IDENTITY_UNVERIFIED` — **только для существующего/реализованного урока**, когда `lesson_id` ожидается, но canonical identity source/alias не подтверждается; запросить минимальную карту, не менять схему приложения.
- **Приёмка:** F1–F3 проверяет полное покрытие B, 3 внутренних и 2 внешних границы блоков, **все** межурочные связи, рост сложности и идентичности. `STAGE_COMPLETE` только при COURSE 1/1, BLOCK 4/4, `N_accepted=N_expected`, обязательных PASS на актуальных версиях и отсутствии препятствующих `FAIL/BLOCKED/NOT_CHECKED`; иначе `STAGE_INCOMPLETE` с остатком/владельцем. Прямая авторская цель в мандате не требует повторного согласования. Документальная готовность не доказывает фактическую успеваемость.
- **Граница записи:** только разрешённые `COURSE.md`, четыре `BLOCK_N.md` и один RUN; не создавать PLAN, готовые уроки/TSX, код, тесты, миграции, новые ID, коммиты, публикации или запуск stage 2/3. [Старые COURSE/BLOCK GUIDE](COURSE_CONCEPT_GUIDE.md) — диспетчеры совместимости. Родительские [AGENTS](../AGENTS.md), [BATCH_WORKFLOW](../BATCH_WORKFLOW.md), общий `pymentor-stage-batch` и его профили относятся **только к stage 2/3**, занятым параллельным preflight; их не менять и не применять к BETA stage 1.
