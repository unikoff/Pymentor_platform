# Работа с методичками Stage 1–5

[START](START.md) задаёт маршрут запуска; полные методички текущего шага задают содержание и приёмку. Требования к теории, практике и визуалу находятся внутри соответствующих Stage. Краткий маршрут и skill их не заменяют. Исторические очереди и передачи отдельных шагов не возобновляются.

- Один запуск выполняет один выбранный Stage до результата или конкретного блокера. Внутренние C/B/F, P1–P4 и M1–M5 выполняются тем же чатом без отдельных сообщений, агентов и согласований. Следующий Stage запускается отдельно; явный ограниченный шаг или аудит без правок соблюдается.
- Stage 1 проектирует главу. Для Stage 2/3 пользователь создаёт форк ровно одного занятия; цель устанавливается по последнему поручению, не по старой очереди. Stage 4 проверяет и исправляет готовое в пределах запроса. Stage 5 одним чатом последовательно проходит назначенный диапазон по своей методичке и пишет ревью без изменения курса.
- Читай общие правила один раз, затем полную методичку текущего шага и нужные источники. Различай планируемую подготовку, доступное объяснение и подтверждённое освоение. Не сокращай полезные объяснения, примеры, практику и визуал ради уменьшения отчёта или входного контекста.
- Пиши только в разрешённые файлы и записи. Сохраняй ID, source_file, пути, порядок задач, прогресс, скрытые проверки и чужие правки. Номера храни строками; будущий runtime ID не выдумывай. Изменение identity требует отдельного согласования.
- Форк не изолирует файлы, Git и браузер. Перед точечной записью перечитай актуальный участок; общий словарь из старой копии не перезаписывай. Не убирай чужой diff через reset/checkout/stash. При конфликте сохрани свою дельту, назови зависимость и продолжай независимое. Используй свою вкладку и проверяй актуальность урока/версии.
- Обычные решения принимай самостоятельно в разрешённой области. Неразрешимый конфликт цели не подменяй догадкой. Модель и полномочия задаёт текущий запуск; дополнительные чаты, диспетчеры и очереди по умолчанию не создаются.
- Проверяй фактический результат. Повторно используй evidence только для той же версии и зависимостей; после изменения повторяй затронутое. Исходник, build и непросмотренный снимок не подтверждают страницу. Недоступная обязательная проверка остаётся НЕ ПРОВЕРЕНО и не даёт полной приёмки.
- Создавай результат Stage, без отчётов и копий черновиков каждого шага. Восстановление и итоговый ответ описаны в [START](START.md#продолжение). После выбранного Stage остановись.
