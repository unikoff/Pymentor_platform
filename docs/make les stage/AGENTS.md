# AGENTS.md — массовый Stage 2/3

Общее правило учебного контента Stage 2/3: не используй U+2014 (длинное тире) в плане или материале, который увидит ученик. Не указывай номер другого занятия в ученической теории, практике, подписи, подсказке или обратной связи. Используй подтверждённое «предыдущее/следующее занятие» или назови тему. Служебные номера, ID, пути и числа в учебных данных сохраняй. При конфликте с защищённым источником сообщи о нём и не засчитывай проверку как пройденную.

- Исходный чат — единственный Coordinator. **Один агент = одно занятие = весь stage**. Не давай исполнителю личную очередь и не запускай новых агентов на P/M-проходы; Coordinator назначает отдельный lesson ID следующему исполнителю по мере доступности слота. Исправление/RESUME того же занятия можно вернуть его владельцу.
- Политика берётся из `C:/Users/Unik/.codex/orchestrator.toml` через штатный runtime. Явный текущий запрос важнее прежнего предпочтения Sol Web/full. Профили не доказывают доступность модели или доверие hooks. Не меняй базовые настройки ради разового запуска.
- Coordinator считает пользователя офлайн на время массового прогона. Сам решает рутинные пробелы по каноническим источникам и сопоставимым принятым примерам; выбирает минимальный обратимый вариант, сохраняющий B, и фиксирует в RUN только существенные допущения. Не ставит массив на паузу и не запрашивает подтверждение для таких решений. Неразрешённый конфликт может затронуть только зависимые ID; независимая очередь продолжается.
- Делегируй полную работу ровно по одному уроку каждому автору, опись только при отсутствии, а общие записи/проверки — одному интегратору. Coordinator сохраняет effective policy, scope и authorization, решения между уроками/концептами, gate и финальную приёмку N/N. Отдельные исследователи, проверяющие и статусные агенты нужны только при конкретном независимом риске.
- [Skill](../../.agents/skills/pymentor-stage-batch/SKILL.md) маршрутизирует, [BATCH_WORKFLOW](BATCH_WORKFLOW.md) задаёт процедуру. Автор читает общие/stage инструкции и нужные первичные источники один раз; изменённое/неизвестное читает адресно. Не дублируй все методички в root или payload.
- Используй имеющуюся опись N и назначения по lesson ID; новая опись нужна только при отсутствии/изменении входов. Готовые независимые уроки запускаются сразу в свободные слоты. Ни обязательного отдельного preflight, ни барьера между пятёрками.
- CREATE: построить по A–B. REWORK: конкретный исходный дефект → смысловая правка объяснения/практики → проверяемое действие ученика. KEEP сильных частей допустим; перестановка JSX и отчётность не заменяют результата.
- Первый рабочий результат — сохранённая содержательная правка или точный блокер. До него не создавай отдельные планы проверок, аудиты и handoff. Многоэтапность улучшает один артефакт, а не умножает отчёты.
- Авторы самостоятельно проходят предметные P1–P4/M1–M5 и адресные локальные проверки. Stage 3 может сдать LOCAL_READY в ожидании общих проверок; это **не COMPLETE**. Не держи автора в ожидании общей сборки, занимая слот без работы.
- У общего физического файла один писатель только на время записи/интеграции; lease не удерживается весь stage. Дельты разных уроков интегрируются одним владельцем, не требуют многоступенчатых разрешений.
- Общие backend/frontend/build/API проверки выполняются одним владельцем на итоговом наборе, с явным покрытием уроков. У каждого урока остаются четыре M5 PASS: backend, frontend, API, страница/runner; уровень 4 включает широкий/узкий вид и обязательные задачи. Общий результат переиспользуется только при совпадающих версиях и покрытии.
- Успешные проверки не повторяются без затронутых изменений. После ошибки — диагноз и адресная правка. После средового отказа — один воспроизводимый blocker, без бесконечного bootstrap. Блокер среды не останавливает доступную редактуру.
- Root получает итог, принимает N/N и исключения; не читает промежуточную работу, не запрашивает статус и не перепроверяет всё за автора. Один компактный [RUN](RUN_TEMPLATE.md), без обязательных per-pass SHA/таблиц/досье. Если действительно нужен ввод пользователя, сообщи один точный вопрос, продолжая независимую работу; не создавай повторный wait-loop.
- Поурочные строки RUN — единый источник истины; gate и сводные числа пересчитываются из них. Изменение входа отменяет только зависимые проверки/статусы. STAGE_COMPLETE требует N/N, P4/PLAN_ACCEPTED или всех четырёх M5 PASS на итоговой версии, интеграции и отсутствия обязательных блокеров. Если запрос явно включает следующий stage, запускай его после полного gate без дополнительного вопроса; неназванные stage и внешние действия автоматически не запускаются.
