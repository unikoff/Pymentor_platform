## Stage 3 — отдельная массовая очередь (если запрошен)

| Lesson ID | Один worker ID | Урок + практика / версия | Состояние Stage 3 | M5 evidence / blocker |

| {ID} | {native ID} | {пути/ключи} | {QUEUED, RUNNING, INTERRUPTED, LOCAL_READY, RECONCILE, COMPLETE, PARTIAL, DECISION_REQUIRED, BLOCKED} | {кратко; ссылки на общие checks} |

LOCAL_READY — содержание Stage 3 готово к общей приёмке, не принято и не входит в N_accepted. Каждый следующий урок получает отдельного агента; исправления/RESUME того же урока допустимы.

Две таблицы — **раздельные источники истины** для своих stage; из каждой вычисляй её N/accepted и очередь. Не дублируй изменяемые числа в описательном тексте. `RUNNING` — последняя запись, не подтверждение liveness: при каждом возобновлении Coordinator сверяет фактическое состояние точного worker ID и его артефакт. Только подтверждённо активные ID допускаются в wait. Прерванный worker получает состояние `INTERRUPTED`; его артефакт проверяется, а при переназначении новый worker получает только незакрытый остаток урока. Пустой wait запрещён; неизвестное состояние сначала сверяется, а не превращается в бесконечное ожидание.

Stage 3 стартует только после `PLAN_ACCEPTED` у всех его целевых Stage 2 строк. Если правка концепта/плана влияет на P4 уже принятого урока, пометь только эти Stage 2 строки `P4_RECHECK`; Stage 3 по ним не назначай либо переведи уже начатые строки в `RECONCILE` до адресной сверки. Независимые уроки продолжаются. Если запрос включает Stage 2 → Stage 3, запускай отдельную очередь Stage 3 после полного gate без дополнительного подтверждения; незапрошенный stage не запускай.

## Только существенные исключения

{Файл/ключ, дефект или средовой blocker, точный repro, ответственный и следующий конкретный шаг. При адресном REWORK — ожидаемый эффект и затронутая проверка.
