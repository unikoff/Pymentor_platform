# AGENTS.md — stage 3 / MAIN

В видимой ученику теории, практике, подсказках и обратной связи не упоминай занятия по номеру. Используй «в предыдущем/следующем занятии» только при подтверждённом соседстве, иначе называй тему. Служебные ID, номера и пути сохраняются; предметные числа в примерах допустимы. Символ U+2014 запрещён во всём целевом TSX и точной записи практики, включая существующие строки, код и комментарии; конфликт с неизменяемым фрагментом фиксируй без молчаливой подмены и без утверждения PASS.

Для массового прогона разрешена локальная сдача `LOCAL_READY`: содержание и доступные локальные проверки готовы, общие checks ожидают итогового набора. Автор не удерживает слот/владение общим файлом в ожидании. Один интегратор выполняет общие проверки с привязкой к версии и покрытым lesson IDs. `LOCAL_READY` не является `COMPLETE`; четыре уровня M5 и поурочные проверки обязательны до итоговой приёмки. Исправления по своему уроку возвращаются его владельцу.

**Один агент = одно занятие = полный stage (P1–P4 или M1–M5).** Одному исполнителю запрещено назначать 2–3 занятия, диапазон для исполнения или личную очередь. Общая очередь массива принадлежит только Coordinator. Для каждого следующего занятия запускается отдельный агент; после результата или блокера текущий агент останавливается. Исправления/RESUME того же занятия можно вернуть его исполнителю. Опись массива принадлежит Coordinator; каждый исполнитель работает только над одним назначенным занятием и завершает его целиком. Это правило заменяет прежнюю схему постоянных очередей на агента.

Применяй эти правила при явно порученном выполнении stage 3. Запрос доработать сами инструкции не запускает генерацию уроков. Общие правила: [BATCH_WORKFLOW.md](../BATCH_WORKFLOW.md), [AGENTS родительской папки](../AGENTS.md).

Исходный чат запуска использует [Skill pymentor-stage-batch](../../../.agents/skills/pymentor-stage-batch/SKILL.md). Если Skill или профиль недоступен через регистрацию, явно прочитай его инструкции поддерживаемым способом **в этом же чате**, без обязательной новой сессии. Профиль Web-исполнителя — [pymentor_lesson_worker](../../../.codex/agents/pymentor-lesson-worker.toml); он не управляет массивом и не создаёт делегатов. Различай фактическую загрузку инструкций и запуск роли.

- **Исходный чат — единственный Coordinator.** Не создавай и не назначай другой чат-оркестратор; результаты возвращаются в исходный чат. Модель, effort, лимиты и способ выполнения бери из актуальной effective task policy, не из фиксированных примеров в этой методичке. Coordinator сохраняет опись N; исполнитель получает одно занятие, завершает M1–M5 и останавливается. Не назначай отдельного ведущего на очередь/интеграцию, если это не требуется отдельным явным поручением.
- Пользователь может быть недоступен весь прогон. Автор не спрашивает его и не ждёт ответа: использует план и канонические источники, принимает минимальное обратимое решение для обычного пробела, помечает существенное допущение для Coordinator и продолжает независимые части урока. Запись за scope запрещена; настоящий конфликт сообщает Coordinator с лучшим безопасным вариантом.
- Один исполнитель получает одно занятие и проходит весь stage; после результата или блокера останавливается. Следующее занятие назначается отдельно. Конкретные лимиты и режимы берутся из effective task policy; этот документ не задаёт параллельный pool.

- Coordinator восстанавливает опись N и принятый план каждого занятия до назначений. Отсутствующий вход фиксируется в N; не запускай stage 2 и не меняй планы внутри stage 3. Заблокированное занятие остаётся в N.
- Для каждого назначения зафиксируй режим **CREATE** (занятие отсутствует) или **REWORK** (занятие/практика уже существуют). В REWORK сначала прочитай фактическую видимую теорию и все задания существующей практики, соотнеси с B, A и принятым планом. Укажи конкретный исходный дефект, проверяемую цель улучшения и работающие части, которые нужно сохранить. Сохраняй уже хорошие объяснения и задания; не подменяй содержательную переработку перестановкой JSX или увеличением числа виджетов. В CREATE обосновывай новый материал через B → проверяемое действие ученика, не выдумывай «до».
- Одно занятие последовательно проходит [M1](01_THEORY_DRAFT.md) → [M2](02_PRACTICE_DRAFT.md) → [M3](03_CONTENT_EDIT.md) → [M4](04_VISUAL_INTERACTIVE.md) → [M5](05_LESSON_ACCEPTANCE.md). Начинай с первого реально неполного прохода, сохраняя принятые части.
- M1: полное точное объяснение с простым входом в сложные механизмы и сохранением профессиональных терминов; M2: самостоятельная практика, проверяющая перенос понимания в действие; M3: снятие воды, дублей и ненужной причинности с сохранением смысла и опор; M4: учебная роль и связность визуалов/интерактивов без набивки квот; M5: предметная и техническая приёмка с проверкой сценария ученика. В REWORK каждый проход фиксирует только обоснованные `ДО → ПОСЛЕ` для затронутых недостатков текста и практики; качество не измеряется числом перестановок. Для CREATE фиксация соответствует целям B, объяснению, самостоятельному действию и критерию.
- Один MD/TSX — один владелец. Для общего `manual.py`, `code_tasks.py`, индекса/реестра одновременно действует один владелец записи; следующий исполнитель получает запись после завершения текущего назначения. Не держи постоянную очередь интеграции. Итог оценивается после сохранения интегрированной версии; fingerprint нужен при конфликте/восстановлении/привязке проверок, а не для каждого прохода.
- Сохраняй ID, строковые номера, `source_file`, имена/экспорты, точные ключи, чужие изменения и границы области записи. Минимальные регистрации допустимы только в уже разрешённой области M5; shared/CSS, загрузчики, концепты и StudyHub не входят в scope автора. Coordinator отдельно разрешает доказуемую минимальную правку непосредственного концепта в границах запуска; после неё переоцениваются только зависимые планы/уроки.
- Сверяй A→B и теорию→самостоятельную практику. Новый паспорт без диапазона не получает выдуманный fallback. На M4/M5 максимум два читаемых абзаца без содержательного интерактива **или** учебного визуала; две обязательные connected-группы всего и ≤6 LinkedNotes. Соседние карточки, схемы и интерактивы допустимы при общем вопросе, сравнении или последовательных шагах одной задачи с видимым выводом; цепь повторных `TrueFalse(is_done) → Note(run()/handle_*) → TrueFalse` без раскрытого механизма, обратной связи и переноса в практику исправляй по смыслу, а не формальной чередовалкой. Сохраняй остальные количественные/технические нормы методичек.
- M1–M4 — содержательные проходы по первому неполному артефакту; не запускай отдельный полный audit на каждом шаге. При REWORK сначала назови наблюдаемый дефект, затем внеси раннюю адресную правку. До зависимых шагов прочитай нужные источники один раз; возвращайся к ним при изменении или пробеле. Перед M5 проверь обычный и ошибочный маршрут ученика: новое понятие объяснено до применения; различающий пример раскрывает механизм; обратная связь указывает причину; самостоятельное задание действительно требует нового действия. Для REWORK предъяви адресный исходный фрагмент → изменённое объяснение/задание → наблюдаемую разницу и сохранённые сильные части. Технический PASS не заменяет такую предметную проверку; фактический прирост знаний без пилота не утверждай.
- Web-исполнитель самостоятельно завершает полный предметный чек-лист M5 и четыре обязательных уровня PASS на согласованной итоговой версии: backend, frontend, фактическая выдача **без утечек hidden tests/эталонов**, открытая страница/runner со всеми обязательными задачами и нужными состояниями/ширинами. Общие проверки переиспользуются только при доказанном совпадении revision и зависимостей; фиксируй область применимости evidence. После правки повторяй только затронутые проверки. Локальное редактирование и доступные проверки продолжаются при недоступной среде; для browser/runner одна диагностика, затем точный actionable blocker без повторного bootstrap. Он исправляет дефекты и перепроверяет затронутое на актуальной версии. Оркестратор принимает подтверждённые краткие результаты по идентичности, путям/ключам, проверкам и остаткам; повторная предметная проверка только при конкретном противоречии, сбое, пропущенном обязательном свидетельстве или прямом запросе пользователя. Автоматический второй проверяющий на каждый урок не назначается.
- Локальные M1–M4, сборка без страницы и текст «готово» не подтверждают финал. Исправляй доступные дефекты в текущем запуске; частичная/недоступная обязательная проверка оставляет занятие PARTIAL, весь stage STAGE_INCOMPLETE.
- STAGE_COMPLETE только после COMPLETE по M5 всех N из N, согласованной интеграции и итоговой сверки переходов. Внешний REVIEW/stage 4 и StudyHub запускаются отдельно.

Прочитай [README](README.md), веди один компактный общий журнал «очередь → исполнитель → выполнено/блокер → результаты/проверки». Оркестратор получает только завершение назначенной порции, блокер или запрос вмешательства; пока исполнитель занят, не читает промежуточные MD/TSX и диалоги, не шлёт «статус?» и «продолжай». Итог исполнителя — компактная сводка по артефакту, четырём уровням, evidence и исключениям; обязательные факты не ограничиваются квотой слов. При продолжении проверь реальное состояние результатов и владельцев файлов, избегай дубликатов.
