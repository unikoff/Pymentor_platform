# Методички Pymentor

Канонический маршрут подготовки и проверки: **COURSE → BLOCK → PLAN → AUTHORING → REVIEW**. Шестой workflow, **StudyHub**, проходит готовый материал как ученик и возвращает обратную связь. Рабочие исполнители используют **ChatGPT Web / GPT-6 Sol / High**; для массового запуска stage 2/3 чат на выбранной пользователем сильной модели выступает оркестратором. Сквозные этапы: **1 — концепт (COURSE и BLOCK), 2 — PLAN, 3 — AUTHORING, 4 — REVIEW**; номера строк таблицы перечисляют workflow, а P1–P4 и M1–M5 обозначают внутренние проходы этапов 2 и 3.

| Workflow | Что передать в отдельный запуск | Результат одного запуска |
| --- | --- | --- |
| 1. [COURSE — общая концепция курса](../make%20les%20stage/1%20stage/COURSE_CONCEPT_GUIDE.md) | Курс/часть, аудитория, подтверждённая A, желаемая B, доступные материалы и целевой путь `COURSE.md`. | Один концепт курса: проверяемая B, границы, маршрут и карта блоков; проверка предпосылок. |
| 2. [BLOCK — концепт блока](../make%20les%20stage/1%20stage/BLOCK_CONCEPT_GUIDE.md) | Актуальный `COURSE.md`, номер блока, его A → B, соседние блоки и подтверждённый учебный контекст. | Один `BLOCK_N.md`: пять основных учебных дней, обязательные подзанятия, паспорта занятий, формат практики и обоснованный диапазон теории. |
| 3. [PLAN — четыре прохода P1–P4](../make%20les%20stage/2%20stage/README.md) | Массив занятий по курсу/главе/блокам/номерам, целевые MD, паспорта из `BLOCK_N.md` и источники A. | Все планы массива приняты; каждый MD после [P4](../make%20les%20stage/2%20stage/04_PLAN_ACCEPTANCE.md): от рамки через теорию и практику до сверки концепта и переходов. |
| 4. [AUTHORING — пять проходов M1–M5](../make%20les%20stage/3%20stage/README.md) | Массив занятий, принятые MD-планы, паспорта, актуальная A, целевые TSX/записи практики и привязки. | Все занятия массива приняты; теория, практика и подключение каждого после [M5](../make%20les%20stage/3%20stage/05_LESSON_ACCEPTANCE.md); проверка четырёх уровней от backend до страницы. |
| 5. [REVIEW — перепроверка занятия](../make%20les%20stage/4%20stage/LESSON_REVIEW_GUIDE.md) | Одно готовое занятие, план, паспорт, реальные TSX/практика, доступные сценарии страницы и runner. | Исправленные подтверждённые дефекты, повторная проверка практики и платформы; для схем также половина окна/контейнера. |
| 6. [StudyHub — прохождение как ученик](../make%20les%20stage/review%20stage/STUDYHUB_LEARNING_WORKFLOW.md) | Одно готовое занятие, состояние ученического проекта **до** него, подтверждённые знания и существующие замечания. | Самостоятельная практика, проверенные знания в `STUDYHUB_LEARNINGS.md` и предметное ревью в `review.md`. |

**Как запускать повторяемо.** Для выбранного workflow открой его актуальную инструкцию; укажи курс, блок, строковый номер занятия/существующий ID, целевые файлы, исходное состояние и разрешённую область изменений. Для PLAN и AUTHORING начни с соответствующей карты, затем читай **текущий проход и необходимые источники**: нет требования загрузить все девять методичек заранее. Пример: «Составь полностью готовый план занятия 6.1 блока 2 через P1–P4; используй паспорт, уточни статус A, сохрани единственный MD и прими план по P4». Если пользователь заказал **полностью готовый план/урок**, выполни весь недостающий последовательный маршрут до P4/M5 в рамках поручения; если заказан только Pn или Mn, заверши только его локальную приёмку. Старые входы [LESSON_PLAN_GUIDE.md](LESSON_PLAN_GUIDE.md) и [LESSON_AUTHORING_GUIDE.md](LESSON_AUTHORING_GUIDE.md) остаются короткими диспетчерами с прежними заголовками и ссылками на новые нормы.

**Массовый запуск:** каждый stage 2 или 3 выполняется отдельно для всего указанного массива по [общему протоколу](../make%20les%20stage/BATCH_WORKFLOW.md), волнами по пять разных занятий параллельно; оркестратор вне пяти рабочих слотов. Полный stage принимается только после завершения всех внутренних проходов каждого занятия и сверки N/N. Внутри маршрута одного занятия P1–P4 пишут в один MD, M1–M5 последовательно уточняют один TSX и одну практику. Общие файлы `manual.py`, `code_tasks.py` и реестры интегрируются последовательно одним владельцем. Отдельный запрос только Pn/Mn сохраняет узкую область и не считается полным массовым запуском. Локальная готовность P1–P3 или M1–M4 не подтверждает итоговый P4/M5; не принимай запланированный результат за освоенный. **REVIEW** остаётся независимой перепроверкой, **StudyHub** — отдельным ученическим прохождением. Исторические копии и ссылки из [`docs/PROJECT_CONTEXT.md`](../PROJECT_CONTEXT.md) сохраняются как контекст, а не второй оперативный источник.
