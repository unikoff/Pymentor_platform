# Методичка: план занятия по концепту

**Совместимый диспетчер PLAN.** Этот путь сохраняется для прежних ссылок из BLOCK, REVIEW, StudyHub и PROJECT_CONTEXT. Рабочие инструкции теперь находятся в [карте четырёх проходов LES_PLAN](../make%20les%20stage/2%20stage/README.md). Окончательный результат — один принятый MD-план одного занятия; содержательная норма каждого действия расположена в соответствующем P1–P4.

Если запрос — **готовый план**, выполни полный P1 → P2 → P3 → P4 последовательно в разрешённой области, начиная с первого неподтверждённого результата. Если запрошен только конкретный Pn, остановись на его локальной приёмке. Ранее принятые части сохрани; создание пользовательских чатов или делегирование из этой методички не следует.

## Главный план работы

[P1 — рамка и начальный MD](../make%20les%20stage/2%20stage/01_PLAN_FRAME.md) → [P2 — подробная теория](../make%20les%20stage/2%20stage/02_THEORY_ROUTE.md) → [P3 — подробная практика](../make%20les%20stage/2%20stage/03_PRACTICE_ROUTE.md) → [P4 — сверка концепта и приёмка](../make%20les%20stage/2%20stage/04_PLAN_ACCEPTANCE.md). Все четыре прохода редактируют один назначенный MD в backend/content/materials; новую версию плана не создавай под каждую стадию. В [README маршрута](../make%20les%20stage/2%20stage/README.md) определены статусы, повторный вход и границы передачи.

## 1. Вход запуска, задача и границы

См. [P1, разделы 1 и 4](../make%20les%20stage/2%20stage/01_PLAN_FRAME.md): одно занятие, номер как строка, подтверждённый ID, целевой MD, паспорт, A → B, разрешённые правки. Пределы P2/P3 и окончательный допуск определяются их собственными инструкциями. Для готового плана одного P1 недостаточно.

## 2. Источники и подтверждение опоры

См. [P1, разделы 2–3](../make%20les%20stage/2%20stage/01_PLAN_FRAME.md) о первичных источниках, четырёх статусах A и паспортном диапазоне; [P4, разделы 1 и 3](../make%20les%20stage/2%20stage/04_PLAN_ACCEPTANCE.md) окончательно сверяет концепт, фактические данные и планируемые предпосылки. Будущую A связывай с предыдущим B и местом подготовки без объявления её освоенной; не заменяй отсутствующий диапазон нового паспорта историческим резервом.

## 3. Теория

См. [P2 — маршрут объяснения](../make%20les%20stage/2%20stage/02_THEORY_ROUTE.md): prerequisites, механизм, самостоятельные примеры, типовые ошибки, опоры для возврата и переход к каждому практическому действию. Готовый ученический текст и TSX создаются на [M1](../make%20les%20stage/3%20stage/01_THEORY_DRAFT.md) после принятого MD.

## 4. Практика

См. [P3 — маршрут самостоятельной практики](../make%20les%20stage/2%20stage/03_PRACTICE_ROUTE.md) и [P4 — сверка практики](../make%20les%20stage/2%20stage/04_PLAN_ACCEPTANCE.md). Здесь описываются действия, реальные входы, наблюдаемые локальные результаты, критерии и связь с теорией. Точные карточки, подсказки, эталоны, тесты и запись в backend относятся к [M2](../make%20les%20stage/3%20stage/02_PRACTICE_DRAFT.md).

## 5. Приёмка и завершение

См. [P4 — полный контроль и статус PLAN_ACCEPTED](../make%20les%20stage/2%20stage/04_PLAN_ACCEPTANCE.md). P1–P3 подтверждают лишь локальный результат. P4 проверяет MD и отдаёт его [AUTHORING](LESSON_AUTHORING_GUIDE.md), без требования уже существующих TSX, API или браузерной страницы. Различай проваленную и недоступную проверку, передавай точные незакрытые зависимости.

## Шаблон плана

Единственный актуальный [шаблон MD находится в P1, разделе 5](../make%20les%20stage/2%20stage/01_PLAN_FRAME.md); полноту заполнения и удаление временных пометок проверяет [P4](../make%20les%20stage/2%20stage/04_PLAN_ACCEPTANCE.md). План включает идентичность, место занятия, A и B, границы, 00 → последовательные смысловые разделы → заключительный маршрут практики. Сохраняй номер, ID и YouTube-комментарий побайтно и в прежнем месте.
