## 1. Назначение, контекст и путь A → B

**A3 = B2:** язык для небольших управляемых scripts; нет собственных функций, локального main.py, меню или репозитория. Не считать запланированное доказанным только существованием концепта.

**B3 = A4:** один собственный StudyHub remote/основной clone/main.py, Python 3.12/.venv/.gitignore и понятный цикл save/run/status/diff/stage/commit/push; самостоятельная диагностика и debugger; понимание функций/локальных имён/ссылок, input и узкого ValueError. В файле четыре компонента:

| Компонент | Точный договор |
| --- | --- |
| `normalize_title(title)` | Strip-результат, регистр/внутренние пробелы сохранены; пустой результат допустим |

Допустимо компактное демо после определений. Нет пользовательского tasks/run/menu, готовых readers/add/find/done/search/stats. Ввод исследуется локально и не добавляет постоянный опрос main.py. Следующий блок заменяет демо меню, сохраняя четыре функции.

В начале функции/ошибки изучаются на платформе, затем создаётся один собственный локальный проект. Установка объяснена до clone/файла, ignore до staging, commit до push. Первая локальная версия и первая публикация оставлены отдельными уроками.

## 3. Паспорта занятий

### 23. Функции: определение, вход и результат

**Основная тема и назначение.** Связать def/вызов с параметрами и return в одном уроке, последовательно усложняя знакомое действие.

**Точка A.** B2: управляемые скрипты на платформе; своих функций и проекта нет.

**Точка B.** Определяет функцию, передаёт аргументы, получает и использует результат; отличает print/return/None.

**Проверка предпосылок.** Опора: готовые вызовы (1, 4) и скрипты/условия/циклы (11–22). Новое: def/параметр/аргумент/return; область локальных имён не считается изученной заранее.

**Предпочтительный объём теории.** **2100–2700 слов** учитываемого текста. Первое def, вызов, вход и программный результат; объяснить исполнение прежде print/return/None.

**Необходимые темы в порядке изучения.**

1. Потребность назвать повторяемое действие; определение не выполняет тело, вызов со скобками выполняет.
2. Сначала функция без входа, затем параметры/позиционные аргументы и соответствие их порядка.
3. Return передаёт значение и заканчивает вызов; вызывающий код продолжает выполнение.
4. Print выводит, но не возвращает вычисленный ответ; отсутствие return и забытая ветвь дают None.
5. Простой договор вход → результат; без defaults/*args/аннотаций/рекурсии.

**Порядок частей без скачка сложности.**

1. Одна функция без параметров: определение и один вызов.
2. Затем параметр и два разных аргумента.
3. После этого return и использование результата; только затем сравнить с print/None.

**Основная практика.** Script на платформе; собственные вызовы определяются в нём, без обязательного solve.

1. Выделить знакомое повторяемое действие, предсказать порядок определения и двух вызовов.
2. Добавить параметры к следующему небольшому вычислению, сохранить результат и использовать дальше.
3. Исправить print вместо return, пропущенный возврат в ветви и несоответствие аргументов после их объяснения.

Подготовка: до выполнения каждой части разобрать соответствующую тему выше; опора перечислена в A. Пример объяснения и самостоятельные данные различаются. Не требовать ещё не названные конструкции.

**Выход и переход.** Маленький самостоятельный шаг: Определить небольшую функцию и использовать её возвращённое значение в следующем действии. Следующая тема: «Локальные имена и состояние аргумента».

### 24. Локальные имена и состояние аргумента

**Основная тема и назначение.** В одном уроке различить область имён и объект: это две связанные причины эффектов вызова.

**Точка A.** Def/параметры/return и ссылки коллекций знакомы.

**Точка B.** Передаёт результаты явно, различает локальную перепривязку и мутацию общей коллекции, выбирает копию по договору.

**Проверка предпосылок.** Опора: функция/результат (23), ссылки/копии (13, 17). Новое: локальное выполнение и связь параметра с объектом; global/nonlocal не нужны.

**Предпочтительный объём теории.** **1800–2400 слов** учитываемого текста. Две связанные модели: локальное имя и общий аргумент. Нужны раздельные трассы до их сравнения.

**Необходимые темы в порядке изучения.**

1. Каждый вызов имеет свои локальные привязки; внешнее одноимённое имя не является тем же состоянием.
2. Промежуточное локальное имя снаружи недоступно: нужное возвращают через return, не global.
3. Параметр связывается с аргументом, не создаёт копию; append меняет общий список, локальное присваивание нового списка — нет.
4. Return не отменяет эффект; поверхностная копия даёт новый внешний контейнер по уже известному ограничению.
5. Явные параметры/результаты вместо скрытой общей коллекции; без closures/global/nonlocal.

**Порядок частей без скачка сложности.**

1. Локальное имя и два независимых вызова на числах.
2. Затем известный список как аргумент: общая мутация против локальной перепривязки.
3. Копия только после объяснения требуемого договора; не смешивать три варианта до первого понятного опыта.

**Основная практика.** Script на платформе; собственные вызовы определяются в нём, без обязательного solve.

1. Проследить два вызова и внешнее одноимённое значение, исправить чтение локального имени снаружи.
2. Сравнить три функции: перепривязка, append общего списка, возврат изменённой копии.
3. До/после каждого опыта проверить исходник и результат, объяснить место изменения. Эксперимент не становится командой Planner.

Подготовка: до выполнения каждой части разобрать соответствующую тему выше; опора перечислена в A. Пример объяснения и самостоятельные данные различаются. Не требовать ещё не названные конструкции.

**Выход и переход.** Маленький самостоятельный шаг: Объяснить отдельно локальное присваивание и изменение переданного списка, проверив исходник. Следующая тема: «Ошибка, причина и регрессия».

### 25. Ошибка, причина и регрессия

**Основная тема и назначение.** Сохранить отдельное первое систематическое знакомство с диагностикой до установки инструментов.

**Точка A.** Конструкции и функции знакомы; типичные сбои наблюдались, но traceback системно не разбирался.

**Точка B.** Различает синтаксис/исключение/логическую ошибку, находит причину и проверяет минимальную правку.

**Проверка предпосылок.** Опора: знакомые операции и функции (1–24). Новое: систематическое чтение traceback и регрессия; except/debugger пока не используются.

**Предпочтительный объём теории.** **1800–2400 слов** учитываемого текста. Чтение трассы, причинное исправление и регрессия; типы ошибок иллюстрируют метод, не требуют заучивания списка.

**Необходимые темы в порядке изучения.**

1. SyntaxError до исполнения, ошибка выполнения в процессе и неверный результат без исключения.
2. Traceback: тип/сообщение, последняя причина, собственные строки и путь вызова.
3. NameError/TypeError/ValueError/IndexError/KeyError/ZeroDivisionError на знакомых операциях.
4. Место чтения неверного ключа может только проявлять дефект создателя; обязательное поле не заменяют догадкой get.
5. Воспроизвести → ожидаемое/факт → значения → причина → fix → прежние случаи; сленг bug/debug/regression объяснять через действие.

**Основная практика.** Script на платформе; собственные вызовы определяются в нём, без обязательного solve.

1. Разобрать короткую трассу функции и назвать вход/строку/причину.
2. Исправить опечатку ключа нейтральной записи, потерянный return и логический подсчёт — отдельными короткими случаями.
3. Проверить ошибочный и ранее рабочий входы. Try/debugger пока не требуются.

Подготовка: до выполнения каждой части разобрать соответствующую тему выше; опора перечислена в A. Пример объяснения и самостоятельные данные различаются. Не требовать ещё не названные конструкции.

**Выход и переход.** Маленький самостоятельный шаг: По одной короткой ошибке назвать ожидание, место проявления, причину и проверку исправления. Следующая тема: «Python и VS Code на компьютере».

### 26. Python и VS Code на компьютере

**Точка A.** Платформенный Python понятен; локальных инструментов нет.

**Точка B.** Проверяет установленный Python 3.12/VS Code, отличает PowerShell от Python-оболочки, выполняет знакомый код локально.

**Проверка предпосылок.** Опора: Python-код и диагностика (1–25). Новое: файлы/пути/терминал/исполнитель; локальных Git/main.py ещё нет.

**Предпочтительный объём теории.** **1800–2400 слов** учитываемого текста. Первый компьютерный контекст: программа/редактор/файл/папка/команда/оболочка и диагностика установки.

**Необходимые темы в порядке изучения.**

1. Python исполняет, редактор редактирует, расширение помогает и не заменяет интерпретатор.
2. Официальная установка/проверка версии; launcher/PATH зависят от ОС и не являются кодом Python.
3. До команд объяснить файл, папку, расширение .py и путь. Терминал принимает команды программ, Python-оболочка принимает выражения; текущая папка влияет на поиск файла. Показать просмотр/смену папки и кавычки для пути с пробелами, затем приглашения терминала/>>> и выход обратно. Оболочка сама отображает результат выражения: это не доказательство print внутри функции; присваивание результата позволяет отделить автоматический показ от печати.

5. Команда не найдена, неверный путь и ошибка Python диагностируются по разным признакам.

**Основная практика.** Локальная установка и оболочка Python; репозитория и main.py ещё нет, отдельный пробный проект не создаётся.

1. По разобранному безопасному пути установить/проверить инструменты и версию, найти текущую папку; запускать команды только после объяснения их роли. Затем открыть Python-оболочку и выполнить знакомые выражения.
2. Закончить оболочку и выполнить команду терминала, объяснить разницу двух приглашений.

### 34. Input, ValueError и безопасный повтор

### Правила последующего авторства

1. A следующего занятия — накопленный выход предыдущего, а не будущий исходник целиком. Концепт задаёт план, но не доказывает внедрение/освоение.
2. Сохранить теорию назначения и механизма, типичные ошибки, прогноз/трассу/исправление/самостоятельное действие. Сокращены уроки и дубли, не объяснения новичку.
3. Основная практика проверяет только объяснённое. Не превращать каждый короткий эксперимент или проверку прежней функции в отдельное занятие.
4. Модельные операции, ввод и вывод имеют названные роли. Не добавлять новый продукт/схему/технологию ради объединения.
5. Продолжается один repo/main.py. Краткие контрольные аргументы проверяют настоящую функцию, не заменяют основной tasks. Секреты/.venv не публикуются, destructive Git-команды не нужны.
6. При локальной проверке объяснить `-i`, выход из run и `>>>` до использования; локальный tasks не становится доступным снаружи сам. Наблюдать его debugger или проверять функции краткими явно заданными аргументами, без return tasks/globals ради проверки.
7. При внедрении согласовать стабильные идентификаторы, порядок, frontend, каталоги практики, ссылки и сохранение прогресса. Таблица прежних номеров служит миграции концептов, не командой перезаписать пользовательский прогресс.
