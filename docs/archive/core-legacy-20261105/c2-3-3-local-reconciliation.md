# PYM-192: локальная сверка подготовленной копии

Статус: **в работе**. Прогон 06.11.2026 выполнен только локально; production и сервер не менялись.

Подготовленная отдельная SQLite-копия прошла `quick_check` и проверку связей. Перед проверкой по решению владельца из копии удалена одна запись прогресса с отсутствующим владельцем. Операция проверена на синтетике, удаление выполнено одной транзакцией; все остальные строки 15 таблиц сверены. Оригинальная SQLite открывалась только для чтения и не изменялась.

Импортёр выполнил dry-run, запись и повтор в отдельной PostgreSQL. При повторе он сравнил каждое отображённое поле всех 15 таблиц: всего **471 строка** после согласованного удаления. Это включает ID, хэши паролей, роли, подписки, прогресс, записи календаря, бронирования и состояния outbox. Повтор не создал новых записей. Подготовленный SQLite-файл побайтово не изменился в ходе прогона.

Четыре существующие сессии проверены через PostgreSQL и выделенный Redis. Это проверка предъявления уже существующих токенов, не вход по паролю или тест интерфейса. В источнике outbox не оказалось неразрешённых статусов; `sent` подтверждает только сохранённое состояние записи, а не реальную доставку. Отправитель и внешние сообщения не запускались.

Условие прогона: даты SQLite без смещения явно трактовались как UTC, как в текущих частях legacy-кода; историческое происхождение каждой даты отдельно не подтверждено. Команда apply заняла **5,76 с** вместе с запуском CLI, проверками ACL и подготовкой Redis, без создания контейнера. Это не нагрузочный тест и не оценка сервера.

После прогона Redis-ключи тестового пространства удалены адресно, отдельные тестовый контейнер и том с копией удалены, прежняя synthetic PostgreSQL восстановлена и проверена. Подготовленная исходная копия остаётся в закрытом локальном каталоге.

Дополнительно на полностью синтетических данных пройден двухрежимный API smoke: **8 тестов**, включая вход, прогресс, задачи, бронирование и восстановление доступа после выхода. Это проверка через тестовый HTTP-клиент, а не браузер и не проверка этих действий на перенесённой пользовательской копии. Предыдущая версия проверки ожидала старый ключ Redis; тест обновлён под фактический prepared-key и повторно прошёл на отдельной PostgreSQL с Redis. Прежняя синтетическая база восстановлена. Использованные синтетические контейнеры остановлены; некоторые синтетические тома сохранены.

Ещё не выполнены парольный login/refresh и пользовательские сценарии progress/booking/edit на перенесённой копии через интерфейс, полный набор интеграционных проверок и сценарии восстановления/удаления данных, включая tombstones. Решение о сроках хранения резервных копий остаётся в PYM-426. Этот отчёт не подтверждает готовность к VPS или релизу.
