## IMPACT: конкретные изменения dispatch / acceptance

1. **Единый preflight-пакет владельца очереди.** До массового dispatch передать W1 список всех N уроков, stable IDs, входные концепты с точной revision (если redirect — разрешённый Git HEAD), A/B, исключения диапазона и границы write lease. W1 возвращает короткий inventory + blockers; root сверяет N/N один раз и не повторяет предметную инвентаризацию.
2. **Идемпотентные назначения и восстановление по событию.** Сохранять `lesson → worker → phase → status → last confirmed artifact` в run journal, повторный запуск только после подтверждённого error/terminal state. W1-R наследует незавершённый остаток, а не переписывает принятую работу; browser и model bootstrap не повторяются без изменения среды/ошибки.
3. **Содержательный контракт REWORK/KEEP.** От worker на каждую существенную правку требовать `было → наблюдаемый дефект → стало → проверяемое действие ученика`. Для нетронутого хорошего объяснения разрешать обоснованный KEEP. Замена `<p>` на `<TrueFalse>`, перемещение текста или снятие номера заголовка не считается улучшением B без нового различающего задания.
4. **Root принимает evidence, вмешивается только по исключению.** Работник сам заканчивает P4/M5 в своём scope и возвращает до 150 слов с artifact paths, N, checks, defects, blockers. Root сверяет покрытие, write lease и совместимость интеграции; дополнительное предметное чтение только при конфликте evidence, непрошедшем контракте или явном запросе. Разделять штатное acceptance от исправления сквозных API/catalog ошибок, которые обоснованно принадлежат root.
5. **Педагогическая приёмка отдельно от сборки.** Пара `до/после` и независимый перенос знания обязательны для REWORK; `tsc`, build и наличие компонентов подтверждают лишь технику. Признак качества интерактива — объяснение принципиально разного результата/ошибки, а не его присутствие. Проверять соседство элементов, чтобы не образовывались повторяющиеся `TrueFalse → Note → TrueFalse` и визуалы без функции.
6. **M5 как матрица наблюдений с честным PARTIAL.** Для каждого урока фиксировать `backend / frontend / API / page+adaptive / manual+runner` с командой, результатом, ошибкой и средой. После shared-регистрации выполнять один адресный интеграционный тест. Если browser/runner блокирован, передать владельцу среды точный repro и оставить `STAGE_INCOMPLETE`; не бесконечно пробовать одинаковый браузерный маршрут и не считать частичный PASS завершением.
