# Итог обновления инфраструктуры Stage 2/3

**Последующее уточнение пользователя:** правило постоянных очередей на исполнителя отменено. Один агент получает ровно одно занятие на полный P1–P4/M1–M5; после результата/блокера останавливается. Следующее занятие получает отдельного агента. Обновлены Skill, общие и локальные AGENTS/README, профили, RUN_TEMPLATE и payload helper. Три regression-теста helper и разбор двух TOML повторно PASS. Описания первоначальной схемы ниже сохраняются как история и не разрешают выдавать несколько занятий одному агенту.

**COMPLETE — инфраструктура и методички.** Реальные занятия в этой задаче не запускались и не исправлялись. Исторический Stage 3 остаётся `STAGE_INCOMPLETE`, M5 COMPLETE 0/10; этот документ не закрывает его.

- Общий Skill, AGENTS, два native профиля, README и методички P1–P4/M1–M5 согласованы. Исходный чат остаётся единственным Coordinator. Постоянные Web-очереди работают автономно; root отвечает за запуск, зависимости и компактную приёмку результата. Подробные инструкции читает исполнитель без дублирования в root.
- CREATE/REWORK и восстановление RESUME разделены. Для переработки требуется связь исходного дефекта, смысловой правки и самостоятельного действия ученика; качественные части допускают KEEP. Косметический diff не доказывает улучшения.
- Простые точные объяснения, развитие практики, учебный ритм и оправданное соседство компонентов входят в приёмку. Лимит двух абзацев не служит поводом для механических цепочек визуалов/интерактивов.
- Ошибка приёмки возвращается адресным поручением; повторяемая причина кратко уточняет следующий dispatch. Сохраняются P4, четыре PASS M5, N/N и честный статус непроверенной среды.
- Helper формирует native `spawn_agent` payload, проверяет настоящий effective `pool` и право High. Он не создаёт пользовательские чаты, не выполняет уроки и не изменяет политику.

## Доказательства и ограничения

[AUDIT.md](AUDIT.md) — факты прошлого запуска, полезные вмешательства и избыточная работа root; [CORE.md](CORE.md), [PLAN.md](PLAN.md), [MAIN.md](MAIN.md) — изменения и проверки авторов; [VALIDATION.json](VALIDATION.json) — итог границ интеграции.

[Три regression-теста](test_core_dispatch.py) PASS, с позитивными/негативными subcases, обоими stages и реальным CLI file-to-file. Формальные учебные кейсы — NOT_RUN, учебный эффект и экономия токенов — NOT_MEASURED. Штатный skill validator недоступен из-за PyYAML; выполнены независимые структурные проверки. Hook trust/enforcement не подтверждены; наличие настроек не объявляется активацией.

Основную работу выполнили четыре native Web-исполнителя. Повторная адресная доработка CORE завершилась ошибкой capacity после сохранения исправлений; root подтвердил результат проверками, другую модель не запускал. Исходная приёмка CORE/PLAN/MAIN и аудит получены. PLAN после готового результата был закрыт на дополнительном необязательном сообщении с выводами аудита; повторная содержательная работа PLAN не заявляется выполненной.

В задаче применён временный full/Web-only/max5 override текущей сессии. После завершения override снят штатной командой `session --overrides reset-override.json`; ответ подтвердил возврат базовых balanced / total 8 / Web 5. Базовый `orchestrator.toml` не переписан. Пользовательское предпочтение full/Web для будущих запусков Stage 2/3 закрепляется в scoped AGENTS и применяется заново как task override. Доверие hooks не изменялось. Коммиты, публикация и автоматический запуск нового stage не выполнялись.
