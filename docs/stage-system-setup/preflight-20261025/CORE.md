## Исправлено

Все исполнители/интеграторы/проверяющие — `chatgpt-web/gpt-6-sol` / `high` с подтверждением живым инструментом.
- [AGENTS.md](../../make%20les%20stage/AGENTS.md) и [BATCH_WORKFLOW.md](../../make%20les%20stage/BATCH_WORKFLOW.md) считают **не более пяти одновременно активных Web/browser turns глобально**, включая чужие Web-задачи; оркестратор отдельно. Отказ общей ёмкости сохраняет задания в очереди до подтверждённого освобождения, без бесконечных повторов, смены модели или закрытия чужих чатов.
- Оркестратор получает краткие доказательства, пути, версии и блокеры; каждый исполнитель читает **полную актуальную методичку своего прохода** до зависимого действия. Опись детерминирована по COURSE/BLOCK/паспортам, включая строковые номера и отсутствующие обязательные подзанятия.
- Для общих физических файлов закреплён **один lease записи** с владельцем, fingerprint, очередью дельт и подтверждённым освобождением; lease независим от Web-слота. [RUN_TEMPLATE.md](../../make%20les%20stage/RUN_TEMPLATE.md) содержит поля фактической модели, ёмкости, отказов и lease. Уточнены восстановление, адресные исправления и повторные проверки после изменения версии.

**Приёмка сохранена:** stage 2 — P1–P4 и `PLAN_ACCEPTED`; stage 3 — M1–M5, `COMPLETE` и четыре актуальных PASS (backend, frontend, фактическая выдача, открытая страница/runner). `STAGE_COMPLETE` только при `N_expected = N_accepted`, интеграции и отсутствии обязательных блокеров. Недоступные API/browser проверки дают `STAGE_INCOMPLETE`, а не предполагаемый PASS.
