## CHANGES

- Проход теперь описан как содержательная работа над тем же артефактом; предыдущие P/M не проходят полную повторную проверку без изменения или конкретного дефекта. Источники читаются перед зависимой работой, с возвратом при изменении/пробеле.
- `REWORK`: назвать наблюдаемую проблему и ожидаемое изменение действий ученика, затем рано исправить текст или практику. Компактный прогресс фиксирует только существенную правку, `KEEP` и исключение; таймеров и diff-квот нет.
- Удалены из stage-specific README/AGENTS старые фиксированные Web-пулы, постоянные контексты, личные очереди и batch-отчёт с лимитом слов. Сохранено правило один исполнитель — одно занятие — полный stage; следующее назначается отдельно.
- M5 сохраняет предметную приёмку и **все четыре PASS**. Добавлено разделение локальной проверки урока и общих технических зависимостей: доказательство можно переиспользовать только при совпадающей revision/зависимостях; после правки повторяется только затронутое. Недоступные browser/runner проходят одну диагностику, затем фиксируется точный actionable blocker; редактирование продолжается, итог остаётся `PARTIAL` при недоступном обязательном уровне.
- Проверка качества по-прежнему включает простое точное объяснение, самостоятельное действие на diagnosed defect, обоснованный `KEEP`, визуально-текстовый баланс и недопущение косметической подмены учебного эффекта.

## SOURCE_EVIDENCE и актуальность

- Локальная база: `docs/make les stage/2 stage/README.md`, `AGENTS.md`, P1–P4; `docs/make les stage/3 stage/README.md`, `AGENTS.md`, M5; общий `BATCH_WORKFLOW.md`. Ранее просмотренные требования подтверждают одно занятие на исполнителя, финальный P4/M5, scoped повторные проверки и четыре PASS; новые правила уточняют стоимость повторного процесса и совместное использование доказательств.
- Текущие project-specific model/pool значения не перенесены в методики; runtime и лимиты направлены к effective task policy. Общие файлы вне зоны этой работы не редактировались.
- Основание заявленного четырёхчасового запуска — пользовательское наблюдение; независимые логи этого прогона в доступном baseline не исследовались. Поэтому причины бюрократии проверены по тексту инструкций, но причинный вклад в elapsed time не измерен.
- Внешние docs/research/community не использовались: задача ограничена согласованием локальных методик; эффекты от процесса требуют пилота.
