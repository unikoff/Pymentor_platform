Нельзя считать этот ключ интегрированным или Stage 3 принятым без новой фактической проверки. Рабочее дерево общее и содержит изменения других задач; они не приписываются автоматически этому ходу.

Удачные элементы: отдельный автор на урок, локальная предметная готовность, параллельная интеграция готовых дельт, одна общая финальная приёмка и сохранение blockers. Оставить скорость и качество важнее минимального числа действий.

Кандидаты на экономию контекста: общую повторяющуюся часть назначений хранить один раз в проектном контексте запуска; передавать на урок только различия при подтверждённом доступе к инструкциям. Использовать многоточечный event wait и не выводить одинаковые полные логи, сохраняя конкретные ошибки/evidence. Перед восстановлением интегратора сверять только соответствующий ключ/версию. Эти изменения не являются fine-tuning модели и не гарантируют экономию.

Сравнительный pilot — NOT_RUN: на сопоставимом массиве фиксировать реальное время, измеримые токены/квоту при доступности, coverage P4/M5, качество и количество повторных правок. Считать candidate, а не подтверждённым улучшением до проверки; локальные примеры и чужие приватные данные не переносить в глобальную память.
