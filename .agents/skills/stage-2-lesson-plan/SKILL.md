# Stage 2: план одного занятия

В пользовательском форке выполни только Stage 2 одного конкретного занятия. Полные содержательные требования восстановлены из `76fc57bf0`: [Stage 2](../../../docs/make%20les%20stage/2%20stage/README.md). Читай полную методичку текущего шага; skill не заменяет требования к глубине, примерам, практике и планируемому визуалу. Не удаляй полезный визуал только потому, что его можно пересказать текстом.

Установи цель по последнему актуальному поручению: курс, глава/блок, одно занятие, паспорт COURSE/BLOCK, A с источниками, B, формат и глубина, один целевой MD. История родительского чата, старые очереди и ответы не меняют назначение. ID устанавливай по источнику, будущий runtime ID не выдумывай. Список занятий не превращай в очередь: до записи нужна однозначная цель. Отсутствие действующего паспорта обозначь как зависимость от отдельного Stage 1.

Прочитай [общие правила](../../../docs/make%20les%20stage/AGENTS.md) и [маршрут P1–P4](../../../docs/make%20les%20stage/2%20stage/STAGE_FLOW.md). Все внутренние методички и шаги сохраняются и выполняются тем же чатом без отдельных назначений. Явно ограниченный шаг или аудит без правок остаётся в его границах.

С начала Stage 2 применяй [требования понятности](../../../docs/make%20les%20stage/1%20stage/02_BLOCK_CONCEPT.md#проверка-инструментов-и-исходных-знаний): действие ученика связано с опорой, полным примером/визуалом и наблюдаемым результатом. Уточняй эту связь в существующем плане и материале, без нового реестра на каждом шаге. Условие объясняет задачу простыми словами, ТЗ технически задаёт её по порядку, неизвестные средства подготовлены до обязательного применения. Планируй учебную функцию визуала и немедленную оценку при его создании на отдельном Stage 3; P4 не подменяет будущий осмотр реализации.

Сохрани один MD-план и выполни полную P4 на его итоговой версии. PLAN_ACCEPTED относится к плану, не к будущим TSX, практике, runner или странице. Форк не изолирует общие файлы и Git: меняй только свой разрешённый MD, сохраняй чужие правки и не очищай общий diff. При конфликте той же записи сохрани дельту и продолжи независимую работу. Непроверенное не является PASS.

После приёмки или конкретного блокера сообщи занятие, путь результата, фактические проверки и остаток. Не начинай другой урок, следующий Stage или создание новых чатов/форков. Для продолжения своего урока используй сохранённые файлы без повторной генерации готовых частей.
