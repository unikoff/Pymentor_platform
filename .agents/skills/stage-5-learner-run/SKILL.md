# Stage 5: ученик и ревью

Прочитай [общие правила](../../../docs/make%20les%20stage/AGENTS.md) и [методичку Stage 5](../../../docs/make%20les%20stage/5%20stage/STUDYHUB_WORKFLOW.md). Один чат проходит весь назначенный диапазон внутри главы, без отдельного аналитика/очереди: теория → практика → развитие одного проекта → знания/ревью → коммит занятия → следующее занятие без команды «дальше». Неполные обязательные результаты и реальные ограничения не скрывай; материалы курса в проходе не редактируй.

До задачи сверяй изученные опоры; пробелы и помощь отмечай. Код и README приложения — `project/`, знания — `knowledge.md`; локальный `review.md` игнорируется и не отслеживается. В main.py нет архива решений и служебных проверок. При необъяснимом отказе checker сохрани точный отправленный код, видимый ответ и источник/версию в review.md; один отказ не доказывает баг курса. После двух попыток без новых данных прекрати угадывание и продолжай независимое.

Git: только назначенная `chapter/NN/vN`, отдельный коммит занятия с проверенным index через `git commit -m` без pathspec. Правила процесса и чужие изменения не смешивай с уроком. Push своей ветки после блока; перед проверкой опубликованного SHA/clone, включая 20.1, — раньше без нового подтверждения. main хранит принятые снимки, исполнитель её не меняет. Вход A, версия и границы — в CHAPTERS.md; итоговый B передаётся на отдельную приёмку. Главы последовательны, новая версия начинается от A, следующая глава — от принятого B предыдущей.

VS Code заменяй настоящими файлами/Python, Postman — агентом/CLI/HTTP-клиентом без обязательного Computer Use. Реальный результат проверяй; чисто интерфейсный шаг допускает SIMULATED_UI без PARTIAL лишь из-за GUI. Замену кратко отмечай, не объявляя её знанием ученика или дефектом курса. Явную остановку соблюдай.

После двух неудачных попыток или зацикливания разрешён один read-only консультант на проблему `gpt-6.1-terra / medium`, без наследования диалога (`fork_context=false`). Сверь текущую схему штатного инструмента; передай короткие обычные условия, факты и попытки. Он не меняет файлы/Git/прогресс и не делегирует. Примени совет, проверь, отметь помощь и закрой помощника; точные параметры, одно уточнение и восстановление ошибки вызова — в методичке.

Проверяй изменённое и обязательное, используй уже полученное свидетельство вместо повторных прогонов. Браузер читай адресно, сохраняя свежие состояния по правилам инструмента. После прерывания сверяй текущую точку с Git; не повторяй существующий коммит из-за старой записи. В сводке — следующее учебное действие, а не ещё не созданный собственный SHA. При сдаче отдельно укажи результат проекта, неподтверждённые проверки и существенную помощь; READY_FOR_ACCEPTANCE не означает принятия в main или самостоятельного PASS всех заданий.
