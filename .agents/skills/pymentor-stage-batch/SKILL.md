# Массовый Stage 2/3

Исходный чат остаётся единственным Coordinator. Один исполнитель получает **ровно одно занятие и весь его stage**, исправления/RESUME этого занятия допустимы; список из нескольких уроков одному автору запрещён. Опись и общая интеграция — отдельные служебные задания, а не дополнительные оркестраторы.

Модель, усилие и ёмкость — из effective policy центрального `C:/Users/Unik/.codex/orchestrator.toml`; запрос пользователя уточняет её через штатный session override. Порядок: `C:/Users/Unik/.codex/skills/orchestrate-codex/references/settings.md`. Не подменяй явное ограничение старым предпочтением Web/full. Native профили [PLAN](../../../.codex/agents/pymentor-plan-worker.toml) и [MAIN](../../../.codex/agents/pymentor-lesson-worker.toml) закреплены за Sol Web/high; при несовместимой policy нужен разрешённый маршрут с фактическими инструкциями, а не обход или ложное объявление модели. Spawn ID не является телеметрией модели; доверие hooks не следует из наличия файла.

Канон запуска: [BATCH_WORKFLOW](../../../docs/make%20les%20stage/BATCH_WORKFLOW.md), [общий AGENTS](../../../docs/make%20les%20stage/AGENTS.md), [Stage 2](../../../docs/make%20les%20stage/2%20stage/README.md), [Stage 3](../../../docs/make%20les%20stage/3%20stage/README.md). Не загружай все источники в root: работник читает относящиеся к своему действию документы один раз, перечитывает изменённое или недостающий фрагмент.

1. Установи stage, диапазон и разрешённые файлы. Используй существующую достоверную опись; при её отсутствии собери одну компактную опись N, ID, источники/A–B, цели и зависимости. Отдельный preflight-агент не обязателен. Не задерживай готовые независимые занятия из-за чужого неполного входа; незавершённые остаются в N.
2. Выдай каждому автору один lesson ID, его пути, CREATE/REWORK/RESUME, наблюдаемый дефект или цель B, конкретный ожидаемый результат и доступные проверки. [build_dispatch.py](../../../scripts/build_dispatch.py) пакует native assignment без чтения полного payload root. Один автор проходит P1–P4 либо M1–M5, без новых делегатов на каждый проход.

   Для массива с одинаковыми входами сохрани один короткий общий контекст запуска в RUN или соседнем файле: запрос, источники/revision, общие границы записи, средовые ограничения и критерии. В личное назначение передай путь и различия конкретного урока: ID, целевые пути, дефект/цель и владение. Роль и skill должны быть реально доступны исполнителю через поддерживаемый выбор или чтение; ссылка не доказывает загрузку. Если чтение файла недоступно, передай нужное содержание явно. Это кандидат на сокращение дублирования; эффект на токены ещё не измерен.
3. Сначала содержательная работа. Для REWORK прочитать достаточные источники → исправить объяснение/практику → проверить эффект. Не делать отдельные исследование, план приёмки и набор отчётов перед первой правкой. В назначении задавай ориентир первого сохранённого смыслового результата; время учитывай по фактическим timestamp, отделяя задержку модели/инструмента от работы. Отсутствие прогресса требует конкретного блокера, а не новой перепроверки.
4. Автор проверяет только своё изменённое и возвращает `PLAN_ACCEPTED`, `LOCAL_READY`, `PARTIAL` или `BLOCKED` с путями и одним примером результата. `LOCAL_READY` в Stage 3 значит: предметные M1–M5 и доступные локальные проверки завершены, общие уровни M5 ещё ожидаются; это не COMPLETE. Объяснение, практика и перенос знания оцениваются отдельно от сборки; KEEP хорошего материала допустим.
5. Когда готовы артефакты, один назначенный владелец интегрирует общие файлы и выполняет общие backend/frontend/build/API проверки **один раз на итоговом наборе**, с поурочным покрытием. Осмотр страницы и прогон каждой обязательной задачи остаются поурочными, но браузер/runner поднимаются один раз на среду. Все четыре уровня M5 обязательны; общий PASS можно сослать на несколько уроков лишь при доказанном покрытии, одинаковой версии и зависимостях. Подробности — канон протокола.
6. Root принимает итог и N/N один раз; не повторяет работу исполнителя и не назначает второго ревьюера по умолчанию. При дефекте — адресный REWORK с ожидаемым эффектом, повторить только затронутые проверки. Не повторять успешный тест на неизменном наборе. Средовой отказ — одна диагностика и воспроизводимый blocker, доступное редактирование продолжается; ложный PASS запрещён.

Один [RUN](../../../docs/make%20les%20stage/RUN_TEMPLATE.md): урок, владелец, артефакт/версия, состояние, проверки/блокер. Ожидай завершение событиями/ограниченным wait, без статусных ping и чтения промежуточных диалогов. Неизвестный исход spawn не равен завершению; переназначение только после сверки состояния. Не расширяй права, не запускай следующий stage или публикацию автоматически. `STAGE_COMPLETE` только при N/N, P4 либо всех четырёх M5 PASS на итоговых версиях.

Для нескольких работающих агентов используй один многоточечный `wait_agent` или доступный event wait для подходящих ID. При неизменном состоянии увеличивай разумный интервал ожидания в пределах инструмента; готовое событие обрабатывай сразу и заполняй освободившийся слот без ожидания волны. Не печатай полный payload, отчёты или логи в контекст root, когда достаточно статуса, путей, остатка и ссылки на evidence; конкретный FAIL и обязательные условия не обрезай. После прерывания интегратора проверь точный ключ и версию перед повтором; неизвестный перенос не равен успешному. Сверка `False` остаётся дефектом интеграции, а не COMPLETE.
