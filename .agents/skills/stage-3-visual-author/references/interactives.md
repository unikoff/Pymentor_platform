# Интерактивы: действие, результат, объяснение

Открывай только для интерактива. Выбери учебный вопрос и различающий случай до выбора компонента. Новое обязательное знание объясняется до проверочного действия; подсказка и ответ не заменяют теорию.

## Выбор по задаче

| Нужно | Компоненты | Важное ограничение |
| --- | --- | --- |
| Предсказать вывод | PredictOutput | Раскрытие ответа не проверяет введённый учеником ответ |
| Проследить выполнение | StepThrough | Просмотр трассы не доказывает самостоятельное написание кода |
| Выбрать причину/проверить границу | QuizCard, TrueFalse, BugHunt | Ошибочные варианты отражают правдоподобную ошибку, разбор объясняет причину |
| Восстановить порядок или связи | CodeSequence, MatchPairs | Порядок действительно значим; несколько допустимых ответов нельзя объявлять единственным |
| Исследовать изменение | BranchExplorer, SliceExplorer или локальный компонент | Ввод/выбор меняет содержательный результат, а не только подсветку |

Контракты: [code-demos.tsx](../../../../frontend/src/lessons/components/code-demos.tsx), [questions.tsx](../../../../frontend/src/lessons/components/questions.tsx), [code-exercises.tsx](../../../../frontend/src/lessons/components/code-exercises.tsx), [explorations.tsx](../../../../frontend/src/lessons/components/explorations.tsx). Читай выбранный компонент, не весь каталог. Новый локальный интерактив нужен, только если существующий не выражает нужное действие и область записи это допускает.

## Пример: различить строгую границу

Применим после объяснения сравнения, с вопросом, независимым от практики. Не создавай второй такой же вопрос рядом, если вывод уже проверен.

```tsx
import { QuizCard } from "../../shared";

<QuizCard
  question="Температура равна 0. Выполнится ли ветка с условием temperature < 0?"
  options={["Да: ноль относится к этой ветке", "Нет: условие требует число меньше нуля"]}
  correctIndex={1}
  explanation="Ноль равен границе, но не меньше неё. При -1 условие истинно, при 0 ложно"
/>
```

У текущего QuizCard один выбор блокирует варианты, а explanation показывается и при ошибке, и при правильном ответе. Поэтому разбор должен быть полезен в обоих случаях. Не обещай повторную попытку, отдельные explanations для каждого варианта или проверку свободного ввода, которых компонент не поддерживает.

## Пример: состояние после шага

```tsx
import { StepThrough } from "../../shared";

<StepThrough
  code={'price = 80\nprice = price - 5'}
  steps={[
    { line: 0, note: "Сохраняем начальную цену", vars: { price: "80" } },
    { line: 1, note: "Вычитаем пять из прежнего значения", vars: { price: "75" } },
  ]}
/>
```

В StepThrough line — индекс строки с нуля, vars — значения после её исполнения. Сохраняй ранее введённые переменные в полной трассе; если показываешь лишь часть, явно назови это. Многострочный code/output передавай JSX-выражением со строкой JavaScript, а не атрибутом с буквальными символами обратной косой черты и n. Для PredictOutput требуется точный stdout, включая конечный перевод строки, когда он значим.

До реализации подготовь всё фактическое содержание: данные, варианты и причины правильности/ошибок; для изменения параметра — начальное значение, допустимые значения и правило результата. Объяснение реакции опирается на подготовленный механизм и данные примера. Свободное исследование не называй проверкой ответа, если компонент не принимает и не оценивает его. Полный [контракт учебного визуала](../../../../docs/make%20les%20stage/3%20stage/04_VISUAL_INTERACTIVE.md#создание-визуала-с-немедленной-приёмкой) используется в рабочем контексте без нового файла.

## Содержательная и визуальная проверка

Проверь обычный и существенный различающий случай: действие ученика → ожидаемое состояние → объяснение. Ответ не угадывается по длине или нелепым альтернативам. Условие, стартовые значения, подсветка строки, вывод и переменные согласованы. Не добавляй будущую конструкцию ради эффекта и не собирай точное решение практики через CodeSequence, BugHunt.fix или разбор.

На странице проверь первоначальный вид, неверный и верный выбор (при блокировке с отдельного сброса/перезагрузки своего примера), раскрытие и переходы по применимости. Не предполагая сохранение, проверь нужный заданием сброс; это не требует изменения прогресса аккаунта. Кнопки доступны клавиатурой, фокус виден, причина ошибки понятна без цвета. Код, варианты и разбор читаются в широком, разделённом и узком контейнере. Если добавлено больше действий, чем нового понимания, упрости интерактив.
